# Archived Reports Authoring Contract

Owner: `team-docs`
Applies to: `docs/archive/reports/**`
Last updated: 2026-05-05

## Purpose

This subtree stores reviewed evidence reports, inventories, audit summaries,
acceptance records, and small machine-readable evidence cited by docs, plans,
ADRs, or gates.

## Allowed File Categories

- Markdown reports, reviewed JSON/TOML evidence, benchmark report summaries,
  README/AUTHORING/index docs, and report-family subdirectories.
- No raw logs, full local transcripts, bulky run outputs, secrets, or
  production data.

## Public/Private Boundary

Everything committed here is public repository evidence. Sensitive or bulky
source material stays in ignored local roots and is summarized/redacted before
promotion.

## Naming Convention

Prefer `YYYY-MM-DD-<topic>.md` for new reports. Existing phase report names may
retain `UPPER_SNAKE` plan identifiers when cited by active plans.

## Test Location

Docs and repository-quality tests under `tests/repo_quality/` validate cited
reports, generated inventories, and lifecycle policy.

## Fixture/Data Policy

Evidence JSON/TOML must be small, reviewed, and tied to a producer or source
inventory. Large datasets and raw benchmark outputs stay out of this subtree.

## Generated File Policy

Generated reports must state the generator command and source inventory. If a
report is regenerated, update it atomically with its source contract.

## Extension Points

No executable extension points live here. Extension evidence may link to
`examples/extensions/` and `architecture/extension_points.toml`.

## Deprecation And Shim Policy

Historical reports remain immutable unless regenerated by their named tool.
Supersede stale reports by adding a newer report and linking it from the owner
plan or reference page.
