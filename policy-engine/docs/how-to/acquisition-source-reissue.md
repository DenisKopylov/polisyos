# Acquisition source reissue and native admission fencing

Original E02 V3 and G decision `AD-E02-B09-01` distinguish an admitted source
occurrence, a candidate's semantic identity and an actual evaluation occurrence.
The source owner replays each historical record under its persisted job after
verifying the caller's unchanged run, tenant and cell. That job is a parser
selector, never a grant to read another case. A selected prior evaluation also
binds the exact candidate/atom, selected context and actual N5 input world.
The optional in-memory WMR field is not evidence: persisted simulations may omit
it, so replay resolves the real selected N5 owner input.

For supported V3/V5 sources, ordinary acquisition reentry reuses the selected
persisted N4 proposal. It recomputes its candidate occurrence in the actual new
context and runs the real N5; it does not ask a new stochastic N4 call to preserve
a candidate by coincidence. Root V3 lineage may cross worker jobs only after
replaying both source/context/declaration owners and matching stable subject,
semantic identity, candidate and profile selection. Legacy source versions stay
readable and use their conservative existing generation path. Missing, foreign
or mismatched source/context/input bytes do not become a reissue claim.

Missing CGF disposition remains `grounding_unavailable`. Where the actual
candidate, problem and requested authority are available, the existing grounding
coverage owner now receives those bindings and emits an unsatisfied routing-only
requirement. It never grants grounding. After a real reentry cycle, the maintained
N7 compiler/planner produces its current report; the old route report cannot
substitute for that new requirement. Planning here does not automatically dispatch
another provider or satisfy a missing external input.

Every maintained native overlay DB mutator shares one physical-file admission
fence. Nested calls on the same thread/physical overlay are reentrant; every
other thread/process waits, including a worker with a copied live context.
Runtime performs sync-to-async/N5 work outside this short native fence and
re-resolves the complete selected native projection and source action fold
under the fence before emitting the re-entry artifact. A separate operation
lock protects only recovery pointers. It grants no native exclusion. The
existing action-job lease, route predecessor and candidate/task frontier remain
the SQL owner's conditional transaction. A future retained terminal must hold
the native fence through that SQL commit; the present re-entry-artifact fence
does not by itself establish a retained-terminal commit contract. The native
fence covers maintained mutation APIs, not external law, unmanaged direct SQL
or arbitrary filesystem corruption. The backend is the existing macOS/Linux
POSIX flock profile.

Pattern pass: P02 reuses real compiler/N4/N5 owners; P05 keeps run/tenant/cell and
worker scopes distinct; P07 replays prior inputs; P29 tests actual served source
consumption and native mutator exclusion; P37 never promotes a selector or missing
CGF marker into authority. This is a source proposal with runtime UNRUN, not full
V3, evaluation equality, a retained terminal/history v3, currentness or G closure.
The complete consumed-basis and retained-history mechanism remains separately
required by the same original V3 criteria.

## Source refresh and the current requirement

The original completed Core job and its persisted, independently replayed N7
compiler/planner/cost route bind the permitted acquisition intent. The current
source cycle is a separate selection obtained by the actual action-head fold.
A source refresh continues that cycle's design problem; it does not apply an
unexecuted N6 design revision. Only selected, content-bound re-entry receipts
which pass event, predecessor, growth and append-only continuation validation
provide such a transition. The production bridge binds the exact Control service to its actual store,
control store, event log and action sink, constructs the canonical route owner
for the actor, and resolves it again. The controller accepts the bound Control
service, derives its actual current action job from the execution context, and
constructs the route reader internally with that service's exact source/event/
action owner chain and the same runtime CAS. It accepts no supplied reader,
callback, receipt, or caller-selected historical job alternative. A constructed
`VerifiedAcquisitionRouteClosure` is not authority.

A current missing-CGF requirement remains unsatisfied. Reusing the historical
source-acquisition intent neither adds a fictitious data distribution to that
requirement nor establishes grounding. The actual new N6 cycle runs its current
compiler/planner again; provider dispatch remains a separate authorized action.
This bounded re-entry mechanism does not implement semantic-equivalence
retention, its new terminal/history versions, or full V3 closure.
