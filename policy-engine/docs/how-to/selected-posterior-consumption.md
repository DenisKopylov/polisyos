# Consume a selected posterior candidate

`propagate_selected_posterior_summary` in `polisyos.foundry.calibration.uncertainty_adapter` is a candidate-only path from an exact selected posterior summary to the existing Monte Carlo consumer. Supply the real artifact store, the profile-bearing summary ref, the separately retained profile-bearing method-evidence ref from the intended producer context, the named point role, the evaluator, and the selected axes. The adapter snapshots both ref identities, fresh-reads the summary and its method result/evidence through the existing selected reader, reconciles the evidence identity and role, requires the nested method-result manifest profile, and only then runs the evaluator. The existing legacy summary reader continues to accept profileless result references when its strict selected-result option is not requested. It also accepts valid JSON-shaped mapping manifests through the existing Core manifest owner. Both selected evidence and summary are read with their complete ref and raw sidecar; the optional profile-only resolver is not required. The result remains gate-ineligible and its unit binding remains `not_established`.

A mismatch or missing selected profile is refused before evaluation. The direct `MonteCarloPropagator.propagate_posterior_summary` method remains supported for caller-supplied candidate DTOs; it does not independently establish a previously selected evidence ref or persisted credible-mass diagnostic. A caller can choose a different internally valid pair of refs, so source identity is reconciled only relative to the separately retained context supplied for this invocation. This path does not prove that a job was the intended one, external issuer/source authenticity, statistical quality, unit meaning, source currentness, or publication authority.

The candidate tests in `tests/unit/scientist/compute/test_selected_posterior_consumer.py` cover controlled method-job/real-CAS inputs, distinct selected profiles, a valid other job with different evidence, an exact summary-byte sibling view, mapping-shaped manifests, valid nondefault full-ref-only stores, a legacy profileless nested result, an asymmetric 100-row two-parameter law, equal-interval mass mutation, unavailable evidence, role/ref rejection, and input-ref mutation. Two jobs with identical complete evidence identity remain indistinguishable by this API; no runtime witness for that case is claimed. They do not replace a native HMC backend run, a real production caller, independent review, or G acceptance.
