## Producer/consumer map

1. **Scheduler → N6 action.** SimpleVOIScheduler._recommended_action defaults to advance. If expected improvement per dollar is below threshold but expected information gain is positive, it leaves advance and records advance_by_information_value; zero information gain instead yields reject (voi_scheduler.py L345–396). N6 calls the scheduler through _schedule_candidate_for_execution, and decide_next_action maps the result into LoopNextAction advance | stop | escalate | blocked (generation_cycle.py L211, L4159–4219). The VOI estimate is explicitly for scheduling shadow revision and does not grant authority (generation_cycle.py L8961–8982).

2. **Direct unsupported-terminal blocked path.** decide_next_action returns next_action=blocked, reason=unsupported_terminal, and scheduler_action=unsupported_terminal when prior_terminal_kind is outside the owner denominator (generation_cycle.py L4170–4178). _run_cycle passes its selected terminal through this function and stores the result (L5774–5808); the N7 re-entry path also calls it (L5481–5505). This cycle-level return does not set run.terminal_status. In run(), the generic non-advance branch only breaks; run-level blocked status/reason are assigned only for the cycle cap, fake-cycle path, and no-retry error (L3702–3726, L3761–3778). Therefore an emitted unsupported-terminal blocked cycle can leave the enclosing run at its default completed status and blocked_reason=None. The selected terminal is normally owner-derived from the canonical denominator, so served reachability of this defensive branch is not established; it remains part of blocked-disposition coherence.

3. **Cycle → run-level block.** GenerationCycleController.run sets terminal_status=blocked at the cycle cap, on a repeated/fake cycle, or on no-retry-without-new-grammar (generation_cycle.py L3702–3726, L3745–3778). At max_cycles=1, the sole cycle can request advance; the next loop iteration reaches the cap, applies _blocked_cycle to that last cycle, and breaks before a second cycle exists (L3707–3712). _blocked_cycle writes next_action=blocked, refinement_decision=block_candidate, search_iteration=blocked_no_retry, and a reason; a pending scheduler action becomes blocked (L9089–9115). _fake_cycle_reason handles the separate repeated-cycle path (L9166–9176).

4. **Run → N9/promotion and board.** After the loop exits with any run-level block, run still computes current summaries, calls _promote_completed_generation, applies its result, and derives decision/research/quarantine/portfolio fronts; there is no terminal_status guard (generation_cycle.py L3761–3811). N9 performs independent subject, epoch, open-world and evidence admissions (L4020–4105), but the owner call does not receive the outer blocked disposition. The decision front is built from N9-certified current-valid summaries (L9208–9238), and summary promotion uses certified IDs (L9241 onward). Confirmed source fact: a blocked run enters the N9 path and summary projection. Not established: that N9 necessarily emits a receipt; its independent gates may refuse.

5. **Validator → recursive terminal.** validate_generation_cycle_run recomputes expected cycle terminal from grounding/value evidence and permits scheduler actions from its denominator plus pending, blocked, and unsupported_terminal (generation_cycle.py L5913–5954). It does not reconcile run terminal_status/blocked_reason with a final next_action=blocked, refinement_decision=block_candidate, and search_iteration=blocked_no_retry; the unsupported-terminal branch can leave a blocked cycle in a completed run. Separately, every adjacent equal content hash unconditionally produces fake_cycle_same_candidate_repeated, even when the duplicate is explicitly marked blocked (L6004–6019). generation_cycle_terminal_state maps run-level blocks to budget_exhausted for the safety cap or recursive_blocked otherwise (L6094–6116). The recursive owner validates first and raises recursive_leaf_generation_cycle_invalid on any issue; only then does it create a leaf whose terminal is owner-derived and equality-checked (recursive_generation_cycle.py L907–929, L371–377, L536–538). Thus invalid blocked records do not reach the recursive terminal consumer.

## Property, P37/P38, controls, falsifier

**One P40 property:** N6 blocked disposition is one owner-owned state across cycle record, run validator, N9/promotion result, candidate fronts, serialized projection, and recursive terminal. A coherent block remains replayable and visible as a typed limitation; it cannot be relabeled completed or yield N9 authority from that blocked run. Candidate-band computation and honest stop/advance remain usable. The blocked-duplicate validator refusal, unsupported-terminal cycle/run mismatch, and unconditional post-loop N9 invocation are manifestations of this same coherence class, not separate instance fixes.

**P37 predicates.** The duplicate detector recomputes equal content hashes from adjacent cycle records. The validator recomputes expected cycle terminal and scheduler-action membership, but does not establish the conjunction for coherent blocked disposition: run status/reason ↔ final VOI/refinement/iteration ↔ no N9 authority. N9 recomputes candidate/epoch/evidence predicates but does not receive run terminal status. Recursive terminal is owner-derived from run status but is unreachable when the validator rejects the leaf.

**P38 divergence.** The property is whether blocked N6 output can be validated, projected, and promoted coherently. The implementation emits a direct unsupported-terminal blocked cycle but can leave its enclosing run marked completed, unconditionally rejects equal adjacent hashes even when explicitly blocked, and invokes N9 after a run-level block. The distinguishing cases are (a) one valid cycle with unsupported-terminal blocked markers but run completed, and (b) a duplicate-free safety-cap run whose run status is corrupted while all final-cycle block markers remain. Marker shape and allowed-action membership do not establish the disposition.

**Removal probe (behavioral, duplicate-free).** Use a one-cycle safety-cap run: let its sole cycle request advance and set max_cycles=1. The next loop iteration reaches voi_safety_cap_reached_without_scheduler_stop, marks the run blocked, and applies _blocked_cycle to the sole record. Assert one cycle so fake_cycle_same_candidate_repeated cannot confound the probe. Mutate only run.terminal_status from blocked to completed, leaving blocked_reason and all cycle markers untouched. The repaired validator must report the specific issue blocked_run_terminal_status_mismatch. If the status-coherence predicate is removed while those markers remain, the mutant is accepted and this negative assertion fails.

**N9 authority control.** Pair blocked suppression with an otherwise equivalent unblocked positive N9 control using the same candidate summary, promotion runtime, and epoch/evidence artifacts. The unblocked control must produce its expected certified candidate/receipt. With only run disposition changed to blocked, the owner must skip authority-producing N9 and produce no receipt, certification, or decision-front entry. This proves the blocked gate fires on disposition while the candidate evidence is held constant.

**Other preserving controls.** Existing test_terminal_projection_preserves_stop_budget_and_abstention requires ordinary stop to remain stop and distinguishes it from abstention (test_generation_cycle.py L3735–3759). Preserve a normal advancing counterexample-driven candidate-band run. test_controller_refuses_live_retry_without_new_grammar is an existing blocked-path control but does not cover status linkage or N9 suppression (L3457–3479).
