# R13 / R12 route and custody map

## Scope and measurement

This is a read-only source map for R13 (ACQ-01 and root-rebuilt stores) and its R12 dependency (N7 re-entry identity/bootstrap drift). It describes the merged Phase 0 tree and proposes a bounded implementation/test sequence. No source or test changes, executions, or governed artifact changes are part of this map.

The complete AST census covered all 2,693 Python files under `policy-engine/src/**/*.py`; it found zero parse errors and 26 direct `FileSystemCAS(...)` AST call sites. Five of those are the E02 additions named by R13. The additional `fabric/retrieval/executor.py` constructor described below predates those five and belongs to the local retrieval arm. These counts describe syntax-level calls, not reachability or authority; the caller map below establishes those separately.

## Served acquisition: authorized action to same-tenant N7 re-entry

The canonical route already exists. It is a later, explicit acquisition action after a generation run identifies a requirement gap; N6 does not fetch data merely because it ran.

1. **Persisted cycle and route.** The HTTP lifecycle compiles and runs the natural-language job and persists its recursive generation run (`runtime/http/services/control/run_lifecycle.py:3266-3379`). The route loop reads the tenant-scoped completed job and a unique costed cycle, then forms a verified route closure carrying the stable design-problem subject and cycle references (`runtime/quality/acquisition_route_loop.py:240-353`).
2. **Authority and journal.** `AcquisitionActionService.request_decision` persists a decision without executing its effect; `execute` reserves the external action and queues the job; `handle_job` reloads the persisted decision before invoking the bound effect (`runtime/http/services/acquisition_action_service.py:323-376,378-468,470-603`). The WDI port resolves the exact live catalog route against authority, provision, and registry (`runtime/http/services/acquisition_surface_execution.py:140-190`). It reserves the attempt and constructs the journal identity/path from tenant, cell, run, and route (`:389-402,663-678`). The journal covers the authorized request.
3. **Data Forge execution.** The port invokes `execute_live_catalog_acquisition` with that bound authority, route entry, constraints, journal, and the bridge-supplied ArtifactStore (`runtime/http/services/acquisition_surface_execution.py:404-466`). The executor validates source lane, license/profile, harness, and constraints, appends the request to the journal, performs ingestion through its `store_factory`, and emits typed live evidence in pending-passport state (`runtime/quality/acquisition_executor.py:716-899,977-997,985-1073`). `_owned_ingestion_store` checks the configured root but returns the supplied store instance; it does not rebuild an unguarded store.
4. **Overlay, passport, native epoch.** The production container installs `AcquisitionWorldGrowthBridge` when the world-growth configuration, source-authority owners, and epoch owner are present (`runtime/http/container.py:435-470`; bridge builder: `runtime/http/services/acquisition_surface_execution.py:697-760`). The bridge is given the exact `control_service._artifact_store`, event log, epoch owner, and PromotionRuntime; the container checks that `PromotionRuntime.store` is the same object as `runtime_api_context.store` (`runtime/http/container.py:233-259,351-364`). The port submits the typed evidence and receipt refs to `AcquisitionWorldGrowthBridge.admit` (`runtime/http/services/acquisition_surface_execution.py:453-466`). The bridge selects the exact tenant/cell/run/route/stable-subject closure (`runtime/quality/acquisition_world_growth.py:210-218`), calls native `admit_acquisition_with_production_semantic_epoch` (`:283-328`), resolves activation, checks passport route/source lane, and measures a positive native membership delta (`:509-552`). Missing or invalid authority is quarantined and does not grow the world.
5. **Persist and re-enter.** The bridge writes the runtime authority artifact through the same store, carrying tenant/cell/run/job closure, same-input closure, and event (`runtime/quality/acquisition_world_growth.py:871-935`). After the port reports `world_committed`, `AcquisitionActionService.handle_job` records `world_committed_reentry_pending` and calls re-entry (`runtime/http/services/acquisition_action_service.py:588-603`; port: `runtime/http/services/acquisition_surface_execution.py:540-567`). `AcquisitionWorldGrowthBridge.resume` revalidates native epoch, overlay, passport, and receipt, then calls the controller's active-acquisition re-entry method (`runtime/quality/acquisition_world_growth.py:740-824`; controller: `runtime/quality/generation_cycle.py:3822-3936`). The validated re-entry receipt/event is persisted through the same store (`runtime/quality/acquisition_world_growth.py:815-824,871-935`).

This is the one world-growth write path aligned with GY N13b: Data Forge overlay admission, passport, and native epoch qualification. It consumes an explicitly authorized/journaled request and retains tenant custody through re-entry. See `docs/plans/active/layer3-slices/GY-engine-subordination.md:2787-2844,5402-5405`. The plan records the earlier ACQ-01 outcome as `typed_deeper_terminal`, with no world-growth epoch (`:5828-5830`); this repair would fix the caller path, not claim the broader GY task complete.

## The local N7 arm that bypasses the canonical route

`GenerationCycleController.run` plans a requirement gap first. If that returns no route, it calls `_run_n7_acquisition_if_requested` (`runtime/quality/generation_cycle.py:3729-3757`). The controller's default `authority_scope` is `production` (`:3463`), yet the local call has no scope guard. The only production-source construction of `RealAcquisitionOwnerGateway` is at `generation_cycle.py:4490`; a full AST search of the 2,693-file source set found exactly one such call.

That local gateway opens `.n7-live-cas` (`runtime/quality/acquisition_planner.py:1405-1452`); the fetch capture helper independently reconstructs a CAS (`:3039-3069`). The in-cycle route carries `capture_store_root`; `_rebuild_n7_acq01_route_context` rebuilds a store and can mint a world-model record, and `_reenter_cycle_after_n7_acquisition` can rebind a candidate atom (`runtime/quality/generation_cycle.py:5023-5110,5345-5445`). This arm bypasses the canonical overlay admission, passport, and native epoch. It must not execute as production authority.

Keep production route planning and typed limitation behavior. Remove the local fetch/write arm from the production controller path. If an explicit contract-testing or demonstration path remains, mark it candidate/non-authoritative in its typed result and require its test to inject the exact fixture store. A textual marker or an `authority_scope` default is not proof of this boundary.

## Stable subject and revised active basis (R12)

`GenerationCycleRecord.design_problem_ref` is the stable subject; optional `design_problem_basis_ref` records the problem snapshot active for that cycle (`runtime/quality/generation_cycle.py:1012-1024`). `_cycle_record` derives the basis from the actual problem used for that cycle and preserves a supplied stable ref (`:9024-9059`); `_cycle_basis_ref` prefers the basis (`:9078-9086`). The served route closure carries the root `compiled.design_problem_ref` and root `compiled.design_problem` (`runtime/quality/acquisition_route_loop.py:321-353`). The bridge currently passes that root problem to `reenter_after_active_acquisition_overlay` (`runtime/quality/acquisition_world_growth.py:795-799`).

The controller first checks the root problem ref against `original_run.design_problem_ref`; that is the stable-subject check and should pass. It then checks `_cycle_basis_ref(source_cycle) != problem_ref` (`runtime/quality/generation_cycle.py:3840-3849`). For an acquisition-required source cycle after cycle zero, the basis may already be a revised snapshot. This is the first identity mismatch: it compares the cycle's active basis to the original root problem ref.

The correct active-basis derivation is from the **previous** cycle, not from the source cycle's own revision request:

- For `source_cycle.cycle_index == 0`, the active problem is the closure's root DesignProblem.
- For `cycle_index > 0`, find the immediately preceding cycle in the same `original_run.cycles` and take that cycle's `revision_request.revised_problem`.
- Require `_problem_ref(active_problem) == _cycle_basis_ref(source_cycle)` and separately require `original_run.design_problem_ref` to remain the stable subject.
- Re-enter using `active_problem`, and pass `stable_design_problem_ref=original_run.design_problem_ref` into `_run_cycle`. The new cycle's basis should be the active problem ref while its stable subject remains the root ref.

Why this distinction matters: `run()` advances `current_problem` from the previous cycle's `revision_request.revised_problem` only when that previous cycle's VOI action is `advance` (`generation_cycle.py:3763-3780`). `_cycle_record` hashes the problem used in the cycle (`:9024-9059`); `_default_revision_request` creates the next problem with grammar/revision updates (`:8869-8906`). The source cycle's own `revision_request.revised_problem` is therefore the *next* problem, not its active basis. Fixing only the initial comparison would leave later currentness/receipt checks comparing or issuing the wrong identity (`generation_cycle.py:3987-3995`). Keep the correction in the existing controller re-entry owner; do not add a bridge↔controller owner.

## Existing bootstrap guard and P38 divergence

## Proposed write/test leases and semantic witnesses

The shared mechanism file `runtime/quality/generation_cycle.py` is owned as one serialized lease across R12 and R13. R1/R2 prerequisites must land first; then sequence as follows so no writer races on that file:

1. **Controller route and identity (R12/R13):** in `generation_cycle.py`, block local gateway execution in production while preserving route planning and candidate computation; correct active-basis derivation and preserve the stable subject. Fold the N7 atom/bootstrap drift into this route class rather than patching its instances.
2. **N5/WMR runtime store (R13):** thread the existing store from PromotionRuntime/HTTP owner through `runtime/http/services/control/generation_cycle.py`, `intervention_substrate.py`, and `data_state_substrate.py`, then the N5/WMR portions of `generation_cycle.py` and `recursive_generation_cycle.py`. Reopen only through the supplied store; avoid filesystem-only `.get_paths` assumptions.
3. **Remaining openings:** remove or inject the supplied store in `acquisition_planner.py` and (if needed) `fabric/retrieval/executor.py` for the explicitly non-authoritative demo route. Replace the training adapter constructor with the configured store factory in `foundry/plugins/training_adapter.py`; do not imply that this establishes a served tenant caller.
4. **Behavioral test set to reserve in the P41 denominator before these writes:** `tests/unit/runtime/quality/test_generation_cycle.py`; `tests/unit/runtime/quality/test_joint_simulation_horizon.py`; `tests/unit/runtime/quality/test_intervention_substrate.py`; `tests/integration/runtime_quality/test_data_state_substrate.py`; `tests/unit/runtime/quality/test_acquisition_planner.py` if its demo path remains; `tests/integration/core_runtime/test_acquisition_authority_served.py`; `tests/integration/core_runtime/test_acquisition_world_growth_chain.py`; `tests/integration/core_runtime/test_acquisition_tenant_custody.py`; and `tests/unit/remediation/test_plg_03.py` if training output behavior changes. This is the expected touched-file set, not a claim that all files have been changed or tested.

Required witnesses:

- **Removal probe:** keep ACQ-01 route/receipt markers but remove the production strangle. The real controller path must turn red if it invokes the local gateway, mints a local WMR, or rebinds the candidate atom without native overlay/passport/epoch admission. The test must drive the controller path, not grep marker names.
- **Positive control:** with no acquisition gap, ordinary candidate generation still proceeds. An unknown owner context may remain a typed candidate limitation, not a refusal of ordinary computation.
- **Served custody positive and negative:** the served WDI path must show the exact guarded/tenant store object flowing from container → executor → bridge admission → re-entry. The owning tenant/cell can read the resulting admitted evidence; a foreign tenant/cell cannot. Existing witnesses to whole served re-entry are `tests/integration/core_runtime/test_acquisition_world_growth_chain.py::test_actual_wdi_admits_delta_and_reenters_same_case` and `tests/integration/core_runtime/test_acquisition_tenant_custody.py::test_actual_acquisition_producers_preserve_tenant_custody_through_reentry`; add or strengthen a production-container composition witness in `test_acquisition_authority_served.py`, because the current dev-profile served test does not establish bridge installation.
- **Identity witness:** use a nonzero cycle index with a changed revision. Assert the source cycle basis equals the previous cycle's revised problem, the stable subject remains `original_run.design_problem_ref`, and the re-entered cycle keeps those two refs distinct. The removal probe should fail if the basis is replaced with the root problem or with the source cycle's next revision.

If the canonical bridge cannot be wired from its existing runtime store without a new owner decision, retain a typed `implemented_but_not_orchestrated` or `bridge_missing` residual, name the missing store/authority owner capability, and do not mint a second world-growth route.
