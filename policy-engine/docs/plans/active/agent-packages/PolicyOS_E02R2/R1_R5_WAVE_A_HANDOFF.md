## Property and governing constraints

An authenticated ordinary natural-language request must be able to compute and retain a candidate when no `CycleSubstrateContext` is established. The absent context travels as a typed, content-bound limitation. The same request must not acquire protected-mode, promotion, publication, or S8 authority from that candidate or from the limitation. Protected work with missing or invalid admission remains observably refused; absence of an EvalSafety attempt never selects the candidate band.

This implements the ratified two-band rule: fail-closed binds protected actions, published claims, and custody facts; candidate work may continue under a declared unknown, which remains a typed limitation on future promotion. An institutional absence is not a reason to remove ordinary capability. Identity and custody also require that the system own what its signatures claim and consume other owners' evidence as typed evidence. [Identity boundary, item 5, `policy-engine/docs/system-design-decisions/policyos-identity-and-custody-boundary.md@873198b24d7fe8edf204be44374d20c9256cd24e:184–199`; S0-K06, `policy-engine/docs/system-design-decisions/stage0-custody-kernel-ratification.md@6397ec2b9ba043c742f096813a0229418721fbfb:46–72,164–176`]

Placement is owner-first (P27): reuse the existing launch/job store, recursive controller, N4 producer, compiled-run owner, and status surface. Close the class with a single admission intake/replay path (P31), not separate HTTP, N4, or fixture selectors. Unknown context remains unknown; no root checkout, client field, or marker may mint owner context. [Failure/repair register, P27/P31, `policy-engine/docs/reference/policy-design-case-failure-patterns.md@7f4cc9ab9541a44c26e4648a2c08326e53743492`]

## Served request and present break

The production front door is authenticated `POST /api/v1/control/runs/nl`: the route registers `control.launch_nl_run`, obtains the server principal, and calls `ControlPlaneService.launch_nl_run` (`routes/control.py:368–390`, blob `f1331c7da27c1d65688d484539063bda66b9357b`). The service assigns run/job IDs, resolves the execution profile, copies request context into the payload, and enqueues the job (`services/control/run_lifecycle.py:4013–4134`, blob `a3827ed1677df17f09827d479db7510ffdb70e6e`). `_enqueue_job` persists the payload and calls `ControlPlaneStore.create_job` (`run_lifecycle.py:2274–2308`, same blob).

At this head, `create_job` writes the mutable row, progress, `job_created` event, and outbox entry in sequence; the event/outbox payload is only `{"state":"pending"}` (`runtime/http/services/control_plane_store.py:2398–2463`, blob `4a49eef3c1d7da25e40436c0346778e28df13034`). The worker loads the payload, and `_admit_evaluation_safety_attempt` returns `None` if the context has no attempt key (`run_lifecycle.py:2856–2895`). In the NL branch, the worker can consequently reach recursive generation without a durable distinction between ordinary candidate intent and protected intent whose evidence disappeared (`run_lifecycle.py:3175–3380`). Mutable `progress` cannot fill that gap.

The HTTP composition tries the existing substrate owner, but raises `cycle_substrate_context_not_established` when an explicit N4 port has no context (`runtime/http/services/control/generation_cycle.py:571–586`, blob `055cca6c9424deac61fa61543143a2a2d2310b1a`). Removing only that refusal still does not restore candidate generation: default `N4GenerationPort.__call__` returns `_N4OwnerContextUnavailableResult` before invoking the existing design-generation owner (`runtime/quality/generation_cycle.py:1510–1558`, blob `65d830f71dccd9c3b1e943e5e132678f7221ed8a`). The canonical `generate_design_candidate_bundle_under_a` already accepts `cycle_substrate_context=None` (`runtime/quality/design_generation.py:884–925`, blob `81875449b9568232790ae1c4602d75dd51b8e07a`). Calling that owner for a positively admitted candidate is the narrow plausible repair; source inspection is not a served positive witness.

The HTTP recursive call also supplies an empty EvalSafety-context mapping in one no-context branch (`services/control/generation_cycle.py:654–669`). In the recursive controller, the exact leaf denominator check is conditional on a populated map (`runtime/quality/recursive_generation_cycle.py:823–839`, blob `ddff9abd228378166bce8437862ebe487ae00149`). R1 must not make that empty-map path a way to run non-simulation work. R5 keeps its separate rule: every non-simulation leaf requires current EvalSafety evidence; a missing protected attempt must refuse before N4/N6 completion.

## Single trusted band owner and branch rules

R1 and R5 use one server-issued, versioned `RunIntentAdmission` artifact and its durable event binding. It is an admission/routing constraint, never promotion or publication authority. Derive intent from the authenticated route/action and the versioned server policy; where a request carries an evaluation-mode token, resolve it with the existing canonical evaluation-mode owner and compare it to the route's permitted action. The client does not set a band. A contradictory, unknown, unreadable, or unreconciled intent is `not_established` and non-runnable. Do not infer `candidate_only` from a missing EvalSafety attempt, a profile label, or caller context.

| Verified outcome | Allowed behavior | Missing or contradictory evidence |
|---|---|---|
| `candidate_only` | Positively selected only for the authenticated ordinary NL action with no protected intent. Run the existing N4 candidate producer with absent context represented as unknown. N5 may return a typed pending/limited result if the world substrate is unavailable. | Never synthesize a WMR/context or claim completed joint simulation. Keep promotion, publication, and S8 authority unavailable. |
| `simulate_only_attempt` | Pure computation only after the canonical mode resolver verifies the exact attempt for this job generation. | Missing/malformed/stale attempt is `not_established`; it does not become candidate or non-simulation work. |
| `eval_safety_required` | Protected/non-simulation action only with current EvalSafety admission and the exact recursive leaf denominator. | Missing, refused, stale, or mismatched EvalSafety is an observable typed refusal before N4/N6 candidate completion; no downgrade. |
| `not_established` | No runnable leaf; expose the typed refusal and retain an auditable failed-safe job result. | This is the result for legacy rows without admission, ambiguous route/mode, artifact/event mismatch, or unreconciled retry ownership. |

Persist the admission reference and digest in the existing append-only `job_created` event and matching outbox payload; bind schema/rule version, job/run, tenant and authenticated actor, exact payload reference/digest, route/action, resolved mode, declared attempt identity and monotonic generation, selected outcome, issue time, and predecessor admission digest on retry. Reopen and reconcile artifact, event, tenant, payload, row, job/run IDs, lease, and attempt before dispatch. A retry is an immutable successor for the same intent and incremented generation; a changed payload or intent requires a new job/run. An ambiguous recovery is refused rather than synthesized as candidate. Use the runtime-supplied tenant-bound artifact store. An orphan artifact without the event binding is non-authoritative. Current source does not implement this admission/replay contract.

The existing `control_jobs.attempt`, event `payload_json`, and outbox `payload_json` provide a migration-free storage shape only if the implementation keeps the binding in those payloads and makes creation atomic or idempotently recoverable. Introducing relational columns/tables requires a named migration in the same write set. Do not rebuild `FileSystemCAS` from a root path. [Store anchors above and `R1_TRUSTED_BAND_MAP.md@5a5ef522881db46de7c8cc6523d38f5a009ad8e3:58–81`]

## Typed limitation, persistence, and consumers

For `candidate_only` without context, extend the existing compiled-run artifact—not a second N4 world or run-band artifact—with a strict frozen v2 field:

```text
CycleSubstrateContextLimitation(
  schema_version="policyos.runtime.cycle_substrate_context_limitation.v1",
  status="not_established",
  code="cycle_substrate_context_not_established",
  design_problem_ref=<the compiled DesignProblem hash>,
)
```

The field is required iff `cycle_substrate_context_ref` is absent and its `design_problem_ref` must equal the wrapper subject. It is absent when the context ref exists. Add it to `CompiledRecursiveGenerationCycleRun` v2 and include it in the v2 self-identity hash. Preserve the exact v1 serializer/key set and canonical bytes; reject the v2 field in v1. Replaying old v1 records must neither synthesize the limitation nor restamp their hashes. These are the six enumerated historical `compiled_run` pointers and the v1/v2 probe identities in `R1_TRUSTED_BAND_MAP.md@5a5ef522881db46de7c8cc6523d38f5a009ad8e3:38–55,76` (wrapper owner: `runtime/http/services/control/generation_cycle.py:449–485,717–743`, blob `055cca6c9424deac61fa61543143a2a2d2310b1a`).

Persist the verified wrapper through the runtime-supplied artifact store and retain its reference in the job's existing compiled-run progress pointer. Every normative/S8 reader must resolve and hash-verify that wrapper; a limitation or missing context caps the result and cannot be reinterpreted as S8 authority. `GenerationSourceRepository` is the existing N4 handoff owner for the served witness; it must be exercised through persist and reopen, not replaced with fixture bytes or another root store (`runtime/quality/generation_source.py`, blob `9bd65c03be46082edb9d0af4749776085ef5569a`). Tenant custody/current-epoch behavior of that handoff remains unestablished and is not closed by an R1 source change.

Expose the readback at the existing authenticated `GET /api/v1/control/jobs/{job_id}` surface. Add strict `ControlJobRunIntentProjection` to `ControlJobResponse` as a projection-only field; include the verified shared outcome, typed refusal where applicable, and the wrapper's context limitation. Derive it by resolving admission/event plus compiled-wrapper bytes—not from `progress`. A legacy NL job without admission projects `not_established`; non-NL jobs may leave the field null. The current DTO has no such field (`core/contracts/control.py:1536–1584`, blob `b9a5fe8f66d159a635bc12adeade419f16c5d9d4`); the current response owner is `ControlJobRecord.to_response` (`control_plane_store.py:868–918`), and the route/lifecycle reader is `run_lifecycle.py:2397–2425` / `routes/control.py:469–486`. This is `surface_missing` until implemented and contract-tested; it is not `surface_out_of_scope`.

## Falsifiers, preserving control, and S8 boundary

**Protected-intent removal probe:** keep enum names, schema markers, route strings, event IDs, and typed DTO declarations intact. Remove the admission/event resolve-bind-reconcile guard while launching a server-authenticated protected/non-simulation intent with no current EvalSafety admission. The unchanged behavioral test must go red by observing candidate/N6 completion or a completed candidate projection. On the repaired path it must observe `not_established`/typed refusal, no candidate-success terminal state, no N4/N6 candidate completion, and no S8 authority. Run a separate variant with all downstream refusal guards disabled so an S8 guard cannot mask the removed run-intent property. A marker check or `ValuePort`-not-called assertion alone is insufficient.

**Candidate-preserving control:** launch the ordinary authenticated NL action with no `CycleSubstrateContext`, no protected mode, and valid `candidate_only` admission. The existing real N4 owner must run; a candidate must persist and reopen with the v2 typed limitation; GET job status must expose the reconciled projection. If no world substrate is available, assert typed N5 pending/limited—not refusal of candidate work and not completed joint simulation. Protected value, promotion, publication, and S8 authority remain absent.

**R5 non-simulation negative:** with `eval_safety_required`, delete the exact-leaf context-denominator guard while retaining its markers. The existing `test_non_simulation_leaf_requires_current_eval_safety_head` and the new exact-denominator negative must fail. Candidate-only is not a relaxation of that guard; custom factories still cannot claim context consumption through their current `(node_ref, problem)` call shape.

**S8 fixture condition:** `test_process_nl_job_enters_persisted_tenant_scope[authorized]` and the authority-positive cases in `test_normative_generation_bridge.py` use fixture N4 ports, not the real N4 → persisted/reopened source handoff. If replay shows the fixture resolves a valid owner-bound current context *and* handoff under the four-base environment, preserve the existing expectation but do not count it as the served positive witness. If it does not, keep S8 blocked; changing the expectation requires P41 evidence that R1/R13 caused the change and the required principal-level decision. The remaining fixture outcomes stay blocked.
