# R1 source map: trusted run band and candidate computation

**Scope:** source-only R1 design review against the product/test blobs cited below. This is a proposal, not a code or runtime receipt. No source/tests were edited or run. It records the candidate-band repair boundary, the S8 authority-fixture gap, and the wider run-intent persistence mechanism required by P40.

## Property and current divergence

**Property:** an ordinary natural-language request can compute and retain a candidate when a `CycleSubstrateContext` is not established, carrying that absence forward as a typed limitation. Missing owner context blocks protected modes, promotion, publication, and S8 authority. A declared protected/non-simulation intent must never silently downgrade to candidate or simulation-only work when its EvalSafety attempt is missing or refused.

The current request has `context: dict[str, Any]`, `execution_profile`, and policy flags, but no typed run-intent/run-band contract. `launch_nl_run` copies arbitrary context into the payload, and the worker treats the EvalSafety attempt as optional: `_admit_evaluation_safety_attempt` returns `None` if its key is absent; only a passed, typed owner admission produces `EvaluationExecutionContext`. Thus absence currently does not say whether this is ordinary candidate work or an intended protected attempt that was dropped. `execution_profile` is deployment policy/profile metadata and cannot substitute for the action band. [control.py@b9a5fe8f66d159a635bc12adeade419f16c5d9d4; run_lifecycle.py@a3827ed1677df17f09827d479db7510ffdb70e6e]

The HTTP composition has an explicit branch for missing owner context. It first tries `_build_cycle_substrate_context_from_owner`, which can resolve existing production WMR/catalog owners and otherwise returns `None`; only then does it raise `cycle_substrate_context_not_established` for an explicit N4 port. Thus “no context explicitly passed” and “context not established” are distinct. Removing that HTTP check alone is insufficient when owner resolution does return `None`: the default `N4GenerationPort.__call__` immediately returns `_N4OwnerContextUnavailableResult` before calling the real design-generation owner. The canonical `generate_design_candidate_bundle_under_a` already accepts `cycle_substrate_context=None`, so the narrow candidate repair is to let the existing N4 owner produce candidate work under that typed limitation. Do not add a second generator or mint a substrate context. [http-generation-cycle.py@055cca6c9424deac61fa61543143a2a2d2310b1a, lines 571–586, 747–801; generation-cycle.py@65d830f71dccd9c3b1e943e5e132678f7221ed8a, lines 1500–1555; design-generation.py@81875449b9568232790ae1c4602d75dd51b8e07a, lines 884–925]

The recursive HTTP call currently sends `evaluation_contexts_by_node={}` when both the EvalSafety and cycle-substrate contexts are absent. `RecursiveGenerationCycleController` checks exact leaf denominator/type only when that mapping is non-empty. That is not enough to preserve a previously declared protected intent. R1 may restore candidate computation in the default candidate band, but it must pass an explicit trusted band through the recursive leaf; R5 independently keeps the non-simulation EvalSafety denominator fail-closed. [http-generation-cycle.py@055cca6c9424deac61fa61543143a2a2d2310b1a, lines 654–669; recursive-generation-cycle.py@ddff9abd228378166bce8437862ebe487ae00149, lines 823–839]

## Narrow owner-first repair

Use one server-owned, typed `RunIntentAdmission` mechanism across launch, persistence, worker replay, and recursive leaf dispatch. Its semantic outcomes should distinguish ordinary `candidate` work from `eval_safety_required` work. The requested band is intent/routing, not authority: an explicit protected request selects the required path but cannot grant it. A passed `EvaluationExecutionContext` remains owner-issued only after the current EvalSafety authority, appointment, evidence, certificate, and replay checks succeed. The existing `recompute_attempt_class` is useful to classify a fully bound admitted attempt from its complete reference/provenance set; it is downstream evidence, not a substitute for persisting the requested band before the attempt exists. [pdc-evaluation-safety.py@e05611289505432f90550aac85375976b38800ad, lines 99–147; run-lifecycle.py@a3827ed1677df17f09827d479db7510ffdb70e6e, lines 2856–2975]

The mechanism must cross the durable boundary as a schema-versioned, content-bound owner artifact/event, not as a `run_band` enum added only to an API DTO or mutable row. Bind at least the job/run identity, request/payload identity and content hash, actor/tenant scope, declared run intent, selected band, attempt/generation identity, and rule/schema version. Have the lifecycle owner create it and the control-store event/outbox carry its exact reference and digest; make the worker resolve and verify that same owner admission against the payload and current job/attempt identity before calling the recursive owner. A reference copied into a mutable row alone is not proof: `ControlJobRecord` currently has no content hash/schema or band field, and `job_created` records only `{"state":"pending"}`. The store already persists a payload artifact and appends creation events; extend those owners and their replay path rather than inventing a parallel job authority store. [control-plane-store.py@4a49eef3c1d7da25e40436c0346778e28df13034, lines 844–867, 2398–2462; run-lifecycle.py@a3827ed1677df17f09827d479db7510ffdb70e6e, lines 2274–2308, 4106–4134]

The worker should preserve `eval_safety_required` when the attempt is absent, malformed, stale, or refused. It may emit or retain a candidate as a bounded intermediate if policy permits, but it must not reinterpret the job as ordinary simulation-only execution or produce a protected value/promotion/publication result. For `candidate`, run the existing N4 producer and N5 simulation with no owner-bound cycle substrate only as candidate computation; surface a typed owner-context limitation into persisted run state and S8 projection. Do not assert tenant-protected WMR or owner-grounded authority from caller context. Keep the root-cycle substrate absence visible through reentry.

### P40 class boundary

The missing launch selector, optional arbitrary `context` key, mutable job-row-only fields, thin `job_created` event, and recursive empty-map bypass are instances of one class: **run intent is not durably bound and replayed from request admission through served leaf execution**. The next fix should widen to the single owner-issued admission artifact/event and its end-to-end consumer, not add separate flags at the HTTP wrapper, database row, EvalSafety helper, and recursive controller. The acceptance chain is producer → immutable artifact/event → persisted job binding → worker replay verification → recursive leaf consumer → typed limitation/authority behavior → semantic negative test.

### Property and tests

- **Removing the property:** retain band markers and request/payload/job IDs, but mutate or omit the owner-bound admission so an `eval_safety_required` job reaches the candidate/simulation fallback with no current EvalSafety head. A behavioral test must turn red by showing protected value work or authority was admitted; the same test must distinguish a genuine `candidate` run whose typed limitation is preserved. Marker presence alone is not a witness.
- **Preserving control:** an ordinary natural-language request without owner context calls the real N4 design-generation owner, reaches N5 candidate simulation, persists a candidate plus typed limitation, and has no promotion/publication/S8 authority. The existing `test_plain_language_front_door_calls_real_design_problem_compiler` is a useful unit control, but it uses an explicit fixture N4 and fixture N5; it is not a served production witness. [test-nl-pipeline.py@3ef4861c26c87ee7abdc9d6e13a4ca16f2654b55, lines 745–835]
- **R5 separation:** retain `test_non_simulation_leaf_requires_current_eval_safety_head` as a non-simulation denial witness. R1’s selector decides the admitted run intent; R5’s denominator predicate decides whether every non-simulation leaf has the current EvalSafety head. Candidate-band flexibility does not relax the R5 guard. ## Decision draft (R1)

- **Decision:** permit ordinary natural-language work to compute a candidate under a missing CycleSubstrateContext, while keeping protected execution, promotion, publication, and S8 authority bound to their current owner evidence.
- **Options and costs:** (A) add the owner-issued, persisted run-intent admission and route missing-context ordinary requests through existing N4/N5 candidate owners; cost is a typed artifact/event plus lifecycle/replay/recursive wiring and behavioral tests. (B) keep all missing-context requests refused until the full R13 owner route exists; cost is a closed ordinary front door and continued over-refusal for work that can honestly be carried as candidate. (C) manufacture a concrete context or trust a request/context marker as authority; rejected because it converts unknown scope into an unsupported custody fact.
- **Premises:** candidate computation can carry the owner-context absence as a typed limitation; candidate output grants no protected value, promotion, publication, or S8 authority. EvalSafety admission remains a separate typed owner check.
- **Remainder:** the S8-positive fixture gap remains until R13 can provide an owner-bound context or the principal explicitly changes the fixture’s authority expectation. Production cross-run owner/epoch currentness remains subject to its own verification.
- **Revisit trigger (falsifier):** a removal probe that deletes the persisted admission/replay binding while retaining its markers still blocks protected work, or an ordinary context-free request cannot reach real candidate computation with no authority effect.
- **Where it binds:** ordinary NL run launch and worker replay, down to recursive leaf; it does not grant authority to any generated candidate or decide an S8 institutional appointment.

## P37 / P38 and limits

- **P37:** request intent is institutionally/user-supplied as intent only; server classification and the immutable admission binding must be recomputed or independently reconciled against authenticated launch identity, exact payload bytes, job/run ID, and attempt. EvalSafety status, mode, certificate, revision head, and complete input provenance remain owner-recomputed/current. An arbitrary context field, execution profile, row value, or present artifact marker is insufficient.
- **P38:** the property is that the served leaf obeys the run band originally admitted and preserves unknown scope. Current implementation branches on context/port presence and optional EvalSafety attempt presence; the recursive denominator guard is conditional on a non-empty map, and the default N4 owner returns no candidate when owner resolution yields no context. A divergent case is an ordinary candidate run after `_build_cycle_substrate_context_from_owner` returns `None` (currently no N4 candidate), or a dropped EvalSafety attempt represented as empty context that loses the declared protected intent.
- **Limits:** source review does not show an existing durable run-band artifact or a served positive candidate path under missing context. It does not prove R13 has or lacks a production source for owner context, authorize changing S8 expected results, or verify behavior. Those require source-owner census and four-base tests after implementation.
