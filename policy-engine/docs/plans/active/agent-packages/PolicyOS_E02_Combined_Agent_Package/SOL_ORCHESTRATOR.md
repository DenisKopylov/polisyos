# Sol — оркестратор совместного ремонта PolicyOS E02

Запусти реализацию данного плана в предоставленном checkout, соблюдая действующие repository инструкции и полномочия пользователя. План не создаёт permission для внешних deployment/publication или удаления пользовательских данных.

Прочитай `EXECUTION_GUIDE.md`, `BUNDLE_INDEX.md`, `bundle_manifest.json`, `MIGRATION_LANES.md`, `LEGACY_CROSSWALK.md`, `CHECKPOINTS.md`. Source facts уже разбиты: не поручай каждому агенту повторное чтение двух огромных аудитов. Индекс и packet дают нужные полные тексты.

Сначала назначь I1 и I2. I1 делает SETUP-01 и единую очередь L/N/C; I2 разрешает proposed paths и initial contract boundaries. Подтверждённая целевая раскладка — 15 прямых leaf workers, не считая Sol: 8 executors, 3 reviewers, 2 preparers, 1 I1 broker и 1 sequential integration writer. Preparer может временно стать девятым executor; при четырёх кандидатах без первого review один preparer/executor может стать четвёртым reviewer. Если runtime фактически даёт меньше seats, используй максимум доступных и зафиксируй предел без ослабления review/write isolation. Лимит модели/threads настраивается отдельно пользователем, не этим JSON. Все workers leaf и не создают субагентов.

Сохранённый historical seed для воспроизводимости (не текущий dispatch и не barrier): CYC-01, SEL-01, STA-01, ING-01, OPT-01, FRY-01, DDM-01, GRF-01, UDF-01. Текущий dispatch идёт из live B+LA rolling queue с минимум пятью полностью специфицированными ready-пакетами сверх active; Sol/I1 выбирают следующий пакет по actual contracts, leases и review capacity. Фактические write leases сверяются с checkout, а не только статическим JSON.

Дальше выдавай динамически один ready packet освободившемуся агенту и держи минимум пять полностью специфицированных ready-пакетов помимо активных. Не вводи очередь «225 B, затем57 LA»; предпочитай следующий готовый шаг начатой migration lane, предотвращающий двойную переделку файла. Нет требования ждать всех участников текущего набора. Review backlog `4` — мягкая пользовательская цель, не admission barrier, не cap executors и не global STOP; небольшой excess запускает rebalancing в review/closeout, но не отклонение независимой работы.

Для dispatch передай ID, exact base SHA, свой worktree, разрешённые production/test/config paths, reviewer, checkpoint и resource class. Учитывай зависит/конфликт/activation/соседство раздельно. I2 хранит actual relocation map; после переезда последующие B tests и imports направляются к новому owner. Не позволяй править/проверять отставшую прежнюю копию и называть это исправлением нового пути.

Не проси агентов постоянно измерять нагрузку. I1 принимает immutable job request, атомарно копирует его байты в unique ready entry и выдаёт из общего бюджета максимум7 resource-bearing process groups/7 L-equivalent units; N/C — один эксклюзивный режим, который дожидается drain L. Пока очередь занята, агенты работают с текстом/кодом/review. Новый embedding/DDM/client/trainer scope не означает несколько параллельных моделей, builds или серверных pipelines. Точные native checks необходимы в ограниченном размере; environment-blocked не green. Permit освобождается после завершения process group, cleanup и сохранения receipt, не после review.

При нескольких допустимых contract profiles подготовь конечный выбор и сохрани existing semantics там, где нет разрешения их менять. Решающую неоднозначность authority/lifecycle передай пользователю кратко, не останавливая независимую очередь. R2 exception и handwritten channel schema нельзя терять под видом cleanup. Никакого нового общего permission/registry framework ради локального ремонта.

I1 принимает commits последовательно; reviewer не автор; повторяются только affected tests на принятом SHA. Завершённый B не пересчитывается дважды в разных LA-пакетах. `legacy_to_bundles.json` задаёт accountable owner и все фазы; merged first phase не done всей карточки. Bridge/retirement/packaging остатки сохраняются в ledger.

Выполни CP1–CP6 по готовности блоков, CP6 последним; это выбранные наборы, не шесть full CI. При наличии прогресса E01 импортируй подтверждённые outcomes по B-ID/commit, не обнуляй branches и не повторяй доказанные repairs. В конце покажи фактическую матрицу B/LA outcomes, retained compatibility, native/deferred checks, принятые commits и проверенный полезный пользовательский путь. Не объявляй все282 записи багами или исправленными лишь по количеству merged packets.
