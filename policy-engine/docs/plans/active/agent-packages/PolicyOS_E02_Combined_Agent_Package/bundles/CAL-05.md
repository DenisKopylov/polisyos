## Поручение и минимальная приёмка

Подготовить разрешённый active plan или условное исполнение с нейтральным patch-пакетом той же структуры. Сохранить порядок зависимостей, merge semantics и логические PRNG-потоки; разделить проверку структуры и runtime вычисление.

**Различающие тесты и сохраняемое поведение.** Отложенный log(x) при x=0 не портит доступный префикс и градиент; активный режим сохраняет реальный отказ на недопустимом входе. Проверить eager, JIT и применимый vmap на маленьком механизме; обе ветви имеют согласованные формы. Счётчик emitter отличает tracing от численного исполнения.

**Не считать исправлением.** Не применять Python if к tracer, не обещать экономию любого lax.cond под vmap, не создавать фиктивные inputs будущему механизму и не отключать finite-guards.

**Цикл работы:** зафиксировать actual scope и нужный characterization; оформить equivalent move и намеренный behavior fix раздельно; выполнить указанные малые tests через I1; независимый reviewer проверяет actual owner; передать commit, path map и остатки. CLI/test selectors разрешаются по настоящему checkout до запуска, не выдумываются из названия находки.

## B185. Неактивный по расписанию механизм всё равно вычисляется и может испортить градиент

**Основание и причина.** В `apply_nodes` сначала вычисляется `active`, но затем безусловно вызываются selector и `mechanism.emit_patches`. Маска применяется к уже полученным patch-records и к PRNG carry. SUM-merge использует `where` и корректно не добавляет неактивное численное значение; это не тождественно пропуску вычисления и его производной. C18.R01–R02; P01–P04.

**Воспроизведение.** Три шага до начала расписания дали три вызова инструментированного emitter. Для модельного delta `log(x)` при x=0 и неактивном узле прямое значение итогового state равно 0, а настоящий `jax.grad` равен NaN. Emitter, поднимающий ошибку отсутствующего входа, также прервал неактивный шаг. Контроль с `lax.cond` дал неактивную производную 1 (сохраняется сам state x), а при активном x=2 — 1,5, как у x+log(x). Это локальные функции, не производственный механизм и не измеренный профиль compiled scan.

**Предпочтительное исправление.** Для заранее известного расписания специализировать только допустимые активные участки либо условно исполнять вычислительную ветвь с нейтральным patch-пакетом той же структуры. Сохранить порядок зависимостей, правила слияния и принятую семантику PRNG. Подготовка структуры и runtime-вычисление должны быть раздельны. Нельзя применять обычный Python `if` к tracer или терять compile-time проверки разрешённых механизмов.

**Оговорки и приёмка.** `cond` трассирует обе ветви, требует согласованной формы и при некоторых `vmap` преобразуется в select; это не автоматическое обещание экономии. Проверить eager/JIT/градиент на разрешённых входах, диапазон расписания и нормальный активный отказ. Настоящий активный NaN остаётся ошибкой. Не отключать finite-guards, не использовать `nan_to_num` и не добавлять фиктивные входы будущему вмешательству. Приоритет высокий для использующего pure-executor маршрута: полезен уже один отложенный механизм, кластер не нужен.
