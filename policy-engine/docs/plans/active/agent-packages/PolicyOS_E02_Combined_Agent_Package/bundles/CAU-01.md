## Поручение и минимальная приёмка

Сначала LA-016: вынести shared metadata из deprecated class без изменения численных helpers и зафиксировать равнозначные old/dedicated запросы. Затем На standard-DiD boundary проверить оценимость pre/post contrast. Исполнить действительно запрошенный covariance profile с cluster IDs и объявленной поправкой. Согласовать critical-value с фактической процедурой и confidence level в обоих DiD/RDD callers. B206 имеет одного владельца здесь; RDD-пакет не делает вторую независимую реализацию.

**Различающие тесты и сохраняемое поведение.** Known ATT=3 сохраняется; t0=0 не даёт идентифицированный DiD-effect. Unit-cluster контроль не получает новую информацию от технического повторения периодов. Уровни 80/99% меняют границы при положительном SE;95% сохраняет допустимый прежний профиль. Малые панели и независимый statsmodels-reference, без утверждения о population coverage. Old/dedicated wrappers на одном effective request дают одинаковые значения/warnings после bugfix; старая обёртка не остаётся владельцем metadata. Снятие registration проверяет CAU-05.

**Не считать исправлением.** Не запрещать t0=0 во всей PanelObservationalData. Не переименовывать HC1 в cluster и не лечить неправильный SE только квантилем. Shared _common.py меняется лишь по явному contract reservation.

**Цикл работы:** зафиксировать actual scope и нужный characterization; оформить equivalent move и намеренный behavior fix раздельно; выполнить указанные малые tests через I1; независимый reviewer проверяет actual owner; передать commit, path map и остатки. CLI/test selectors разрешаются по настоящему checkout до запуска, не выдумываются из названия находки.

## B204. Стандартный DiD принимает отсутствие предшествующего периода за пригодный дизайн

**Приоритет:** высокий на стандартном DiD-маршруте; небольшой адресный ремонт. **Основание:** PanelObservationalData, _run_standard_did и _parallel_trend_diagnostic; ID01–ID04. [C20.R02, R04]

**Проблема.** Общий panel-контракт допускает time_treatment=0. Стандартный оцениватель не добавляет требование ненулевого pre-периода. Все значения Post равны единице, а столбцы Post×Treat и Treat совпадают. np.linalg.lstsq возвращает решение недоопределённой регрессии, и вызывается build_success_report. При t0<3 диагностика параллельности возвращает passed=True с причиной insufficient_pre_periods. Это полезное указание причины, но не проведённая проверка предпосылки.

**Воспроизведение.** Четыре единицы с рядами [10,12], [14,16], [2,4], [6,8]; первые две treated, t0=0. Настоящий перенесённый panel-валидатор принимает вход. Ранг матрицы равен 2 при четырёх столбцах; численно возвращается ATT=4 и запрашивается SUCCESS-report, pre_periods=0. Это лишь часть межгруппового различия, а не идентифицированная разность изменений. ReportFixture регистрирует конструирование; нативные IR-сертификаты и downstream-gates не исполнялись.

**Рекомендуемое исправление.** На входе именно standard-DiD проверить наличие пригодных pre/post наблюдений и обоих сравниваемых режимов, затем определить оценимый контраст. При отсутствии pre сохранить описательные межгрупповые различия либо маршрутизировать на другой обоснованный дизайн. Не запрещать t0=0 в общей модели PanelObservationalData, если такой объект нужен другим методам. Для pre-trend различать невычислимость, неотвержение и найденное нарушение; не назначать «доказано» на основании одного p-value.

**Приёмка и положительные контроли.** Известный ATT=3 на корректной панели восстановлен. Нечисловой outcome и повторное поперечное сечение отвергнуты действительными перенесёнными валидаторами; отсутствие control — существующим методом. Новый контроль должен исключить только неидентифицированный DiD-контраст, не сломав эти пути. Ненулевой pre-период необходим, но сам по себе не доказывает параллельные тренды.

## B205. Запрошенная covariance не исполняется: HC1 считает повторные периоды новой информацией

**Приоритет:** высокий для панельной неопределённости; малый/средний ремонт существующей оценки. **Основание:** _ols_hc1, _run_standard_did и сигнатура зарегистрированного standard-метода; SE01–SE03. [C20.R02, C20.E02]

**Проблема.** Метод декларирует cov_type и cluster_var, но всегда вызывает _ols_hc1. В отчёт записывается предоставленная строка cov_type, не фактически применённый estimator covariance. HC1 учитывает неодинаковые дисперсии строк, но не воспроизводит кластерную зависимость одной единицы во времени.

**Воспроизведение.** Для 40 единиц и двух периодов параметр HC1 и параметр cluster дали один standard_error=0,713261564323; во втором отчёте записано cluster. Десятикратное повторение тех же столбцов времени без новых единиц сохранило ATT=3,357319184071, но уменьшило HC1-SE до 0,220393653335. Независимый контроль statsmodels cov_cluster по единицам с отключённой маловыборочной поправкой дал 0,647984177731 до и после повторения. Это не оценка реального покрытия интервалов, а различающий пример единицы информации.

**Рекомендуемое исправление.** Разрешать фактическую covariance-стратегию по объявленному дизайну и кластерным идентификаторам. Группировать score-вклады по независимой единице, сохранять эффективный метод, число кластеров и выбранную поправку. При слишком малом числе кластеров — ограниченная диагностика и подходящая процедура, а не автоматическое признание асимптотики. Неподдержанный cov_type должен приводить к точному ограничению, не к переименованию HC1. HC1 остаётся допустимым в обоснованном независимом режиме.

**Производительность.** Существующую линейную точечную оценку можно сохранить. Sandwich-meat собирается из заранее рассчитанных score-вкладов; покомпонентный Python-цикл по каждой строке заменяем матричным накоплением без построения N×N. Это не требует нового универсального estimator или повторного обучения на каждом типе интервала.

**Приёмка.** Совпадение точечного ATT; совпадение действительного HC1 с statsmodels — уже положительный локальный контроль. Для исправления нужны unit-cluster эталон, перестановка строк, неизменность при чистом техническом повторении и честный ответ на неизвестную cluster-переменную. Маловыборочные поправки могут менять значения: контроль использовал CR0 именно для отделения их от повторной информации.

## B206. В DiD и RDD уровень интервала меняет подпись, но не границы

**Приоритет:** высокий и локальный. **Основание:** _run_standard_did и RegressionDiscontinuity.pure_step; CL01–CL03. [C20.R02–R03]

**Проблема.** Обе функции читают confidence_level, но используют константу z_critical=1,959963984540054. Новое значение уровня передаётся в report без изменения границ.

**Воспроизведение.** Standard DiD при 0,80 и 0,99 вернул один интервал [1,959352206441; 4,755286161700]. RDD также сохранил одинаковые границы для двух уровней. Для того же DiD-SE контроль с NormalDist дал ширину 1,828162948802 для 80% и 3,674480076956 для 99%, тогда как исходный путь использует 95%-квантиль.

**Рекомендуемое исправление.** Один раз разрешать критическое значение из фактического уровня и распределения выбранной процедуры. Для оправданной нормальной асимптотики достаточно соответствующего NormalDist; кластерные/маловыборочные процедуры могут требовать иных степеней свободы или bootstrap. Валидация уровня должна предшествовать дорогому вычислению, а результат хранить одновременно запрошенную и эффективную процедуру.

**Приёмка и граница.** 95% сохраняет прежний результат; повышение уровня при том же положительном SE расширяет интервал; недопустимый уровень отвергается адресно. Эта правка не исправляет неправильный SE из B205 или отсутствие bias correction из B210. Её нельзя представить как доказательство покрытия всей семейной реализации.

## LA-016. DiD umbrella-wrapper удерживает метаданные новых методов

**Слияние / разделение ответственности**

**Статус.** Deprecated агрегатор подтверждён; новые классы всё ещё зависят от него.

**Точная область:**

`src/polisyos/foundry/methods/catalog/causal/did.py#DifferenceInDifferences`

**Что установлено и почему это legacy-кандидат.** DifferenceInDifferences выбирает standard/staggered по флагу и переводит старые slot names outcome_panel/treatment_indicator. Уже есть StandardDifferenceInDifferences и StaggeredDifferenceInDifferences, но они читают metadata старого класса; общие _run_* helpers тоже берут assumptions из него. Удаление «только deprecated класса» сломает живые пути.

**Что сохранить.** Оба numerical helpers, общий контракт панели, assumptions/citations/equations и alias-mapping старых slots для объявленного перехода. Dedicated methods — более точная интерфейсная декомпозиция, не доказательство исправленной статистики.

**Куда перенести / с чем объединить.** Существующие dedicated classes в том же did.py. Общие определения поднять в независимые module constants либо маленький adjacent shared module только при оправданном размере. Legacy class оставить временным адаптером, затем снять регистрацию.

**Порядок миграции.** Сначала отвязать metadata от deprecated class; мигрировать old FQN, флаг staggered и имена slots в явный dedicated request. Сохранить старое чтение frozen plans по утверждённой версии. Не менять численный estimator в той же relocation-правке.

**Приёмочная проверка.** Одинаковые эффективные запросы обеих оболочек дают одинаковый результат и warnings; registry не предлагает старую generic route для нового планирования; старые replay inputs обрабатываются согласованно.

**Приоритет.** Высокая отдача при средней цене; хороший ограниченный consolidation-пакет.

**Граница вывода.** Это не основание удалять did.py целиком. Переход к dedicated class не исправляет сам собой ранее замеченные inferential-дефекты.

**Основания:** E29.
