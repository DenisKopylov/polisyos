## Поручение и минимальная приёмка

Один подготовленный panel/cohort view с корректным not-yet-treated eligibility, включая anticipation. Совместно определить независимые единицы, influence/cluster-resampling, aggregate estimand и H0/statistic; не чинить p-value косметически отдельно от уровня bootstrap.

**Различающие тесты и сохраняемое поведение.** Одна ATT(g, t) ячейка с варьирующими единицами не имеет искусственно точный[5,5]. Корректный нулевой тест отделён от доли |boot|>=|att|. При anticipation=1 уже затронутая когорта не используется как чистый control; a=0 сохраняет нормальный путь. Механические unit-тесты малы; bounded независимый null/coverage smoke только K5.

**Не считать исправлением.** Не увеличивать n_bootstrap для стабилизации неправильной формулы, не считать небольшой smoke аттестацией номинального покрытия. Если сильная inference не готова, вернуть честный point-only и оставить соответствующую часть незакрытой.

**Цикл работы:** зафиксировать actual scope и нужный characterization; оформить equivalent move и намеренный behavior fix раздельно; выполнить указанные малые tests через I1; независимый reviewer проверяет actual owner; передать commit, path map и остатки. CLI/test selectors разрешаются по настоящему checkout до запуска, не выдумываются из названия находки.

## B207. Bootstrap готовых ATT(g,t) не восстанавливает неопределённость панельных наблюдений

**Приоритет:** высокий; содержательная замена уровня повторной выборки, не увеличение n_bootstrap. **Основание:** _cohort_time_att и _run_staggered_did; SB01–SB05. [C20.R02, C20.E01]

**Проблема.** После расчёта ATT по когортам и времени повторно выбираются индексы этих уже агрегированных ячеек. Исходные единицы, их внутрипанельная зависимость и общие контрольные наблюдения в bootstrap не участвуют. Поэтому получаемый разброс относится не к принятой процедуре наблюдения данных.

**Воспроизведение.** Одна когорта, один post-период, treated-изменения [2,4,6,8], control-изменения 0. ATT=5, но любая повторная выборка единственной ячейки даёт 5. При 200 и 2000 повторениях интервал [5,5]. Эффект сохраняется при 80 единицах и 160 панельных строках. Полный перебор 256 стратифицированных повторных выборок четырёх treated-единиц даёт разброс средних, SD=1,118033988750 и процентильный интервал [3,7]. Это контроль механизма, не утверждение о номинальном покрытии на этой малой выборке.

**Рекомендуемое исправление.** Сохранять влияние каждой независимой единицы на набор ATT(g,t), затем повторно выбирать единицы/кластеры либо применять совместный multiplier-bootstrap к этим вкладам. Один draw должен согласованно действовать на все ячейки, имеющие общие наблюдения. Агрегируемый estimand, веса когорт и горизонтов объявляются отдельно: нынешнее взвешивание размера когорты по ячейкам не названо универсально ошибочным.

**Экономный путь.** Один подготовленный panel-view, заранее рассчитанные допустимые группы, исходные разности и score-вклады; далее пакетная линейная алгебра. Это может быть значительно дешевле повторной сборки и подгонки всех моделей на каждом bootstrap. Поисковые проходы с point-only результатом остаются возможными, но не получают выдуманный интервал.

**Приёмка.** Одна ячейка с варьирующими единицами не вырождается только из-за числа ячеек; постоянный модельный эффект сохраняется; идентичности единиц и повторов записаны. Затем нужны независимые симуляционные проверки покрытия при серийной корреляции и нескольких когортах. Официальная реализация did использует единичные influence-вклады и multiplier/cluster-процедуры; она не запускалась здесь. [C20.E01]

## B208. Staggered p-value сравнивает bootstrap с самой оценкой, а не с нулевой гипотезой

**Приоритет:** высокий вместе с B207; не ремонтировать отдельно косметическим сдвигом. **Основание:** _run_staggered_did; PV01–PV02. [C20.R02]

**Проблема.** p-value вычисляется как доля |boot|≥|att| с поправкой +1. Нецентрированный bootstrap обычно расположен вокруг наблюдаемой оценки; такая доля сама по себе не является хвостовой вероятностью статистики при нулевом эффекте.

**Воспроизведение.** В одной шумной ячейке из B207 одновременно получены ATT=5, CI=[5,5], p=1. На иллюстративных draws [4,9;5;5,1] исходный счётчик с +1 даёт 0,75, а счётчик отклонений boot−att относительно нуля — 0,25. Последний показан только как различение объектов сравнения, не как универсально корректная bootstrap-процедура.

**Рекомендуемое исправление.** Задать H0, тестовую статистику, её масштабирование и допустимый способ получения нулевого распределения совместно с уровнем повторной выборки. Использовать согласованную инверсию интервала/теста или проверенный центрированный/studentized/bootstrap-тест согласно дизайну. Если такой вывод не вычислен, сохранить ATT и имеющуюся диагностику, указав p-value как отсутствующий.

**Приёмка.** Увеличение реального эффекта при фиксированном шуме не должно механически удерживать p около 1/2. Проверять null-калибровку, мощность и соответствие интервалу на одних единицах. Больше bootstrap-повторов стабилизирует ошибочную формулу, но не исправляет её; +1 исправляет разрешение счётчика, а не выбор распределения.

## B209. Anticipation учитывается в baseline treated-группы, но не при выборе not-yet-treated controls

**Приоритет:** высокий для ненулевого anticipation, локальное расширение определения группы. **Основание:** _cohort_time_att; AN01–AN03. [C20.R02, C20.E01]

**Проблема.** Baseline сдвигается на group_start−1−anticipation, но control_mask допускает любую группу с timing>t. Группа, в которой уже действует разрешённый эффект предвосхищения, продолжает считаться нетронутым контролем.

**Воспроизведение.** Когорта g=2 имеет истинный эффект 2. Когорта g=3 уже в t=2 меняется на 10, поскольку anticipation=1; ещё одна единица никогда не treated. Для ATT(2,2) текущий not-yet-control даёт −3, тогда как never-treated и контроль timing>t+anticipation дают 2. При anticipation=0 и фактически отсутствующем раннем эффекте исходный выбор правильно даёт 2.

**Рекомендуемое исправление.** Формировать admissible-control по полной временной области воздействия, включая anticipation и необходимые baseline-окна. Сохранять идентификаторы использованных ячеек/когорт и правило контроля. Если пригодных controls нет, сохранить пробел конкретной ячейки и изменить область агрегирования только явно.

**Производительность и приёмка.** Подготовить cohort-time eligibility один раз и использовать также при повторных выборках. Не запрещать not-yet-treated или anticipation вообще: они полезны при корректных условиях. Контроль должен охватить границу g=t+a, никогда не treated, недостаточный baseline и case a=0. Внешняя документация определяет anticipation как период возможного влияния до назначения; это не подтверждение любой эмпирической гипотезы о его длине. [C20.E01]
