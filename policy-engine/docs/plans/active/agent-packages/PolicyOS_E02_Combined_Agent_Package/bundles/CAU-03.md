## Поручение и минимальная приёмка

Отделить поддержанный uncorrected local-polynomial от реально исполняемой bias-corrected процедуры. Убрать N×N diagonal weight matrix и повторную факторизацию без одновременной неявной смены covariance. Подключение RBC выполняется только через проверенный профиль/зависимость с фактическими параметрами.

**Различающие тесты и сохраняемое поведение.** Curved data с requested correction не даёт прежний uncorrected результат под флагом True. Uncorrected допустим отдельно. На 400 точках weighted-vector formula сохраняет point/SE и не создаёт 400×400. Kernel/order/rank и nonpositive-bandwidth контроли. Настоящий RBC-профиль — ограниченный K5, не повторные установки библиотек каждым агентом.

**Не считать исправлением.** Не называть quadratic fit robust bias correction. Честный unsupported corrected mode устраняет ложное обещание, но не считается внедрением самой RBC; capability-debt остаётся явно отмеченным.

**Цикл работы:** зафиксировать actual scope и нужный characterization; оформить equivalent move и намеренный behavior fix раздельно; выполнить указанные малые tests через I1; независимый reviewer проверяет actual owner; передать commit, path map и остатки. ## B210. RDD сообщает включённую bias correction без её вычисления

**Приоритет:** высокий для заявленного режима corrected inference; малый честный ограничитель плюс отдельный методологический ремонт. **Основание:** RegressionDiscontinuity.pure_step и его signature; RD01–RD03. [C20.R03, C20.E03]

**Проблема.** Параметр bias_correction используется лишь при заполнении method_params. Численно вычисляются разность локальных intercept и её текущая стандартная ошибка; дополнительных производных, correction-term и соответствующей variance-адаптации нет. Внутренний комментарий о heuristic bandwidth уже честен — его не следует превращать в заявление о точном IK-selector.

**Воспроизведение.** На 200 точках с истинным разрывом 3 и различной кривизной слева/справа оба значения флага дали estimate=2,793901410060 и CI=[2,754318328822;2,833484491298]. Флаг в metadata поменялся, вычисление — нет. Полином второй степени восстановил 3 в этом точном полиномиальном случае, но этот контроль не является реализацией robust bias correction (RBC). Неположительный bandwidth существующий метод правильно отвергает.

**Рекомендуемое исправление.** Разделить реально поддержанный обычный local-polynomial результат и подтверждённую RBC-процедуру. До внедрения последней явно ограничить requested corrected mode либо предложить разрешённый uncorrected результат с его областью применения, а не переписывать флаг в True. Если подключается профиль rdrobust, сохранить фактические bandwidth, порядки аппроксимации, variance-настройки, version и данные, не создавая конкурирующий причинный facade.

**Приёмка.** Настоящая curvature-проверка, известный скачок, контролируемая гетероскедастичность и finite-sample coverage. Численное включение correction должно изменять действительную вычислительную цепочку там, где поправка ненулевая. В этой работе rdrobust не установлен и не запускался. Обычную подгонку не следует блокировать полностью из-за неготовности более сильного inferential-профиля.

## B211. Локальная RDD-подгонка материализует квадратичную диагональную матрицу весов

**Приоритет:** высокая экономия относительно малого объёма правки на используемом RDD-пути. **Основание:** _fit_local_polynomial; RD04–RD05. [C20.R03]

**Проблема.** Для n наблюдений одной стороны создаётся np.diag(weights), затем XᵀWX и XᵀWy. Большая N×N матрица не нужна для диагонального оператора; дополнительно pseudoinverse одинаковой маленькой XᵀWX вызывается дважды.

**Воспроизведение.** На 400 точках одной стороны зафиксирована матрица 400×400, 1 280 000 bytes. Векторно-взвешенный design с двумя столбцами занял 6400 bytes. Диагонально-свободная формула дала тот же intercept=3,040424179788 и SE=0,005783542516. Независимый weighted-QR совпал по точке. Это сравнение выделенных структур и значений, не измеренный коэффициент ускорения всего RDD.

**Рекомендуемое исправление.** Минимально: Xᵀ(w⊙X), Xᵀ(w⊙y), одна разрешённая факторизация; не менять одновременно статистический смысл residual covariance. Следующий численно устойчивый вариант — weighted QR/SVD, масштабирование running variable относительно bandwidth и контроль ранга. Увеличение числа точек тогда не создаёт искусственный расход O(n²) только ради хранения весов.

**Приёмка.** Сопоставить точку, SE текущего профиля и effective sample count на всех поддержанных kernel/order. Случаи недостаточной опоры сохраняют точный отказ. Исправление производительности не доказывает правильность нынешней covariance или RBC — B210 остаётся отдельной задачей. Пакетирование нескольких bandwidth допускается только с корректной идентичностью выбранной области и профиля.
