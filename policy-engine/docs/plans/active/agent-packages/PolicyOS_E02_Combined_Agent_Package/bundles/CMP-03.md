## Поручение и минимальная приёмка

Сначала проверить допустимость ребра одинаковым semantic/partial контрактом; затем для малой задачи использовать matching/ограниченный augmenting-path ремонт вместо жадной безвозвратной привязки. Финальный DAG валидировать целиком.

**Различающие тесты и сохраняемое поведение.** Flexible source связывается со вторым обязательным входом, fixed — с первым; полное решение найдено. Переименование нейтральных slots не меняет существование решения. Auto и explicit одинаково отвергают запрещённую семантику и неполноту.

**Не считать исправлением.** Не ослаблять unit/shape/contract checks. Не выбирать содержательно неоднозначную связь только ради полного matching.

**Цикл работы:** зафиксировать actual scope и нужный characterization; оформить equivalent move и намеренный behavior fix раздельно; выполнить указанные малые tests через I1; независимый reviewer проверяет actual owner; передать commit, path map и остатки. CLI/test selectors разрешаются по настоящему checkout до запуска, не выдумываются из названия находки.

## B47. Жадный autolink может остановиться, хотя полное совместимое связывание существует

*Источник карточки: C03-06. Код прочитан в C03; локальные проверки, не полное исполнение PolicyOS.*

**Приоритет и охват:** S–M; когда используется автоматическая сборка.

**Основание.** Во втором проходе SlotLinker._link_auto входы рассматриваются по имени, а выбранный source помечается used и больше недоступен. При равных оценках _select_best_candidate выбирает минимальное имя источника. Алгоритм не перераспределяет прежнюю привязку, если следующий вход остался без источника. [N04]

**Различающий пример.** Источник a_flexible имеет contract_id=None, b_fixed — B. Первый вход c_first требует B, второй d_second — A; остальные типы, единицы и формы одинаковы. Правило контрактной совместимости допускает flexible к обоим, fixed только к первому. Жадный выбор flexible→first оставляет второй вход пустым; полное решение fixed→first, flexible→second существует. В локальной проверке использованы именно эта совместимость и равенство остальных score-компонент, но полный SlotSpec/реестр проекта не импортировался. [N08]

**Предлагаемое исправление.** Для небольшого списка слотов — полное двудольное matching по уже проверенной совместимости либо ограниченный ремонт через увеличивающий путь. Сначала максимизировать полноту допустимого назначения, затем применять предпочтения. Явное mapping остаётся самым дешёвым временным маршрутом для известной цепочки. Не ослаблять unit/shape/contract/semantic-проверки и не изобретать данные.

**Приёмка.** Пример выше связывается полностью; действительно невозможный набор остаётся неполным с точными причинами. Переименование нейтральных слотов не меняет сам факт существования допустимого назначения. Неоднозначность, влияющая на смысл, требует явного выбора, а не оптимизации по удобному имени.

**Граница.** Это маленькая задача соединения входов, не полный поиск комбинаций сотен методов. Польза зависит от частоты autolink; её численно не оценивали.

## B48. Ручная и автоматическая привязка применяют разные семантические проверки

*Источник карточки: C03-07. Код прочитан в C03; локальные проверки, не полное исполнение PolicyOS.*

**Приоритет и охват:** S–M; согласованно с B45/B47.

**Основание.** _link_explicit после проверки типов вызывает _check_semantic. Второй, type-based проход _link_auto после find_compatible_slots этого вызова не содержит. Нижний checker сравнивает contract_id, единицы, SlotType, форму и bounds; он не является проверкой именованных семантических групп. Последующий CrossMethodValidator сообщает semantic_slot как warning даже при strict=True. Поэтому одна и та же type-compatible связь, запрещённая именованным семантическим правилом, может быть принята автоматически и отклонена при явном mapping. [N04, N05, N08, N09]

**Предлагаемое исправление.** Одна финальная проверка связывания для автоматического и явного пути: обязательные условия применяются до выбора и повторно к полному результату построения. Для действительно допустимого семантического преобразования использовать явный существующий adapter/контракт. Не «лечить» расхождение отключением ручной проверки. Неизвестная семантика должна оставаться объявленно неизвестной, а не автоматически получать доказательную силу.

**Смежный контроль.** У _link_explicit и _link_auto также различается обработка неполной связи при allow_partial_links=False. Это внесено в приёмку паритета как дополнительное статическое наблюдение, а не отдельная новая карточка или новый эксперимент. Для multi-source DAG полноту проверять по всем входным привязкам, а не требовать, чтобы каждое отдельное ребро снабжало все входы.

**Приёмка.** Один набор source/target даёт одинаковую обязательную семантическую оценку в обоих режимах. Заведомо допустимая связь проходит; ошибочная — не проходит; явное преобразование проверяемо. Неполный и полный DAG различаются одинаково при ручной и автоматической сборке.

**Граница.** Локальный опыт использует заданный семантический oracle и проверяет расхождение ветвей, не весь runtime. Это защита корректного расширения композиции, не утверждение о реально принятом ошибочном управленческом решении.
