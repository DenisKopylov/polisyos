## Поручение и минимальная приёмка

Разделить устойчивый предмет задачи, версию основания и occurrence кандидата. Разрешить реальное обновление данных/модели/метода без обязательной новой грамматики; перевыпустить согласованные bindings и построить текущий фронт без потери истории.

**Различающие тесты и сохраняемое поведение.** Тот же кандидат на новой версии данных переоценивается и имеет новый occurrence; прежняя попытка остаётся читаемой. Новый UUID при тех же inputs не создаёт бесконечное исследование. Изменённая популяция/модель не использует старое основание. В K1 проверить T2 на настоящем входе.

**Не считать исправлением.** Не отключать context/hash validation; не dedupe по одному candidate_id и не считать timestamp научным прогрессом.

**Цикл работы:** зафиксировать actual scope и нужный characterization; оформить equivalent move и намеренный behavior fix раздельно; выполнить указанные малые tests через I1; независимый reviewer проверяет actual owner; передать commit, path map и остатки. CLI/test selectors разрешаются по настоящему checkout до запуска, не выдумываются из названия находки.

## B09. Полезное продолжение не обязано расширять грамматику

*Источник карточки: A:B09. Унаследовано из прочитанной сводки A; не новый интеграционный прогон.*

**Происхождение и подтверждение:** P1/P2; код и локальные проверки предыдущих пакетов. `enforce_no_retry_without_new_grammar` отказывает и при новом candidate_ref, и при упрощении A+B → A, если не появились новые грамматические элементы. Валидатор также требует новой грамматики и отвергает повтор содержимого кандидата в следующей итерации. [A.R04: 2820–2965, 3880–4170; A.H1; A.H2]

**Экономное расширение:** разрешать повтор при изменении существенного исследовательского основания: данных, связанной модели, применимого метода, исправленного ограничения или явно разрешённой проверки устойчивости. Прогресс определяется фактически потреблёнными объектами и целью шага, не новым timestamp/UUID. Отдельно ограничиваются технические retries и повторения измерений.

**Критерий:** тот же кандидат с новыми реальными данными переоценивается; тот же кандидат на тех же входах под новым именем не запускается бесконечно. Обновляются и переход, и последующий валидатор. Проверяется идентичность occurrence и привязка к исходной/пересмотренной задаче.

**Ограничение и приоритет:** отдельный путь re-entry после active overlay уже существует; прежнее обобщение «невозможно продолжать без новой грамматики вообще» не принимается. Высокое влияние, средняя контрактная сложность; не просто удалить исключение.

## B27. Пересмотр меняет идентичность задачи, а контекст остаётся прежним

*Источник карточки: L:F25. Унаследовано из Library S01; не дублируется с A.*

**Основание:** Статический межкомпонентный вывод; сценарий условен. **Происхождение:** P4 — новая находка. **Приоритет:** A вместе с B09. **Охват изменения:** M.

**Наблюдение и барьер.** _default_revision_request меняет runtime_hints. _problem_ref хэширует полный model_dump, включая эти hints. N6 продолжает с revised_problem, но держит прежний _cycle_substrate_context; проверки N5/N7 сравнивают context.design_problem_ref с hash активной задачи. При достижении такой итерации возникает риск собственного context_mismatch. [L.S18, L.S25, L.S03, L.S04, L.S22]

**Минимальное расширение.** Разделить постоянную идентичность исследовательской задачи и версию состояния её исполнения либо перевыпускать связанный context при пересмотре. Поддержать явный переход с указанием изменённых оснований. Не просто отключать проверку равенства.

**Проверка результата.** Допустимая вторая итерация получает согласованный context и проходит; изменение предмета, популяции либо модели не переиспользует старые доказательные привязки. Проверить исходный и пересмотренный запрос в общей сохранённой истории.

**Граница вывода.** Полный второй цикл не запускался; вывод относится к пути, который действительно достигнет advance и повторно использует прежний context. Смена hash не является доказательством нового знания.

## B28. Кандидат и его повторное исследование смешиваются в общем списке идентификаторов

*Источник карточки: L:F26. Унаследовано из Library S01; не дублируется с A.*

**Основание:** Код + локальный предикат знаменателя P4-05. **Происхождение:** P4 — новая находка. **Приоритет:** A вместе с B09/B10. **Охват изменения:** M.

**Наблюдение и барьер.** N6 расширяет summaries между циклами; _derive_fronts записывает candidate_id каждой строки. Валидатор требует полного совпадения множества/кратностей и одновременно отсутствия повторов front_ids. Повторное наблюдение того же candidate_id вступает в противоречие с такой схемой. [L.S04, L.S12, L.S19]

**Минимальное расширение.** Использовать существующую идентичность появления кандидата в конкретной итерации, отдельно от предметной идентичности кандидата. История сохраняет все появления; текущий фронт показывает однозначно выбранную актуальную версию. Согласовать ссылки и привязку promotion.

**Проверка результата.** Один кандидат на двух версиях данных представлен без потери истории и без дубликатов текущего фронта. Итог второй попытки не присваивается первой. Проверить, что downstream получает нужную occurrence.

**Граница вывода.** Локально проверен только предикат; конкретное появление повторяющихся ID в генераторе не измерялось. Запрещено исправлять слепым dedupe: он потеряет версии и может перепривязать доказательства.
