## Поручение и минимальная приёмка

Один конечный source/config/FQN/file-loader/package census четырёх узких областей. Удалить Foundry ранние DTO и Data Forge codegen descriptor только при отсутствии необходимой роли; pipeline/schemas перевести на canonical kernel/schemas. Для пустого Foundry tombstone заменить требование успешного import отрицательной архитектурной проверкой. Каждое условное решение фиксируется отдельно; обнаруженный внешний contract сохраняется/мигрирует, а не угадывается.

**Различающие тесты и сохраняемое поведение.** Проверить AgentType/RegionProfile/SimulationConfig, GeneratedSchemaModule и три schema aliases, relative/string/generated consumers. Canonical classes identity и schema evolution/migrations работают; retired reexports не возвращаются. Нативные выбранные schema tests сейчас, объединённый wheel/sdist inventory в CP6. Неизвестный внешний consumer означает compatibility_pending конкретного имени, не блок всего ремонта.

**Не считать исправлением.** Не удалять kernel/schemas, pipeline/materialize, действующие Foundry contracts или отрицательные tests. Не создавать новый генератор ради codegen placeholder. Не переносить устаревшие DTO на всякий случай.

**Цикл работы:** зафиксировать actual scope и нужный characterization; оформить equivalent move и намеренный behavior fix раздельно; выполнить указанные малые tests через I1; независимый reviewer проверяет actual owner; передать commit, path map и остатки. CLI/test selectors разрешаются по настоящему checkout до запуска, не выдумываются из названия находки.

## LA-005. Foundry domain/schema: остаточная ранняя предметная схема

**Прямая очистка: перенос логики не нужен**

**Статус.** Сильный кандидат, но отсутствие внешних потребителей не доказано.

**Точная область:**

`src/polisyos/foundry/domain/schema.py`

**Что установлено и почему это legacy-кандидат.** Файл задаёт три AgentType, RegionProfile и небольшой SimulationConfig. Здесь нет исполнительной логики. Предметные поля ранней фиксированной популяции находятся в слое, от которого Foundry уже отделил runtime contracts. Адресный поиск RegionProfile вернул только определение; это поддерживает, но не завершает доказательство retirement.

**Что сохранить.** Только реально подтверждённые persisted inputs или example requirements. Не переносить весь DTO «на всякий случай»: это размножит старую схему.

**Куда перенести / с чем объединить.** При отсутствии потребителей — удалить без переноса. Если живой economic-plugin действительно использует региональные параметры, адаптировать нужные поля в его существующий state/config; для демонстрационного сценария — в принадлежащую ему fixture. Не помещать устаревшую схему в общие Foundry contracts автоматически.

**Порядок миграции.** Проверить FQN, AgentType, SimulationConfig, relative imports, YAML/JSON schemas и исторические артефакты. При обнаружении внешнего пути сначала однозначный converter и release note; без него прямое удаление преждевременно.

**Приёмочная проверка.** Поиск по полному дереву и сборке distribution, импортные и сценарные tests, round-trip обнаруженных старых inputs. Проверка одного символа не заменяет проверку всех трёх типов.

**Приоритет.** Дешёвая очистка при подтверждении неиспользования.

**Граница вывода.** Поиск GitHub ограничен индексом и выборкой; он не устанавливает абсолютный ноль callers. Это кандидат на прямое удаление логики, а не уже утверждённый delete-plan.

**Основания:** E08, E36.

## LA-006. Foundry domain/mechanisms: пустой tombstone с тестовым контрактом

**Вывод compatibility после миграции**

**Статус.** Legacy namespace подтверждён; есть явный потребитель-тест.

**Точная область:**

`src/polisyos/foundry/domain/mechanisms/__init__.py`

`src/polisyos/foundry/domain/mechanisms/README.md`

**Что установлено и почему это legacy-кандидат.** Пакет намеренно пуст; его единственная заявленная роль — оставаться импортируемым, чтобы тест проверял отсутствие прежних reexports. Это законченный compatibility-остаток, а не производственная механика. Однако существующий тест сейчас прямо требует успешного импорта package.

**Что сохранить.** Гарантию, что удалённые submodules и legacy reexports не возвращаются. Сам пустой package для этой гарантии не обязателен.

**Куда перенести / с чем объединить.** Переносить вычисления некуда: их уже нет. Сохранить отрицательные проверки в tests/unit/foundry/hygiene и архитектурном lint; краткую историю retirement — в migration docs. После LA-005 можно отдельно рассмотреть удаление всего пустеющего foundry/domain/.

**Порядок миграции.** В одном изменении обновить policy удаления package и тест: проверять его отсутствие либо обнаружение запрещённых файлов, а не доступность пустой оболочки. Проверить docs/lifecycle gate. Не удалять полезную отрицательную проверку вместе с stub.

**Приёмочная проверка.** Старые FQN не импортируются, banned reexports не появляются в новых фасадах; discovery и packaging не восстанавливают директорию.

**Приоритет.** Низкая цена, небольшое упрощение дерева.

**Граница вывода.** Не готово к одному rm без изменения тестового контракта. Поддержка старого package как официальной внешней точки ещё требует решения владельца.

**Основания:** E09, E10.

## Исходное решение LA-026

Источник LA_r09, строки 1372–1417; полный текст, не только выполняемая здесь фаза.

<!-- SOURCE_BEGIN LA:LA-026 -->
## LA-026. Schema codegen: остаточная декларация вместо генератора

**Прямая очистка: перенос вычислительной логики не нужен**

**Точная область:**

`src/polisyos/data_forge/kernel/schemas/codegen.py`



**Статус.** Сильный кандидат на прямую очистку; полный ноль потребителей не установлен.



**Что установлено и почему это legacy-кандидат.** Файл прямо назван Phase 0A placeholder. Его единственное содержательное определение — GeneratedSchemaModule с тремя строками module_name, schema_id и schema_version. Нет генерации, записи кода или преобразования схем. Действующий schemas/__init__.py экспортирует registry, evolution и migrations, но не этот тип. Адресный поиск GeneratedSchemaModule вернул только определение. В отличие от реального малого компонента, здесь сохранилось предварительное обещание будущей функции, а не её реализация.



**Что сохранить.** Реальные SchemaRegistry, правила evolution и migration, существующие внешние генераторы и поддержанные сериализованные описания, если их потребители будут обнаружены. Не удалять весь kernel/schemas и не заменять его placeholder новым framework.



**Куда перенести / с чем объединить.** При отсутствии необходимых потребителей удалить файл без переноса. Если три поля используются как устойчивый descriptor, поместить именно этот контракт рядом с фактическим schema registry или владельцем генерации. Новый генератор не требуется создавать ради сохранения имени codegen.py.



**Порядок миграции.** Проверить класс, полный модульный путь, относительные импорты, schemas/ABI, package data и сохранённые payload. Отдельно подтвердить, что runtime не загружает его по имени файла. Затем убрать точный файл и связанные декларации, оставив историю в Git. Обнаруженный реальный внешний контракт сначала получает converter или период совместимости.



**Фактическая проверка и приёмка.** P02 подтверждает отсутствие методов и три объявленных поля через AST точного blob; P01 проверяет его Git SHA. Для удаления в проекте нужны поиск по полному доступному дереву, сборка distribution и schema-tests. Проверка AST не доказывает отсутствие внешнего клиента.



**Приоритет.** Высокая ясность, малая цена. Сокращение ложной функциональной поверхности, не обещание ускорения вычислений.



**Граница вывода.** Поиск не является полным caller census. Декларативная модель сама по себе не бесполезна; вывод обусловлен placeholder-ролью, отсутствием экспорта и ненайденным потребителем в проверенной области.



**Основания:** E69, E70. Локальные проверки: P01, P02.

## LA-027. pipeline/schemas: законченный перенос, но остаётся второй адрес

**Завершение compatibility-миграции**

**Точная область:**

`src/polisyos/data_forge/kernel/pipeline/schemas/__init__.py`

`src/polisyos/data_forge/kernel/pipeline/schemas/README.md`



**Статус.** Совместимая обёртка подтверждена; перенос вычислительной логики уже не нужен.

Путь удерживает старую раскладку pipeline/schemas, хотя текущий владелец расположен выше. Точный поиск полного import-prefix не дал результатов, но это не заменяет проверку относительных и строковых ссылок.



**Что сохранить.** Идентичность трёх классов, текущую canonical реализацию kernel/schemas, контракты миграции/эволюции и доступ к старым форматам. Удаление Python-адреса не является основанием переписать данные.



**Куда перенести / с чем объединить.** Существующий src/polisyos/data_forge/kernel/schemas/. Никаких новых schema-модулей создавать не требуется. Удалить только совместимый pipeline/schemas после завершения адресной миграции; pipeline/materialize и assets остаются.



**Порядок миграции.** Обновить source/config/docs/generated consumers и правила public surface. Если адрес поддержан внешне, выдержать действительное окно совместимости. Затем убрать alias и пустой каталог. Устаревшие примеры в активном плане следует исправлять как навигацию, сохраняя исторические записи отдельно.



**Фактическая проверка и приёмка.** P03 исполняет точный initializer с fixture canonical-module и подтверждает identity всех трёх экспортов. В проекте проверить реальные imports и schema-тесты, сборку wheel/sdist и чтение исторических fixture. README прочитан только на уровне состава дерева; его текст не использован как самостоятельное основание.



**Приоритет.** Небольшая отдельная очистка. Низкий вычислительный эффект, но исчезает лишний рекомендуемый адрес.



**Граница вывода.** Последняя возвращённая path-history запись от 5 мая 2026 года относится к реорганизации, а не доказывает отсутствие поздних клиентов. Нельзя удалять kernel/schemas или его миграционные readers по соседству.

## K03. schemas/abi_models.py

В прочитанной части это ABIModelEntry registry со ссылками на настоящие DTO и schema files, а не дублирующие определения этих DTO.

**Решение:** Не переносить весь реестр в один продуктовый домен по числу файлов. Возможность generative consolidation требует отдельной проверки downstream generation. [E35]

<!-- SOURCE_END LK:LK03 -->

<!-- SOURCE_BEGIN LK:LK10 -->
## K10. Малый materialize.py выполняет настоящую функцию

Его AssetDefinition связывает спецификацию с callable; декоратор сохраняет связь; plan_asset_specs упорядочивает зависимости и отвергает отсутствующую зависимость и цикл. Три контрольных случая P20–P22 прошли на выбранной исходной функции с минимальными fixture-спецификациями. Это не полный materialization executor, но и не бессодержательный placeholder. **Сохранить реальные контракты и planner; не приписывать ему неисполненные возможности распределённой системы.** [E72]

<!-- SOURCE_END LK:LK10 -->

<!-- SOURCE_BEGIN LK:LK25 -->
## K25. Data Forge graph migration не равен двум линейным runners

Полная реализация допускает несколько переходов из одной версии, сортирует исходящие рёбра и строит кратчайший путь. В контрольном графе с двумя равными по длине путями порядок регистрации не изменил выбранные `low → vialow`; повтор exact-edge отвергнут, формат двухкомпонентной версии не прошёл schema validation. Это самостоятельные полезные свойства. Его shallow copy и отсутствие auto-stamping прямо соответствуют описанной функции, хотя их нельзя подменять Common guarantee. **Не удалять registry и не объявлять его готовой заменой Common/IR.** [E180, E195–E196; r07-P10–P12]

<!-- SOURCE_END LK:LK25 -->
