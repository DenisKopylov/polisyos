## Поручение и минимальная приёмка

Определить единый backend mapping закона с настоящей параметризацией для sampler/analyzer. Передать version-compatible seed/Generator библиотеке, разделить logical substreams и убрать global NumPy reset.

**Различающие тесты и сохраняемое поведение.** Корректно заданные UNIFORM/NORMAL действительно меняют sample support/квантили. Одинаковый seed повторяет малую выборку; порядок независимых задач не меняет inputs; внешний RNG не сбрасывается. Один маленький настоящий SALib/SciPy путь выполняется в слоте N.

**Не считать исправлением.** Не копировать только dists без смысла mean/std/bounds. Не читать неоднозначные старые планы как uniform; не превращать reuse в новую реплику.

**Цикл работы:** зафиксировать actual scope и нужный characterization; оформить equivalent move и намеренный behavior fix раздельно; выполнить указанные малые tests через I1; независимый reviewer проверяет actual owner; передать commit, path map и остатки. ## B100. Sampling и analysis используют разные определения распределений параметров

**Основание и область:** две функции `_plan_to_salib_problem` в sampling.py и analysis.py, `ParameterSpec`. Высокий при неравномерных распределениях; M. [C09.R01, R03, R05, E02]

**Проблема.** В sampler передаются только имена, число параметров и пары границ. `distribution` отсутствует. Analyzer для того же плана добавляет `norm`, `lognorm` или `triang`. Таким образом, изменение заявленного распределения не изменяет переданное sampler описание, а два этапа уже не ссылаются на одно определение эксперимента. Это не утверждение, что каждый SALib analyzer использует эти метки одинаково; первичен сам разрыв между планом и генерацией.

**Локальный опыт D1–D3.** Для NORMAL и UNIFORM с одинаковыми границами sampling-helper вернул одинаковые словари; analysis-helper для NORMAL добавил `dists=['norm']`. Для UNIFORM оба совпали. Эти helpers исполнены целиком. Реальная SALib-выборка не генерировалась.

**Рекомендуемое решение.** Единое разрешённое определение распределений и преобразования в backend, используемое и producer, и analyzer, сохранённое с дизайном. Не ограничиваться копированием поля `dists`: интервальные границы, параметры нормального/логнормального закона и параметры треугольного закона имеют разный смысл. Нынешние `lower_bound/upper_bound` с проверкой порядка нельзя автоматически переименовать в mean/std. Неоднозначные старые планы должны получать адресное уточнение/миграцию, а не молча исследоваться как uniform.

**Приёмка.** Проверить содержательное изменение сэмплов при смене закона с фиксированным допустимым RNG; support, квантили и способ усечения; round-trip описания; совпадение sampler/analyzer fingerprint. Нормировка и независимость параметров являются научными предпосылками и не создаются удобством адаптера. Для однозначного UNIFORM сохранить нынешний работающий путь.

## B101. Seed плана не доходит до локального генератора библиотеки, но меняет глобальный NumPy state

**Основание и область:** sensitivity sampling/analysis и `_set_numpy_seed`; актуальные интерфейсы SALib и SciPy. M, либо S для явной передачи поддерживаемого seed. [C09.R01, R03, E01]

**Проблема.** Sampling вызывает `np.random.seed(plan.seed)`, но не передаёт `seed` в вызовы SALib. В sensitivity analyzers он также не передаётся. У библиотечных реализаций, использующих собственный Generator/QMC, глобальное legacy-seed не заменяет seed конкретного генератора. Одновременно helper меняет случайное состояние соседних потребителей. Это зависит от версии/backend; не следует объявлять одинаково неверными все SALib-реализации.

**Локальный опыт S1–S4.** Boundary-spy подтвердил отсутствие `seed` в переданном вызове при `plan.seed=13`. Настоящий SciPy QMC дал разные сетки после одинаковых `np.random.seed(13)`, но одинаковые при явном seed самого Sobol-генератора. Этот опыт не назван запуском SALib. RANDOM_TAIL использует свой `default_rng(plan.seed)` и повторяет собственные значения, но всё равно сбрасывает внешнее состояние через предшествующий helper.

**Рекомендуемое решение.** Передавать seed/Generator через поддерживаемый versioned backend API; независимые стадии sampling, model randomness и uncertainty получают определённые под-потоки. Сохранить идентичность реплики и дизайна при resume и кэшировании. Не использовать глобальный reset в общем процессе. Для неизбежного legacy backend нужна изоляция, а не один локальный lock, которого не соблюдают остальные библиотеки.

**Приёмка.** Одинаковый полный запрос в заявленной версии воспроизводим; другая seed/replica меняет нужную случайную часть; перестановка независимых задач не меняет их входы. Повторная статистическая реплика и cache-hit не должны считаться двумя независимыми наблюдениями. Подключение локальных генераторов не удостоверяет само по себе сходимость или достоверность модели мира.
