## Поручение и минимальная приёмка

Канонически нормализовать уже известное обратное направление без потери marks. Для частично ориентированных и lag-графов выбрать supported consumer/явное корректное преобразование; если его нет, вернуть ограничение конкретного маршрута, не произвольный DAG. Сохранить компактный temporal input и контроль нулевого лага.

**Различающие тесты и сохраняемое поведение.** PAG X←Y не превращается в X→Y. CPDAG triangle не получает labelDAG поверх цикла. Lag=1/lag=2 различимы после round-trip; autoregression разрешается в подходящем temporal contract. Малое конечное развёртывание четырёх времён сохраняет ацикличность. Static DAG остаётся рабочим.

**Не считать исправлением.** Не удалять неудобные рёбра/лаги, не отключать DAG validation. Полная поддержка всех PAG/temporal families не является предварительным условием статического K5; незавершённые capability части отмечать отдельно.

**Цикл работы:** зафиксировать actual scope и нужный characterization; оформить equivalent move и намеренный behavior fix раздельно; выполнить указанные малые tests через I1; независимый reviewer проверяет actual owner; передать commit, path map и остатки. CLI/test selectors разрешаются по настоящему checkout до запуска, не выдумываются из названия находки.

## B214. Проекция PAG/CPDAG разворачивает известное направление и может создать цикл

**Приоритет:** высокий при передаче графа DAG-потребителю; нормализация известного направления дешева, выбор допустимого расширения — отдельная задача. **Основание:** полный _graph_projection.py, CausalGraphModel и GCM-fit caller; GP01–GP04. [C20.R08–R10]

**Проблема.** Единственный признанный полностью ориентированным случай — tail на src и arrow на dst. Случай arrow на src и tail на dst означает известное обратное направление, но обрабатывается как неопределённость: метки меняются на tail/arrow без перестановки концов. Для неопределённых рёбер применяется тот же порядок хранения, после чего graph_type заменяется на DAG через model_copy без повторной валидации.

**Воспроизведение.** В PAG ребро X←Y стало X→Y и получило orientation_uncertain=True. Полный неориентированный CPDAG-треугольник, записанный A—B, B—C, C—A, стал циклом A→B→C→A с меткой DAG. Численная фикстура графа — не полный native DTO; допустимость такого reversed edge и запрет циклов в настоящем DAG проверены чтением контракта.

**Рекомендуемое исправление.** Сначала канонически нормализовать уже известные направления, сохраняя origin и marks. Затем либо использовать допускающий частичную ориентацию идентификатор, либо строить согласованное расширение с проверкой направлений, ацикличности и свойств класса эквивалентности. Для PAG произвольный выбор одного DAG вообще не заменяет causal-identification по допустимому семейству; исследовательскую модель нужно сохранять условной.

**Положительные контроли.** Готовый корректный DAG возвращается без изменения; bidirected edge заменяется общим latent U и двумя исходящими рёбрами. Это полезные существующие части. Уточнение не должно превращать все частично определённые графы в полный отказ: можно сохранять несколько допустимых моделей или ограниченный результат. Простое удаление ребра цикла либо отключение DAG-validation неприемлемо. Исправленная нормализация одного известного reversed edge проверена отдельно; общий sound-extension алгоритм здесь не реализован.

## B218. Временной граф теряет лаги при экспорте, а лаговая самозависимость отвергается как обычный self-loop

**Происхождение и приоритет:** C21-03. Высокий при передаче temporal discovery в статические методы; иначе условный. Основания: `CausalGraphModel` validation/export, adjacency и GCM parent-view. [C21.R01–R02, C21.R05]

**Проблема.** Контракт хранит `lag` и допускает взаимные лаговые рёбра, проверяя ацикличность лишь для одновременных. Но `to_dot` не передаёт lag и использует одно имя переменной на все времена. Общие ADMG-операции включают лаговые отношения как статические, тогда как GCM parent-map их пропускает. Одновременно любая связь `src==dst` отвергается до проверки лага. Поэтому разные потребители получают разные временные модели из одного объекта.

**TIME01–TIME04.** X→Y с lag=1 и lag=2 дают один и тот же DOT. Допустимый в DTO граф X→Y lag=1, Y→X lag=1 после статического представления имеет цикл. Простая авторегрессия X(t−1)→X(t), записанная одним именем и lag=1, отвергается. Контрольное конечное развёртывание обратной связи на четыре момента, восемь узлов, ациклично.

**Исправление.** Разрешать временную семантику на границе потребителя: координата `(variable,time)`, соглашение о лаге, начальные условия и горизонт. Использовать подходящий temporal-consumer либо конечное развёртывание только нужной области запроса. Для чисто статического потребителя возвращать точную несовместимость, если временное преобразование ещё не выполнено.

Параметризация одной переменной во времени и явные временные узлы могут сосуществовать через однозначный адаптер. Не следует просто разрешить все self-loops, отбросить лаг или удалить неудобное ребро для получения DAG. Нулевая задержка в обычном DAG по-прежнему требует запрета цикла. Проверка expanded-формы должна относиться к фактически читаемым данным и временам, иначе правильный рисунок не обеспечит правильного расчёта.

**Приёмка/граница.** Round-trip должен различать lag1/lag2 и сохранять причинное время. Для известного статического DAG путь не меняется. Контрпример касается принятого compact temporal-формата; отдельный маршрут, сразу создающий явные временные узлы, может не испытывать этого дефекта. Не установлено, что вся временная часть системы использует данный экспорт.
