## Поручение и минимальная приёмка

Узко разрешить reuse действительно зафиксированных inputs/model/settings/scope вместо лексического запрета каждого URL. В пределах допустимого reuse объединить одинаковые in-flight запросы; явно обработать owner/deadline/cancel и publication.

**Различающие тесты и сохраняемое поведение.** Frozen snapshot со ссылкой reuse-ится; живой URL без снимка — нет. Четыре одинаковых разрешённых miss дают один provider-call; другой seed/tenant — отдельный. Отмена одного follower не лишает результата остальных; error не оставляет вечный flight.

**Не считать исправлением.** Не удалять URL/uncertainty_notes ради guard; не считать temperature=0 разрешением склеить намеренные независимые реплики.

**Цикл работы:** зафиксировать actual scope и нужный characterization; оформить equivalent move и намеренный behavior fix раздельно; выполнить указанные малые tests через I1; независимый reviewer проверяет actual owner; передать commit, path map и остатки. CLI/test selectors разрешаются по настоящему checkout до запуска, не выдумываются из названия находки.

## B67. Лексический запрет кэширования исключает и неизменяемые доказательные входы

*Восстановленный источник: Library-S02/U45. Уровень подтверждения не повышен.*

**Происхождение:** C03-04. Исторический C03 альтернативной Library-ветки; не новый C05.

**Приоритет:** После сквозной проходимости; оптимизация с ограничениями. **Охват:** S–M.

**Наблюдение.** `_cache_skip_reason` запрещает reuse, когда в тексте встречаются http/https, query_traces, claim_supports или uncertainty_notes. Поэтому даже ссылка на неизменяемый commit либо уже замороженный пакет с полем uncertainty_notes вызывает retrieval_freshness_guard. Это консервативный барьер, защищающий от устаревания; не ошибка, позволяющая ложный допуск. Но он исключает типичный доказательно насыщенный материал из дешёвого повторного использования.

**Минимальное расширение.** Сохранять общий запрет для непривязанных живых источников. Предусмотреть узкий путь reuse, когда фактические входные bytes/артефакты, версия модели и существенные параметры зафиксированы и разрешены для данного потребления. Проверка должна опираться на настоящие ссылки и hashes, а не на заявление cacheable=True от агента. При каждом чтении сохранять актуальную проверку доступа и ограничения использования.

Не удалять URL из текста ради прохождения cache guard, не заменять его регулярным выражением «похоже на commit», не продлевать TTL без основания. Наличие URI само по себе не является ни доказательством изменяемости, ни доказательством неизменяемости.

**Приёмочная проверка.** Один и тот же разрешённый замороженный пакет действительно переиспользуется; новая версия материала, изменённая модель, другие параметры или утраченное право чтения исключают hit. Живой URL без проверенного снимка остаётся некэшируемым. Tool-calls, потоковые ответы и намеренные независимые повторения не получают разрешение только от этого расширения.

**Граница.** Испытан лишь перенесённый предикат на строках; реальный выигрыш времени и денег ещё не измерен. Это предложение повысить экономичность уже правильного вычисления, не новый обязательный gate перед первым результатом. Связано с S01/S06, но не требует массовой переобработки корпуса.

## B68. Одновременные промахи кэша не объединяются в одну разрешённую работу

*Восстановленный источник: Library-S02/U46. Уровень подтверждения не повышен.*

**Происхождение:** C03-05. Исторический C03 альтернативной Library-ветки; не новый C05.

**Приоритет:** Условная экономия малых параллельных ветвей. **Охват:** S–M.

**Наблюдение.** InMemoryPromptCache защищает get/put блокировкой, но CachingLLMClient выполняет последовательность get → await provider → put без общей записи «работа по этому ключу уже идёт». Несколько одновременно пришедших одинаковых miss могут вызвать несколько внешних генераций. В локальной async-модели четыре одинаковых запроса дали четыре provider-вызова; последующий последовательный запрос уже был hit. Изменённый seed правильно потребовал новую работу.

**Минимальное расширение.** Для заранее допустимого повторного использования добавить в существующую обёртку небольшую in-flight запись по полному ключу и общему допустимому контексту: одна задача производит результат, остальные ожидают его. Общий Task должен иметь владельца, предел времени и очистку записи после ошибки; отказ одного ожидающего не должен автоматически отменять необходимую другим работу. Это не distributed lock и не новый сервис.

**Ограничения объединения.** Не объединять независимые стохастические повторения, разные seeds/инструкции/снимки, разные разрешения доступа, несовместимые tenant scopes или разные цели допустимого reuse. Даже temperature=0 не превращает два желаемых независимых вызова в один эксперимент. При неидемпотентном внешнем действии такое объединение не заменяет отдельную политику действия.

**Приёмочная проверка.** Четыре разрешённых одинаковых ожидания дают один фактический provider-call; другая версия/seed — отдельный. Отмена одного ожидания не лишает результата остальных, общий deadline и бюджет соблюдены, исключение producer не оставляет вечный in-flight.

**Граница.** Текущий cache thread-safe относительно контейнера; наличие нескольких miss не доказывает ошибку его целостности. Это недостающая оптимизация выбранной формы reuse. Масштабируемость, межклиентское разделение кэша и производственная частота дублирования не проверены. Контроль использует фикстурный cache с lock и упрощённым ключом.
