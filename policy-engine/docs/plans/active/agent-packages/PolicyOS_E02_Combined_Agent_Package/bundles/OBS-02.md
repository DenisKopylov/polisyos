## Поручение и минимальная приёмка

Исправить B147 в sources.py с учётом новых явных helpers UDF-02. Fallback до первого yield может сменить reader; после выдачи — resume на точной подтверждённой позиции snapshot либо согласованная отмена draft-generation. Позиция учитывает разные metric frames внутри batch.

**Различающие тесты и сохраняемое поведение.** Сбой до выдачи, после первого batch и между двумя metric frames не повторяет префикс и не теряет наблюдения. На двух blocks проверить итоговые shard IDs/counts, snapshot и отсутствие full-read memory обхода. Малый настоящий Parquet-reader плюс controlled failure.

**Не считать исправлением.** Не удалять одинаковые значения как duplicates и не менять snapshot по местному offset. Не подменять поток giant full-read.

**Цикл работы:** зафиксировать actual scope и нужный characterization; оформить equivalent move и намеренный behavior fix раздельно; выполнить указанные малые tests через I1; независимый reviewer проверяет actual owner; передать commit, path map и остатки. CLI/test selectors разрешаются по настоящему checkout до запуска, не выдумываются из названия находки.

## B147. Запасной путь чтения после частичной выдачи повторно публикует уже выданный префикс

**Основание и область:** `_iter_observation_metric_frames` охватывает одним try не только открытие Parquet, но цикл чтения, преобразование и yield отдельных metric-frame. В except выполняется полное чтение того же пути и преобразование с row_offset=0. D2-потребитель сохраняет каждый выданный фрагмент, увеличивает счётчики и соединяет shards без удаления повторов. [C13.R05]

**Проблема.** Переключение после первого опубликованного блока отличается от переключения до начала работы. Генератор не отзывает уже выданные результаты; fallback начинает с начала. Потребитель получает прежний префикс ещё раз, возможно с повторными observation_id и уже другими batch-index. Полное чтение также может потребовать больше памяти, чем исходный потоковый маршрут.

**Локальное свидетельство P34–P37.** Источник-фикстура с `[10,20,30]` без сбоя выдал три значения. После выдачи `[10,20]` reader-фикстура подняла OSError; fallback выдал все три заново, итог `[10,20,10,20,30]` и два повторных observation_id. Сбой до первого опубликованного блока не создавал дублей. Контроль продолжения от подтверждённой позиции того же неизменяемого источника сохранил три значения. PyArrow и настоящий Parquet не запускались: reader, batches и mapper заменены явно описанными интерфейсами; pandas и порядок yield/except реальные.

**Рекомендуемое исправление.** До выдачи разрешён альтернативный reader того же запроса. После выдачи — либо продолжение от подтверждённой границы конкретного снимка, либо отмена всей ещё не опубликованной генерации с согласованным удалением/отзывом её draft-выходов до полного replay. Курсор должен учитывать частичную выдачу нескольких metric-frame внутри блока, а не только число исходных строк. Фактическую публикацию и учёт нельзя делать невидимыми для fallback.

**Приёмка.** Ошибка до первого yield, после первого блока и между двумя метриками блока; одинаковые исходные строки не теряются и не размножаются. Другой reader не меняет snapshot/область/схему. Проверить downstream shards и итоговые счётчики, а не только список значений генератора. Ошибка допуска, схемы или семантики не маскируется как временная ошибка формата.

**Не делать и границы.** Не удалять все одинаковые значения: они могут быть настоящими повторными событиями. Не считать локальный offset достаточным при изменяемом файле. Предыдущая B81 касалась пропуска необработанного блока при checkpoint; здесь противоположная проблема — повтор выданного префикса при смене reader. Дорогой full-read fallback должен оставаться в принятом ресурсном режиме, а не автоматически обходить ограничение памяти.

## K12. read_api содержит проверки, а не только forwarding

В Ukraine read_api кроме ленивых экспортов есть проверка и сохранение точных bytes, размеров и hashes и явные ограничения назначения receipts. Это не лишняя оболочка, которую можно обойти прямым открытием файлов. В то же время D5 receipt не является готовым сертификатом любого демографического каталога. LA-032 использует этот подход как существующий материал для адаптера, а не автоматически расширяет его область. Чистый build_static_aging_state также остаётся полезной отдельной операцией.
