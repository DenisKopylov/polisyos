## Поручение и минимальная приёмка

Исправить join-before-drain: контролируемо читать канал параллельно живучести либо передавать маленькую существующую artifact-ref. Разделить compute и delivery timeout; согласовать выбранный процессный старт и cleanup с macOS.

**Различающие тесты и сохраняемое поведение.** В отдельном тестовом процессе маленький результат и 1MiB доставляются без ложного timeout. Compute timeout прекращает только принадлежащее тесту вычисление; сбой отправки не публикует success. Проверить сериализацию и отсутствие висящих собственных потомков после завершения.

**Не считать исправлением.** Не запускать большой payload во множестве агентов. Не менять fork на spawn одним словом без сериализации/владения; не заявлять Linux/Ray/Temporal coverage по Mac-тесту.

**Цикл работы:** зафиксировать actual scope и нужный characterization; оформить equivalent move и намеренный behavior fix раздельно; выполнить указанные малые tests через I1; независимый reviewer проверяет actual owner; передать commit, path map и остатки. CLI/test selectors разрешаются по настоящему checkout до запуска, не выдумываются из названия находки.

## B24. Готовый большой результат может выглядеть как зависший вычислитель

*Источник карточки: A:B24. Унаследовано из прочитанной сводки A; не новый интеграционный прогон.*

**Подтверждение:** код, официальная документация Python и P06. В обоих процессных timeout-путях сначала ожидается завершение дочернего процесса, затем читается multiprocessing.Queue. Дочерний процесс передаёт model_dump результата. При большом сообщении завершение отправки может ждать чтения родителем, который ждёт завершения ребёнка. [A.R11: 335–445; A.E01]

В локальном опыте с 64 байтами процесс завершился. С 1 MiB тело работы завершилось, но после ожидания 0,6 с процесс оставался жив, результат не получен. При чтении очереди до join те же 1 MiB доставлены, процесс завершился примерно за 0,004 с. Это воспроизведение механизма на стандартной библиотеке, не запуск реального метода PolicyOS.

**Экономное расширение:** ограниченно читать канал одновременно с контролем живучести; либо хранить объёмный результат через подходящий существующий artifact store и передавать небольшой проверяемый указатель. Различать compute timeout и delivery timeout. Не увеличивать время ожидания как основной ремонт.

Дополнительно wrapper явно использует fork и daemon=True. В многопоточном окружении и для методов, создающих дочерние процессы, это отдельные проверяемые ограничения. Переход на spawn/forkserver требует корректной сериализации и владения ресурсами, а не замены одного слова. Принудительная остановка не должна оставлять подтверждённые наполовину записи.

**Критерий:** малый и большой результаты возвращаются; compute timeout действительно прекращает работу; авария во время отправки не создаёт успешный receipt. Проверяются очистка и точка фиксации результата. Высокое влияние и средняя сложность; существенная поправка к B14.
