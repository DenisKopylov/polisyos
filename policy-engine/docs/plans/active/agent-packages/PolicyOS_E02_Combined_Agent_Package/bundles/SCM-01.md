## Поручение и минимальная приёмка

При fit сохранить необходимый наблюдаемый закон корней или явный источник/неизвестность. Согласовать family payload от fitting до query/twin; для уже сохранённого простого polynomial формата выполнить именно его, не linear surrogate с чужим маленьким residual noise.

**Различающие тесты и сохраняемое поведение.** Y=3T+2Z, Z=99/101, do(T=1) даёт условное среднее около 203, не 3. y=x² при x=2 выполняет 4, не 1.36 с почти нулевым noise. LINEAR y=1+3x остаётся 7. Неинтервенируемые зависимые корни сохраняют joint relation; недостающий корень не становится тайным N(0,1).

**Не считать исправлением.** Не изобретать данные корня и не выдавать warning за исправление закона. Generic polynomial support не означает автоматическую работу любого нелинейного abduction.

**Цикл работы:** зафиксировать actual scope и нужный characterization; оформить equivalent move и намеренный behavior fix раздельно; выполнить указанные малые tests через I1; независимый reviewer проверяет actual owner; передать commit, path map и остатки. CLI/test selectors разрешаются по настоящему checkout до запуска, не выдумываются из названия находки.

## B221. Fitting игнорирует наблюдаемые корни, а query придумывает для них стандартный Normal

**Происхождение и приоритет:** C21-06. Высокий для fit→query при неинтервенируемых наблюдаемых корнях. Основания: HybridSCMFit root-skip, SCM-validator и missing-mechanism sampler. [C21.R04–R06]

**Проблема.** `HybridSCMFit.pure_step` пропускает вершины, не входящие в множество non-roots. Общий `StructuralCausalModelSpec` требует механизмы только для некорневых узлов. Query при отсутствии механизма генерирует N(0,1) и пишет warning. Наличие данных корня на входе fit не приводит к их сохранению в выполняемой модели.

**ROOT01–ROOT02.** Для T→Y, Z→Y данные удовлетворяют Y=3T+2Z, Z принимает 99 и 101 со средним 100. OLS дочернего узла правильно восстанавливает коэффициенты 3 и 2. Уменьшенный driver повторяет обычную observed/no-prior ветвь и сохраняет только механизм Y. При do(T=1) query генерирует Z со средним 0,007724 и получает среднее Y=3,015448 вместо ожидаемого около 203. Добавление существующего EMPIRICAL-контракта корня с mean100/std1 с теми же случайными реализациями даёт 203,015448. Дочерний OLS не меняется.

**Исправление.** При сборке модели определить покрытие всех необходимых для запроса корней: наблюдаемый закон, фактическое условие, явно выбранная внешняя модель или нерешённый пробел. Для доступных данных переиспользовать существующие carriers/ссылки, а не терять их и затем изобретать default. Совместный закон нескольких корней сохраняется там, где он требуется; независимость не возникает из раздельного хранения.

Missing-root default может быть полезной гипотезой в явно объявленной исследовательской модели. Он не эквивалентен fitted distribution. При наличии такого предположения оно входит в идентичность результата и ограничивает его применение. Глобально запрещать partial SCM не требуется.

**Граница.** Полный HybridSCMFit/DoWhy не запускался: использован явно сокращённый driver DATA_FITTED-ветви и выбранный query-loop. Warning существует; ошибку нельзя называть полностью скрытой. Явное вмешательство или наблюдаемое условие, полностью определяющее корень, может исключить потребность в его естественном законе для конкретного запроса.

## B222. Сохранённый полином исполняется как линейная аппроксимация с шумом от более точной модели

**Происхождение и приоритет:** C21-07. Высокий при использовании ADDITIVE_NOISE/poly-пакета; условная достижимость. Основания: `_fit_additive_noise_poly`, `_sample_node_value`, аналогичный twin-helper. [C21.R04–R05, C21.R07]

**Проблема.** Fitter сохраняет и линейные коэффициенты, и полиномиальную модель. `noise_std` берётся из остатков полиномиального fit. Query для ADDITIVE_NOISE меняет family на LINEAR и использует линейные коэффициенты вместе с этой новой, потенциально очень малой дисперсией. Warning о fallback присутствует, но численный закон уже другой.

**POLY01–POLY02.** На 101 точке x∈[−2,2], y=x² сохранённый полином даёт при x=2 значение 4 с точностью floating-point. Query выдаёт 1,36 со стандартным шумом около 4,9×10⁻¹⁶. Иными словами, аппроксимация с большим смещением исполняется почти детерминированно. Положительный LINEAR-контроль y=1+3x даёт 7 при x=2.

**Исправление.** Один выполняемый контракт family для fit, sampling, abduction и twin-world. Первое недорогое расширение — корректный evaluator уже сохраняемого полиномиального формата без cross-terms; сложные семейства можно оставить с явной недоступностью или обозначенной аппроксимацией. Если используется линейный surrogate, его расхождение и шум оцениваются для surrogate, а не заимствуются из другой модели.

Не следует добавлять произвольный большой шум, считать warning коррекцией значения или запрещать все nonlinear-модели. Поддерживаемый ограниченный полином уже содержит достаточно информации для точного исполнения своего заявленного семейства.

**Область.** В прочитанной стандартной observed-data ветви HybridSCMFit выбирает LINEAR, а автоматический вызов polynomial-helper оттуда не установлен. Поэтому это дефект совместимости подготовленного payload/helper с публичным query, не утверждение, что каждый обычный GCM-fit автоматически обучает и теряет полином. Полный native pipeline и контрфактическая инверсия нелинейного шума не выполнялись.
