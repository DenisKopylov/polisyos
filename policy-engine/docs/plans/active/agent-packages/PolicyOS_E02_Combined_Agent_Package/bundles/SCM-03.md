## Поручение и минимальная приёмка

Для perfect intervention подставить действие до заменённого механизма и готовить только действительную область запроса с factual dependencies. Разрешать stochastic law один раз, сохранять тип политики; устойчивый truncated-normal sampler не заменяется clipping после rejection-limit.

**Различающие тесты и сохраняемое поведение.** DoX=2 даёт Y=7 даже если старый natural X не нужен/невычислим; shift=5+2 всё ещё требует естественное 5.20 посторонних корней не вычисляются без запроса full-trace. Typo-law не превращается в atomic=7. Truncnorm[8,9] имеет внутренние значения, не 100 граничных восьмёрок. Логические seeds сохраняются при сужении плана.

**Не считать исправлением.** Не отсекать нужные factual ancestors/sharedU, не увеличивать rejection-limit вслепую. Atomic fallback — другой отдельно принятый запрос, не успешное завершение исходной stochastic задачи.

**Цикл работы:** зафиксировать actual scope и нужный characterization; оформить equivalent move и намеренный behavior fix раздельно; выполнить указанные малые tests через I1; независимый reviewer проверяет actual owner; передать commit, path map и остатки. CLI/test selectors разрешаются по настоящему checkout до запуска, не выдумываются из названия находки.

## B224. Идеальное do сначала выполняет заменяемый механизм; нерелевантные узлы расходуют работу и память

**Происхождение и приоритет:** C21-09. Высокий для проходимости atomic-запроса; оптимизация после проверки графового смысла. Основание: `_simulate_samples` и контраст с twin-path. [C21.R05, C21.R07]

**Проблема.** В каждом прогоне сначала собираются родители и вычисляется естественное значение узла; затем для treatment применяется intervention. Даже идеальное do, полностью заменяющее механизм, поэтому зависит от исправности и стоимости старого механизма. Кроме того, цикл проходит весь граф и сохраняет массивы всех вершин, хотя обычному запросу часто нужен только заданный исход.

**EXEC01–EXEC03.** При do(X=2), Y=1+3X и некорректном старом intercept X sampler поднимает ValueError до применения действия. Вычисление Y с уже заданным X правильно даёт 7. Для X,Y и двадцати независимых посторонних корней на десяти реализациях выполняется 220 вызовов node-sampler и сохраняется 220 значений. Для известного ограниченного запроса достаточно десяти вычислений Y; результат тот же 7. Это число вызовов и удерживаемых значений, не измеренное ускорение большого приложения.

**Исправление.** На основе правильной graph-surgery заранее подготовить активный план конкретного запроса. Для perfect intervention подставлять действие до вызова заменённого механизма. Обрабатывать необходимые предковые зависимости и фактические условия, сохранять full-trace только при действительной потребности. Кэшировать план по неизменяемому графу и семантике запроса, а не по имени outcome без контекста.

Обычный сдвиг требует естественного значения: контроль current5+shift2 даёт7. Поэтому перенос treatment-ветви должен учитывать тип операции. Для counterfactual нельзя отсечь нужных предков factual-evidence, а для зависимых U — скрытые общие причины. Уплотнение плана не должно менять поток случайности незаметно: полезны логические под-потоки по узлу и реплике.

**Положительная граница.** Twin-loop уже не вызывает естественный механизм treatment при явном действии, то есть соседний подход существует. Единичная ошибка старого механизма в опыте допустима в generic fixture; проверка более строгого producer может предотвратить её раньше. Она всё равно показывает ненужную зависимость perfect do от заменяемого вычисления.

## B225. Ошибка стохастической политики меняет вмешательство; хвостовой truncnorm превращается в атом

**Происхождение и приоритет:** C21-10. Высокий для заданного стохастического закона; небольшой первый ремонт sampler. Основание: `_sample_stochastic_distribution` и `_apply_intervention`. [C21.R05]

**Проблема.** Ошибка разбора стохастического распределения при наличии fallback_treatment_value приводит к atomic do, хотя исходный InterventionSpec остаётся STOCHASTIC. Записывается warning, но исполняется другая политика. Отдельно truncnorm делает не более 200 rejection-попыток, затем берёт ещё один обычный normal и обрезает его до границ. Ограничение времени разумно; замена условного распределения обрезанным значением — нет.

**LAW01–LAW04.** `typo(0,1)` с fallback7 выдаёт десять семёрок и одно предупреждение. Без fallback существующая ветвь правильно отказывает. Для `truncnorm(0,1,8,9)` сто samples потребовали 20 100 normal-draws; все результаты равны нижней границе8. Настоящий SciPy truncnorm на том же диапазоне дал сто внутренних значений, среднее8,116469, ни одного граничного атома. Uniform(2,3) в положительном контроле сохранил поддержку.

**Исправление.** Разрешать и проверять intervention-law один раз до sampling. Для поддержанного truncnorm применять устойчивый алгоритм условной хвостовой выборки, например существующий SciPy с корректным переводом границ в стандартизованные a,b; не умножать rejection-лимит вслепую. [C21.E06]

Неподдержанный закон даёт адресный capability-result либо отдельный явно выбранный альтернативный запрос. Atomic-альтернатива может быть полезной, но не считается завершением исходной стохастической задачи. Warning сохраняется и не заменяет эту привязку. Операция TRUNCATED как clipping естественного значения может быть самостоятельной правильной политикой; она не тождественна conditional truncnorm.

**Приёмка.** Проверять положительную масштабную величину, поддержку, вырожденные и хвостовые случаи, фиксацию random-stream, отсутствие неразрешённой смены политики. Для дорогой модели парсинг и подготовка закона переиспользуются; каждая новая научная реплика остаётся отдельной реализацией. Настоящий policy-authority/registry/публикация здесь не запускались.
