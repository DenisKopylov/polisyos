## B18. Отсутствующий численный исход превращается в наблюдаемый ноль

*Источник карточки: A:B18. Унаследовано из прочитанной сводки A; не новый интеграционный прогон.*

**Подтверждение:** код и локальный опыт P01. `_ncm_outcomes` читает отсутствующие `counterfactual_result`, `world_summaries`, исход и mean через значения по умолчанию, заканчивая `float(stats.get('mean', 0.0))`. Пустой ответ и настоящий mean=0 дают одинаковый `{'y': 0.0}`. В другом контуре `_coupled_queue_value` также может вернуть 0 при отсутствии траектории и итогового значения. [A.R08: 1520–1640; P01/P04]

**Почему это связано с расширением:** после восстановления положительного пути B04/B08 такой результат станет легче доставить пользователю. Проходимость нельзя улучшать за счёт молчаливого численного заполнения. Хэш доказывает неизменность нуля, но не наличие основания для нуля.

**Экономное расширение:** проверять присутствие нужного исхода и числовую пригодность; настоящий ноль сохранять как число, отсутствие — как отдельный локальный результат без подставленного эффекта. Успешно вычисленные независимые исходы можно сохранить с точной неполнотой. Проверка должна быть по объявленным выходам метода, а не списку вручную известных имён.

**Критерий:** пустой пакет, отсутствующий один исход, явный ноль, NaN/inf и повреждённая структура различаются. Исчезновение требуемого выхода не даёт положительного численного результата.

**Приоритет и предел:** высокая значимость до первой положительной выдачи, низкая/средняя сложность. Опыт использует модельный выход; сквозной production-случай не воспроизведён.

## B20. Несовместимые воздействия могут молча перезаписываться по порядку

*Источник карточки: A:B20. Унаследовано из прочитанной сводки A; не новый интеграционный прогон.*

**Подтверждение:** код и локальный опыт P02. `_ncm_intervention` последовательно пишет значения в словарь по имени переменной. Для A: x=1 и B: x=2 результат A,B — x=2, B,A — x=1. Аналогичное накопление через update/присваивание есть в overrides других контуров. В прочитанном `JointSimulationRequest` наличие атомов проверяется, но отдельное правило разрешения именно этих коллизий не представлено. [A.R08: 220–245, 1490–1560]

**Экономное расширение:** на границе композиции определить отношение операций над одним slot: действительно совместимые, явно последовательные с объявленным порядком, либо несовместимые. Использовать имеющийся merge/slot/constraint механизм; не вводить «последний wins» по случайному порядку списка. Одинаковые присваивания могут объединяться с сохранением обоих источников только при допустимой семантике.

**Критерий:** перестановка неупорядоченного множества совместимых атомов не меняет результат. Конфликтные атомы дают явный отказ/вопрос до вычисления. Объявленная последовательность сохраняет порядок как часть семантики и идентичности.

**Приоритет и предел:** высокий для составного первого примера; низкая/средняя сложность. Установлен локальный порядок перезаписи, а не обход всех возможных upstream-защит. Интеграционный тест должен показать, достигают ли такие атомы данного перехода.

## B22. Недостающие точки траектории не должны незаметно достраиваться последним значением

*Источник карточки: A:B22. Унаследовано из прочитанной сводки A; не новый интеграционный прогон.*

**Подтверждение:** код и P04. В системно-динамическом и реестровом контуре при короткой trajectory используются final_stocks/последний элемент; coupled-очередь при выходе за длину берёт final_queue_length. Запрошенная временная сетка может получить значения за пределами реально возвращённых точек. [A.R08: 1110–1310, 1530–1575]

**Экономное расширение:** договориться о нумерации и числе точек, наличии начального состояния, конечного шага и единиц времени. Допустимое hold-last/interpolation должно быть явным преобразованием с происхождением, а не способом скрыть усечение. При отсутствии покрытия выдавать частичную траекторию, не распространять её дальше под видом полного расчёта.

**Критерий:** короткая, пустая и полная траектории различаются; начальный/конечный шаг не путаются. Изменение horizon.step либо обрабатывается корректно, либо ограничение видно. Частичное покрытие не становится сигналом стабилизации модели.

**Приоритет и предел:** высокий до показа динамического эффекта; низкая/средняя сложность. Использование final_state иногда является корректным контрактом метода; задача — доказать это для данного выхода, а не запретить любую допустимую реконструкцию.
