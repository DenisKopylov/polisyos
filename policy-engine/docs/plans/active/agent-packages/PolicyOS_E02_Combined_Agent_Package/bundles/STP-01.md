## Поручение и минимальная приёмка

Привязать embedding-сигнал к итерации/input/model; текущий пропуск не сравнивать как свежую пару. В plateau определить signed improvement и абсолютный масштаб возле 0 без бесконечного ложного прогресса.

**Различающие тесты и сохраняемое поведение.** Одинаковые старые embeddings+ошибка текущего не подтверждают convergence. Настоящие две актуальные одинаковые записи дают ограниченный результат. Лучшее 0 и последующие положительные losses не означают improvement=inf; улучшение отрицательных/малых значений считается в правильном направлении.

**Не считать исправлением.** Не считать economic stop смысловой сходимостью; не заменять ноль произвольным большим epsilon, не выводить свежесть из длины списка.

**Цикл работы:** зафиксировать actual scope и нужный characterization; оформить equivalent move и намеренный behavior fix раздельно; выполнить указанные малые tests через I1; независимый reviewer проверяет actual owner; передать commit, path map и остатки. CLI/test selectors разрешаются по настоящему checkout до запуска, не выдумываются из названия находки.

## B41. Сбой текущего измерения сходства может подтвердить сходимость по старым векторам

*Источник карточки: C02-08. Унаследовано из полного C02/r01; 25 исторических локальных записей.*

**Источник:** C.Q11. **Свидетельство:** код detector; C1–C3. **Достижимость:** используется embedding_cosine либо semantic-компонента multi_signal. Подключение check_with_text к главному N6 в данном проходе не установлено.

`check_with_text` добавляет вектор при успешном embedding. При ошибке он регистрирует degraded-событие, но не добавляет запись о пропуске; затем `_do_check` увеличивает номер итерации. `_check_embedding_cosine` сравнивает последние два доступных вектора без проверки их принадлежности текущей итерации.

В контрольной последовательности min_iterations=3: векторы итераций 1 и 2 одинаковы, измерение третьей не удалось. Детектор получил semantic-convergence по векторам 1 и 2. При доступном и отличающемся векторе третьей остановки не было. Метрики в модели менялись 10→20→30; выбранная стратегия проверяла семантический, не числовой сигнал.

**Разумное расширение.** Хранить сигнал вместе с iteration/input-ref и версией модели измерения. Пропуск текущего сигнала остаётся пропуском; старое значение не приобретает новую дату. Это не требует падать целиком: можно продолжить внутри бюджета либо использовать иной заранее разрешённый актуальный критерий. Числовая неизменность или экономический лимит не должны автоматически называться доказанной смысловой сходимостью.

**Проверка:** отказ/отсутствие текущего embedding не создаёт semantic-convergence; корректные одинаковые текущие векторы дают соответствующий ограниченный результат; другая размерность/версия embedding не сравнивается без совместимости. Приоритет условный до подтверждения использования detector в нужном пользовательском пути.

## B122. Достигнутый ноль превращает ухудшение в бесконечное «улучшение» критерия плато

**Основание и область:** `ImprovementPlateau.check`; PL1–PL5. Это конкретная знаковая ошибка в особой ветви, а не предложение менять все stopping-эвристики. [C11.R02]

**Проблема.** Если исторический минимум близок к нулю, любой достаточно ненулевой недавний минимум даёт `improvement=inf`. При минимизации положительное новое значение после нуля — ухудшение, но оно проходит как бесконечно большой прогресс и не запускает stopping.

**Проверка.** При patience=2 последовательность `[0, 1, 1]` не остановилась, а `[1, 2, 2]` остановилась. Настоящее улучшение `[0, -1, -1]` правильно продолжилось, равенство `[0, 0, 0]` правильно завершилось. Различающий контроль со знаковым gain остановил ухудшение и сохранил отрицательное улучшение.

**Рекомендуемое исправление.** Сначала вычислять знаковую разность `best_historical - best_recent`, затем сравнивать её с определённым для цели абсолютным и относительным порогом. Масштаб около нуля задаётся контрактом метрики или явно принятой политикой; машинный epsilon сам по себе не определяет содержательно значимое улучшение.

**Границы.** Здесь проверялась минимизационная конвенция, уже используемая контроллером. Необходимо отдельно нормализовать направления и учитывать неизвестные/non-finite результаты. Серия отказов без конечной оценки — не доказательство научной сходимости, даже если ресурсный предел должен её остановить.

**Приёмка.** Ноль, малые значения обоих знаков, регресс и реальный прогресс; критерий после нормализации согласован с направлением цели. Ранее полученный полезный результат сохраняется независимо от того, что следующий шаг остановлен как плато. Повышение терпения и увеличение числа прогонов не устраняют ошибку знака.
