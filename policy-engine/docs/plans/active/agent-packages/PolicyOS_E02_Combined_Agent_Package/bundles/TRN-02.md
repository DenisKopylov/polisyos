## Поручение и минимальная приёмка

Сохранить ArtifactRef найденного запуска и читать точно её, не повторять ANN нулевого вектора. Кэшировать историю по immutable snapshot. Изменения native index и metadata публикуются одним согласованным поколением после успешной подготовки.

**Различающие тесты и сохраняемое поведение.** Рост ANN-каталога не прячет известную ref. Новый snapshot того же run_id не возвращает старую историю. Sorting потребителя не мутирует следующий hit. Ошибка native add/load не смешивает имена/векторы. Малый native индекс из десятков векторов проверяется в K3.

**Не считать исправлением.** Python rollback не доказывает откат частично изменённого native index; такое поколение нужно изолировать/восстановить. Не перестраивать полный индекс на каждом чтении.

**Цикл работы:** зафиксировать actual scope и нужный characterization; оформить equivalent move и намеренный behavior fix раздельно; выполнить указанные малые tests через I1; независимый reviewer проверяет actual owner; передать commit, path map и остатки. CLI/test selectors разрешаются по настоящему checkout до запуска, не выдумываются из названия находки.

## B129. Точная ссылка на найденный запуск теряется, а история заново ищется среди соседей нулевого вектора

**Основание и область:** регистрация записывает `artifact_id` в метаданные векторного индекса. `find_similar_runs` возвращает RunFingerprint без этой ссылки. `_load_run_evaluations(run_id)` затем делает новый ANN-query с нулевым вектором и `top_k=1000`, сканируя ответ в поиске точного run_id. Ошибки чтения найденного артефакта подавляются и выглядят как пустая история. [C12.R01, C12.R03]

**Локальный результат:** в детерминированной индексной фикстуре зарегистрированы 1000 посторонних записей и требуемая история. По настоящему запросу искомый запуск найден, его bytes доступны, но ограниченный нулевой запрос его не вернул: loader получил ноль вместо одной оценки. На малом индексе, где запись случайно вошла в ограниченный ответ, чтение успешно. Недоступный artifact_id дал ту же пустоту. Это не измерение нативного порядка соседей HNSW, а демонстрация неэквивалентности точного чтения и ограниченного similarity-search. P04–P07.

**Потеря:** рост памяти может закрывать ранее доступный опыт. Для каждого найденного запуска добавляется не относящийся к задаче поиск; увеличение `top_k` повышает стоимость, не создавая гарантии точного lookup.

**Рекомендуемое решение:** передавать полученную проверяемую ArtifactRef/версию снимка вместе с результатом discovery и читать непосредственно её. Для уже известных run_id использовать существующее точное отображение ключа на версию артефакта, а не геометрический запрос. Индекс остаётся средством обнаружения; CAS — владельцем содержимого. Отделить отсутствие записи, недоступность хранилища, повреждение и неподходящую схему.

**Приёмка:** история, найденная в индексе размером более 1000, читается без второго ANN; изменение `top_k` discovery не меняет адресуемость уже выбранного артефакта; повреждённая ссылка не подменяется другой похожей историей. Строгие фильтры применимости учитывать до окончательного лимита, но не смешивать их с адресным чтением.

**Приоритет и оговорка:** высокий и относительно дешёвый: необходимая ссылка уже существует. Новое хранилище не требуется; права и целостность при прямом чтении сохраняются. Нулевой cosine-вектор здесь не обвиняется в конкретном нативном исключении — оно не воспроизводилось.

## B133. Кэш истории привязан к изменяемому run_id, а не к версии её артефакта

**Основание и область:** `_eval_cache` адресуется только по run_id. `register_run` может заново записать историю и перезаписать метаданные того же ключа индекса, но кэш не инвалидируется. Loader отдаёт сам сохранённый список; последующий отбор сортирует его на месте. [C12.R01, C12.R03]

**Локальный результат:** зарегистрирован score 1, выполнено чтение, затем тот же run_id зарегистрирован с новым артефактом и score 9. Тёплый manager прочитал 1; новый manager — 9. Изменение params возвращённого списка видно следующему тёплому чтению, но не меняет bytes текущего артефакта. P18–P20.

**Потеря:** одинаковый запрос имеет разный результат в зависимости от времени жизни manager. При долгой работе словарь также не ограничен; сама ограниченность кэша, однако, не исправляет неверную идентичность.

**Рекомендуемое решение:** определить контракт run_id. Если история завершённого run неизменяема, отвергать противоречащую перерегистрацию; если допускаются снимки, run_id — alias к текущей проверяемой ArtifactRef, а кэш содержимого адресуется её digest/версией. Для ограниченного кэша выбирать LRU/TTL по цене повторного чтения, не выдавая eviction за стирание происхождения. Хранить неизменяемые records; сортировать представление или индексы, не общий кэш. Большие массивы повторно глубоко не копировать без необходимости.

**Приёмка:** новый допустимый snapshot одинаково читается холодным и тёплым путями; replay конкретной старой ссылки остаётся старым; мутация потребителя не меняет общий результат; ограничение памяти не скрывает действительный артефакт. B129 должен передать точную ссылку, иначе этот ремонт останется неполным.

**Приоритет и оговорка:** высокий при повторной регистрации/переиспользовании manager. Если действительный маршрут гарантирует неизменяемый run_id и одно чтение, описанное устаревание может не реализоваться. Увеличение размера кэша не решение.

## B134. Ошибка нативного индекса публикует несогласованные векторы и метаданные

**Основание и область:** `VectorMemoryStore.add` меняет Python-списки/отображение ключей до `add_items`. При замене существующей записи metadata тоже меняется первой. `load_from_artifact` перезаписывает конфигурацию, ключи и метаданные до загрузки bytes нативного индекса. При неудаче прежний индекс может остаться связанным с новым словарём имён. [C12.R03]

**Локальный результат:** исполнен полный Python-модуль с отказоустойчивой HNSW-интерфейсной фикстурой, а не нативной библиотекой. Ошибка capacity при втором добавлении оставила Python len=2 при одной нативной записи; следующий запрос двух соседей упал. Неудачное обновление A оставило старый вектор с новыми metadata. Неудачная загрузка нового bundle оставила старый индекс, но прежний label 0 стал возвращаться под именем B. Нормальный add/query сохранил согласованность. P21–P25.

**Потеря:** ошибка одного дополнительного примера может сделать непригодными уже доступные воспоминания либо связать их не с тем источником. Это больше, чем локальный отказ новой записи. Документация HNSW подтверждает ограниченную вместимость, операции изменения размера и ограничения конкурентности add/query; точное внутреннее поведение нативной ошибки здесь не измерено. [C12.E01]

**Рекомендуемое решение:** подготовить новое состояние до публикации и фиксировать согласованное поколение индекса и metadata. Для load сначала полностью собрать и проверить отдельный candidate-index, затем атомарно переключить ссылки под короткой синхронизацией. Для add/update предварительно проверить форму, конечность, ёмкость и права; после успешной нативной операции публиковать metadata. Если нативная библиотека допускает частичную мутацию до ошибки, простой откат Python-списка недостаточен: нужны инвалидирование поколения/восстановление из известного снимка либо иной гарантированный протокол. Общие метаданные не отдавать как бесконтрольный изменяемый объект.

**Приёмка:** отказ добавления не портит старые запросы; failed load оставляет прежнее полностью согласованное поколение; загрузка без нужных bytes не публикуется частично; проверены capacity, неверная форма и настоящие нативные исключения. Resize допустим только внутри выделенного ресурса. Не снимать лимиты и не перестраивать весь индекс на каждом нормальном запросе.

**Приоритет и оговорка:** средний объём, высокий эффект на устойчивость использующей HNSW памяти. Обычная ветка функционирует в контроле. Не заявлены нативный стресс-тест, конкурентная атомарность CAS или готовность распределённого индекса.
