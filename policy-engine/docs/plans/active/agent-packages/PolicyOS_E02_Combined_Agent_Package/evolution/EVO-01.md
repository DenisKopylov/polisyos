## S01. Гибридное получение приоров по потребности

**Барьер:** предварительно обработанный корпус может быть полезен как навигация, но его старые confidence и классификации не всегда допустимы в текущем вычислении. В `BuildLiteraturePrior` есть отдельный `historical_confidence_blocked`. Это не доказательство отсутствия соответствующей литературы. Более того, описание метода содержит фразу «Empty prior = no matching literature found», хотя код возвращает пустой prior и при отсутствующем пути, и при историческом слое. Семантику пустого результата в метаданных и читателях следует исправить вместе с маршрутом. [A.R17]

**Предложение:** локальный корпус как карта → адресный запрос от конкретной недостающей связи/параметра/контекста → первичный текст → извлечение точных фрагментов → проверка применимости → сохранённый пакет для конкретной задачи. Не менять проверку старого confidence на автоматическое доверие свежему источнику. Использовать существующие `PriorMiner`, `BuildLiteraturePrior`, Scholar и артефактные контракты. [A.R14–A.R17]

Находка может быть гипотезой механизма, структурной предпосылкой, диапазоном параметра или материалом для численного prior; не каждая публикация обязана превращаться в число. Доверительный интервал статьи не является автоматически prior нужного параметра. Поисковый hit, точное цитирование, качество идентификации и переносимость — разные проверки.

Сохранять запрос, границы поиска, версию источника, извлечение, контекст, преобразования, отрицательные результаты и исключения. По возможности сохранять разрешённые bytes; при ограничениях доступа — достаточную законную provenance, не выдавая недоступный текст за прочитанный. Повтор закрытого случая читает сохранённую версию; новое знание создаёт новую версию, не переписывает прошлое. Недоступный corpus не является основанием изобретать приор.

**Проверка:** сравнить corpus-only, runtime-only и hybrid на одинаковых задачах и бюджетах; качество связи source→claim, контрсвидетельства, стоимость, время и повторное использование измерять отдельно. Расширение поиска не должно увеличивать ложное признание обоснованности.
