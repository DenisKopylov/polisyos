## Architecture already selected; keep implementation within it

1. **One owner per meaning, shared bridges only where needed.** Reuse current Runtime acquisition/action boundary, Fabric for source capture, Core for storage, Lex/legal/Data Forge domain owners for their meanings, security/rights owners for permissions, Scientist/Claim Ledger/Decision Validity for their decisions and lifecycle, and Atlas as projection. R9 A0 names one accountable Runtime integrator for the first vertical; this coordinates the chain and does not become a semantic or legal owner. A new sovereign lifecycle, permission, scheduler, procurement, or institutional-administration service is rejected absent a concrete owner-boundary decision.
2. **No universal lifecycle DTO, status lattice, or clock envelope.** Compose sparse native records and owner handoffs. CTM and S0 are binding. A local adapter maps evidence but never reinterprets legal dates or grants authority. Keep an advisory assessment separate from the canonical consumer’s actual reaction.
3. **Prefer existing execution/storage machinery.** R9 selects the existing control store/worker by default; a new workflow engine or stronger distributed transaction needs measured recovery/history/topology evidence. Use owner-local atomicity and prepared/reconcile or a cutoff-qualified projection where boundaries do not share a transaction. For source consistency, use a genuine consistent cut if available, else verified overlap, else honest interval/partial. Begin with coarse invalidation; optimize only after measuring fan-out. Preserve unknown optional facets as inert candidates when lawful; unsupported required behavior limits that operation. Unknown backup/deletion scope means quarantine/reconcile and an explicit limitation, never a false all-copy-erased claim. These are R9 implementation recommendations consistent with S0/CTM, not universal schemas.
4. **Free growth remains open-ended.** Constitution Rule 12 and GX require search over typed indexes, no hand-maintained domain/family fallback, and zero code change for a correctly-added resource inside a supported capability class. A new capability is complete only with contract/artifact, producer, persistence, orchestration bridge, consumer, verification, audience surface or explicit out-of-scope, and negative/semantic proof. A new meaning or unsupported behavior needs its owning extension and end-to-end evidence; it must not be laundered by a registry label or `trusted=true` default. AP12's second-source witness is a test of class extensibility, not permission to make the first source the product’s universe.
5. **Atlas follows runtime and audience rules.** One runtime authority lattice; no route-local status enums. Full detail preserves material grounds, countergrounds, limitations, and alternatives only for authorized audiences. Public disclosure follows PV. A signed/public currentness claim needs its scoped watch/duty owner, deadline, reaction and current projection path before publication; candidate or explicitly historical/as-of use can proceed earlier.

## Minimum invariants every affected artifact/surface must carry

1. **Authority:** exact claim/purpose/audience and `authoritative_for` / `may_not_use_for`; source class and grounding method; producer/verifier provenance; candidate vs admitted posture; weakest-boundary reason; explicit unsupported/contested/unknown limitations. No caller-supplied boolean, source label, transport success, hash, or UI calculation can satisfy a semantic gate (P32/P37/P38).
2. **Scope:** jurisdiction/domain/tenant and operation/purpose/recipient where material; declared unknowns and assumptions; certified envelope. Unknown is not silently replaced with a default. Scope closure is needed only for the protected action/claim it governs (S0-K06).
3. **Status:** reuse the existing composed lattice and its mixed-outcome rules; keep interaction and capability readiness orthogonal. Readiness cannot upgrade authority. Missing links use the existing precise capability-reality labels, including `absent/unallocated` when no admitted chain/owner exists.
4. **Time/history:** preserve relevant CTM-native temporal roles, source/version, receipt and transaction cutoff, admission purpose/cutoff, rule/schema version, valid/effect window and replay context as applicable. Never synthesize source time from processing time or claim `current` from freshness alone. Corrections and revocations append typed relations; current reactions are authored by canonical owners.
5. **Ownership:** name the producer, semantic/admission owner, permission owner, claim/publication consumer, surface owner, and verifier where applicable. Integration contracts stay local to native owners; an appointment or reviewer does not gain broader authority than its named act. No new sovereign subsystem by implication.
6. **Evidence and verification:** bind actual source content and target/use relation, full material lineage/parents, uncertainty and countergrounds; classify every gate predicate as `recomputed`, `independently_reconciled`, `consumer_asserted`, `institutionally_supplied` or `not_established`, freeze that label at admission, and fail closed on the last three. Verify the property through a real consumer, one distinguishing negative, and a remove-property/keep-markers probe.
