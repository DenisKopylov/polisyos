# R17 — Семантические проверки длительной жизни дизайна

Будущие acceptance obligations, **product_execution=UNRUN**, только после принятого E02 и scoped rebind. Ни одно число случаев ниже не является числом passed tests. Полный native consumer denominator выводится из accepted source. Positive обязан достигнуть полезного результата; blanket deny не проходит. Removal меняет реальный механизм, сохраняя его markers; expected negative не маскирует setup error. Existing R15/R16 cases не отменяются и не считаются повторно новой работой.

<a id="Q01"></a>
## Q01 — Закрытие, старая edition, независимое чтение

Создать реальный native design bundle с альтернативами и выбранным basis; закрыть, сохранить, выпустить новую edition, удалить зависимость от author process/current pointer. Fresh reader получает законно сохранённые original machine/human views и reasons/limitations старого результата. Partial raw custody явно различается с полным удержанием. Negative: потерянный обязательный model/input/rule или подмена edition не должны давать complete/replayable. Removal: убрать closure traversal, сохранить valid manifest/hash; независимый expected actual read-set обнаруживает пропуск. Owner: DES-06/LIF-07/OPS-05.

<a id="Q02"></a>
## Q02 — Представление и научный смысл

Выбранная migration делает старый формат читаемым, сохраняет original ref, conversions/rules/units и новую rendition; reader не использует сегодняшний parser default для прошлого meaning. Positive bounded historical interpretation допускается без обещания executable replay. Negative: отсутствующий decoder/model/runtime или недоступный источник не скрывается. Removal: убрать representation dependency, leave schema/version markers. Old executable не запускается при чтении; явный authorized replay изолирован с собственным budget. Owner: DES-06/07, LIF-07, OPS-05.

<a id="Q03"></a>
## Q03 — Fixity, corruption, migration и cold retrieval

В независимой сохранённой копии восстановить испорченный chunk, проверить actualbytes, provenance repair и authorized cold read; sampling receipt ограничен проверенным множеством. Negative: silent-corrupt primary нельзя «починить» новым hash; одна и та же failure domain не считается независимой копией. Missing cold object, provider timeout и истёкший use grant дают отдельные outcomes. Removal: убрать fixity/readback из actual reader при сохранённых receipt fields. Owner: OPS-05, selected OPS-10; local mode имеет самостоятельный witness.

<a id="Q04"></a>
## Q04 — Историческая подпись и renewal

Выбранный проверяемый historical signature chain до retirement/compromise сохраняет ограниченную историческую проверяемость, новая подпись запрещена неуполномоченному issuer. Successful timely renewal и fresh verifier подтверждают actual chain/objects/algorithm policy. Negative: отсутствующая pre-compromise timestamp/custody, поздний «исправляющий» timestamp, утраченные bytes при требуемом rehash не дают той же гарантии. Removal: убрать renewal verification либо независимый successor trust check, keep fields. Owner: OPS-11. Не выдавать timestamp за current truth или lawful retention.

<a id="Q05"></a>
## Q05 — Hold, erasure, backup и restore frontier

Scoped hold сохраняет только разрешённые копии и запрещает обычный use; lift hold запускает актуальную проверку, не automatic release/delete. Backup до revoke восстанавливается в quarantine; актуальная rights history оставляет revoked material недоступным. Negative: истёкший tombstone при ещё restorable старой копии; S3 delete marker при доступной version; неизвестный escrow/plaintext нельзя назвать crypto-erasure. Removal: убрать replay more recent rights или actual copy inventory. Owner: LIF-05/OPS-05/10/12. Applicable legal conflict передаётся компетентному owner и ограничивает затронутую операцию, не весь candidate поиск.

<a id="Q06"></a>
## Q06 — Закрытие организации и передача custody

Получатель читает exact permitted archive и явно принимает scope, duties и verification material; старый owner фиксирует transfer/cutoff. Negative: uploaded zip, новый self-signed root, передача private key или accepted invitation не доказывают succession. Missing recipient/authority/source rights оставляет конкретный scope untransferred; копии и публичные обещания не исчезают молча. Removal: убрать recipient intake/duty acceptance, keep transfer label. Owner: OPS-11/LIF-04/05.

<a id="Q07"></a>
## Q07 — Silent sources и доказанная no-change проверка

Scoped source coverage (interval, partition/incarnation, last cut/replay floor) плюс actual reconciliation подтверждает no material change; duty записывает результат и next obligation. Negative: heartbeat жив, feed стоит; источник изменился по тому же URL; событие предшествует enrollment; history compacted; partition omitted. Пустой inbox не может подтверждать актуальность. Removal: убрать coverage reconciliation, оставить successful poll. Owner: CAP-04/LIF-02/OPS-11.

<a id="Q08"></a>
## Q08 — Cumulative change, drift и реальные labels

Проверяемое изменение затронутого basis даёт immediate currentness reaction и полезный scoped rerun/исследовательскую ветвь. Цепь малых изменений достигает существенного отличия от last accepted basis и выявляется. Benign covariate drift не считается доказанным effect loss; поздние labels не подставляются нулями, thresholds имеют selected rationale. Removal: убрать cumulative anchor либо разделение drift/outcome/causal evidence; независимый выбранный oracle выявляет ложный вывод. Owner: LIF-07/LIF-02/DES-04/GYD-09/10.

<a id="Q09"></a>
## Q09 — Duty, ресурсы и reissue fence

Настоящий event порождает durable duty; restart/retry не теряет её и не дублирует effect. Пока пересчёт ждёт budget, current use квалифицирован. Полезный no-change завершается без принудительного new edition. Reissue с actual issuer/grounds fence создаёт новый связанный выпуск; при отсутствующей authority typed-empty/refusal остаётся корректным исходом. Negative: no standing duty/expired custody нельзя выдать за вечный auto-rerun, успешный numerical exit не переподписывает claim. Removal: убрать duty recovery или expected-head/source/right-cut fence. Owner: LIF-04/06/LIF-02/DEB-06/OPS-11.

<a id="Q10"></a>
## Q10 — Предложение, правовой акт и исполнение

Обычный candidate и его публикация сохраняют incumbent. Реально допущенное подтверждение конкретного акта меняет только его legal scope/time; независимый operational input устанавливает только подтверждённое исполнение. Positive можно проверить synthetic signer/institution fixture, ясно обозначив отсутствие настоящего мандата. Negative: candidate ID, layer REPLACE, подпись без applicability/competence, institutional self-assertion без требуемой reconciliation не становятся authority. Removal: убрать actual act/authority verification. Owner: CAP-05/CNT-04/LIF-01/02/UI-19.

<a id="Q11"></a>
## Q11 — Частичная замена и живой incumbent

V1 действует в R/S; V2 вводится только в R для новых участников в t2, protected cohort остаётся V1, фактический rollout начинается t3. Fresh trajectory и history consumers показывают смесь и shared capacity/lag/commitments. Candidate V3 сравнивается с этой смесью и supported uncertainty, а не с пустым миром. Для actual-operation claim один выбранный source-qualified rollout record с exact custodian/source identity проходит CAP-04 persistence/verification → LIF-02 → fresh DES-11/UI consumer; при отсутствии настоящего входа этот claim limited, synthetic witness доказывает только механизм. Negative: global current flag или newest-arrival-wins, automatic rollback costs=0, смешение уже понесённых затрат с будущими incremental costs. Removal: убрать scoped relation/time или incumbent consumption. Owner: DES-11/GYD-30/DES-03/LIF-02.

<a id="Q12"></a>
## Q12 — Late corrections, конфликт и временные запросы

Исправление t2 приходит в t4: старый as-known(t3) остаётся воспроизводим по сохранённому basis, current view отражает correction, новые кандидаты используют новый admitted cut. Conflicting competent sources остаются scoped contested до applicable adjudication, не newest-wins. Negative: backdated knowledge leak, cycle predecessor→self, future-effective act выдан за current. Removal: убрать knowledge cutoff/old-edition preservation; независимый temporal oracle выявляет различие. Owner: LIF-02/DEB-06/DES-11/UI-04/19.

<a id="Q13"></a>
## Q13 — Exposure, target и method-qualified эффект

В двух sites один published V2, но разный реальный receipt; выбранный поддержанный estimand использует правильный exposure/target/measurement history. Population weights change не выдается за изменение within-group effect; carryover не приписывается целиком V2. Для selected case проверить достаточные aggregate inputs либо finer records, не требовать личные данные по умолчанию. Negative: publication date вместо actualreceipt, непроверенная extrapolation, неподходящий static estimator при time-varying confounding/interference. Removal: убрать evidence-to-estimand binding, keep version markers. Owner: CNT-06/08/DES-12/GYD-09/12. Дополнительный actual fixture: credible announcement t1 вызывает известный response до legal t2/receipt t3; selected analysis учитывает его либо честно ограничивает эффект. Remove announcement exposure, keep version/rollout labels: полный положительный effect claim обязан измениться/ограничиться, не приписать весь t1–t3 сдвиг V1. Unknown awareness — limitation/scenario, не zero.

<a id="Q14"></a>
## Q14 — Адаптивное обучение и память

Policy-induced shift становится useful O2 hypothesis/study, затем отдельно допущенным O1 result при достаточном дизайне; source correction пересматривает exact result. DES-08 разрешённый scoped lesson действительно меняет поиск, оставаясь candidate/qualified. Negative: selection/look denominator исчез после version bump, protocol rewrite выдан за preregistration, зависимая новая выборка названа independent, memory использует недопущенный чужой case. Removal: убрать actual look/eligibility/qualification consumption. Owner: DES-08/12/GYD-09/10/12/CNT-08.

<a id="Q15"></a>
## Q15 — Продуктивный scoped доступ и соседние consumers

Именной cross-project reviewer читает exact shared view; raw source остаётся у custodian. Same-cell role без object relation не разрешает read; разрешённая relation с неподходящим purpose тоже не даёт source use. Foreign/absent IDs дают одинаковую предусмотренную notfound projection. Search/count/autocomplete/link/cache/browser/audit проверяются в actual selected denominator, включая existence-sensitive metadata. Removal: убрать owner resource resolution или emitter gate; actual private canary становится обнаружимым. Owner: OPS-06/LIF-05/CAP-03/UI-02/03/04.

<a id="Q16"></a>
## Q16 — Revocation race и ошибки policy evaluation

Положительный long job/stream выдаёт разрешённый результат; revoke между staging и commit побеждает по доказанному generation/causal fence. Обнаруживаемые пределы уже отданных stream chunks отражены в selected consistency profile. Negative: stale token/cache, cache-bypass без causal cut, missing required attribute, ошибочная applicable forbid при рабочей permit не допускают защищённый action. Unrelated доказанно неприменимая policy error не останавливает весь сервис. Removal: убрать current generation или required-policy diagnostic handling. Owner: OPS-06/LIF-05/LIF-04. Provider-race witness ставит revoke между check/enqueue и actual release: если revoke победил в declared ordering, sink не получает canary. При release-before-revoke измерить разрешённый in-flight scope; uncertain external acceptance сохраняется indeterminate и не дублируется. Удаление реального egress release fence при intact local commit gate обязано провалить этот witness.

<a id="Q17"></a>
## Q17 — Delegation, LLM и производные outputs

Task-bound actor получает только разрешённый контекст/tool/effect и полезный answer; model output остаётся candidate. Broad service token не расширяет user/source rights. Query-only profile сохраняет разрешённый result/receipt и не сохраняет raw canary в actual selected prompt/log/cache/CAS/provider-temp sinks. Provider unable to satisfy contract исключается для этого use, не считается прошедшим. Derived summary/model/embedding release проверяется выбранным disclosure rule. Removal: убрать target/recipient/egress check либо memory eligibility. Owner: DES-09/DES-08/OPS-06/09/CAP-03/06.

<a id="Q18"></a>
## Q18 — Mode parity, public/private и offboarding

Selected local/team/hybrid/public mode показывает одну честную историю authorised audiences; public projection не раскрывает restricted ancestors/IDs и не требует публикации private completed case. Correction linked to prior public bytes, не «удаляет интернет». Offline read следует explicit cutoff; cloud restore/revoke проверяются отдельно только если профиль выбран. Export/ingest/transfer проверяют recipient и actual content/rights; downloaded copy не объявляется отозванной без proof. Removal: убрать recipient check/restore rights replay/public link gate при intact UI labels. Owner: OPS-05/06/09/10/11/12/UI-02/03/04/08/19/DES-06. Для выбранного offline profile восстановить pre-update VM snapshot со старым signed package и clock: generation/time defense либо честный as-of cutoff предотвращают неподтверждённые current-right actions, сохраняя действительно разрешённое historical use.

## Полнота и цена проверки

У каждой `r17_extension` есть requirement, positive, adversarial, removal, D-slice и Q-case. [Machine obligations](r17-capability-obligations.json) выводятся из полного набора изменённых строк, mirror должен совпадать. Cases Q01–Q18 — группы свойств, не конечный allowlist schemas/consumers и не 18 независимых full suites. Обязательные inputs выводятся из native contracts; candidate fixture никогда не доказывает внешний реальный факт. Accepted source/input/backend freeze и независимые reviews предшествуют одной существующей дорогой wave; targeted checks до неё учитывают blast radius.

Pattern pass: P01/P02/P03/P04/P05/P07/P08/P09/P10/P13/P14/P15/P27/P29/P31/P32/P33/P35/P37/P38/P40/P41. Runtime evidence в этом документе отсутствует; сохранённые исследовательские outputs не являются PASS.

## R24: lawful derivative и actual read

Для Q03/selected recovery проверить отдельно permitted retained derivative после
raw erasure и use, которому всё ещё нужен raw parent. Первый может пройти при
достаточной retained verification/current-use basis; второй остаётся limited.
DES-06 показывает эту границу и не обещает невозможный raw replay. Удаление
actual dependency/rights qualification обязано обнаружить как false admission,
так и blanket false refusal. Затем заменить cold locator/version или late chunk
между verification и consumption: protected reader не должен принять иные bytes.
Late-corrupt-final-chunk probe проверяет actual egress/effect sink: integrity-dependent
partial output не выходит до whole-stream verification. Chunk release допускается
только по qualified per-unit verification без заявления whole-stream integrity;
removal release fence должен обнаружить ранний выход, даже если final hash красный.
Повтор whole archive scan и RAM materialization не являются критерием качества.
