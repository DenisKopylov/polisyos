# R19: проверка содержания и полного потока

Статус: будущие acceptance obligations, все product executions UNRUN. Реализация и эти проверки выполняются после фактической приёмки E02. [84 решения](../solutions/lifecycle-r19/README.md).

## 1. Единица проверки

Единица — named claim/use и его end-to-end property. Для каждой `r19_extension.question_slices` исполнитель фиксирует exact candidate/tree/input/profile/backend, native producer/artifact/bridge/consumer, public audience/carrier и limitations. `positive`, `adversarial`, `removal` в task catalog являются обязательствами, а не готовыми PASS.

Проверка должна пройти настоящий путь: содержательный input → native producer → persisted artifact/event → lifecycle effect → fresh process/HTTP/API/CLI/browser/export consumer из выбранного surface set. Constructor/schema/keyword/hash-marker не заменяет property. Если невозможно исполнить часть пути, указывается точный missing label и минимальный закрывающий input/capability; область не исчезает из denominator.

## 2. Независимость и oracle

Автор реализации не выдаёт независимый review своего кода. Reference result берётся из другого метода/аналитического расчёта/independent source/readback с обоснованным scope. Две копии одной статьи, одинаковый базовый dataset, evaluator из того же кода или LLM-пересказ не становятся независимыми основаниями. При этом локально пересчитываемое математическое свойство не требует выдуманного второго внешнего издателя.

Для каждой authority predicate указываются resolve/content binding/verifier provenance и класс установления. Нельзя повысить self-attestation через правильный schema shape. Published source supports только названную адаптацию; не доказывает implementation quality, external fact или authority.

## 3. Обязательные сквозные различающие случаи

| Свойство | Положительный сигнал | Минимальный контрпример/удаление |
|---|---|---|
| Conditional result vs endorsement | Проверенное сравнение подписывается с явными assumptions | Удалить collective mandate: conditional result остаётся допустимым, коллективный winner — нет; удалить scientific basis: mandate не спасает результат |
| Stable target vs realization | Изменён measured count при том же target rule — uncertainty same target | Тот же count, другое inclusion rule — отдельный target |
| Causal structural claim | Подтверждённый неоднородный edge сохраняется при малом среднем эффекте | Удалить structural identification, оставить near-zero ATE: edge deletion не admitted |
| Simultaneous uncertainty | Actual family/look/dependence rule покрывает заявленный set | Pointwise 95% интервалы без family evidence не дают set guarantee |
| Output attribution | Прямой delta равен сумме выбранных Shapley shares | Для .60/.90/.50/.70: Δ=.10, φD=.25, φM=−.15; I=−.10 отдельно, повторное добавление I ошибочно |
| Search path robustness | Выбранные interaction pairs тестируются с frozen comparison | OFAT проходит, pure interaction меняет winner; full robustness остаётся limited |
| EVSI scope | Gross estimate с явными utility/prior/observation law | Удалить cost: gross остаётся, net/rank отсутствует; capacity отдельно меняет feasibility |
| Adaptive statistics | Accepted plan, dependency/look/restart continuity реально consumed | Сбросить state или нарушить p/e validity, оставить FDR label: guarantee исчезает |
| Opaque provider quality | In-envelope invocation content-bound к stable evaluated profile | Alias прежний, relevant behavior/route/envelope иной: прежняя qualification не переносится |
| Audience understanding | Ответы читателя совпадают с независимым meaning oracle | Advice-first ответ нельзя назвать independent pre-advice baseline |
| Currentness | Реальное изменение или qualified own assessment обновляет enrolled claims | Recompute delayed, markers прежние: fresh API/UI/export не остаются current green |
| Scoped arithmetic vs joint-policy claim | Exact observed quantities support a qualified sum; grounded coupling supports a separate joint-policy claim | Сохранить одинаковые units, но сложить stand-alone causal effects без decomposition/system evidence: joint effect не established; scope арифметического результата не расширяется |
| Public capacity | Exact supply/window/roster поддерживает joint feasibility | 70+70 при100 infeasible; GPU permit не заменяет specialist-hour denominator |
| Future custody | Новая duty имеет accepted coverage/cutoff относительно capacity | Owner/due markers есть, покрытия нет: нельзя обещать currentness |
| Runtime restore | Epoch/fence survives selected restore or resume refuses | Старый worker + restored attempt: stale completion отвергается, unknown effect удерживает permit |
| Due uncertainty | Time basis доступен и применим к duty | Clock/store недоступен: отсутствие overdue event не доказывает timeliness |
| Existence privacy | Authorized state сохранён; public absence/denial indistinguishable в выбранной модели | Скрыть body, оставить count/link/error/cache различие: protection не установлена |
| Selected deployment | Exact local/remote/offline closure и readbacks проверены | Локальный PASS не даёт remote CAS/worker parity; unselected tiers не блокируют |

Эти случаи не являются закрытым тестовым списком: выбранный native schema/rejection set/callsite census порождает дополнительные siblings и вариации. После complete-by-construction проверка не превращается в бесконечное recursive verifier testing.

## 4. Поверхности и переносимость

Перед wave вычислить actual affected consumer set по accepted source: runtime/public API, CLI/MACHINE, browser, search/index/cache, audit/export, selected offline rendition и выданные projection references. Нельзя требовать все возможные deployment/locale в каждом slice, но выбранный public claim должен покрывать фактически обещанный set. `surface_out_of_scope` требует явного reason и не выдаётся за готовность этой поверхности.

Meaning, accessibility, translation provenance и legal/authority equivalence — разные свойства. Выбранный PDF/DOCX/print/offline artifact связывается с exact bytes/edition/locale/time через DES-06/07; UI screenshot не проверяет его. Старые скачанные копии остаются historical/as-known; не обещать глобальный recall. Rights probes сравнивают absent/denied без утечки через count/errors/links и проверяют authorized reader отдельно.

## 5. Статистика и научные residuals

При empirical qualification заморозить target population, strata, sampling/assignment, outcome/oracle, exclusions, uncertainty method, selection/looks, threshold basis и limitations. Нет универсального sample count, p-value, fairness score, TTL или automation-bias cutoff. Непроверенные strata не наследуют общий PASS. Hypothetical margin даёт conditional equivalence при подходящем методе, но не утверждение о социальной несущественности.

Source/data drift, model inadequacy, uncertainty inflation и external legal invalidation не сливаются в одну степень «confidence». Native owners решают соответствующие predicates; их композиция сохраняет contestation и невозможность сравнения. Если отделить влияния невозможно, показывается residual/interval, а не правдоподобное точное разложение.

## 6. Экономика verification

Проверки масштабируются по изменённому механизму и его consumer closure. Preparation/read-only design не ждёт code freeze; интегрированный deciding wave ждёт exact composed source/input/backend freeze и independent reviews. Новый contract delta требует affected consumers; неизменная часть не гоняется заново без причины. Serialize только реальный contended resource, не всю программу.

Сохраняются полные deciding outputs и removal receipts; tracked source не дублируется. Raw dumps — ignored path@sha. Исторический FAIL не объявляется inherited без P41 exact pre-slice reproduction и complete input disjointness. Лимит ресурса, unavailable input, skipped backend, setup ERROR и product FAIL учитываются отдельно.

Документационные проверки этого пакета — JSON parse, exact84 coverage, mirrors, сохранение старых task fields/edges, reference checks и independent design review. Они не исполняют и не удостоверяют перечисленные product properties.
