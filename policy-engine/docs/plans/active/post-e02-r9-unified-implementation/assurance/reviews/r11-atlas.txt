## Findings

### A-R11-1 — Medium — alreadydeclared (P35/P38/P02): DS19 task acceptance covers only `entries[]`

**Evidence:** the full-file census above comes from `policy-engine/architecture/atlas_surfaces/frontend-disposition-register.json` (array starts at lines 1152, 5749, 5794, and 35777 respectively). UI-09 names the 261 entries, binds its owner path to `#entries[]`, and requires a census “maps each entry” (`policy-engine/docs/plans/active/post-e02-r9-unified-implementation/tasks.json:4552-4574`). The workstream likewise describes UI-09 as the full `entries` census (`.../workstreams/04-atlas.md:64`). P0-REBIND says all inventories need routes and that a dropped source obligation must be detected, but its source IDs are the broad `Atlas DS0–DS21` label and its owner path is the manifest/original owners, without naming the four register arrays (`tasks.json:7700-7716`).

**Counterexample:** all 261 entry rows remain mapped, while the 46 `open_debt` supplemental rows disappear from the route crosswalk; UI-09's stated positive still passes. The same omission hides 22 seeded negatives from exact task input binding. The two subunits also need explicit closure classifications: one is already deleted/strangled (`feature-whatif::legacy-local-whatif-subgraph`), while `route-app-layout::ru-ui-catalog` is frozen DS0 continuity, not new locale work. The negative lifecycle field is deletion state, not proof a test is implemented.

**Smallest doc fix:** bind all four top-level arrays in P0/UI-09 with the complete source path and counts, then require every row to resolve to an owner task, accepted closure receipt, `obsolete_by_deletion`, or explicit `out_of_scope`. Add a drop-one-row probe per array (including an open supplemental and a seeded negative) that blocks dispatch. Keep the already-deleted WhatIf and frozen DS0 subunit as explicit terminal dispositions; do not reopen them.

### A-R11-6 — High — alreadydeclared (P05/P26/P29/P38): UI-02 can close without DS12's public telemetry and packet-privacy negatives

**Evidence:** DS12 makes the public operational bar explicit: no third-party trackers, security headers, mobile support, i18n/plain-language, and a public telemetry posture in which telemetry is self-hosted/scrubbed/absent (`POLICYOS_ATLAS_SURFACE_IMPLEMENTATION_MASTER_PLAN.md:1815-1828`). The live audit's seeded `DS1-N020` requires no identifier/payload to leave through beacon/fetch/Sentry, including route, query, tags, breadcrumbs, and extras (`policy-engine/docs/reference/frontend/atlas-live-application-audit.md:832`). `DS1-N023` requires classification/redaction before signing and tests encoded/nested/private values (`:835`). UI-02's `source_ids` omit both negatives, and its listed adversaries cover candidate/wrong-view/rights/intent/signature/proof-leak but not telemetry transport or publication redaction (`tasks.json:3905-3942`).

**Counterexample:** a request can fail closed for signature or rights while a configured beacon/Sentry path still emits a signed route/query identifier; or a packet builder can sign an encoded/nested private field while its marker/signature checks pass. Those outcomes leave UI-02's listed positive and adversarial conditions green.

**Smallest doc fix:** add N020/N023 as named UI-02 inputs and assert the actual public route and transports do not egress identifiers/payloads, plus builder-level rejection/redaction for encoded/nested private fields before persisted signing. Add explicit no-third-party telemetry/security-header acceptance or a source-qualified out-of-scope decision. The UI-02 task already owns the public surface; this is an acceptance gap, not an unassigned DS12 owner.

### A-R11-8 — Medium — alreadydeclared (P02/P36/P37): DS14's PA2 obligation is inconsistent and has no program task binding

**Evidence:** Atlas inventory says DS14 renders both PA2 and PA3 (`inventory/atlas.md:36`), while the authoritative master assigns PA2 as a DS9 pre-action gate and DS14's distinct work is PA3 compression-loss/authority-delta disclosure (`POLICYOS_ATLAS_SURFACE_IMPLEMENTATION_MASTER_PLAN.md:1646-1653, 1988-1994`). UI-05 names GY-PA3, DS9, and the GY-I+DS9 gate, but no PA2 artifact, wrong-role/TTL, or contestability acceptance (`tasks.json:4204-4218`).

**Counterexample:** DS9's human approval UI can prove the PA2 gate locally while an outward DS14 agent/tool orchestration path invokes a delegated action without checking the same role/TTL packet. Conversely, a proposal-only DS14 surface may correctly have no action gate; the current route does not state which case applies.

**Smallest doc fix:** correct the Atlas inventory's PA2/PA3 ownership wording to match the master and record the bounded consumer decision. If DS14 can dispatch actions, bind the PA2 pre-action artifact and wrong-role/expired-TTL/contestability negatives to UI-05 (or a DS9-owned accepted bridge); if it cannot, mark that external act `out_of_scope` and preserve DS9's bounded internal gate receipt. Populate `program_tasks` with the resulting route.

### A-R11-9 — Medium — alreadydeclared (P04/P10/P38): DS21 acceptance does not preserve all cause classes or same-world provenance

**Evidence:** DS21's governing constraints require all four typed causes (`prediction_error`, `implementation_failure`, `measurement_change`, `behavioral_response`), permit only prediction-error effect updates, keep unresolved/compound causes unresolved, and place deployment updates and acquisitions into one growing world (`POLICYOS_ATLAS_SURFACE_IMPLEMENTATION_MASTER_PLAN.md:2041-2054`). UI-08 positive asserts only “Only `prediction_error` updates effect”; its adversarial cases name protective action, unresolved cause, stale branch, and candidate status but not the other three distinct classes or same-world provenance (`tasks.json:4498-4501`). The workstream repeats the narrower acceptance (`workstreams/04-atlas.md:60`).

**Counterexample:** `measurement_change` or `implementation_failure` is collapsed into a generic changed estimate and the consumer still satisfies the only explicit positive; or deployment and acquisition updates render as separate worlds while the prediction-error check passes.

**Smallest doc fix:** add a four-class acceptance matrix proving only prediction error changes the effect posterior, unresolved/compound remains unresolved, and other cause classes remain distinct. Add a version/provenance assertion that acquisition and deployment updates land on the same growing world branch, with no merge or operational action.
