## Remaining finding

### A-R11-10 — Medium — alreadydeclared, same A-R11-7 class one level deeper (P38)

**Source-qualified evidence:** the current UI-04 retained property says only “accessible response/history” (`tasks.json:4331-4333`). The cited retained marketing Phase 5.7 criteria are more specific: large-text mode, screen reader, and plain language (`policy-engine/docs/plans/active/POLICYOS_ATLAS_PRODUCT_MARKETING_CLIENT_SURFACES_MASTER_PLAN.md:3515-3516`); acceptance requires formal Ukrainian and Russian register where applicable (`:3520-3524`), and verification names large-text, screen-reader, and plain-language checks (`:3526-3530`). UI-04's task positive still asserts generic visible response/supersession, while its adversarial cases cover privacy, silent removal, formal/informal status, and binding status but do not bind these language/accessibility properties (`tasks.json:4262-4265`).

**Counterexample:** a consultation history can be visible and preserve all listed privacy/status semantics while failing the source-stated register or accessibility modes; the generic “accessible response/history” property does not distinguish that failure.

**Minimal document fix:** either preserve the explicit formal Ukrainian/Russian-register and large-text/screen-reader/plain-language acceptance and verification in UI-04, or mark the omitted portions `integrate`/`out_of_scope` with the responsible owner and trigger. Keep external moderation, court/appeal, and dispute adjudication outside PolicyOS ownership; this finding does not justify a new moderation subsystem.

## Bounded DS2 reconciliation note — no new finding

The `ds2_unbound_adoption_ids` member is a distinct DS2 set, not a fifth DS19 array: the frontend register declares the 233-row DS2 source, 173 mapped plus 60 unbound, and forbids rewriting DS2 verdicts (`policy-engine/architecture/atlas_surfaces/frontend-disposition-register.json:13-18, 27-48, 51-112`). A stdlib walk of the complete two-file JSON source set found all 60 IDs resolve uniquely to DS2 ledger entries; their ledger verdict distribution is 26 `defer`, 24 `admit_after_refactor`, and 10 `reject`, and each row carries decision, evidence, revisit, and next-owner fields (`policy-engine/architecture/atlas_surfaces/atlas-v15-adoption-ledger.json#/entries`). The DS2 adjudication report is authoritative for those adoption decisions but expressly cannot prove integration or browser/AT/production maturity (`policy-engine/docs/reference/frontend/atlas-v15-adjudication.md:24-30`).

The disposition already in the current plan is appropriate: DS19 records `233 = 173 mapped + 60 unbound` and says those are DS2 evidence edges, not parallel estate owners (`policy-engine/docs/plans/active/atlas-slices/DS19-false-substrate-strangle-wave-journal.md:126-133`); the Atlas inventory marks DS2 `closed_compact`, says verdicts are not automatic implementation assignments, and gives no DS2 program task (`policy-engine/docs/plans/active/post-e02-r9-unified-implementation/inventory/atlas-inventory.json:110-116`). Therefore do not add these 60 IDs to the DS19 261/85 census or create a blanket UI task. Reopen only when an accepted-source delta satisfies a specific ledger row's recorded revisit condition; route that row to its existing `next_adjudication.owner_slices` and preserve the DS2 verdict history.
