# Charter, entry and source precedence

**Goal:** implement R9 and the complete reconciled unfinished scope of GY, Atlas and the debt register through existing owners, then commission an explicitly bounded practical-use profile.

**Architecture:** reuse-first, native meaning owners, one integration authority, full vertical increments. This is a documentation/execution design, not a new product service or new authority lattice.

## Entry is an actual E02 decision

Before product code, tests, schemas, migrations, generators or governed artifacts are changed under this program, G must have actually accepted E02. Resolve the existing G decision and its exact accepted source tree, input/backend scope, deciding evidence and limitations. Use that decision's existing format; do not make a newly invented universal receipt schema or a second acceptance bureaucracy a prerequisite.

The planning assumption is full completion of E02. If actual acceptance differs, record the concrete delta and seek the owner's disposition for that delta. Do not silently weaken the user’s entry condition. Before entry, permitted work is documentation, source reading, research and non-executing test/oracle design.

An entry record links: accepted source/tree; G acceptance reference; separate finding dispositions; exercised backend/input scope; surviving limitations; reviewed integration baseline; and pathwise reconciliation with this plan's observations. A passed implementation slice and a finding closure remain different facts. Ref names, a date, a model-written summary or a file called `acceptance.json` cannot open the entry gate.

## Source precedence and full scope

1. Human instructions and ratified constraints bind the work. Proposed SDD paragraphs do not acquire authority by inclusion in a plan.
2. Current canonical task disposition, including explicit later correction, binds historical status. The old Atlas marketing master is supporting material, not a second execution backlog.
3. Accepted E02 outputs are reusable predecessors only for the exact property they establish. Reuse does not close a broader consumer/whole-property obligation.
4. New program task IDs partition remaining work; they do not rename findings or rewrite historical closure. Source links retain original IDs and their different denominators.
5. Every nonclosed debt row has a route: an existing mechanism task, a dedicated debt packet, an external-input-dependent remainder, a post-E02 overlap check, or an explicit independent horizon with owner and trigger. No row disappears into a generic “later” bucket.

The program includes implemented-but-unmeasured source tasks where the remaining acceptance conjunction matters. Conversely, source status `executed` is preserved and the existing mechanism is not rebuilt merely because its product use has residuals.

## Four independent planes of progress

Track (a) architecture choice, (b) implementation delivery, (c) evidence/acceptance, and (d) institutional/operational authority. An LLM can propose (a), code can deliver (b), a real verifier can establish scoped (c), and competent external sources supply the facts used in (d). None automatically substitutes for another.

An external absence blocks its affected action or claim, not all engineering. A typed-empty signer slot does not block a pure verifier or candidate computation. A current public signature does require the selected custody duty before issuance. Candidate, as-of/historical, protected-use and public-current profiles have different commissioning obligations.

## Finishing this program

Program completion means every original remainder has a reconciled disposition and each claimed capability has passed its complete scoped acceptance. It does not mean every external institution has supplied a fact or every optional deployment tier has been commissioned. A genuinely unavailable external fact is recorded with exact consumer, supplier, required evidence, attempted alternative, consequence and re-entry trigger. An internal bridge, parser, migration or researchable contract cannot be relabeled “external” to finish early.

The first practical-use admission is a separate decision over a named question, population, period, actors, sources, permissions, surfaces and claim band. It never erases the rest of the programme. The plan assumes no calendar deadline, invented productivity ratio, compulsory cloud vendor, fixed number of policy domains or universal data envelope.
