# Change control, preservation and E02 rebind

The root integrator owns this program's integration branch, task manifest and aggregate journal. Individual workers own only leased paths. Keep source history append-only; read branch attachment before work/commit; commit clean boundaries; never repair unexpected branch/HEAD/tree state by reset, rebase or checkout.

## After actual E02 acceptance

1. Resolve the accepted G source/tree and decision, not the moving implementation topic. Preserve separate acceptance and closure lists.
2. Diff only owners consumed by scheduled tasks against `inventory/sources.json`; reconcile their full code/test/schema/generated/readers footprint. Do not repeat unchanged old reviews.
3. For each affected task, classify the mechanism as retained, already satisfied by accepted E02, partial reuse, or still required. Explain the actual changed property and consumer. Update dependencies and lease sets accordingly.
4. For each debt row, match its exact complete predicate against accepted evidence. Keep status unless its canonical closure owner actually closes it. An accepted adjacent mechanism is a predecessor, not a closure.
5. Resolve the branch divergence pathwise. The G documentary branch, local main, remote main and E02 candidate are different observations. Normal reviewed integration preserves upstream history and legitimate unrelated changes.
6. Save a compact rebind record with prior plan commit, accepted E02 identity, changed task IDs, source obligations, decision evidence and remaining inputs. No raw copies of tracked source.

## During implementation

Changes to local implementation within the selected contract stay with the owner. Changes to shared schema/version, authority/status/time semantics, scientific guarantee or public promise require an explicit proposal with options, costs, evidence, migration and falsifier. G resolves architecture within its authority; SDD amendments require the human's approval. Independent tasks continue while that decision is pending.

On an unexpected dependency, first look for an existing producer/bridge, then extend it. The worker returns a concrete boundary packet instead of stopping with “needs another agent”: exact input, existing producer searched, reason it is insufficient, available implementation/research route, smallest decision and what can proceed now. Two same-class review escapes invoke P40: widen the invariant or record a falsifiable bounded residual rather than patch an endless series of cases.

## Recovery and reassignment

Record current branch/head/tree, committed source and companion paths, unique uncommitted work if any, exact last completed command, complete deciding output, pending effect and limitations. Preserve work before machine transfer. A Git bundle or normal reachable topic is preferred to an inaccessible raw archive; verify receiving object/tree identity and bytes. Never create executable upload workarounds in the repo. A lost tool session is `ERROR/incomplete`, not product FAIL/PASS. Unknown remote effects require reconciliation before retry.

Release leases at committed boundaries; do not occupy a writer while awaiting an external input. Reassignment reads the previous delivery and exact write set first. Superseding a plan row appends a rationale and routes every original obligation to its successor; historical evidence remains linked.
