# Completion is a staged predicate, not a task checkbox

This is a planning procedure over existing task/journal/native evidence. It adds no product status enum, receipt service or institutional authority. The machine contract is [stage-requirements.json](stage-requirements.json); `tasks.json` supplies each consumed stage and specific conditional requirements.

## Four decisions

| Decision | Required basis | What it does not establish |
|---|---|---|
| Owner readiness | Internal mechanism, exact version, complete companions, independent scoped review and local property proof | Authentic external act, whole composed property, original closure |
| Selected composition | Every activated supplier's persisted output, exact verifier/use owner, fresh consumer and permitted surface | Original obligations outside that claim, deployment authorization |
| Execution permission | Actual selected resource/rights/site grant; stop/refusal rule; independent runtime permission | Product acceptance or external institutional competence |
| Original disposition / first use | Complete rebound original criterion set, competent decisions and actual commissioning | Nothing is inherited merely from a local done flag |

`depends_on` uses `dependency_stage`; ordinary edges consume owner readiness. `acceptance_dependencies` and `conditional_acceptance_requirements` are composition witnesses, not blanket source-build edges. `execution_requirements` authorize a run at its named stage. Never union these into an untyped DAG: capture/frontier and source/currentness mutually prove a composition after independently staged owner delivery. The selected stage graph must still be acyclic; a real cycle is returned as an explicit contract/handoff problem.

## Selected facets and second-source custody

P0 establishes complete criteria and owner templates. CNT-01/OPS-01 later bind the actual case/profile and root expands the selected graph before dispatch or re-dispatch. Each selected facet has an original criterion, producer task, persisted artifact or explicit typed absence, verifier/use owner, consumer/status effect and surface. If law matters, CNT-04 → CAP-05 → CNT-08/09 is required; testimony uses CNT-07 → CNT-08/09. Unselected facets are explicit, not assumed satisfied. A new selection invalidates its affected evidence.

LIF-08 requires a named second-source CAP-02 sub-slice and actual capture receipt. If that selected transport/parser is not supported, root allocates its bounded CAP producer task before composition; LIF-08 remains producer_missing. Two different URLs through the same convenient fixture do not establish the declared independent layout/continuity property.

CAP-04 source changes must reach LIF-02 and UI-19's fresh claim/decision currentness projection. UI-17 proves acquisition status, not the separate current-validity predicate. Exact native API/MACHINE/publisher paths are resolved at accepted-source rebind. Public raw bytes may be out of scope without erasing an authorized status surface.

## Freeze can preserve unresolved external facts honestly

FINAL-FREEZE consumes internal owner readiness and **current truthful dispositions**, not all future external positives. GYD-01's mechanism may be ready while GY-O0-NC-01 authentic near-miss remains unobserved; DEB-09 can have correct intake/refusal while an appointment remains absent; CNT-09 can have working mechanics while commissioning is pending. None receives closure credit. A missing internal producer cannot be renamed an external input.

The near-miss criterion concerns a real attempted field-pilot request **blocked before execution**. It does not require conducting an unsafe policy trial. Existing history is usable only if it produces the original canonical production-lane receipt with verifiable provenance. The current plan establishes no such receipt. If the original criterion needs a policy decision, submit its exact alternatives to the competent owner/human and continue independent engineering.

Unselected deployment tiers require original conditional scope, explicit non-claim and activation trigger. Selecting a tier later requires its real evidence; an arbitrary tier omission cannot discharge mandatory original work.

The frozen tree is initially the review candidate. After accepted blocking fixes and independent delta review, root records the **final replay identity**: tree, inputs, backend/profile and consumed upstream refs. The expensive wave uses that identity. A later dependency change invalidates affected evidence; the one-wave economy never permits reuse of an obsolete tree.

## Release remains a distinct complete-set decision

FINAL-USE reads all rebound GY/Atlas/debt/R9 original dispositions as well as FINAL-REPLAY. An unresolved mandatory original keeps release blocked even when every owner mechanism is locally ready. A diagnostic replay with unavailable inputs is useful but not accepted programme closeout. Bounded honest residuals, including missing out-of-band runner attestation, cannot disappear because their truthful limitation works. If completion requires scope change, prepare an explicit ID/claim/risk/authority proposal for the human; this document grants no waiver.

Preparatory publication tests, controlled candidate rehearsals and a real policy deployment are different acts. No public launch or actual first practical use occurs before FINAL-USE plus the required external authorization. UI-02 and OPS-02 may verify internally earlier under the relevant resource/rights permits.

## Documentary falsifiers

Before dispatch: select legal/testimony facets and remove their supplier binding; the selected composition must become not ready. Leave a mandatory original open after all owner predicates are ready; freeze/review may proceed but FINAL-USE must refuse. Change T0 to T1 after blocking review repair; the final replay record must bind T1, retaining only justified unchanged review scope. These are future procedure assertions, not product test receipts.

Pattern pass: P01/P02/P03, P05/P07/P08, P35/P37/P38/P40. The repaired class is one phase/activation predicate error, not an instance-specific series of waivers.

Machine manifest convention: `acceptance_dependencies` contains task IDs only. Native evidence requirements (for example actual frozen profile or relevant method verifier) are separately retained in `acceptance_evidence_requirements` and, where necessary, `acceptance_owner_binding`; an empty dependency list never discharges them. These remain composition constraints, not additional hard-build edges.
