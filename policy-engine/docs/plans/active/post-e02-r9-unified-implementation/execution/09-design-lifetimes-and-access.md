# R17 — Параллельная подготовка и соединение жизненного цикла

Все этапы ниже начинаются после фактической приёмки E02 и адресного accepted-source rebind. D1–D7 дополняют existing task owners; 121 root task сохранены. R17 не добавляет global dependency edges: preparation и acceptance — разные отношения. Единственный писатель actual semantic owner сохраняется; read-only reviews и независимые oracles не занимают его write lease. Future runtime hierarchy/agent limits остаются из общего плана и фактических инструментов.

Shared writers — существующие LIF-02 claim/currentness, LIF-05 rights, LIF-07 manifest/influence, DES-06 output, DES-11/GYD-30 trajectory seam, OPS-06 authz и соответствующие generated DTO owners. Unselected cloud/air-gap/TRE/crypto provider не блокирует local candidate pilot. Необходимые local rights, useful restore и currentness checks не отменяются словом «pilot».

## Минимальная последовательность без искусственной сериализации

1. После P0 scoped rebind назначить exact existing writers, отделить productive candidate scope от authority-sensitive real use, выбрать preservation/access/deployment profile. Новые схемы — только при доказанном отсутствующем native смысле.
2. Параллельно готовить D1 producer/reader, D2 storage/duty, D3 event/currentness, D4 transition, D5 method binding и D6 access. Independent reviewers заранее строят Q01–Q18 контрпримеры. Shared schema changes сериализует только её писатель; readers/tests готовятся одновременно.
3. Соединять небольшие реальные chains по готовности suppliers. Candidate successor analysis не ждёт внешнего legal act; actual-replacement claim ждёт. Useful read не ждёт всех format conversions; заявленная конкретная old-format гарантия требует actual representation witness.
4. Готовить D7 consumers параллельно, но завершать по реальному output. На выбранном composed lifecycle закрыть exact producer/artifact/bridge/consumer/surface gaps, включая denied/refused и useful positive.
5. Existing FINAL-FREEZE → independent FINAL-REVIEW → одна FINAL-REPLAY → FINAL-USE. R17 сам не добавляет дорогую replay wave. Post-freeze blocking deltas объединяются; unchanged evidence не гоняется заново без причины.

## Внешние inputs и полезная работа при их отсутствии

| Не хватает | Что инженер может сделать сам | Что нельзя создать архитектурным решением |
|---|---|---|
| Настоящий replacement/commencement/delivery record | Typed intake/verification/consumer, synthetic adversarial fixture, conditional incumbent scenario | Компетенцию учреждения, совершённый act, фактическое receipt |
| Source-specific retention/hold/rights | Existing resolver и copy/restore mechanism, policy versioning, выбранный разрешённый synthetic/public material | Универсальный lawful retention срок, erasure waiver, лицензию получателю |
| Long-term timestamp/trust authority | Adapter и bounded verifier/recovery cases, readable historic record | Достоверную прошлую timestamp или authority при утраченном chain |
| Monitoring data или labels | Coverage/late-input handling, no-change discriminator, study/acquisition path | Текущую causal effect или completeness невидимого мира |
| Remote/offline инфраструктура | Полезный local path и contract/adapter preparation | Remote parity/SLA или offline instant revocation |

После каждого limited/blocked результата исполнитель указывает exact missing input/property, уже выполненный bounded mechanism, проверенные альтернативы и минимальный следующий supplier. Не возвращаться к пользователю из-за routine owner rebind или ещё не сделанной своей engineering работы. Genuine authority choice остаётся human/institutional boundary. No default-self-attestation.
