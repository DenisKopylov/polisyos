## Почему такая граница

Use the already-authored R16 native slices: C1 compiler/joint execution, C2 selected temporal/cyclic boundary and recovery, C3 influence/cache. These are distinct properties and writers; C3 remains LIF-07's influence owner with GYD-30 only as the actual Foundry reader. Reconcile PDC/IR certificate ownership once, keep one GYD-30 joint-result writer, and join only selected slice outputs. Do not create per-family branches, a second lineage/scheduler, or a blanket external simulator mandate.

## Общие условия родителя

Названные ниже свойства сохраняют все применимые original criteria, extensions, status/authority/time/rights и mandatory companions. Root/lead перед назначением раскладывает **каждый** source clause в существующий coverage journal; этот пример не заменяет такую раскладку. Один actual semantic owner и write lease сохраняются. Независимая подготовка возможна по согласованному интерфейсу; composition и protected use требуют настоящих supplier outputs.

План не даёт права выбирать только удобные profiles или считать unknown applicability исключением. Условный join включается по фактическому контракту/claim. Родитель требует полный selected denominator и fresh end-to-end witness; локальные PASS не суммируются в closure.

## GYD-30-C1 — Canonical compiler, exact joint execution and full method-family coverage

**Свойство.** The selected complete participant graph executes with owner-derived typed facets and an actual joint witness; every current source-derived Ukraine method family reaches a real workflow consumer or exact limitation.

**Граница и owner.** One canonical CompositionCertificate/compiler/method-chain owner after PDC/IR duplicate reconciliation; GYD-30 owns shared compile/execute/schema paths.

**Входы.** Resolved ProgramGraph/ExecPlan; Versioned producer/adapter/consumer contracts and required facets; Complete current method-family source set; Actual participant outputs and exact joint oracle

**Результат.** Typed joint result/certificate; Full contract-to-workflow coverage receipt with fresh consumers

**Подготовка.** Rebind actual dispatch, order and consumers; Re-enumerate the full accepted method-family set; historical 13 is not a cap; Derive requiredness from owner contracts

**Composition join.** Reuse R16 C1. Preserve B01/C01/C02 semantics; pairwise or marginal evidence cannot stand in for the tested joint property. C2/C3 join only when selected by the real case.

**Полезный positive.** Actual multi-participant output matches an independent coupled oracle and each source-derived family reaches its consumer or declared limitation. A suitable independently derived analytic/exact or validated native reference is allowed; an external simulator is not required, and self-comparison of the same implementation is not an independent oracle.

**Различающий negative.** Missing/duplicate active node, raw-order fallback, registry-only fake capability or first-family-only coverage fails. Unsupported feedback/cycle must be refused here even when supported temporal/SCC slice C2 is not selected.

**Matched removal.** Remove a non-first family consumer or final joint property while keeping first-family/certificate markers; full coverage or joint oracle fails.

## GYD-30-C2 — Selected temporal/cyclic boundary and state recovery

**Свойство.** For a selected temporal or zero-lag SCC claim, actual clock/order/state transitions and checkpoint/recovery cover every affected participant.

**Граница и owner.** Reuse R16 C2; DES-11 owns temporal adapter changes, GYD-30 consumes the actual joint result. Conditional on selected profile.

**Входы.** Clock/step/event and initial-state contract; Selected SCC/temporal participants; Participant reset/replay/state schema; Actual residual and final materialization

**Результат.** Typed temporal/cyclic joint execution and state-recovery receipt

**Подготовка.** Select only supported clock/cycle property; Rebind adapter and shared Foundry-file leases; Pin checkpoint eligibility and state identity

**Composition join.** Feed the validated adapter/result into C1's joint consumer; an unsupported opaque state remains one-shot, limited or refused.

**Полезный positive.** Real action order, step and recovery reproduce a supported temporal result with exact final-state scope.

**Различающий negative.** Invalid event order, unavailable reset, stale state, or an SCC drawn narrower than the actual invocation closure cannot claim completed joint output. In particular, a whole-plan map invoking a non-repeatable participant outside the declared SCC cannot pass by checking only declared members.

**Matched removal.** Remove state/recovery/finalization binding while keeping convergence labels; temporal guarantee fails.

## GYD-30-C3 — Exact influence/reuse at the Foundry reader

**Свойство.** Cache reuse is admitted only when actual reads, negative dependencies, rights/currentness and semantic basis match; otherwise recompute or limit.

**Граница и owner.** Reuse R16 C3: LIF-07 owns influence/reuse relation; GYD-30 owns only its actual Foundry cache reader.

**Входы.** Actual dependency/read set; Artifact/model code/law/profile/config; Rights and current-use scope; Cached result and selected guarantee

**Результат.** Verified reuse, recompute/miss, or typed limitation with reason

**Подготовка.** Bind the native influence contract and actual cache reader; Keep RUN-local retry semantics distinct from cross-run reuse

**Composition join.** Selected reuse proof supplies C1/C2 inputs; unknown dependencies force conservative recompute, never an empty dependency set.

**Полезный positive.** Exact unaffected result is reused or a fresh result matches clean recomputation under the same selected guarantee.

**Различающий negative.** Hidden negative dependency, changed law/rights or stale basis cannot hit cache by equal bytes/ABI alone.

**Matched removal.** Remove actual read/currentness binding but keep cache labels; false reuse or stale result is detected.
