# CAP-04.adopter-reports — Сохранить свидетельства adoption и вреда отдельно

Группа: [G02 — Смысл оснований: право, метрики, ценности и участники](../../groups/G02.md). Родитель: [CAP-04](../../parents/CAP-04.md). Роль: `input`.

Плановая рабочая карточка. Реализация только после E02 acceptance и exact source/lease rebind; эта запись не является execution grant или closure. [Общие правила](../../README.md).

**Проверяемый результат.** Complaint, adoption, harm or disagreement remains attributed testimony/operational evidence, not a legal act, causal effect, intent or resolved dispute.

**Предпочтительное решение.** Reuse the permissioned report/evidence path in S13-M3 and S14-M5/R18-D14-Q05/R18-D22-Q05: preserve the report as attributed candidate evidence with edition, audience, scope and times, then resolve only the affected own claim through LIF-02 and the selected CNT-09/UI-04 reader. This card maps the existing report intake and fresh reader now; E02 rebinds selected paths/lease but does not defer discovery. No adjudicator or enforcement workflow is added.

**Граница владельца.** Adopter/institution owns its report/act; competent evidence/legal/causal owners interpret it. CAP-04 binds typed evidence and owns internal discovery of the selected permissioned intake, persisted receipt and actual reader. E02 confirms accepted path/lease before writes, not before repo reconnaissance. If no chain exists, report precise absent/unallocated or consumer_missing. Parent lease: `write:source-event-adapter/{owner}`; exact paths/overlap remain unresolved, with no child lease inference.

**Входы.** Actual adoption/operation, complaint, harm or disagreement report with source role, provenance, scope, event/known time and correction; internal anchors S13-M3, S14-M5, R18-D14-Q05 and R18-D22-Q05 for intake/reader discovery.

**Выход и consumer.** Candidate report receipt preserving competing accounts and times, plus internal permissioned intake→persisted receipt→fresh reader/projection map or a precise missing-chain state; no causal/legal/status result.

**Что можно готовить независимо.** Now trace the current permissioned report intake and persisted receipt to existing LIF-02, CNT-09 and UI-04/UI-19 readers using S13-M3/S14-M5 and R18-D14-Q05/R18-D22-Q05; record actual audience/claim scope and correction path.; Use E02 to bind the accepted selected path and parent lease before writes; external report supply and competent interpretation remain external.; Keep allegation, corroborated event, causal finding and adjudication separate; append a scoped own-claim reaction only when the admitted evidence changes that claim.

**Где результат соединяется с другими.** Only competent owner-admitted evidence supports a claim; LIF-02 sees only separate verified source events.

**Positive.** Fresh reader resolves authentic report/source/time and dispute scope.

**Distinguishing negative.** Unsigned complaint, favorable report or recommendation marker cannot prove action, causal impact or legal resolution.

**Matched removal.** Keep report markers but remove provenance/source role/correction binding; reader limits or refuses.

**Граница контекста.** This card must discover the existing report producer and consumer internally; only the report itself and external interpretation are institution/adopter supplied. E02 rebinds path/lease, it does not start the search. Preserve consumer_missing if no actual reader is found; no notification, case manager or adjudicator is created.
