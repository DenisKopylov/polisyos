# OPS-02.local-candidate — Пройти локальную кандидатскую репетицию

Группа: [G09 — Развёртывание, исполнители, хранилища и ресурсы](../../groups/G09.md). Родитель: [OPS-02](../../parents/OPS-02.md). Роль: `verification`.

Плановая рабочая карточка. Реализация только после E02 acceptance и exact source/lease rebind; эта запись не является execution grant или closure. [Общие правила](../../README.md).

**Проверяемый результат.** После restart свежий reader находит persisted quarantine receipt, отдельное admission result и разрешенный artifact; capture/status сами по себе не дают admissible read.

**Предпочтительное решение.** Exercise existing acquisition route, embedded ControlWorker, SQLite WAL and filesystem CAS end to end. Use synthetic input, loopback, the commissioned finite expiry/workload/budget and the initial one-active-operation rehearsal profile unless a different measured profile is commissioned.

**Граница владельца.** This is an integrated verification/runbook result under OPS-02 `write:exact-path/{canonical_repo_path}`; exact test/runbook paths and overlaps with acquisition, ControlWorker, SQLite and CAS owners are resolved after accepted-source rebind. It does not write OPS-01 commissioning, OPS-05 restore, OPS-07 billing, LIF-06 admission or FINAL-USE approval.

**Входы.** OPS-01 commissioning receipt and finite limits; Existing acquisition/job/receipt/admission owners; LIF-06 enforced host/input/decoded-byte/concurrency/memory/scratch envelope for the local rehearsal; OPS-08 only when multiple process classes/replicas share the host; OPS-05 restore result if restore is exercised; OPS-07 account/secret result for any approved paid call; Source-owner grant for any non-synthetic input and reuse

**Выход и consumer.** Persisted operator pilot record plus job/receipt/admission outputs read by a fresh authorized consumer after process restart; actual cost/resource/failure evidence is retained for the tested workload.

**Что можно готовить независимо.** Route-to-consumer and scenario preparation can proceed against agreed existing owners. Run only after actual E02 acceptance, accepted-source rebind, commissioned local profile and phase resource permit. Synthetic local rehearsal is not first practical use; FINAL-USE is required only for that later selected action.

**Где результат соединяется с другими.** Request → durable job/receipt → quarantine → separate admission → fresh read; permitted reuse rechecks current rights. Restore consumes OPS-05, account spend consumes OPS-07, and hard host bounds consume LIF-06 (OPS-08 for shared multi-process scope). These conditions do not become unconditional task edges.

**Positive.** A restarted reader resolves the persisted admitted artifact and provenance; within the commissioned finite scope, a permitted second use reuses the evidence with current rights and recorded resource/cost bounds.

**Distinguishing negative.** Foreign job id, expired grant, worker restart, unknown provider effect/charge, mismatched restore or exhausted limit creates no false completion and stops only affected work; unrelated candidate work remains eligible on its own scope.

**Matched removal.** Remove quarantine, separate admission or fresh readback while retaining receipt/status markers; the pilot cannot be accepted.

**Граница контекста.** One local rehearsal journey is retained as an end-to-end witness, not a second acquisition/restore/budget/scheduler capability. No private input, paid provider or FINAL-USE action is inferred. P01/P02/P29 require persisted producer→bridge→fresh consumer evidence.
