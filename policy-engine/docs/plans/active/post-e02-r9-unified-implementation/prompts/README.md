Use [orchestrator](orchestrator.md) in the future execution chat only after actual E02 acceptance. Root supplies the accepted immutable base and the current plan commit. It admits [writer](writer.md), [reviewer](reviewer.md), [verification](verification.md) and [foundation supplier](foundation-supplier.md) assignments, directly or through a runtime-permitted [lead grant](lead.md).

Resolve placeholders before dispatch. A worker receives a ready, bounded work packet derived from the parent task or coherent conflict-free property across tasks: exact assigned clauses and necessary contracts, upstream artifacts, full companions and read/write/resource lease. Root retains complete parent obligation routing; a broad parent ID is not a hidden assignment to implement every sibling. Use [R25 decomposition](../execution/task-decomposition/README.md) and its [packet template](../execution/task-decomposition/work-packet.md). A planning role does not gain product ownership by title. Only a lead holding an explicit root grant may create one level of children, if the runtime permits it. Leaf prompts never delegate. The global ceiling is100 non-root agents including all leads and descendants, not100 per lead. Runtime direct-only rules take precedence.

The prompt is an implementation aid, not a replacement for canonical AGENTS/CONTRIBUTING, actual E02 acceptance, original criteria or commissioned authority. Unavailable external evidence stays scoped; implementation research and independent tasks continue.
