## Как понимать «полный список»

Полнота здесь означает явный охват заявленной карты жизненного цикла и всех полученных исследовательских вопросов с disposition, а не доказательство отсутствия любых будущих неизвестных. Система открыта новым доменам, источникам, институтам и обстоятельствам. Поэтому реестр сохраняет scope/источники наблюдения и допускает дальнейшее дополнение без ложного обещания universality.

Каждая строка содержит конкретный вопрос, что уже предусмотрено, какой смысл остаётся неуточнённым, жизненный пример последствий, ссылки на существующие задачи/документы и boundary. `existing_task_ids` — точки сопоставления, **не назначение новой работы этим исполнителям**. Novelty относится к проработке документации, не к runtime наличию. `own/integrate/observe` — исследовательская классификация plane по существующей custody boundary; спорная классификация явно отмечается, ratification не производится.

## Что будет следующим отдельным этапом

Сначала рассмотреть и согласовать этот реестр. Затем для выбранных групп провести исследования вариантов, предложить решения/проверки, определить дополнения существующих задач или обоснованные новые задачи и выполнить циклы независимого redteam. R18 сейчас проверяет **охват и точность вопросов**, не проводит преждевременную приёмку ещё не спроектированных решений. Реализация остаётся после E02 acceptance.

## Ограничения исполнения исследования

Только документация, узкие read-only чтения и primary-source web research. Без product imports/tests/builds, установок, серверов, production reads, больших выгрузок и уборки диска. Root пишет tracked документацию; независимые прямые субагенты не создают детей и сохраняют только компактные ignored research reports. Результаты субагентов — candidate inputs до root review. Наличие документа или формулировки не означает готовую capability.

Pattern pass: P01/P02/P03 — вопросы охватывают реальный полный путь, не отдельные контракты; P04/P05/P07/P08/P15 — status/authority/time/LLM boundaries; P13/P27/P31 — не создавать повторные owners или новые системы из списка рисков; P35/P36 — полный declared denominator и проверяемые ссылки; P37/P38 — вопрос касается действительного свойства; P40 — варианты одного класса не раздувают список независимых gaps. Product execution UNRUN; E02 acceptance не меняется.
