# Совместное исполнение разнородных моделей: исследование и путь реализации

23 октября 2026. Source-bound архитектурное исследование на `528ec2576393e8aa9a0238ae4172336ccf76a057`; static inspection, **runtime UNRUN**. Этот документ конкретизирует conditional scope GYD-30, DES-03/11 и OPS-08. Он не принимает E02, не меняет SDD и не требует FMI/HELICS для каждого case. Implementation начинается только после E02, scoped source rebind и согласования реально затронутого native interface.

## 1. Зачем системе композиция моделей

Один policy design может соединять tax-benefit rules, поведение домохозяйств, capacity услуг, физическую инфраструктуру, агентное распространение и агрегированные бюджетные последствия. Каждый компонент отвечает на свой вопрос и может иметь свой scale, solver, period, population и validity envelope. Сложить outputs недостаточно: transfer одного компонента может быть расходом другого; меры меняют поведение и исходное распределение; feedback возвращается в первый компонент.

Нужно различить три отношения: **вычислительная зависимость**, **каузальное/содержательное соответствие** и **пригодность совместного вывода**. Выполненный DAG доказывает только исполнение зависимостей. Unit conversion не доказывает, что переменные означают одно и то же. Сходимость feedback не устанавливает истинность equilibrium или причинного ответа. Общая PolicyOS claim зависит от всех material bridges и их реально проверенных границ.

Root отдельно прочитал topological order, actual graph order consumption, feedback map injection/solve/persistence и IR certificate completeness scope. Fixed-point solver на этом pin выбирает один найденный converged result по numerical residual/distance; это вычислительная политика выбора candidate, **не** основание считать найденный equilibrium единственным или социально предпочтительным. Rebind проверяет downstream multiplicity handling; отсутствие нужного semantics — owning extension, не смена whole engine.

Независимый source red-team уточнил три реальные границы reuse, root перечитал их в коде. `FeedbackStateSnapshot` содержит compact solver vector, не полный checkpoint всех participants. В `execute/api.py` после solve исполняется final graph run и persist получает `outcome.converged`; на прочитанном участке не пересчитывается сходимость actual final observed vector к solved vector. `MapEvaluation.noise_sd` переносится как diagnostic, тогда как `feedback/diagnostics.py::converged` использует residual/step/budget checks, не noise-aware inference. Наконец `max_steps` в inspected posture не является aggregate CPU/RSS/CAS budget: каждая map evaluation может писать artifacts, а multi-start/Jacobian/multiplicity умножают вызовы. Это **статические integration risks, не исполненные runtime FAIL**; accepted E02 rebind должен проверить актуальность и весь consumer closure.

## 3. Предпочтительные уровни интеграции

| Реальная форма задачи | Предпочтительный путь | Когда расширять |
|---|---|---|
| Acyclic static/period calculation | Existing ProgramGraph/ExecPlan, native method adapters, CAS result bindings | Если producer→consumer meaning/period/unit/support bridge ещё не представлен |
| Stateful one-way / настоящий lag | Existing temporal executor с declared lag и boundary mapping | Если событие/период/held input не соответствует actual model semantics |
| Same-time feedback / algebraic coupling | Existing Foundry fixed-point owner, compact named coupling variables, pure/restartable map | Если модели имеют скрытое состояние, временное продвижение или solver capabilities за этим scope |
| Независимые stateful simulators с clocks/events | Один локальный coupling adapter/master внутри existing execution/resource boundary; внешний standard runtime только по concrete need | Когда уже установленный native runner не может представить нужную synchronisation/recovery property |

Это уровни сложности, не последовательные обязательные milestones. Для новой supported model family должны меняться registration/adapters/config и нужные owner-specific contracts, а не центральный список отраслей. Неподдерживаемые required semantics остаются явной limitation; registry label не делает их поддерживаемыми.

Temporal reuse в этой таблице ограничен существующими domain-specific discrete-step producers. Инспектированный executor с integer steps не является готовым calendar/event/multi-clock adapter. Нужный cross-model mapping сначала проверяется на selected case; поддержка до этого not_established, а реально отсутствующая связь назначается native owner как bridge_missing. Это не повод запрещать уже поддержанный integer-step run.

**Не вводить цикл в обычный execution DAG.** Classify material dependencies как same-time, explicit lag или event transition. Zero-lag strongly connected component может исполняться как один поддержанный coupling block внутри внешнего acyclic graph. Это execution grouping, не доказательство допустимости циклического SCM или сохранения identification. Последовательный implicit lag нельзя использовать для «устранения» материального instantaneous feedback без отдельного approximation basis.

## 4. Полный путь данных и результата

1. **Question → model selection.** DES-03/11 выбирает models/method profiles из native registry по нужной claim/decision и supported regime. Bind exact executable/backend/model version отдельно от ABI; include independent model validity/causal grounds через CNT-06. Unknown model weights сохраняются неизвестными; не выбирать ensemble average по умолчанию.
2. **Typed port relation.** Producer slot → native adapter → consumer slot. Material relation содержит variable/construct identity, unit/scale/price basis, entity/population/spatial support, time role/interval, stock/flow/intensive quantity, lag и допустимые преобразования. Это sparse owner-native relations; большинство приложений не требует всех facets. Dimensional equality не равна смысловой или causal equivalence.
3. **Mapping validation.** Explicit aggregation/disaggregation/crosswalk с provenance и assumptions. Means/ratios не суммируются как totals; годовой stock не размазывается автоматически по дням; currency conversion не выбирает discount law. Entity birth/death/merge и меняющиеся geography denominators видимы. Unknown boundary mapping ограничивает только dependent calculation/claim.
4. **Resolve inputs and states.** Pin source snapshots/cutoffs, incumbent/initial conditions, external forcing, parameters, constraints, master/adapter version, selected dependence и environment posture. Input availability не доказывает custody/currentness. Rules/model/source updates адресно инвалидируют affected cache и current claim.
5. **Execute.** Native owner проводит выбранный DAG/lag/fixed-point/clocked run с одним shared resource admission. Remote execution остаётся supplier contract CAP-06/OPS-09, не потерей input/result lineage. Нельзя отправлять private inputs в generic model service из-за того, что он реализует нужный interface.
6. **Persist.** Existing CAS сохраняет native outputs, required state/checkpoint refs, mapping/coupling identity, iterations/events, diagnostics и completeness. Независимый fresh evaluator не должен читать mutable working memory исполнителя. Не копировать весь массив на каждый edge: content-bound chunks/views с verified lifetime/rights допустимы, когда native consumer умеет их читать.
7. **Qualify and consume.** GYD-30 связывает actual joint witness, GYD-31 сохраняет наборы/uncertainties, N6 сравнивает, Atlas/DES-06 показывает limitations. Numerical failure не превращается в социальную infeasibility. Numerical success не выпускает promotion. Same-named IR/PDC certificates связываются только typed semantic relation, не cast по имени.
8. **Reuse/change/recovery.** Reuse exact pure result требует подходящего cache identity **и** current-use admission. Resume включает state/RNG/event frontier, а не только seed. Право/модель/контекст изменились — новый scope/version или refusal. Старая simulation остаётся исторической; external act не rollback.

## 5. Синхронизация, сходимость и неопределённость

**Clocks.** Policy/legal effective time, observation/receipt, model virtual time, solver iteration и wall clock различны. Calendar month не фиксированное число секунд. Bridge объявляет interval endpoints, aggregation/interpolation/sample-hold semantics, event ordering и relevant timezone. Simultaneous events не получают причинный порядок от thread scheduling. Late event либо входит в новое replay/candidate calculation, либо требует supported state restore — никогда не стирает прошлую опубликованную историю.

**Feedback.** Для pure algebraic map повторное вычисление не нуждается в mutable-state checkpoint. Если member меняет состояние/RNG, каждый trial начинается с того же допустимого snapshot либо детерминированно пересоздаётся/replays из immutable inputs. Иначе повторный вызов — другая задача, не итерация той же fixed point. Step rejection/event localization должно согласованно восстанавливать все затронутые participants; нельзя откатить только быстрый model.

**Eligibility и final-result fence обязательны, а не labels.** Минимальный native reuse scope — deterministic map **conditional on one frozen scenario/shared-shock identity**. Доказать reset/replay/purity для полного selected participant closure и actual inputs; compact vector snapshot этого не доказывает. Если это недоступно, stateful/non-replayable coupling остаётся unsupported для данного profile, при сохранении допустимых one-shot candidates. Отдельно final materialization обязана recompute residual по actual emitted final vector относительно selected solved vector и связать certificate с exact final artifacts. Несовпадение, изменившийся participant, input или hard constraint → downgrade/refusal affected joint claim. Даже совпавший один final residual не доказывает general repeatability, поэтому final fence не заменяет eligibility.

**Convergence.** Scale/units-aware residual и tolerance происходят из selected numerical profile. Residual small не гарантирует small solution error в плохо обусловленной системе и не доказывает existence/uniqueness global equilibrium. Multi-start может обнаружить multiplicity, но не доказать отсутствие остальных equilibria. Preserve branches/model-dependent feasibility; selection branch требует самостоятельного содержательного основания. Nonconvergence, budget exhaustion, discontinuity, missing member и unsupported coupling не сливаются в generic success.

**Splitting and fidelity.** Explicit/lagged splitting годится при реальном лаге или обоснованной численной approximation. Step refinement, alternative order, residual and conservation checks — диагностика numerical adequacy; несколько совпавших step sizes **не** математический error bound. Если claim требует гарантированной границы, нужны поддержанный error estimator/proof assumptions или более слабая claim. При узком decision margin проверять возможную смену feasible/Pareto membership; не вводить единый scalar margin для несравнимых objectives. Повышение fidelity — по useful error/cost, не обязательное применение самого дорогого solver.

**Randomness and correlation.** Общие exogenous drivers задаются один раз на scenario/replicate и передаются по explicit relation. Keyed random streams отделяют независимость draw от недетерминированности scheduling; от одинакового integer seed зависимость не возникает автоматически. Common random numbers для сравнения стратегий допустимы при обоснованном matching of shocks; endogenous exposure/agent creation может требовать иной mapping. Monte Carlo error, numerical approximation, model uncertainty и causal/measurement uncertainty сохраняются отдельно. Отсутствие known dependence не разрешает independent default.

Fixed-seed/sample-path equilibrium не является equilibrium **expected-response map**. Для последнего требуются отдельные выбранные estimator, sampling/dependence и noise-aware stopping/uncertainty rules с consumer; reported `noise_sd` в текущем result не устанавливает такую гарантию. До этой owning extension expected-map claim остаётся not_established; scenario-conditional deterministic calculation не блокируется. Нельзя замаскировать случайный map под deterministic, увеличив tolerance после результата.

**Conservation.** Domain owner определяет, что сохраняется: internal fiscal transfer, население с явными входами/выходами, энергия с loss/source terms и т. п. Не все экономические quantities консервативны. Проверять transfer один раз по связанным sender/receiver records; похожее имя денежного output не означает один и тот же ресурс. Good aggregate fit не компенсирует потерянный flow.

## 6. Какие технологии полезны и чего они не делают

- [FMI 3.0.2](https://fmi-standard.org/docs/3.0.2/) задаёт interfaces Model Exchange, Co-Simulation и Scheduled Execution; master/co-simulation algorithm не задаётся стандартом. State/step/event capabilities нужно проверять у конкретного FMU. Executable package не является sandbox или доказательством корректности.
- [OMSimulator](https://openmodelica.org/doc/OpenModelicaUsersGuide/latest/omsimulator.html) — кандидат на reuse, когда есть реальные FMI/SSP models и его solver/master profile подходит. Не добавлять его ради собственных уже работающих native methods; сначала проверить supported model versions, loop/event handling, recoverability и ресурсный профиль.
- [HELICS timing](https://docs.helics.org/en/latest/user-guide/fundamental_topics/timing_configuration.html) — пример координации time requests/grants у отдельных federates. Он не устанавливает общий numerical equilibrium, смысл переменных или causal law. Нужен при независимых processes/event-driven participants, не для обычного DAG.
- [BMI](https://bmi.csdms.io/en/latest/bmi.spec.html) — interface model initialize/update/get/set/time/metadata. Полезен для конкретного external model adapter; не заменяет coupling algorithm или гарантию state snapshot/replay.
- [OpenFisca periods](https://openfisca.org/doc/coding-the-legislation/35_periods.html) показывают calendar-aware rule calculation; [UKMOD labour-supply extension](https://euromod-web.jrc.ec.europa.eu/research/publications/enhancing-tax-benefit-modelling-functionality-labour-supply-responses-ukmod) — пример отдельного behavioral response поверх tax-benefit расчёта. Вычисление правила и прогноз реакции не следует сливать в одну гарантию.

Выбор — native DAG + existing fixed-point **по умолчанию для поддержанного scope**. Внешний protocol/master выбирается по measured unmet property, не как универсальный стандарт PolicyOS. Даже при использовании стороннего master native owner сохраняет input identity, permissions, budget, result admission и custody. Numerical master не является вторым compute scheduler.

## 7. Память, вычисления и восстановление

- Plan validates declared dimensions/links/resource needs до materialization; данные обрабатываются bounded chunks или native views, где это поддержано. Zero-copy не даёт права держать revoked raw buffer; lifecycle/lifetime explicitly owned.
- Использовать rolling windows, output projection и sparse checkpoints по replay cost/diagnostic need. Preserve deciding diagnostics и точно необходимые lineage/state; полный каждошаговый dump не default. Нельзя удалять unique state, нужное для advertised resume, под видом reproducible scratch.
- Параллельны независимые scenarios/replicates/model branches и действительно независимые DAG nodes. Для coupled cycle параллельный Jacobi и последовательный Gauss–Seidel — разные algorithms; порядок является частью provenance, не свободной оптимизацией. Nested models получают части общей capacity, а не каждый новый полный cap.
- OPS-08 связывает фактический **полный** denominator feedback map calls, finite-difference/Jacobian probes, multi-start, retries, final materialization и CAS bytes с общей admission. Current inspected `max_steps` не доказывает этот cap; aggregate resource property пока not_established. При exhaustion сохраняются нужные deciding receipts и honest incomplete outcome, не обещание успешного equilibrium.
- Cache pure evaluations по executable/model/adapter/inputs/state/time/coupling/shock/fidelity identity. Counterfeit determinism или скрытый mutable source запрещает exact reuse. Bitwise, tolerance-qualified и distributional replay имеют разные promises; qualified equivalence задаётся native profile до результата.
- External executable запускается через существующую isolation/supervision boundary, с minimum capabilities, bounded memory/CPU/output и current source rights. Package metadata не разрешает network/institutional effects. Если нужный external provider не replayable, receipt фиксирует это; repeated call не становится deterministic local step.
- **Provider calls внутри solver считаются evaluations, не только retries.** По умолчанию capture/fetch выполняется до loop и frozen permitted results становятся inputs. Если действительно нужен remote pure evaluation, CAP-06 должен обеспечивать request identity по exact input/scenario/model, deterministic result binding, permitted audience и receipt/reconciliation; повтор того же запроса не создаёт необъяснимый повторный charge/disclosure, а иной input является новой отдельно учтённой работой. Homotopy, finite differences и multi-start также расходуют общий permit и применимый monetary/disclosure allowance. Нельзя считать идемпотентность бесплатностью или правом на unlimited calls. Не-replayable/non-idempotent external act остаётся вне map; institutional action запрещена внутри simulation независимо от retry count.
- Partial failure остаётся partial: быстрые components не выпускают complete joint result при отсутствующем required slow member. Durable per-attempt history отделена от numerical state rollback. Не повторять реальный внешний расход/вмешательство ради retry simulation.

## 8. Различающие проверки после E02

| Свойство | Positive | Falsifier / removal |
|---|---|---|
| Actual joint path | Typed output одного native model реально меняет второй и fresh joint consumer | Подменить связь статическим похожим output при сохранённых graph IDs |
| Temporal meaning | Согласованные period/lag/event semantics и independent small oracle | Month→seconds default, wrong interval endpoint, simultaneous event race, один откатившийся member |
| Population/units | Проверенный mapping меняет нужный support/quantity | Mean как sum, stock как flow, stale geography, неверная price basis |
| Dependence | Shared driver/common transfer связан один раз | Независимо redraw shared shock; повторно сосчитать transfer/evidence |
| Numerical adequacy | Known fixed point / stable bounded lag model с profile diagnostics | Oscillation, ill-conditioning, undisclosed multiple roots, false step-bound claim |
| Authority | Valid numerical result сохраняет отсутствующее empirical/causal grounding | Сохранить solver/convergence certificate и убрать target/causal grounds: promotion не проходит |
| Recovery/resource | Supported resume/replay и aggregate cap сохраняются | Hidden RNG/state, stale checkpoint, missing member, multiplied nested quota |
| Final materialization | Actual persisted final vector удовлетворяет selected residual и связан с его certificate | Map игнорирует seed/меняет скрытый state только при final run, но старый `converged` остаётся true; final consumer обязан отказать |
| Stochastic scope | Frozen-scenario result отображается именно как conditional; отдельно проверен expected-map profile, если он заявлен | Diagnostic `noise_sd` или fixed seed выдан за noise-aware convergence/expected equilibrium |
| Extensibility | Новая conforming модель того же supported interface добавляется без search-core edit | Новый semantics спрятан в label, обязательный unsupported facet молча проигнорирован |

Оракулы готовятся independently от simulator; manufacturing a convergence/certificate JSON не тест. Эти случаи входят в selected GYD-30/DES-10 verification, не отдельный обязательный большой replay. Для реального scientific claim нужны соответствующие authentic validation inputs; controlled execution proof их не создаёт.

**Малый numerical oracle для первой coupled цепи:** два native test models задают `x = 1 + y/2` и `y = 2 + x/4`; единственное решение — `x = 16/7, y = 18/7`. После действительного coupling run fresh result должен согласоваться с этой независимой алгеброй в выбранной tolerance. Сохранить отдельные standalone outputs, но убрать cross-model exchange — oracle расходится. Вариант `x = 1 - x` показывает, почему осцилляция конкретной Picard iteration не равна отсутствию equilibrium: решение `x=1/2` существует. Profile может выбрать иной поддержанный solver либо честно ограничить numerical claim; нельзя подписать «policy infeasible» от max iterations. Математические controls не калибруют социальную модель.

## 9. Решения и следующий шаг исполнителя

**Можно реализовывать после E02 в действующих полномочиях:** выполнить bounded owner/caller census; связать уже поддержанные acyclic producers; разнести существующие certificate meanings; добавить actual content-bound mapping/consumer и semantic probes; использовать native fixed-point для соответствующего pure/restartable map; восстановить пропущенные companions. Это не требует предварительного нового SDD только из-за слова «model».

**Scoped owner choice до нового coupling claim:** точный поддержанный algebraic/time/event profile; meaningful port/target mapping; numerical evidence и limitations; selected external adapter; memory/recovery/determinism promises. Выбор не должен блокировать unrelated DAG work. Если решение меняет shared ABI, owner, authority/time semantics или публичное promise за существующим SDD — подготовить отдельный proposal для G/пользователя с alternatives, migration, impact и falsifier. Этот research dossier такого согласования не подменяет.

**Внешние genuine inputs:** actual model licenses/executables, calibration/measurement/transport grounds, incumbent facts, custodian rights и implementation-response data. При их отсутствии internal mechanisms/candidate scenarios готовятся, а dependent empirical/authority claims остаются limited/not_established. Не объявлять все эти inputs обязательными для каждого локального mathematical witness.

Pattern pass: P01/P02/P03/P05/P07/P08/P10/P13/P14/P17/P19/P24/P25/P27/P29/P31/P32/P37/P38. Цель — один source-bound путь с проверяемыми meaning/numerics/authority границами; не universal state object и не новые parallel certificate/optimizer/custody owners.
