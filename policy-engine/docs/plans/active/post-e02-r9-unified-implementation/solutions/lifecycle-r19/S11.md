### S11-M1. Поведенческая квалификация разрешённого provider use по task profile

**native_owner.**

Расширять DES-10 quality comparison и DES-09 invocation ledger; LIF-07 связывает фактическое влияние, LIF-02 меняет current claims. CAP-04 сообщает только реально доступные provider events.

**reuse_anchors.**

- **path**: policy-engine/src/polisyos/scientist/orchestration/llm/provider_quality.py
- **symbol**: ProviderModelQualityObservation; DefaultProductionModelChoice; build_provider_model_quality_ledger; _review_default_model_choice
- **observation**: Static: keyed provider/model/fingerprint, 14-day default; no bound profile or task-specific usage.

- **path**: policy-engine/src/polisyos/runtime/quality/prompt_tool_ledger.py
- **symbol**: ModelProviderConfig; ModelAssistedStepLedger; PromptToolParserAuthorityLedger
- **observation**: Static: invocation, inputs/context, tools/parser and optional fingerprint already bound; no profile-quality disposition consumer.

- **path**: policy-engine/src/polisyos/runtime/http/services/control/nl_pipeline.py
- **symbol**: provider_observations; build_provider_model_quality_ledger (8446–8525)
- **observation**: Static: fingerprint is SHA-256(provider+label); selected quality comes from same run report, not serving identity or longitudinal eval.

- **path**: policy-engine/src/polisyos/runtime/quality/scorecard.py
- **symbol**: _provider_model_quality_gate
- **observation**: Static: generic default review/runtime-ref gate, no exact-profile comparison; existing scorecard can surface one.

**decision.**

Treat qualification as a stable, versioned task/use profile plus explicit input/context envelope, not as one profile per invocation. Resolve applicable dimensions from the actual selected use/claim and owner contract; verify each N/A rationale against that use, distinct from missing/unknown. No hidden wildcard: version the allowed envelope and representative eval cases; changed load-bearing dimensions or out-of-envelope calls cannot inherit qualification. Every call/output still binds exact rendered prompt, context/case, tools, route/version if returned and output refs; in-envelope variation keeps the same profile but distinct influence. DES-10 evaluates a frozen representative set across the envelope, not each prompt. Opaque version stays not_established. P15/P32/P37/P38 target: actual resolve/bind/verify at DES-09 consumer.

**alternatives.**

- **option**: Доверять alias/hash строки и общему 14-дневному окну.
- **tradeoff**: Скрытый remap и task/language drift останутся green; code default не обосновывает свежесть.

- **option**: Полностью запретить opaque provider.
- **tradeoff**: Не даёт поведенческого знания и зря закрывает полезную candidate работу; rights/egress запреты решаются своими owners.

- **option**: Отзывать все прежние outputs при любом drift.
- **tradeoff**: Смешивает текущую eligibility с истинностью истории и затрагивает неповлиянные outputs.

**contract.**

Bind profile/version, use/consequence, explicit envelope/allowed routes, owner-derived applicable dimensions (N/A rationale resolved against actual use, not self-attested; N/A ≠ absent), representative eval refs, per-applicable-dimension oracle, denominator, method/threshold, time cut and provenance. Each call/output separately binds profile ref, selector/route/request ID/served version if exposed, exact prompt/context/case/tool/parser/config/output refs and time. Resolve to the profile only inside its declared envelope; no wildcard. Required missing evidence or out-of-envelope use limits that use. In-envelope variation does not requalify but its exact refs remain attached for LIF-07 influence.

**flow.**

- DES-10 freezes representative, stratified cases and evaluates only applicable dimensions: a format profile may justify N/A for legal/method criteria; legal use must bind its norm source.

- Persist profile/applicability rationale, eval refs, denominator, thresholds and cut; N/A and missing required evidence remain distinct.

- DES-09 binds each call’s exact context/case/tool/output refs and resolves only in-envelope calls to the stable profile; no per-prompt profile creation or out-of-envelope inheritance.

- Scorecard surfaces bounded disposition; LIF-07 tracks actual call influence and LIF-02 scopes current claims.

**migration.**

Legacy ledgers lack resolved applicability/envelope: do not invent past N/A, intent or exact context. Preserve as-known; they cannot qualify new default use until new evidence. Reassess current use only if qualification was load-bearing or a proven defect reaches it through actual influence.

**free_grow.**

Add new cases/provider facts to current typed sources/eval packs. N/A is profile-local, not global; new cases grow the eval version. No new domain tree.

**resource_behavior.**

Use bounded representative cases across the declared envelope, not full eval per call. Set sample/cadence/cost by consequence; 14 days/three samples do not prove adequacy. Sparse strata stay not_established.

## R18-D11-Q01. Связать свежесть модели с текущим допуском профиля

Для выбранного task profile по какому основанию оценка provider/model/profile остаётся свежей, и как переход `require_review`/`demote`/`block_production_approval` либо нераскрытая смена версии отражается на допуске конкретного использования и currentness зависимых результатов? В частности, что делать с текущим use, если provider сохраняет публичный alias, но не даёт стабильный fingerprint или change event, и какие зависящие от фактического влияния outputs требуют переоценки, ограничения либо только исторической маркировки?

**Выбранное решение.**

Freshness qualifies allowed provider use for a stable, versioned task/use profile and explicit envelope. Only applicable quality dimensions need evidence; justified N/A differs from missing required evidence. Every invocation binds actual context/case/tools/output, but an in-envelope context change alone neither creates a profile nor erases qualification. Out-of-envelope or load-bearing changes cannot inherit it. Opaque model identity stays not_established; behavior evidence covers only the tested profile/window.

**mechanism_ids.**

- S11-M1

**specific_steps.**

- Define stable profile by intent/consequence, risk band, provider route, versioned prompt/tool/parser settings, explicit input/context envelope and applicable quality dimensions derived from the use contract. Record reasoned N/A, never as default/wildcard.

- DES-10 freezes representative strata/cases and per-applicable-dimension oracles, denominators, thresholds and max-gap. Format-only use needs its format oracle; legal use cannot omit or waive a required norm ref.

- DES-09 binds every actual prompt/context/case/tool/parser/config/route/output ref. Calls inside the declared envelope resolve to one profile while retaining distinct lineage; outside-envelope or changed load-bearing use is limited/requalified.

- Quality dispositions act prospectively; LIF-07/02 reassess only dependent current uses when approval was load-bearing or a verified defect influenced them. Preserve as-known and independently grounded outputs.

**authority_time_status.**

These actions qualify only the allowed use of a provider for one profile; they never make output authoritative. require_review permits limited candidate continuation, demote removes this profile's default approval, and block_production_approval blocks only production-default qualification; all remain subject to independent rights/egress and claim gates. Vendor event uses its admitted scope/effective time; behavioral failure is known at observation time, with onset bounded only by probes. Reassess current claims only where qualification was load-bearing or a verified defect has actual influence. No retroactive invalidity by default; independently verified outputs retain their own basis.

**external_inputs.**

- Provider request/response ID, served model/route/region/version when exposed; missing metadata remains not_established.

- Source-qualified release/remap/retirement/incident notice and scope if actually available; missing feed is not a no-change receipt.

- Independent profile cases/oracles, authorized thresholds/window and permitted access/cost from existing evaluation, governance and egress owners.

**unresolved_research.**

- Opaque service cannot reveal hidden snapshot or exact drift onset; probes bound observed behavior, not absence of unobserved change.

- Silent-update frequency and rare-error sample power are unknown; measure miss/false-alert/cost per profile. Until then use bounded candidate path and limit production claims to tested strata.

**Изменения существующих задач и различающие проверки.**

- **task_id**: DES-10
- **role**: assurance
- **delta**: Freeze representative cases across stable profile envelope; bind per-applicable-dimension oracle/denominator. Reasoned N/A differs from unknown/missing; no full eval per invocation.
- **positive**: Format-only/no-norm profile passes its independent format oracle; two in-envelope contexts share qualification but retain distinct case/output refs.
- **adversarial**: Legal use omits required norm, falsely marks N/A, changes holdout with model, or calls outside envelope; no inherited clean verdict.
- **removal**: Remove applicability/envelope matching but retain labels; required-norm omission or outside-envelope case still passes.

- **task_id**: DES-09
- **role**: primary writer
- **delta**: Bind stable profile/disposition plus exact per-call prompt/context/case/tool/parser/config/route/request/output refs. In-envelope context variation is invocation lineage, not a new profile; out-of-envelope calls cannot borrow approval.
- **positive**: Different in-envelope calls resolve to one fresh profile with separate actual refs; legal call resolves its required norm dimension.
- **adversarial**: Context/tool/route escapes envelope or required source is absent while profile ID remains unchanged.
- **removal**: Remove actual envelope/content check, retain profile refs; outside-envelope invocation is accepted.

- **task_id**: LIF-07
- **role**: primary writer
- **delta**: Keep exact per-call context/case influence even for shared stable profile; profile qualification is not cache identity or independence.
- **positive**: Different in-envelope calls remain distinct; drift re-evaluates only outputs/claims actually dependent on changed profile/call.
- **adversarial**: Same profile/alias/output bytes hide different context/tools and lineage.
- **removal**: Remove context parents, keep profile ID; fresh consumer sees falsely collapsed influence.

- **task_id**: LIF-02
- **role**: consumer
- **delta**: Consume quality changes at the actual source/time cut; update claims whose admissibility depended on that profile. An empty vendor feed is not no-change, and in-envelope context variation alone does not create per-call requalification.
- **positive**: Dependent current claim receives scoped limitation/review after detected regression; unrelated profile is unaffected.
- **adversarial**: No vendor event, stable alias, delayed scheduler, but paired probes fail.
- **removal**: Remove current-head reaction; fresh reader still shows old approval.

- **task_id**: GYD-20
- **role**: assurance
- **delta**: Separate historical reconstruction, version status and exact invocation refs from fresh stochastic calls.
- **positive**: Old trace reconstructs with version known/unknown; new call gets separate identity, even under same profile.
- **adversarial**: Same profile/alias is mistaken for byte-identical replay despite new context or unknown version.
- **removal**: Remove exact invocation refs but keep profile/replay labels; version-specific replay claim fails.

## self_attack

- **case**: Format-only quoted-text extraction has no legal norm/method; two distinct calls lie inside its declared envelope.
- **repair_or_bounded_limit**: Reasoned N/A plus independent format oracle permits one profile qualification; exact refs remain attached to both calls/outputs.

- **case**: Legal call omits a required norm but marks it N/A, or a call changes context beyond the declared envelope while profile labels stay intact.
- **repair_or_bounded_limit**: Derive applicability from actual use; missing is not N/A. Consumer limits that call; useful in-envelope candidate work continues.

- **case**: Two calls share a profile and output bytes but used different retrieved sources.
- **repair_or_bounded_limit**: Retain distinct context refs/influence; same profile/bytes proves neither identical lineage nor independence.

## limits

- Provider's hidden serving state and event-feed completeness are external facts; absent those, attestation is only observed profile behavior in a bounded window.

- 14-day default and three samples are current mechanisms, not universal freshness or statistical adequacy.

- Quality does not establish egress permission, law, causal correctness or truth of a generated claim; existing rights, egress and admissibility owners remain authoritative.

- Static owner inspection only; end-to-end runtime composition/evaluation is UNRUN pending E02 acceptance. No live-provider behavior was tested.

## root_resolution

- **review_id**: RT-S11-F01
- **disposition**: addressed
- **resolution**: Stable use-profile/envelope/applicable dimensions are separate from exact call refs. N/A is checked against actual use; missing ≠ N/A; DES-10 evaluates representative cases, DES-09 binds every invocation/output. Outside-envelope use cannot inherit approval; positive format-only and negative required-norm/removal witnesses added.
