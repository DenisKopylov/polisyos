Имена полей/артефактов ниже задают семантические обязанности и минимальные связи. Окончательные DTO, owner и версии связываются с принятым E02 source; существующие owners/registries расширяются без параллельных систем. Статические наблюдения не доказывают runtime absence или PASS.

## Повторно используемые механизмы

### S16-M1. Один LIF-06 permit owner: duty reserve + fairness остаточной capacity

**native_owner.**

LIF-06 owns the single permit decision; reuse accepted E02 owner or extend only that seam. OPS-08 enforces its host profile; OPS-11 supplies duties; OPS-07 keeps separate provider-spend ownership.

**reuse_anchors.**

- **path**: runtime/http/services/control_plane_store.py
- **symbol**: ControlPlaneStore._job_transaction
- **observation**: Static: durable job transaction, not aggregate permit/physical cap.

- **path**: runtime/http/services/control_worker.py
- **symbol**: ControlWorker.dispatch_once; _run_with_lease_heartbeat
- **observation**: Static: attempts/heartbeat exist; per-worker concurrency is not host capacity.

- **path**: core/security/tenant_quota.py
- **symbol**: TenantQuota
- **observation**: Static: per-tenant quota, not shared-host admission.

**decision.**

Before each custody-bearing signature/renewal, LIF-06 checks OPS-11 owner-approved duty/scope/cadence/due/cutoff against OPS-08 measured enforceable capacity and accepted commitments. Admit only bounded coverage or authorized cutoff; otherwise refuse with measured gap/commitments and feasible scope. No perfect future availability or invented priority. Then order duties on supplied inputs; DRF only comparable divisible residual classes, native caps/reservations for storage, rates, GPU. Sustained overload has no finite-wait guarantee; LIF-02 limits only enrolled dependent claims; candidates/unrelated claims continue.

**alternatives.**

- **option**: FIFO/cost sort
- **tradeoff**: Hidden arrival/price policy; noisy tenant can starve duty.

- **option**: Strict custody priority
- **tradeoff**: Can starve candidate work and mis-rank incomparable duties.

- **option**: DRF for all work or new scheduler
- **tradeoff**: DRF misses duty time/safety; new owner duplicates LIF-06.

**contract.**

Versioned permit binds profile principal/parent-org, claim duty, scope/due/cutoff, job+attempt, rule/profile, invocation closure, measured vector and accepted commitments. Admission precedes signature/renewal. Persist acceptance, permit, usage and disposition; usage is recomputed/reconciled. Only enforceable capacity counts; monetary refusal cost only with OPS-07 evidence. Unknown/missed due flows to enrolled claims via LIF-02.

**flow.**

- OPS-11 supplies competent owner and bounded duty; DES-04/12 supply candidate intent.

- LIF-06 prechecks new claim duty against OPS-08 capacity and commitments; admits bounded coverage or measured-gap refusal/cutoff.

- LIF-06 reserves terminal fan-in; orders eligible duties; uses DRF only for comparable divisible residuals, native controls otherwise.

- Persist in existing control records; OPS-08 enforces; LIF-04 holds permit through live/unknown effects.

- Fresh LIF-02 limits affected enrolled claims only; candidate and unrelated work continues.

**migration.**

Keep one LIF-06 owner; census nested work, classes, profile principals/anti-Sybil aggregation and enforcement. TenantQuota/transaction is not aggregate capacity. Before new custody duty, require measured coverage or owner-approved cutoff. Under overload stop bulk, expose gap and reconcile; never promise a future slot.

**free_grow.**

New classes reuse generic LIF-06 descriptors; new physical dimensions need enforcing adapters; priority semantics need selected profile inputs.

**resource_behavior.**

Bound nested/recovery peak; transfer parent permit before child wait; TTL never frees live work. Unenforced dimensions defer/refuse. Refusal names measured gap/commitments and feasible authorized cutoff; no unsupported dollar estimate.

### S16-M2. Store-time lease eligibility; generation fencing for safety

**native_owner.**

LIF-04/ControlPlaneStore owns lease, attempt and local completion fence; OPS-04 composes its worker; OPS-03 reads health; LIF-06 holds capacity until reconciliation.

**reuse_anchors.**

- **path**: runtime/http/services/control_worker.py
- **symbol**: ControlWorker.__init__/_run_with_lease_heartbeat
- **observation**: Static: monotonic is maintenance-only; lease renewal uses store.

- **path**: runtime/http/services/control_plane_store.py
- **symbol**: _utc_now; job_execution_fence; _require_current_job_execution_record; _job_fence_where
- **observation**: Static: app-UTC expiry/local fence; no shared-clock or provider fence established.

- **path**: policy-design-custody-time-model.md
- **symbol**: §2-§5
- **observation**: CTM keeps operational time distinct from source/effective/knowledge time.

**decision.**

Expiry enables recovery only; receiver-checked durable generation fences stale writes. ControlPlaneStore owns selected-backend lease time/serialization; worker UTC is not shared, monotonic is elapsed-only, logical time is not TTL. Keep CTM/source/effective/known-at, OPS-11 duty due and lease expiry distinct. Bind duty due owner, interpretation/zone, source/uncertainty, cadence/cutoff. Unevaluable due limits only enrolled dependent claims via LIF-02; no event/heartbeat is not timely coverage. Unprovable lease refuses only dependent operation; independent safe cancellation/revocation/limitation/reconciliation uses its own durable path or stays pending. No new clock service.

**alternatives.**

- **option**: Per-worker UTC
- **tradeoff**: Skew/step may reclaim early; no late-request fence.

- **option**: Persist monotonic readings
- **tradeoff**: Host/process epoch resets; incomparable across restart.

- **option**: Logical clock TTL
- **tradeoff**: Orders causality, not elapsed time.

- **option**: Assumed bounded wall clock
- **tradeoff**: Ordinary SQL/UTC proves no bound; require selected backend evidence.

**contract.**

Lease binds backend/profile, job/worker, durable attempt, rule version, store-time grant/renew/expiry and effect state. OPS-12 is a runtime fence only if verified scope binds the exact ControlPlaneStore/job epoch across the same failover/restore path. Otherwise LIF-04 refuses protected resume/reclaim, preserving uncertain effect and LIF-06 permit until reconciliation. External effect needs receiver fencing; else indeterminate. OPS-11 due basis is separate; unknown limits only enrolled dependent claims via LIF-02.

**flow.**

- LIF-04 atomically grants next attempt/expiry in ControlPlaneStore; worker renews and local writes recheck owner+attempt.

- Failover/restore must preserve attempt epoch; absent proof, protected resume/reclaim refuses.

- OPS-12 counts only with verified exact store/epoch/restore binding; offline-rights rollback alone is insufficient. Sink fence or indeterminate effect.

- Keep LIF-06 permit through live process/effect reconciliation; independent cancel/revoke/limit uses its own durable path.

- OPS-03 reports worker/store readiness; OPS-11 due uncertainty separately reaches enrolled LIF-02 claims.

**migration.**

Qualify backend, clock, failover/restore and sinks; app `_utc_now` plus SQL expiry proves no shared bound. Preserve attempts; fabricate no legacy fence. OPS-12 needs exact store/job-epoch restore binding or LIF-04 refuses protected resume. Bind OPS-11 due basis separately. SQLite-local and remote PostgreSQL are not assumed equivalent.

**free_grow.**

Handlers reuse ControlWorker/ControlPlaneStore. New sinks declare fence or idempotency/reconciliation support; new backends need a qualified adapter, not a universal clock service.

**resource_behavior.**

TTL cannot free live work. Unfenced effect keeps permit until reconciliation. Unknown due limits only claims enrolled in that duty; unrelated claims/candidates continue. Safe lease-independent transitions need their own durable path.

## R18-D16-Q01. Как распределять дефицитную мощность между обязанностями?

Когда общей мощности не хватает на custody/revalidation, control/recovery, новые дела и candidate research, кто и на каком основании выбирает порядок? Какова единица справедливого распределения (tenant, организация, дело, человек, duty), допустимы ли starvation и отсрочка, и как очередь влияет на visible overdue/currentness и принятие будущих custody-обязательств? Критерий выбирается для реального профиля, без второго scheduler и без скрытого социального ранжирования по arrival order или цене задачи.

**Выбранное решение.**

Before custody-bearing signature/renewal, OPS-11 supplies owner-approved bounded duty/cutoff and LIF-06 checks it against OPS-08 measured capacity plus existing commitments. Admit bounded coverage; otherwise refuse with measured gap or authorized cutoff/scope. No perfect future availability, invented weights, or monetary cost without OPS-07 evidence. DRF is only for comparable divisible residuals; other resources use native controls. Overload has no finite-wait guarantee: LIF-02 limits only enrolled dependent claims; candidates/unrelated claims continue.

**mechanism_ids.**

- S16-M1

**specific_steps.**

- Rebind one LIF-06 owner; OPS-08 measures/enforces selected resource classes.

- OPS-11 binds competent owner, duty scope/cadence/due/cutoff; selected profile supplies authenticated principal/parent-org and anti-Sybil aggregation.

- Before signature/renewal, compare bounded duty with measured capacity/commitments; record coverage or measured-gap refusal/authorized cutoff.

- Reserve terminal fan-in; order on owner inputs; apply DRF only to comparable divisible residuals and native controls otherwise.

- Saturate profile principals with a future duty; query fresh LIF-02/job readers.

**authority_time_status.**

M1: owners supply duty/profile/cutoff; capacity is recomputed/reconciled before admission; LIF-02 owns scoped claim reaction.

**external_inputs.**

- Service owner: profile, authenticated principal/parent-org, aggregation, enforceable classes/fairness inputs.

- Custody owner: competent duty owner, scope/cadence/due/urgency and bounded coverage/cutoff.

- Provider owner: OPS-07 charge evidence if monetary cost is claimed.

**unresolved_research.**

No literature sets normative priority or finite wait under sustained overload. Owners choose scope/capacity/cutoff; PolicyOS can refuse new duty with measured gap while candidate work continues.

**Изменения существующих задач и различающие проверки.**

- **task_id**: LIF-06

- **delta**: Pre-admit claim duty against OPS-08 measured capacity/commitments; preserve R16 nested denominator and R17 scoped revalidation.

- **removal**: Remove capacity check, keep markers; fresh dependent reader must change.

- **task_id**: OPS-08

- **positive**: Measured load/cap covers admitted duty.
- **adversarial**: Per-process caps multiply or class is unmeasured.
- **removal**: Remove shared enforcement, keep markers; admission/reader changes.

- **task_id**: OPS-11

## R18-D16-Q02. Какие часы определяют lease и просрочку worker?

Какая временная основа и отношение порядка определяют lease expiry, freshness heartbeat и due-time долгой обязанности между worker и control plane на разных host, после restart и при сетевом разделении? Как runtime различает это время от model/event time, source effective time и known-at cutoff, и что остаётся установленным, если один clock или связь с ним недоступны?

**Выбранное решение.**

ControlPlaneStore owns selected-backend lease time/serialization; expiry is recovery only and durable receiver-checked attempt fences writes. OPS-12 counts only if verified scope binds this exact store/job epoch through the same restore path; otherwise LIF-04 refuses protected resume/reclaim and retains uncertain effect/permit for reconciliation. OPS-11 due basis is separate; if unevaluable, LIF-02 limits only enrolled dependent claims. Unrelated claims/candidates continue. Independent safe transitions use their own durable path or stay pending; unfenced provider effect is indeterminate.

**mechanism_ids.**

- S16-M2

**specific_steps.**

- Rebind backend/clock; separately bind OPS-11 due owner, interpretation/zone, source/uncertainty, cadence/cutoff.

- Atomically grant/renew/reclaim durable attempt; test restore monotonicity with old worker alive.

- OPS-12 gets fence credit only for verified exact store/epoch restore binding; otherwise refuse protected resume. Fence local/sink writes or reconcile indeterminate effect.

- Test skew, step, restart, partition, restore and safe cancel/revoke during store loss.

- Cross OPS-11 due under clock/store outage with heartbeat intact; query fresh LIF-04/OPS-03 and affected/unrelated LIF-02 readers.

**authority_time_status.**

M2: backend owns lease; OPS-11 owns due basis; LIF-02 scopes effect to enrolled claims. CTM/source/effective/known-at stay distinct.

**external_inputs.**

- Backend owner: clock, hosts, restore path and durable generation semantics.

- Provider: receiver fence or idempotency/reconciliation contract.

- Custody owner: due interpretation/source/uncertainty/cadence/cutoff and dependent-claim enrollment.

**unresolved_research.**

Qualify actual backend/restore path and sink before fencing claims. Without proof, refuse protected resume and preserve indeterminate state; unknown due affects enrolled claims only. No universal clock needed.

**Изменения существующих задач и различающие проверки.**

- **task_id**: LIF-04
- **role**: primary writer
- **delta**: Prove monotonic attempt across exact restore path or refuse resume/reclaim; preserve R16/R17 cancel/effect recovery.
- **positive**: Old completion fails; unknown effect holds permit; safe independent cancel may proceed.
- **adversarial**: Restore 8→7 while worker/effect 7 lives.
- **removal**: Drop restore fence, keep markers: stale write; drop reconciliation: blind retry.

- **task_id**: OPS-04
- **role**: consumer
- **delta**: Supervise same ControlWorker/ControlPlaneStore lease; no queue.
- **positive**: Restart claims same durable owner; fresh API reads result.
- **adversarial**: Skewed/disconnected worker claims completion.
- **removal**: Drop shared lease, keep health; stale runner admitted.

- **task_id**: OPS-03
- **role**: consumer
- **delta**: Expose worker lease/store readiness, distinct from OPS-11 due and LIF-02 status.
- **positive**: Store loss degrades dependent readiness; unknown due limits enrolled claims.
- **adversarial**: Heartbeat fresh across due with no proof.
- **removal**: Drop live lease read, keep health; profile appears ready.

- **task_id**: LIF-06
- **role**: consumer
- **delta**: Permit lifetime follows process/effect through R16 nested and R17 duty work.
- **positive**: No double admission before exit/reconcile.
- **adversarial**: Clock jump frees permit while worker lives.
- **removal**: Drop reconciliation, keep TTL; usage diverges.

- **task_id**: OPS-12
- **role**: input collection
- **delta**: Offline rights/anti-rollback is not runtime fencing absent exact verified store/job-epoch and restore-path binding.
- **positive**: Exact binding proves restore generation; else resume refuses.
- **adversarial**: Offline rollback marker stays while runtime row rewinds.
- **removal**: Drop exact binding, keep markers; LIF-04 refuses, not fences.

- **task_id**: CAP-04
- **role**: assurance
- **delta**: Keep source-native position distinct from lease expiry and OPS-11 duty due; unknown due scopes only enrolled claims.
- **positive**: Late event keeps source/known-at cut, separate from attempt/due.
- **adversarial**: Wall clock/heartbeat hides omission or false coverage.
- **removal**: Drop source identity, keep timestamp; stale head passes; source time cannot replace due.

- **task_id**: OPS-11
- **role**: input collection
- **delta**: Bind due owner, instant/civil interpretation/zone, source/uncertainty, cadence/cutoff separately from lease time.
- **positive**: Reader evaluates covered duty on selected basis.
- **adversarial**: Outage crosses due with owner/heartbeat intact.
- **removal**: Drop due/source binding, keep text; no timely-coverage proof.

- **task_id**: LIF-02
- **role**: consumer
- **delta**: Limit only claims enrolled and dependent on missed/unevaluable duty; no global downgrade.
- **positive**: Affected enrolled claims limit; unrelated/candidates continue.
- **adversarial**: Outage emits no overdue event.
- **removal**: Drop due/enrollment reaction, keep labels; readers fail to diverge.

## self_attack

- **case**: Saturated service accepts new signature despite no future duty slot.
- **repair_or_bounded_limit**: Pre-admit measured bounded coverage or refuse with gap/authorized cutoff; keep candidates/unrelated claims.

- **case**: Restore rewinds 8→7 while worker/effect 7 lives; OPS-12 scope is offline only.
- **repair_or_bounded_limit**: Require exact runtime binding; else refuse protected resume, retain permit and reconcile.

- **case**: Duty crosses due during outage; heartbeat remains and no overdue event emits.
- **repair_or_bounded_limit**: Limit enrolled dependent claims only; missing event is not coverage; keep time roles distinct.

## limits

- Static design only; runtime admission/clock/enforcement/restore tests remain UNRUN.

- Source uses app UTC for lease checks and local monotonic for maintenance; no universal bug or clock claim.

- LIF/OPS/R16/R17 retain duty, reserve, cancel, nested accounting, currentness and offline cutoff; no new scheduler/status/clock service. OPS-12 is conditional.

- No numeric quota, weights, SLO, cost or skew tolerance; no universal clock or production RPO/RTO claim.
