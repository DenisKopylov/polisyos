Статус: выбранные направления для реализации после фактической приёмки E02. Это документация, не product PASS, не acceptance/closure и не ратификация SDD.

Имена полей/артефактов ниже задают семантические обязанности и минимальные связи. Окончательные DTO, owner и версии связываются с принятым E02 source; существующие owners/registries расширяются без параллельных систем. Статические наблюдения не доказывают runtime absence или PASS.

## shared_authority_time_status

Across all questions, software/version/provenance is evidence about operation, not policy/source authority. Supplier facts are institutionally_supplied and need content/scope reconciliation; trust claims need verifier provenance. Bind valid/effective/recorded/retrieved/observed/known-at separately with audience. Unknown grounds limit affected protected use; scoped candidate work may continue. Historical reproducibility is not current admissibility. Emergency authority must resolve from current OPS-01 grant/delegation, not a role name. Policy succession remains institutionally grounded under R17 D4.

## shared_contract

For each selected operation/cell/call bind exact software subject, version/provenance/verifier, profile/config, loaded generation, relevant runtime/API/worker/schema/state/dependencies, migration/trust/rights/rule generation, purpose/audience and effective/observed/known-at times. Include only selected deployment boundaries: OPS-09 site worker, OPS-10 remote CAS, CAP-06 remote effect/recipient, OPS-12 offline bundle; DES-09 actual provider call. Persist receipt→bridge→fresh consumer; unknown selected edges are not empty. Owner status gives exact basis/limit; markers, aliases and self-report are not proof.

## shared_unrun

All cited OPS/CAP/LIF/DES product verification is UNRUN/planned_after_E02_acceptance at baseline. Acceptance needs accepted-source rebind and selected producer→persisted receipt→bridge→fresh consumer; exercise only selected OPS-09/10/CAP-06/12 boundaries and an emergency test varying only resolved OPS-01 delegation. Static proposal, not product PASS.

## R18-D17-Q01. Состав совместимого выпуска

Какие сочетания версии пакета/сервиса, API и ABI, persisted/runtime-state схем, runtime и worker, connector, method/plugin, model artifact/provider profile и правил допускают конкретные операции: новый запуск, чтение, продолжение, replay или rollback? Где задаётся поддерживаемая совместимость для каждого такого сочетания, включая независимо выпущенные компоненты?

**Выбранное решение.**

Считать совместимость для actual dependency closure каждого start/read/resume/replay/rollback, а не Cartesian product. Version namespaces остаются за owners; composition сверяет реальные state/API/ABI/runtime/worker/plugin/connector/model/rule relations и нужные cross-owner pairs. В выбранном profile добавлять только его actual boundary: OPS-09 hybrid site worker; OPS-10 remote CAS; CAP-06 remote effect/recipient; OPS-12 offline bundle/import; DES-09 фактический provider call. Не выбранные tiers не активируются и не наследуют parity. Unknown selected edge ограничивает только dependent protected operation. Read может быть historical; resume требует exact checkpoint/state law; replay различает deterministic rerun, recorded response и новый stochastic/provider call; rollback только если прежняя пара читает записанные bytes и не возвращает новые rights. SemVer/schema range/release fragment сами по себе свойства не доказывают. Механизм: S17-M1/M2/M4.

**mechanism_ids.**

- S17-M1

- S17-M2

- S17-M4

**specific_steps.**

- Resolve owner-derived dependency closure from actual profile/job/manifest/loaded registry; include only selected deployment boundaries and retain unknown dynamic inputs.

- Check exact writer→reader/state/migration direction and selected hybrid/CAS/remote-effect/offline interactions.

- Persist exact version/provenance/rule/time refs; fresh consumer reads decision and limits.

**authority_time_status.**

Shared authority/time; unknown loaded/model version = not_established.

**external_inputs.**

- Upstream compatibility обещания и фактические resolved model/plugin/connector версии.

- Реально оставленные reader/writer/artifacts и выбранный профиль.

**unresolved_research.**

Универсального окна версий не обосновано. После E02 rebind посчитать только actual retained versions selected profile и проверить operation-specific cross-owner pairs; полнота hidden provider/build inputs остаётся bounded limitation.

**Изменения существующих задач и различающие проверки.**

- **task_id**: OPS-05
- **role**: primary writer
- **delta**: Bind migration support to actual state dialects/readers and direction.
- **positive**: Each selected live reader consumes supported old/new bytes.
- **adversarial**: New bytes exist but strict old reader remains; N−1 label is green.
- **removal**: Drop real read check but keep version marker: fresh restore refuses/quarantines.

- **task_id**: OPS-04
- **role**: primary writer
- **delta**: Check actual API/worker/handler mix under non-atomic rollout.
- **positive**: Authorized job persists a result readable by fresh API.
- **adversarial**: Old worker accepts new state/handler under same FQN.
- **removal**: Drop dispatch gate but keep profile label: affected operation becomes unready.

- **task_id**: LIF-07
- **role**: consumer
- **delta**: Bind executable/model influence separately from current-use right.
- **positive**: Changed used code changes identity/recompute; unrelated artifact is reused.
- **adversarial**: Same ABI/FQN hides changed semantics; old cache still appears current.
- **removal**: Drop dependency edge but keep field: fresh reader misses/limits.

- **task_id**: OPS-09
- **role**: primary writer
- **delta**: Only if hybrid selected: qualify actual site-worker contract/generation and bounded source-side output.
- **positive**: Selected worker returns a permitted output/receipt under its qualified contract.

- **task_id**: OPS-10

- **delta**: Only if remote CAS selected: qualify adapter owner, bytes, version and restore/read path.
- **positive**: Fresh remote reader returns exact permitted older/newer object under qualified adapter.
- **adversarial**: Backend label unchanged; adapter returns stale version or wrong cell object.
- **removal**: Drop adapter/read/restore conformance but keep backend enum: remote read quarantines.

- **task_id**: CAP-06

- **positive**: Same operation receives a validated receipt for the authorized recipient.

- **task_id**: OPS-12
- **role**: consumer
- **delta**: Only if offline selected: bind local bundle generation, import and explicit as_of/anti-rollback.
- **positive**: Protected read/resume is supported by the imported local generation and cutoff.
- **adversarial**: Cloud is current while an offline cell restores an older VM/clock/bundle.
- **removal**: Drop generation/as_of check but keep bundle marker: local protected reader refuses.

## R18-D17-Q02. Окно смешанных версий

Какой период сосуществования старой и новой версии разрешён при rolling upgrade для API, workers, connectors/plugins, model providers, caches и persisted artifacts? Какие задания могут быть начаты, продолжены или завершены во время перехода, и какое состояние остаётся после частичного rollout, отмены, retry или отката?

**Выбранное решение.**

Нет общего времени или N-1 окна. Mixed state допустим, пока actual old/new readers, writers, state bytes, active attempts and consumers совместимы для выбранной operation; если выбраны hybrid/remote/offline paths, включить OPS-09/10/CAP-06/12 по их own contracts. OPS-05 expand→dual-compatible→verify→contract; OPS-04 pins attempts to execution generation. Неизвестный worker/adaptor limits только зависимые admissions. Cancel/lease expiry не доказывают stop provider; LIF-04 reconciles before retry. Rollback только если он читает записанное state и сохраняет rights; иначе forward repair/quarantine. См. S17-M4.

**mechanism_ids.**

- S17-M1

- S17-M2

- S17-M4

**specific_steps.**

- Read per-replica worker/API and only selected site/CAS/offline generation; for a selected offline operation bind the actual local bundle import generation/as_of and fresh local reader; retain exact rollout cohort.

- Pin attempts to valid lease/right/state cut; include selected remote-effect receipt.

- After cancel/indeterminate provider outcome, reconcile before retry; contract old generation only after actual readers/jobs drain.

**authority_time_status.**

Shared authority/time; bind generation, active lease, state cut and sent/not-sent/indeterminate effect; unknown drain limits that operation.

**external_inputs.**

- Operators disclose active processes and chosen deployment semantics.

- Provider supplies idempotency/lookup/cancel window; service owner supplies restore target.

**unresolved_research.**

Actual overlap duration depends on selected target and live attempts; determine with one selected transition after rebind, not a default duration.

**Изменения существующих задач и различающие проверки.**

- **task_id**: OPS-04
- **role**: primary writer
- **delta**: Test actual API/worker overlap plus OPS-09 site worker when hybrid is selected.
- **positive**: Allowed mixed-version job completes and fresh API reads it.
- **adversarial**: Old worker or selected site worker writes after schema migration; incompatible resume.
- **removal**: Drop generation check but keep green labels: admission fails.

- **task_id**: OPS-05
- **role**: primary writer
- **delta**: Check real reader/write/migration/rollback; include OPS-10 CAS or OPS-12 bundle only when selected.
- **positive**: New state remains readable by qualified rollback pair or held for forward repair.
- **adversarial**: New bytes exist; selected remote/offline reader cannot parse or qualify them.
- **removal**: Drop restore round-trip but keep migration version: restore stays quarantined.

- **task_id**: LIF-04
- **role**: consumer
- **delta**: Keep attempts, remote receipts and cancellation distinct across rollout.
- **positive**: Restart recovers one reconciled effect without losing duty.
- **adversarial**: Reply lost; blind retry follows idempotency expiry.
- **removal**: Drop remote reconciliation: recovery reader refuses success/retry.

- **task_id**: CAP-06
- **role**: input collection
- **delta**: Only for selected remote execution: retain permission, recipient and sent/not-sent/indeterminate receipt across rollout.
- **positive**: Same authorized operation resumes after reconciliation without duplicate or lost effect.
- **adversarial**: Recipient/rights change during mixed rollout after a remote request was sent.
- **removal**: Remove receipt/recipient recheck but keep attempt ID: recovery remains indeterminate/refused.

- **task_id**: OPS-12
- **role**: consumer
- **delta**: Only when offline is selected for this operation, bind the exact bundle and actual local import generation/as_of to a fresh local reader; runtime/cloud currentness is separate.
- **positive**: Hold cloud/API state fixed; after the selected bundle is actually imported, its exact local generation/as_of and fresh reader support the operation.
- **adversarial**: Cloud/API is current but the selected offline cell still has the old bundle; its protected read remains limited/not current.
- **removal**: Remove local import/as_of or fresh-reader binding while retaining runtime-current markers: the offline operation cannot read green.

## R18-D17-Q05. Срочный security patch

Как определяется и уполномочивается срочная реакция, когда уязвимость или компрометация затрагивает уже установленный компонент, normal release freeze действует, а последний rollback target тоже уязвим? Какие действия допустимы для затронутых jobs и offline cells до доставки исправления, и какая evidence/compatibility basis нужна для ускоренной promotion?

**Выбранное решение.**

Emergency path reuses fail-closed supply-chain/canary owners, but exception authority must resolve from the current OPS-01 commissioned grant/delegation: exact temporary technical actions, affected uses, audience and expiry. A named security/release/service owner alone cannot suspend the institution policy or widen audience. Without delegation, contain only PolicyOS’s affected protected use and keep unrelated/candidate work available. Verify advisory/range against deployed SBOM/digest/readback; patch still needs trusted provenance and selected reader/state proof. Vulnerable rollback is prohibited for affected protected paths; isolate, forward-patch or quarantine. For a selected offline use, status changes only after OPS-12 binds the actual signed bundle import, local monotonic generation/as_of and fresh local reader; cloud/API patch status is not install proof. LIF-04 reconciles in-flight effects; claim impact routes S14 D14-Q02, policy succession R17 D4. See S17-M5.

**mechanism_ids.**

- S17-M5

- S17-M4

- S17-M2

**specific_steps.**

- Verify alert issuer/range and deployed digests; resolve OPS-01 grant/delegation for exact emergency action, audience, affected use and expiry.

- If delegated, record bounded exception; otherwise suspend only the affected PolicyOS protected use. Do not convert this hold into an institution-wide stop.

- Canary/forward patch within scope; reconcile effects. If offline is selected, use OPS-12 to bind actual local bundle import/generation/as_of and a fresh local protected reader before changing that cell status; then expire the exception.

**authority_time_status.**

Shared authority/time; reconcile advisory to deployed digest; exception has named owner/expiry. Claim reaction routes S14; succession R17 D4.

**external_inputs.**

- Supplier/CERT provides verified affected range; OPS-01 record supplies currently effective delegated actions/scope/audience/expiry.

- Security/release owner supplies urgency and patch choice only within that grant; unknown authority limits broader action.

- Offline operator supplies local import/freshness evidence.

**unresolved_research.**

No universal severity→deadline conversion. Where exact impact or inventory unknown, limit that scope; no unsafe rollback or all-system stop by default.

**Изменения существующих задач и различающие проверки.**

- **task_id**: OPS-05
- **role**: assurance
- **delta**: Keep selected reader/migration/restore quarantine checks on emergency patch.
- **positive**: Forward repair or compatible restore enables fresh protected read.
- **adversarial**: Only rollback image is vulnerable; old snapshot lost rights revocation.
- **removal**: Remove real rights/readability reconciliation: restore stays quarantined.

- **task_id**: OPS-11
- **role**: input collection

- **adversarial**: Compromised root self-signs successor, or OPS-11 is misused as institution delegation.
- **removal**: Remove independent recovery check: signature markers alone fail.

- **task_id**: LIF-04
- **role**: consumer

- **positive**: Confirmed effect survives restart; future effect remains held.

## R18-D17-Q07. Повторная приёмка после обновления

Какая часть existing commissioning receipt остаётся применимой после выпуска новой версии, и какие изменения требуют нового подтверждения оператора или институционального владельца? Как это различается для обычного cloud rollout, локальной установки и выбранного air-gapped profile?

**Выбранное решение.**

Каждый новый digest требует linked technical transition/commissioning receipt. Текущий OPS-01 grant/delegation может заранее покрывать compatible same-scope routine/emergency updates; тогда новая версия не требует повторного внешнего approval. Новый competent-owner approval нужен только при фактическом изменении гранта/recipient/egress, model/provider, trust root, secrets, retention/copies, schema recovery, locality, audience или service target за пределами разрешенного envelope. SemVer не решает. Локальная receipt не доказывает cloud/hybrid/offline parity; selected OPS-09 site, OPS-10 CAS, CAP-06 recipient/effect and OPS-12 offline owners confirm only their chosen boundary. Vendor EOL/security prompts review, not automatic consent. См. S17-M2/M5.

**mechanism_ids.**

- S17-M5

- S17-M2

- S17-M1

**specific_steps.**

- Compare new digest/profile with parent receipt and exact changed behavior/scope.

- If within preauthorized envelope, write linked release transition receipt and get selected operator action plus fresh per-instance readback.

- If an external right/custody/target changed, hold only dependent operations for that owner and recommission only selected cell/profile.

**authority_time_status.**

Shared authority/time; software receipt does not renew rights; separate approval-effective, release, install and observed times.

**external_inputs.**

- Institution defines delegated release changes and authority reapproval scope.

- Each selected site/cloud/offline owner confirms actual rollout/targets and local custody facts.

**unresolved_research.**

Whether a change requires renewed approval depends on selected grant, legal scope and operator delegation; no universal per-version rule. Material external-boundary changes go to competent owner.

**Изменения существующих задач и различающие проверки.**

- **task_id**: OPS-01
- **role**: primary writer
- **delta**: Bind child receipt to exact prior grant/delegation and new digest; distinguish preauthorized rollout from changed external scope.
- **positive**: Same-scope patch fits resolved delegation; changed audience/recipient/authority boundary holds for competent owner.
- **adversarial**: Same SemVer changes recipient/purpose/root beyond delegated scope but inherits approval.
- **removal**: Drop changed-scope comparison but keep receipt IDs: fresh commissioning refuses only uncovered action.

- **task_id**: OPS-03
- **role**: consumer
- **delta**: Admit from observed selected profile, not desired config.
- **positive**: Only observed selected cells become ready.
- **adversarial**: Cloud desired state is green; one replica remains stale.
- **removal**: Drop generation readback but keep health fields: readiness fails.

- **task_id**: OPS-12
- **role**: consumer
- **delta**: If offline selected, verify local signed monotonic bundle/as_of and operator receipt.
- **positive**: Local update appears only after actual import/readback.
- **adversarial**: Cloud is green; offline cell runs old VM/clock.
- **removal**: Drop anti-rollback check: local protected reader refuses.
