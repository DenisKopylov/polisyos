## Findings

1. **HIGH — UI-02 appointment/PR1 band conflation.** **P40: same P05 class, one level deeper (data-only versus pilot-grade gate).** Anchor: `atlas_public-proposal.json:189,212–217,223–225,228`. The row correctly says a signer is not needed to build the capability, but it then says the data-only record is issued “under signer policy,” places signer/holder appointment in the external-input list, and groups it with the record gate. Counterexample: the data-only `GY-PR1a` path is ready while no institutional appointment exists; the page can still issue that permitted record with the signer slot empty. Source: master plan §8.5 lines 214 and 1761–1770; current inventory lines 47 and 60. **Correction:** state three independent predicates across the whole row: capability/refusal surface; data-only issue after applicable `PR1a` evidence, without appointment; pilot-grade/signature claim only after `PR1b` plus the actual applicable signer/holder mandate. Keep appointment out of the data-only gate.

2. **HIGH — UI-12 maps test failures to environment blockage and narrows the valid topology to cloud.** **P40: same P38 proxy/status class.** Anchor: `atlas_data-proposal.json:570,592–595,622–627,629+`. The proposal makes a Cloud PostgreSQL DSN/identity a required input and says “any skip” or any non-green four-case run is `environment_blocked`. Counterexample: a commissioned local real-PostgreSQL run executes all four cases and exposes two replay winners; that is a failed property (`FAIL`), not an unavailable environment. A skip can be environment-blocked only when a preflight establishes that the required environment was unavailable before the case ran; an unexplained skip/missing case is `UNRUN` (or `FAIL` if the harness claims completion). The historical cloud-verification owner is a route, not the database property: master plan line 732; the reconciled debt row says it records only the foreign owner and does not specify the property/closure (`inventory/debt-inventory.json:6909–6937`). **Correction:** allow any commissioned real PostgreSQL profile; classify only pre-execution environment unavailability as `environment_blocked`; preserve assertion failures as `FAIL` and incomplete/skip evidence as `UNRUN`. Pin cloud identity only when cloud is the selected profile. PostgreSQL 18’s documented Read Committed predicate recheck supports the mechanism but does not require cloud topology ([version-pinned PG 18 docs](https://www.postgresql.org/docs/18/transaction-iso.html)).

3. **HIGH — UI-08 assigns persistence to the readout.** **P40: same P27 owner-bypass class.** Anchor: `atlas_data-proposal.json:367–371`, especially step 2 (“Persist causal record…”). Counterexample: UI-08 writes a record/head while GY-O3 also owns versioned `WorldModelRecord` write-back, producing competing world histories or freshness decisions. The preferred solution and alternative at lines 340 and 383–384 correctly assign the one branch/write-back to O1/O3; the implementation step contradicts them and the source task’s “no implied second world or merge” (`workstreams/04-atlas.md:60,126`). **Correction:** O1/O3 emit and persist the causal/world artifacts; UI-08 consumes those exact artifacts and persists no world state. If a projection/audit receipt is needed, keep it in its existing owner and do not make it a second causal record.

4. **MEDIUM — UI-17 hides an otherwise valid VOI value when acquisition cost is unknown.** **P40: same P10 semantic-conflation class, at the display gate.** Anchor: `atlas_data-proposal.json:792–823`, especially step 4; cross-check `inventory/debt-inventory.json:6283–6303` and `execution/07-scoped-readiness.md:37`. The preferred solution and composition contract correctly separate producer-backed VOI from cost, but step 4 disables the numeric claim if *cost* is absent. Counterexample: DS15 emits a valid numeric expected-decision-value/VOI ref and basis while its route-specific cost schedule is unresolved; suppressing VOI falsely reports the metric as unavailable. **Correction:** independently gate VOI on its own producer/ref/basis/currentness; show cost as `unknown`; do not calculate net value, authorize acquisition, or claim a positive route until cost and any required utility/rights inputs are available. The scoped-readiness source explicitly says acquisition cost does not supply the VOI metric.

5. **MEDIUM — UI-02 public-page accessibility and audience checks are too weakly specified.** **P40: same public-surface adequacy class already handled more fully in UI-01/UI-04.** Anchor: `atlas_public-proposal.json:193,220`. “Retain/check” locale and plain-language posture does not preserve the task’s original public operational bar as an acceptance discriminator. Counterexample: the page is mobile-responsive and has a locale flag, but the citizen cannot reach status by keyboard or hear a refusal/currentness change with a screen reader; generic “plain-language” copy also changes the meaning of a limitation. Source: task `UI-02.positive`; `workstreams/04-atlas.md:81–89,93,124,132` (DS6 owns shared i18n). **Correction:** bind UI-02 to the actual-page checks already specified for this public surface: WCAG 2.2 AA, keyboard/focus, reflow/large text, screen-reader order and status, no color-only authority/currentness cue; English-authored primary, Ukrainian translation, Russian legacy-frozen; audience-qualified plain-language review without inferring comprehension. W3C defines testable AA criteria including 320 CSS-pixel reflow and assistive-technology status messages ([WCAG 2.2 Recommendation, fixed edition](https://www.w3.org/TR/2024/REC-WCAG22-20241212/)); DfE’s guidance ties plain language to user needs and research ([official guidance](https://design.education.gov.uk/content-design/plain-language)).

6. **MEDIUM — UI-07 delays interface-level preparation until the whole producer chain is accepted.** **P40: same false-sequencing class covered by the shared stage rule.** Anchor: `atlas_data-proposal.json:288–292`, step 1. “Wait for accepted N13b producer, persistence, orchestration, invalidation, and replay/re-entry evidence” places all contract/projection preparation after full producer readiness. Counterexample: owners agree the existing `DerivationRecipe`/`DerivationCertificate` contract, versions, fields and distinguishing oracle; UI can prepare the projection against that exact interface while the supplier completes persistence/re-entry. `execution/07-scoped-readiness.md:21–25` and `solutions/00-shared-decisions.md:69–72,91` expressly permit isolated prep after interface agreement while retaining real-producer/fresh-reader composition. **Correction:** permit contract comparison and isolated projection prep after recorded exact interface agreement; keep the actual accepted N13b event, persistence, invalidation, replay and fresh consumer as composed-acceptance gates. If semantics cannot be agreed, wait on that named unresolved predicate.

7. **LOW — UI-14 leaves content normalization and retained-manifest size ambiguous.** **P40: new, bounded exact-byte-parity ambiguity.** Anchor: `atlas_data-proposal.json:719,740–744,760–769`. “Normalized policy paths/content digests” could mean normalizing content before hashing, although step 3 correctly asks for path/byte comparison; the manifest could also become a redundant derived dump. Counterexample: a mirror differs in raw policy bytes but a content normalizer maps both versions to the same digest, so the parity gate stays green. **Correction:** normalize path spelling/order only; hash raw source and packaged file bytes. Retain a concise source-commit/chart-identity/parity receipt and deciding comparison output; retain a complete manifest only when needed to prove the full set, never another policy-content copy. This follows the shared receipt rule (`solutions/00-shared-decisions.md:73–77`).

8. **LOW — Two external technical citations are mutable/version-misaligned for replay.** **P40: same P07 source-version/replay class.** Anchor: `atlas_data-proposal.json` source entries `R13-ATLAS-PG-{ISOLATION,LOCKS,INSERT,UPDATE}` and `R13-ATLAS-HELM-PROVENANCE`. The PostgreSQL citations use `/docs/current/` while naming version 18; today that URL resolves to PostgreSQL 18, but follows “current” later. Helm’s current provenance page identifies itself as v4.3.1 and warns that it has not yet been updated for Helm 4, so it cannot support future version-specific command assumptions ([official Helm page](https://helm.sh/docs/topics/provenance/)). **Correction:** pin PostgreSQL claims to `/docs/18/`; pin Helm evidence to the actually selected deployment major or keep the claim explicitly limited to generic package checksum/signature integrity and verify against the deployed major. This is citation replay hygiene, not evidence the stated generic property is false today.

## Attacks cleared by the submitted text

- **UI-06/AQ1:** explicitly derives all eight current ceiling relations from the canonical owner, keeps set/interval/unknown/incomparable distinct, and gates actual quantity display on accepted DS7 value/basis. No scalarization gap found. OpenAPI 3.1.1 accurately says `discriminator` cannot alter validation and oneOf alternatives must be listed ([official spec](https://spec.openapis.org/oas/v3.1.1.html#discriminator-object)).
- **Authority and consultation:** UI-01/UI-10 consume server identity/verifier results; UI-04 separates formal acts, informal statements and PolicyOS reactions, preserves closed bytes/lineage, and forbids automatic dispute resolution or treating consultation as binding. It does not mislabel access-audit as the comment ledger.
- **Generated family and institutional boundary:** UI-20 regenerates the owner-defined API family, requires runtime evidence resolution, and explicitly says a private issuer supplies no institutional mandate/signature. TypeScript’s handbook confirms `private` is type-check-only and runtime lookup can access it ([official handbook](https://www.typescriptlang.org/docs/handbook/2/classes.html#caveats)); the proposal’s bounded claim is accurate.
- **No blanket platform/framework tax:** UI-03 reuses one index, UI-07 rejects a second provenance service, UI-14 keeps ops/deploy ownership and can retire the mirror, and UI-15 proposes an owner decision rather than a new site/CMS. UI-08 rejects a second world-write path in its alternative (but step 2 above still needs correction).
- **DS19 denominator:** UI-09 covers all four register arrays and treats the 85-row auxiliary map as assignment/conflict input, not accepted closure. The notes supply the JSON path/file denominator and the map SHA/observation commit; 179/138 are overlapping dimensions, not a total.
