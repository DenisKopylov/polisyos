## Bounded implementation slices

### CAP-01 — Exact-source reconciliation and candidate discovery

**Goal / owners.** Reuse preseed catalog modules and runtime `SemanticDatasetCatalog`/planner to resolve a declared evidence gap into a candidate set, then route only an exact, source-bound candidate to the appropriate existing producer. Reconcile source IDs, profile/schema, selector and requested time before admitting a candidate. A discovery prompt, model response, search hit, or registry row is never an admitted source. Source identity and connector selection stay in existing registries/owner APIs; do not add a parallel global list.

**Boundary and typed data.** Keep `DatasetResolutionPlan`, `DatasetDiscoveryCandidate`, `SourceContract`, `CatalogFetchRequest` and `CatalogFetchBinding` as existing types. Where missing, add a strict candidate receipt at the discovery/owner boundary only after A0 selects its owner: input gap/ref and requested scope; candidate source + contract revision; discovery method/provider/model trace if used; selector/profile/schema; recorded time; declared assumptions; status candidate/ambiguous/unavailable. Fields that decide authority, permission or completeness must be resolved from owner evidence, not copied from candidate prose. Do not turn unresolved source-right questions into defaults.

**Bridge and result.** Feed the resolved candidate into the existing source-specific producer and persist the discovery/candidate receipt beside the acquisition journal. Consumers receive the exact resolution and reason/status; no silent “best match.” Include a user/audit/API surface that distinguishes `candidate`, `ambiguous`, `not_admitted`, and resolved owner receipt. Use the located `runtime/http/services/acquisition_action_service.py::AcquisitionActionService` and production execution port; A0 rebinds them and identifies only the remaining generic planner/reuse gap.

**Acceptance.** Positive: a preseed candidate and a runtime candidate for the same exact source/profile converge on a single owner resolution and produce the same candidate basis; after owner admission, consumer can resolve exact source/profile. Adversarial: ambiguous selector, stale contract revision, fake source ID, LLM-injected URL, candidate with self-asserted license, or “no hit” all stay non-authoritative and do not call a live connector. Removal: delete the source/contract/profile binding while retaining DTO field names and a “resolved” marker; owner resolution must fail and consumer must not receive data. Assert the full path from a gap through persisted candidate receipt to consumer/API, not just model/schema construction.

### CAP-02 — Shared capture, transport policy, and complete snapshot

**Goal / owners.** Establish one capture-and-reuse route for preseed/runtime inputs, starting with the R9 A1 bounded WDI response only after A0. Extend/wire `execute_live_catalog_acquisition`, connector observer/fetch contracts, `DataSnapshot`/`EvidenceBundle`, `ArtifactManifest`/`FileSystemCAS`, and cursor owner. Capture transport metadata and bytes as one immutable representation; consumer opens that exact root by content identity. HTTP redirects must be authorized hop-by-hop before each request; constrain DNS/IP, socket destination, proxy, credentials, scheme and redirect count under the approved connector policy. Validate decompressed size separately from wire bytes.

**Grounded protocol fields.** Reuse `CatalogContentIdentity(source_path, content_sha256, byte_size)`, `ArtifactRef`/manifest identity and existing `FetchResult` (`final_url`, `redirect_chain`, ETag/Last-Modified, content hash, `raw_artifact_ref`, fetch profile), IR pagination fields, `PartitionCursorState`, and `LiveSourceExecutionEvidence`. Add only owner-approved missing fields, likely: exact prior representation/ref for 304; requested/effective locator per hop; page/continuation and response completeness; profile/schema; expected previous frontier/attempt fence; measured wire/decompressed sizes; capture time. Do not call a page complete just because it is page 1, `max(offset)` is high, an ETag exists, or `total` matches a current response.

**304/range/pagination contract.** `304 Not Modified` can reuse only a retained exact representation whose bytes/hash/profile/source/permission binding resolve; absent or inaccessible body means `unavailable`, never an empty zero-row dataset. `206`/range requires a matching validator and byte interval, reassembled in order and verified against exact whole-representation identity; mismatches remain partial/unavailable. Cursor checkpoint and artifact head update must be one expected-head/fenced commit so an expired/stale attempt cannot publish. For sparse feeds, require native continuity/completeness evidence, not a dense-offset assumption. The current single-page WDI check remains fail-closed until a separately tested pagination contract supports more pages.

**Acceptance.** Positive: first allowed bounded capture produces a durable root/receipt; a second run uses the same exact root without refetch; verify body hash/profile/permission on resolve. Adversarial: crash after page before cursor, crash after cursor with unreadable child, timeout/partial body, total/pages mismatch, over-limit decompressed body, changed ETag with same URL, 304 without retained body, invalid range validator/gap/overlap, stale writer after a newer head, redirect to disallowed host/private IP or credential-forwarding hop, pagination continuation with changed selector. Removal: remove exact-body binding or expected-head fence while keeping checkpoint/ETag/status fields; negative path must stop being positive. Surface partial vs unavailable vs complete with exact reason and root; log denial without leaking restricted body. Include consumer read and audit receipt in the semantic probe.

### CAP-03 — Purpose-aware owner admission and immutable library promotion/reuse

**Goal / owners.** Make native owner admission the only bridge from captured root to reusable library. Reuse `build_admission_passport`, `admit_acquisition_with_semantic_epoch`, `revalidate_admission_passport`, `CanonicalAcquisitionAuthority.resolve_live_source_execution`, scoped `ArtifactManifest`, `FileSystemCAS`, and `CatalogFetchBinding`. A library is a content-addressed root plus append-only admission/reuse records; it is not a mutable “current CSV” directory or an assertion of rights.

**Admission facts.** Passport must resolve+bind+verify the exact retained root, source receipt, content hash, schema/profile and complete capture; recompute allowed purpose/audience/processing/retention from the appropriate owner evidence; and pin rule/schema version, authority purpose, provenance, recorded/effective time semantics and current review state. Keep factual truth, permission to process, and permission to publish as separate checks. Existing `LocalSourceRightsDeclaration` can supply only the scoped fact its owner actually vouches for; missing/exhausted/ambiguous evidence remains unadmitted. Never infer institutional identity, signer competence, rights scope or legal custody from a hash/signature field.

**Bridge and result.** Successful admission emits immutable owner receipt/event bound to root and purpose, then makes the root resolvable by exact identity through `CatalogFetchBinding`/the owning consumer. Reuse rechecks current purpose rights and profile without rewriting original capture. A second consumer cannot bypass admission by reading CAS directly; enforce at the class boundary (single intake/single governed read) or record the exact out-of-scope boundary. API/audit surface exposes admitted/limited/contested/blocked/unavailable reason, permission basis and as-of time without disclosing protected content.

**Acceptance.** Positive: admitted WDI root is promoted once and resolved by exact body on second use under an allowed purpose; same root under a fresh, allowed purpose is reused with a new permission decision and trace, no recapture. Adversarial: right absent/expired/revoked, purpose mismatch, wrong tenant/cell, changed content under same URL/ETag, substituted manifest/input, missing source-body verifier, stale passport, profile/schema mismatch, or permission changed between check and governed effect must deny or return bounded indeterminate. Removal: delete resolve+content-bind+verifier provenance while leaving `admitted`/`verified` labels and hash fields; promotion must fail. API test must consume the denial and not expose bytes.

### CAP-04 — Source update/retraction, dependency enrollment, and fresh projection

**Goal / owners.** Use exact admitted source roots as dependencies of the actual claim/decision owner. Wire source change/retraction and rights change through `ClaimDependencyFieldRegistry`/`ClaimDependencyDenominatorReceipt`/`ClaimLedgerOwnerPort`, `epoch_validity_cascade` producers, `DecisionValidityService`, append-only claim lifecycle, and publisher. The change source is an institutionally supplied or independently reconciled event only when that authority exists; otherwise preserve it as an unverified candidate and do not advance an authority-grade current projection. Change event identity, source generation, recorded/effective times, exact affected root/relation and audience must be kept distinct.

**Bridge and behavior.** Enroll source dependencies before relying on absence or current validity. A late, backdated or missed event invalidates/reissues only projections whose actual dependency denominator intersects the changed source; unrelated sources remain current. A scheduler-off consumer performs a fresh owner read/cut and refuses stale cached green. Historical publication stays append-only and authentic; current state becomes pending, limited, contested or blocked until reevaluated. Academic `_parse_retracted_ids` is a narrow work-ID implementation, not generic retraction; keep it as a source-specific adapter, not the lifecycle owner. Source change/correction must not itself assert legal consequence.

**Acceptance.** Positive: mutate an enrolled source generation and observe persisted event, scoped invalidation, fresh recomputed projection and audit/publication surface; an unrelated generation does not invalidate that claim. Adversarial: late/backdated event before enrollment, missing journal segment, event storm/lagging reverse index, stale root, rights update racing public commit, unrelated-source change, no scheduler, ambiguous relation. A committed result must have an owner witness/cut or explicit bounded limitation; double-read alone is not a fence. Removal: remove the generation/dependency relation but leave the event and “current” marker; fresh consumer must not remain green. Include a public projection/API that distinguishes historical validity from current status.

### CAP-05 — Official/legal source grounding and temporal relation

**Goal / owners.** Build a legal-source-specific adapter into the shared acquisition/admission path, not a parallel authority system. Reuse `require_legal_source_relation_verification`, Lex normpack applicability owner, cited source and claim types, `CitationRef`, and exact content/root. The system may establish that it captured a source and that a verifier produced a scoped relation result; it may not invent an official publisher, competent signatory, custody chain, legal force, interpretation, or notification recipient.

**Protocol boundary.** Keep source authenticity, legal relation, applicability, text/effective-time, translation, and policy claim support as separate typed evidence. Relation evidence should bind exact artifact/version/hash and the verifier/source of the attestation, jurisdiction/topic/scope if grounded, observed and effective time separately, original/translated occurrences, verification rule/version and explicit limitations. If an external authority fact or recipient is not supplied and verifiable, emit unresolved/limited/refusal; do not fill it with a URL, model inference, signature presence or metadata adjacency. Re-evaluation after changed/repealed/corrected text uses a new root/event and fresh applicability projection; preserve old bytes and historical decision.

**Acceptance.** Positive: known verified fixture relation yields a source-bound legal applicability result and citation surfaced to the consuming decision. Adversarial: spoofed official-looking URL, mismatched hash/version, unsigned or self-attested relation, wrong jurisdiction/effective interval, translation-only challenge, repeal/correction arriving late, unknown recipient, or valid signature with unverified relation all remain limited/refused as appropriate. Removal: remove verifier provenance/relation binding while preserving citation and “verified” marker; legal consumer must refuse admissibility. Surface exact source/version, relation status, time basis and limitation; do not publish restricted full text.

### CAP-06 — Restricted source handling and remote/private compute boundary

**Goal / owners.** Reuse `AccessScope`, `AuthzInput`, `classification_allowed`, scoped filesystem CAS, partitioned-ingestion plan, `AsyncFetchLease`, control-plane job/outbox and `ControlWorker` only as components of a source-root-bound operation. Make permission check before bytes leave a governed surface, bind execution to exact root/executable/recipient/purpose, and reconcile remote acceptance/completion/cancellation. This is an integration contract with external institutions/providers; PolicyOS owns its typed fail-closed evidence and resulting claims, not their sovereign grant or remote execution.

**Boundary/result.** Resolve source rights and target classification before network or derivative effects; record allowed/denied purpose, audience, tenant/cell, recipient and policy version. Remote job receipt binds exact input root hashes, executable/version, recipient/provider, idempotency key and request time; lost response, provider acceptance ambiguity, timeout or local lease loss produce `indeterminate/pending` until lookup/reconciliation, never asserted completion or cancellation. Data leaving local scope needs an explicit remote permission/result; no permission or credential may be inferred from local authz state. The checked factory’s tenant-scoped guarantee is filesystem-only; S3/GCS scoped support and remote parity remain separate mechanisms.

**Acceptance.** Positive: permitted synthetic source root and executable enter controlled provider fixture; receipt resolves to same input/executable/recipient; output is admitted only after owner validation and becomes a versioned artifact with permission lineage. Adversarial: denied/revoked grant before request, changed grant during stream, wrong tenant, restore after deletion, provider accepted/response lost, expired idempotency window, cancel before/after remote accept, local lease lost, output swapped, malicious recipient, or provider 429/shared credential overload. Remove permission check while retaining a green authorization label, or remove provider receipt content-binding while retaining IDs; boundary must reject. Surface actual recipient/input/executable and pending/indeterminate/denied/complete state, bounded for restricted audience.
