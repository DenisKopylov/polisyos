# Atlas v15 Adjudication

## Scope And Authority Boundary

This report adjudicates the sha256-frozen Atlas v15 archive against the
[living v4 baseline](./atlas-live-application-audit.md#sharedui-families-audited-12-of-12-owning-89-of-89-components)
and the [DS0 source decisions](../../brand/ATLAS_SOURCE_OF_TRUTH.md#d1---canonical-source-supersession-and-docs-lifecycle).
It is authoritative for DS2 adoption decisions and Phase-A planning input. It
may not be used as evidence that a component is integrated, browser-tested,
manually AT-tested, authority-compatible, publicly safe, package-publishable,
or production `stable`.

The archive itself makes the same essential limitation: its readiness overlay
is “ZIP/archive-level hardening only,” with product integration, runtime
browser checks, and manual assistive-technology validation deferred
(`BEST_IN_CLASS_READINESS.md:1-5`). DS2 preserves that limit even where an
archive report says `PASS` or a component manifest says `stable`.

## Conformance Battery

### Result

**Archive verification is internally useful but constitutionally
insufficient.** The 45 physical verification artifacts collapse by exact
content and generated-projection identity to 32 logical reports. DS2
classified **45 of 45 physical reports and 32 of 32 logical reports** before
assigning any token, component, or pattern verdict.

The archive's primary `scripts/verify.py` gate does not execute the product
package or a browser. It checks 33 artifacts for presence and ten report files
for pinned regular-expression markers, including a hard-coded expected
component count of 56 (`scripts/verify.py:7-25,36-52`). The full verifier does
execute 17 archive-local Python generators and linters and records exit codes
(`scripts/run_full_verify.py:9-31,42-67`), so it is stronger than presence
alone, but its outputs still prove only archive-local generator/linter
behavior. Neither path supplies PolicyOS repository integration, runtime
authority semantics, deployed performance, browser behavior, or manual AT.

The best-in-class report is even narrower: it marks 51 named documentation and
metadata paths `PASS` when present, then checks that the self-scored area list
is complete and the component-health count equals the same manifest
(`dist/verification/best-in-class-readiness-report.md:1-61`). Its `PASS`
cannot establish the truth, adoption, or effectiveness of those policies.

## Conformance Negative Controls

- Removing a runtime semantic while retaining the expected report marker can
  leave `scripts/verify.py` green; therefore its report is rejected as a repo
  gate under P29.
- Deleting a best-in-class policy's effectiveness while retaining its file can
  leave the readiness lint green; therefore presence is not adoption or
  maturity evidence.
- A manifest row and state-matrix row can agree while the component fails in a
  browser or launders a UI-local authority status; therefore matrix parity is
  retained only as an input to DS4/DS6.
- Numeric self-scores and component-health labels have producer provenance,
  not independent verifier provenance; they cannot raise maturity.
- Exact duplicate projections add zero independent evidence. They are retained
  in physical coverage but share one logical decision.

### Named mode and projection gaps

- Warm dark is the dominant value conflict: effective comparison is 21 exact,
  45 mismatched/conflicting, and eight missing registry variables. The archive
  cold blue-graphite palette cannot replace accepted ADR-047 warm-dark values.
- Live theme runtime supports persisted `light | dark | system` with resolved
  `data-theme`; v15 uses `auto`, CSS media, and `data-atlas-theme`, without
  equivalent storage hydration. A DS4 adapter is required.
- Density names align, but only comfortable spacing matches. Compact and
  condensed differ on all four live controlled spacing variables, and v15
  omits the live scale controls.
- Responsive sources contain mutually incompatible breakpoint systems and all
  29 responsive-source leaves are omitted from CSS/TS/Figma projection;
  Tailwind has no screens map.
- The data-viz substrate is substantial, but namespace drift remains and the
  blue secondary semantic conflicts with D02. DS16-specific gaps are described
  below.
- Manual high contrast, forced colors, reduced motion, and print each need a
  live-semantics adapter and DS6 evidence. Color-safe, large-text, and the three
  transparency variants remain deferred because no live consumer exists.

The sunset rule is uniform: the living v4 token path remains transitional
winner until DS4 generates the governed facade/CSS, binds consumers, reproduces
warm dark and runtime controls, and passes the existing drift gate plus DS6
mode evidence.

## DS16 And Other High-Risk Deltas

### Data visualization is not DS16 authority

The archive model is scalar and point-centric: `ChartPoint.value` is required;
`UncertaintyBand` always draws a midpoint and falls back from `low/high` to
`value`; no set/outer-set type exists; `unknown` and `incomparable` are not
first-class; and basis, deflator, derivation recipe, certificate binding, and
the required observed/derived/deployment-update provenance classes are absent.

The generic visualization grammar and most renderers are admitted only after
refactor as projection substrate. The current `UncertaintyBand` claim is
rejected as DS16 truth. Revisit requires runtime `ValueOuterSet`, basis and
certificate UI, provenance classes, unknown/incomparable rendering, and a
red-first negative proving a point estimate cannot silently collapse an outer
set.

### Responsive and package conflicts

The archive contains four incompatible breakpoint descriptions: five window
classes at 0/600/905/1240/1440; seven breakpoints at
0/520/760/980/1180/1440/1680; six at 0/480/760/981/1280/1680; and prose at
320/480/768/980/1280/1680. The taxonomy row is rejected as authority until DS4
selects one source and migrates every live consumer.

package is private `@policyos/atlas-ui@15.0.0` and `UNLICENSED`, while DS0 owns
private `@polisyos/atlas-ui@0.1.0`. The package tree has 535 files: 97 source

compiled trees have 398 byte-identical members and one generated-timestamp
delta; each compiled manifest has seven broken export targets caused by stale
`./dist/...` paths. Wholesale import and compiled mirrors are rejected. Only
selected source/build semantics may be refactored under the DS0 package home.
