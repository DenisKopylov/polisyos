# CTL-02 — содержательные даты и воспроизводимый RNG/checkpoint
## C16 · выпуск v014 · 31 октября 2026 года

**Исходные задачи:** B124/B125/B126. **Очередь:** LANE-02; следующий пакет — STP-01. Зависимость реализации от OPT-02 не отменена порядком read-only аудита. **Исследованный commit:** `20d9009be21097bfbdc38a546a15cc60213b8ace`. Репозиторий, проектные тесты, конфигурация, lockfiles и зависимости не изменялись.

## Решение по пакету

**Частично проверен; полное закрытие не заявлено.** Все три первоначальных механизма существенно изменены. В generic subject больше нет рекурсивного удаления дат по имени; Python RNG имеет версионный codec; Sobol сохраняет фиксированный seed, пространство, действительный backend/version, префикс и курсор. Положительные Python/SciPy/PyTorch проверки выполнены, включая запись JSON и чтение в отдельном процессе. Это исполнение пяти blob-сверенных модулей в изолированном пространстве импортов, не штатного установленного PolicyOS. [S01–S06; P01–P04, P07, P14–P17]

**C16-R01:** состояние с отсутствующим Sobol checkpoint сначала правильно ограничено, но повторный `get_state → JSON → set_state` превращает неизвестную историю в допустимую пустую последовательность. Ограничение совместимости не переживает собственную сериализацию. [P24–P27]

**C16-R02:** неполная проверка Python RNG перед изменением живого объекта. Неверный внутренний индекс доходит до `Random.setstate`, который меняет Gaussian-cache до отказа; NaN/inf в этом cache вообще принимаются. Это две проявленные части одного договора валидации/применения RNG, не повреждение всех случайных потоков. Uniform-vector в отказном примере остался прежним. [P11–P13]

Отдельно зафиксированы **C16-T01** — конфликт старых test_frontier-ожиданий с новой семантикой raw subject, и **C16-G01** — квадратичная подготовка Sobol-префикса при последовательном росте cache. Последнее — измеренная локальная цена подготовки, не заявление о времени работы всей системы. [P05, P28]

## 1. Исходные критерии и смысл для универсального проектирования

[Исходный E02](../05_Источники/CTL-02_исходные_строки.txt) требует сохранять предметные даты, отдельно учитывать известную служебную оболочку, восстанавливать Random через JSON и одну логическую Sobol-последовательность при разных формах запросов. Повреждённое или несовместимое состояние должно иметь точный исход; новое случайное исследование не называется replay старого.

Установка пользователя сохранена: LLM предлагает гипотезы и постановки, алгоритм предпочтителен там, где обеспечивает более универсальное и масштабируемое исполнение. CTL-02 не требует детерминированного генератора всех политик. Он обеспечивает более узкое свойство: изменение даты начала действия меняет исследуемый предмет, а техническое сохранение состояния не подменяет уже выбранный эксперимент другим.

## 3. B124: даты уже не исчезают из предмета

`frontier.py` не содержит старого рекурсивного `_strip_volatile_candidate_fields`. `policy_candidate_hash` для обычного dict проверяет JSON-native форму и хэширует весь предмет. Название `timestamp`, `created_at`, `_starts_at`, `_strategy_metadata` само по себе не делает значение служебным. Предложение с типизированным `CandidateStrategyContext` разделяет subject и пять поддержанных transport fields. Перед использованием hash проверяется, что материализованный payload совпадает с subject; чужой explicit/metadata hash не заменяет пересчитанную идентичность. [S01, S06]

P01 изменил только `semantic.interventions[0].starts_at`. Получены разные hash и два элемента фронта при векторах `(0,10)` и `(10,0)`. P02 сохранил различимость пяти подозрительных по названию ключей и инвариантность к порядку ключей JSON. P03 показал, что изменение объявленного transport-ID и service iteration не меняет предмет. P04 отверг неизвестную `CandidateProposal.metadata.created_at` и не-JSON значения, не удалив их молча. P06 вернул старое suffix-stripping только в контроле — даты снова слились. [P01–P06]

**Не нужно требовать, чтобы raw dict автоматически игнорировал любой created_at.** Такой dict в нынешнем контракте сам является предметом. Роль даты определяется действительным producer/schema, а не суффиксом. Объявленную дату регистрации можно вынести в поддержанную внешнюю запись, но нельзя присвоить такую роль произвольному полю задним числом. Отказ неподдержанной metadata — не доказательство, что продукт умеет все необходимые transport-времена; эту более широкую возможность здесь не заявляем.

### C16-T01: две несовместимые семьи ожиданий в тестах

`tests/unit/scientist/search/test_frontier.py` по-прежнему требует одинаковый hash для разных `trace_id`, `_debug`, metadata.generated_at и `_strategy_metadata` в **сыром dict**, а его dedupe-test ожидает одну запись для разных raw trace_id. Полный текущий helper делает противоположное. P05 получил разные hash и два элемента; это адресное исполнение механизма, **не свежий запуск project pytest**. [S07]

Более новый `test_candidate_identity_semantics.py` специально требует сохранения raw `_starts_at`, `execution.created_at`, `__user_input`, `_strategy_metadata.seed`, а одинаковость transport-ID проверяет через `CandidateStrategyContext`. Он также включает более сильные source/registry tests; эти downstream части здесь только прочитаны в указанном диапазоне. [S08]

Ремонт tests должен сохранить различие двух ролей. Не возвращать старое общее стирание ради зелёного теста и не удалять содержательные проверки дат. Для технической оболочки использовать настоящий поддержанный контракт. Наличие file-name `test_ctl_02.py` не критерий: предложенный E02 файл на SHA не найден (404), но адресные тесты существуют у текущих владельцев.

## 4. B125: обычное восстановление Random работает

`get_state` сериализует Python state как объект с codec/version и отдельными полями vector/gauss_next. Decoder восстанавливает только требуемый tuple vector; arbitrary metadata остаётся своей структурой. В основной проверке после нескольких вызовов Random и одного gauss совпали следующие восемь uniform-чисел и сохранённое следующее Gaussian-значение. Непустые model bytes и вложенный metadata-list пережили сериализацию. [S02, S03; P07–P08]

Некорректные codec/version, длина vector, булево gauss_next и отсутствие Python state дают точные отказы без изменения target в проверенных случаях. Чужая strategy identity отвергается раньше. Поддержанный direct legacy tuple позволяет продолжить Python stream; его старое unversioned JSON-представление не принимается как будто совместимое. [P09–P10, P31–P32]

### C16-R02a: отказ не атомарен для Gaussian-cache

Место: `base.py:_validate_python_random_state`, строки 438–460, и `BaseSearchStrategy.set_state`, строки 117–200.

Последний элемент внутреннего Python state — индекс; собственный validator проверяет его тем же диапазоном `0 <= item < 2**32`, что и слова состояния. Значение **625** проходит эту проверку, но реальный native setter отвергает его. Перед вызовом native setter `random.Random.setstate` уже присваивает `gauss_next`. Этот порядок прочитан и в официальном CPython 3.14, но весь опыт исполнен в 3.13.5. [E02; P12]

| Поле | До неудачного restore | После отказа |
|---|---:|---:|
| Gaussian-cache | −0.4006425444330575 | **777.0** |
| Следующий `gauss(0,1)` | Должен продолжить старый cache | **777.0** |
| Uniform-vector | Исходный | Не изменился |
| Iteration | 0 | Не изменился |
| Ответ `set_state` | — | `ValueError: invalid state` |

Таким образом, вызывающий получает отказ, но живой объект уже не эквивалентен прежнему. **Не установлено**, что штатный поиск уже потребляет `.gauss` или что испорчен его обычный `.random`-поток: RandomSearchStrategy использует именно `.random`. Это подтверждённая локальная ошибка атомарности поддерживаемого RNG-state, не доказанный неверный выбор политики.

### C16-R02b: нечисловой Gaussian-cache принимается

`gauss_next` проверяется на int/float, но не на finite. Вызовы через настоящий `StrategyState.to_artifact/from_artifact` приняли NaN, +inf и −inf; следующий настоящий `.gauss(0,1)` вернул соответствующее нечисловое значение. JSON default Python сохраняет такие токены в данном serializer; реальный CAS и его более строгие правила не запускались. Нельзя заключать, что такая запись прошла production-хранилище. [P11]

**Severity: medium, условно на повреждённом checkpoint и использовании Gaussian-state; confidence high для локального механизма.** Направление — полный schema-specific validator (в том числе final index и конечность cache), затем применение только после проверки на временном Random либо эквивалентная атомарная процедура. Не пересевать генератор молча и не заменять ошибочный cache нулём. P13 на временном native RNG сохранил target неизменным при том же отказе; это direction-control, не product-патч.

## 5. B126: нынешний обычный поток уже воспроизводим

`_sobol_candidate` использует один `_sobol_seed`, проверяет весь прежний префикс и actual sampler identity/version. Checkpoint содержит codec и algorithm version, пространство, dimension, seed, fallback/scramble, cursor и cache. В restore сначала воспроизводится ожидаемый префикс и проверяется **действительный** backend — одной импортируемости зависимости недостаточно. [S02, S04]

**Исполненные положительные проверки:**

- SciPy 1.17.0: восемь поштучных запросов совпали с одним запросом восьмого индекса и последующим чтением всех точек; после checkpoint совпала следующая точка.
- PyTorch 2.10.0+cpu: тот же контроль прошёл на настоящем SobolEngine, один CPU-thread.
- Для каждой библиотеки JSON был записан во временный файл, затем прочитан отдельным subprocess. Совпали следующая Sobol-точка, восемь uniform-чисел и Gaussian-cache. Это новый процесс **изолированного source-profile**, не независимый установленный PolicyOS.
- Mixed integer/categorical/log-space сохранил параметры и relaxed-vector после replay; канонизацию discrete execution этот опыт не переаттестовывает (OPT-02).

[P14–P18]

Негативные контроли отвергли другую область при той же размерности, cursor/cache mismatch, другой backend/version, изменённый префикс, неизвестный codec и чужую стратегию. При контролируемом runtime failure torch использовался настоящий SciPy и записывалась его идентичность. При дополнительно недоступном SciPy сработал настоящий Python Random; checkpoint явно сообщил `fallback=true, scramble=false`. Возвращение другого backend не стало скрытым replay. [P19–P23, P31]

Сохраняется разграничение: одинаковый воспроизводимый префикс не доказывает независимость реплик, качество GP или статистическую эффективность оптимизации. Для неполного Sobol-префикса не заявлены balance-гарантии полного `2^m`-дизайна. Предупреждения SciPy сохранены в протоколе. Правильность не требует выполнить дополнительные дорогие policy-оценки только ради степени двойки. [E03]

### C16-R01: несовместимость теряется при повторном export

Место: `set_state` missing-Sobol branch, строки 176–200; `get_state`, 103–115; `_sobol_state`, 256–286.

Вход без Sobol-состояния разрешён для Python-восстановления, но устанавливает `_sobol_checkpoint_compatible=False`. Прямой следующий Sobol-вызов правильно отказывает: `versioned sampler state is missing`.

Однако `get_state` не учитывает этот флаг и выпускает **новый полный Sobol-объект с пустым cache и cursor=0**. Следующий restore принимает его как настоящий и ставит compatible=True.

```text
Checkpoint: Python state есть, Sobol state отсутствует
→ set_state: Python восстановлен, Sobol ограничен
→ _sobol_candidate: адресный отказ
→ get_state → JSON → from_artifact
→ set_state другого объекта: Sobol считается совместимым
→ запрошенная Sobol-точка вычисляется без восстановления прежней истории
```

P24 использует сериализуемый versioned Python state без Sobol; P25 повторяет direct tuple-форму из действующего legacy-теста. Обе дали потерю отказа после re-export. Действительно свежая, ещё не использованная последовательность в P27 восстановилась нормально и не должна быть запрещена ремонтом.

**Severity: medium; confidence high для локального round-trip.** Не доказано, что выданная новая точка обязательно отличается от неизвестной старой; как раз исходных данных для такого сравнения нет. Ошибка — появление утверждения совместимости без восстановленного основания, а не измеренный downstream ущерб.

Минимальное направление: сохранить отсутствие/непригодность Sobol-state при экспорте либо явно отвергнуть заявление воспроизводимого Sobol-checkpoint; продолжение законного Python stream можно оставить. P26 удаляет искусственно созданный sobol-блок только в audit-control — следующий reader сохраняет отказ. Не нужно менять сам sampler, запрещать все legacy states или подменять их seed новым экспериментом под прежней меткой.

## 6. Цена подготовки: масштабируемость без смены научного эксперимента

При каждом расширении cache метод заново запрашивает `index+1` точек от начала. Для 32 последовательных индексов действительно подготовлено **1+…+32=528** точек, тогда как один запрос 32-точечного префикса подготовил 32. Чтение уже известной точки вызвало 0 новых sampler-вызовов. Это счётчик подготовки, **не число policy-симуляций и не коэффициент ускорения всей системы**. [P28]

G01 — дополнительное инженерное улучшение, не основание отрицать исправление воспроизводимости. При релевантном workload можно продолжать живой sampler в рамках запуска, а восстанавливать один раз с проверенным cursor/prefix; текущая схема и отказ сменившемуся backend сохраняются. Само воссоздание sampler и fast-forward с нуля на каждой точке ещё не доказывает линейность. Нельзя возвращать старый seed от cache-length или менять число дорогих исследований ради удобного batch. Оба официальных backend имеют средства продолжения, но экономия должна измеряться на выбранной реализации. [E03, E04]

## 7. Что подтверждают существующие тесты

`test_space_codec.py` уже проверяет deterministic sampling, incremental/batch/checkpoint, точный legacy-denial, изменённое пространство, cursor, повреждённый prefix, неизвестную version, отсутствующий Python RNG и чужую стратегию. Эти тесты содержательны и должны оставаться. Однако legacy-тест заканчивается на **первом отказе**, не делает re-export и второй restore. Native-index rejection с контролем неизменности Gaussian-cache в прочитанном наборе не найден. Это характеристика прочитанного файла, не полный census всех tests. [S09]

`test_frontier.py` имеет устаревшие raw-volatile ожидания; новый `test_candidate_identity_semantics.py` задаёт противоположную предметную семантику и stronger source/reader tests. Не нужно создавать ещё одну параллельную test-family ради имени CTL-02. [S07–S08]

**Адресные штатные команды следующей приёмки — UNRUN:**

```bash
cd policy-engine
uv run pytest -q tests/unit/scientist/search/strategies/test_space_codec.py tests/unit/scientist/search/test_frontier.py tests/unit/scientist/search/test_candidate_identity_semantics.py
```

Для полной B125-приёмки отдельные поддержанные concrete strategy/model states должны пройти собственные persisted round-trips; GP training/conditioning и learned model persistence относятся также к OPT-03. Их не следует объявлять исполненными по базовому RandomSearchStrategy. Native PolicyCandidateSchema producer→evaluation→CAS reader также здесь не исполнялся. Недоступность этих областей не отменяет прямые Python/SciPy/PyTorch результаты текущего прохода.

## 8. Исполнение и ограничения

**32 ограниченных наблюдения — 32 MATCH, 0 ERROR.** MATCH означает совпадение с заранее записанным наблюдением, включая остаточные дефекты, а не product PASS. Сохранены [код](../04_Проверки/C16_CTL02/probe_ctl02.py), [полный протокол](../04_Проверки/C16_CTL02/bounded_diagnostics.json) и log. Первый exploratory script — отдельное исследование механизма, его вывод не суммируется с финальными 32 наблюдениями; ошибки harness в финальном запуске отсутствовали.

Полные `base.py`, `types.py`, `space.py`, `frontier.py`, `random.py` побайтово совпали с Git blob соответствующего SHA. Сохранены две точные DTO-class выдержки с настоящим Pydantic. Использован изолированный import namespace; objective symbols — import-only fixtures, операции score запрещены assertion; JSON-native stable serialization — явно ограниченная стандартная fixture. Полные native package initialization, objective admissibility, policy_schema branch, actual StrategyAdapter, GP, CAS, HTTP и LLM не исполнялись. Пять source modules не переименованы в установленную копию продукта.

Среда: CPython 3.13.5 / Linux; NumPy 2.3.5; SciPy 1.17.0; torch 2.10.0+cpu; Pydantic 2.13.5. CPU sampler проверялся последовательно; native thread limits = 1. Поддержанный contributor baseline проекта — Python 3.14; запуск на нём остаётся отдельной приёмкой. Прямое чтение raw GitHub в контейнере получило DNS error; исходники прочитаны штатным connector. Ничего не устанавливалось. [environment.json](../04_Проверки/C16_CTL02/environment.json)

Более широкая цель сохранена: система должна продолжать исследование после сохранения, не повторять лишнюю подготовку и не смешивать даты действия с датами управления. Ремонт принадлежит существующим identity/state owners; новый search-framework не назначается.

29 проверок целостности досье прошли без ошибок.
