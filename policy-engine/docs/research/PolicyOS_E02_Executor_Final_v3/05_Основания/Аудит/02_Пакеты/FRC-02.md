# FRC-02 — реальный прогнозный producer и ограниченный S10 bridge
## C31 · 31 октября 2026 года

**Исходный ID:** LA-051, этап 2/2 и accountable closure. **Порядок:** 31/127. **Срез:** `20d9009be21097bfbdc38a546a15cc60213b8ace`. Аудит без изменения продукта.

## Решение

**Реальный producer уже существует; оставлять вывод «bridge не найден» было бы неверно.** ForecastOwner исполняет выбранный ETS на training slice, сравнивает predictive intervals с отдельным holdout, сохраняет report/uncertainty/diagnostics и передаёт результат существующему neutral calibration owner. Run-bound service добавляет содержательно связанные role references, сохраняет evidence, вновь читает его и вызывает S10. Это не перенос прежней формулы finite CI в новый файл.

Одновременно это **predictive interval coverage**, не CI причинного эффекта. Самостоятельный ForecastOwner сохраняет `bridge_pending`; это ограничение его результата, а не доказательство отсутствия последующего service bridge. Наблюдаемый ряд может получить ограниченный calibration record, но N4 policy-outcome tier остаётся blocked без relation к целевой метрике. Такую границу нельзя «исправлять» снятием запретов.

**25 MATCH, 0 ERROR** в финальном ограниченном запуске. Исполнены реальные bridge/DTO definitions и Holt helper, но CAS/ref/owned IO — явные фикстуры. Native test attempt остановлен до collection: отсутствует pytest. Полное закрытие LA-051 не заявляется. Узкий подтверждённый остаток **C31-R01**: дробные metadata counters усечением превращаются в допустимые целые при reconciliation.

## 2. Настоящий producer, а не фиктивное имя

`ForecastOwner.run` разрешает snapshot/data и exact model/policy profiles; проверяет выбранный profile member по row count и hash ряда; режет training/holdout по явному split. Затем вызывает зарегистрированный ETS через MethodDispatcher, требует NumPy backend, правильные horizon/target/method, соответствие interval points прогнозу, finite bounds и rolling-origin observations. Это содержательная численная работа над выбранными входами. [S02:647–800](https://github.com/DenisKopylov/polisyos/blob/20d9009be21097bfbdc38a546a15cc60213b8ace/policy-engine/src/polisyos/scientist/methods/backtesting/forecast_owner.py#L647-L800)

Сохраняются training slice, MethodArtifact, uncertainty bundle, PIT evidence и настоящая continuous calibration. Из holdout независимо считаются numerator/denominator, сверяются с bins/observations настоящего diagnostics report. Backtest plan использует уже рассчитанные forecast/intervals, не подменяет их benchmark; report повторно открывается, проверяются exact edges и отсутствие trust eligibility. [S02:833–1091](https://github.com/DenisKopylov/polisyos/blob/20d9009be21097bfbdc38a546a15cc60213b8ace/policy-engine/src/polisyos/scientist/methods/backtesting/forecast_owner.py#L833-L1091) [S02:1093–1240](https://github.com/DenisKopylov/polisyos/blob/20d9009be21097bfbdc38a546a15cc60213b8ace/policy-engine/src/polisyos/scientist/methods/backtesting/forecast_owner.py#L1093-L1240)

Методовый owner действительно строит Holt point forecast; неопределённость у соседнего rolling-origin residual producer. P21 исполняет только точные `_holt_linear` и `_exponential_smoothing_result`: training 10…19 даёт 20,21,22. **Полный uncertainty/dispatcher/owner run этим не доказан.** Прочитанная часть uncertainty builder рассчитывает horizon-wise ошибки по rolling origins; наличие малой выборки и marginal scope не превращается в универсальную гарантированную calibration. ## 4. Подтверждённый локальный остаток

### C31-R01 — дробные metadata counts теряют смысл при нормализации

`_coerce_int` делает `int(value)` прежде, чем проверять знак и целочисленность. При actual observed 2/2 и metadata counters `2.9/2.9` получается usable evidence без failure codes; **P17 доведён до persist и load через actual bridge definitions с fixture CAS**. `-0.1` становится 0 и также не определяется как invalid count (P18). Boolean отдельно отвергается (P19). [S01:1446–1463](https://github.com/DenisKopylov/polisyos/blob/20d9009be21097bfbdc38a546a15cc60213b8ace/policy-engine/src/polisyos/calibration/forecast_bridge.py#L1446-L1463) [S01:1852–1859](https://github.com/DenisKopylov/polisyos/blob/20d9009be21097bfbdc38a546a15cc60213b8ace/policy-engine/src/polisyos/calibration/forecast_bridge.py#L1852-L1859)

Это нарушение заявленного reconciliation, но не подмена самих наблюдаемых hits: bridge по-прежнему считает настоящие bounds, а текущий ForecastOwner обычно формирует integer counters. Не доказаны upstream malformed output или production bypass. Минимальное продолжение — проверять неотрицательную целочисленность до преобразования, сохраняя отдельно обоснованную legacy политику текстовых целых. Не нужен новый calibration service.

## 5. Что ещё не квалифицировано

- **C31-G01:** native CAS/owned JSON admission, MethodDispatcher, full ForecastOwner, service и S10 short chain. Найден полный existing test `test_frc_02_empirical_bridge.py`; его запуск завершился exit1 до collection с `No module named pytest`. Зависимости не ставились. Это блок среды, не дефект продукта.
- **C31-G02:** source population/time/issuer явно not_established; N4 outcome-to-observed-metric relation не установлена. Typed N4 consumer поэтому сохраняет series calibration record, но блокирует outcome-calibrated tier. Нужно связать выбранный LLM-сформулированный вопрос с доступным observed metric через существующих owners и проверить нужный scope, а не требовать универсальный детерминированный изобретатель моделей. Threshold и finite-sample suitability сохранять как ограниченный screening, не как внешнее полномочие. ## 6. Доказательства, ограничения и следующий шаг

Все probe observations — сконструированные различающие случаи, **не эмпирический научный корпус**. Pydantic/NumPy настоящие; bridge/DTO bodies неизменены. Ref DTO, in-memory CAS и IR owned IO являются явными seams. Первый harness запуск ошибся namespace resolution; только harness исправлен, все логи сохранены. Финал25 MATCH включает R01 и не равен product PASS. Ни один existing repository test не исполнен успешно.

Сохранить полноценный прогнозный producer, measured counts, exact source-profile edges, воспроизводимость, historic semantics, conservative credibility и purpose denials. После локального R01 — выполнить найденную короткую native цепочку в поддерживаемой среде; затем квалифицировать **один** полезный outcome binding, не перестраивать архитектуру.
