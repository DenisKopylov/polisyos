# Переоценка предписаний: сохраняем смысл, не консервируем способ ремонта

Это текущие аналитические решения независимого досье, не тайное изменение исходного E02 и не запись от имени product principal. Основания, ограничения и нужная проверка указаны рядом. Полный исходный текст сохранён.

## REQ-01 / LA-045–046: не восстанавливать family fallback ради preserve

**Историческое предписание:** при точной private-чистке не затронуть живую heuristic и сохранить opt-in поведение.

**Нынешняя ситуация:** heuristic намеренно retired; новый тест закрепляет её отсутствие. Первый отчёт правильно обнаружил изменение, но его значение для цели нужно оценивать отдельно.

**Текущая оценка:** отсутствие этой эвристики не самостоятельный продуктовый дефект; возвращать её не назначается. Содержательное основание — [Rule 12](https://github.com/DenisKopylov/polisyos/blob/20d9009be21097bfbdc38a546a15cc60213b8ace/policy-engine/docs/system-design-decisions/universal-policy-design-system-vision-and-organizing-rules.md#L198-L230): capability должна открываться через corpus discovery, а не список специальных семейств. Проверяется replacement: реальные explicit requirements, useful candidate proposals, найденные ресурсы, реальный consumer и historical readers.

**Что остаётся непроверенным:** полнота discovery и реальное принятие его результата downstream. «Fallback удалён» не означает «универсальная замена готова». Историческая формальная запись retirement не становится главным blocker вместо этой проверки.

## CYC-01 / B02: не навязывать общий неизменный context всем операциям

**Историческое предписание:** провести один точный context через стадии.

**Сохраняемый инвариант:** одна операция использует согласованные problem/model/data/catalog identities; подмена обнаруживается.

**Текущая оценка:** для разных детей, ревизий и world versions могут потребоваться разные явно связанные contexts. Существующие maps/capsules/reissue owners следует использовать, а не свести всё к одному Python-object. Источники: [HTTP maps](https://github.com/DenisKopylov/polisyos/blob/20d9009be21097bfbdc38a546a15cc60213b8ace/policy-engine/src/polisyos/runtime/http/services/control/generation_cycle.py#L2580-L2780), [leaf consumption](https://github.com/DenisKopylov/polisyos/blob/20d9009be21097bfbdc38a546a15cc60213b8ace/policy-engine/src/polisyos/runtime/quality/recursive_generation_cycle.py#L3450-L3630), [reissue](https://github.com/DenisKopylov/polisyos/blob/20d9009be21097bfbdc38a546a15cc60213b8ace/policy-engine/src/polisyos/runtime/quality/generic_simulation_admission.py#L945-L1140).

**Проверка:** новое основание действительно меняет расчёт и его lineage; старый результат остаётся читаемым; чужая популяция/модель не заимствует прежний допуск. Наличие метода reissue само по себе этого ещё не доказывает.

## CYC-01 / B01–03: не превращать отсутствие эмпирической authority в запрет всей исследовательской работы

**Сохраняемый инвариант:** реальные права на данные/расход/эффекты соблюдаются, результат не получает большей силы, чем основание.

**Текущая оценка:** явно условная симуляция полезна без доказанного эффекта в мире. Положительный контролируемый тест и честное ограничение — настоящее достижение, хотя не универсальная рекомендация. Конечная граница должна определяться назначением вывода, а не минимальным статусом любой несвязанной подсистемы. Основания: [Vision](https://github.com/DenisKopylov/polisyos/blob/20d9009be21097bfbdc38a546a15cc60213b8ace/policy-engine/docs/system-design-decisions/universal-policy-design-system-vision-and-organizing-rules.md#L40-L103), S03/S07 исходного E02 и разделение purpose в текущих owners.

**Проверка:** полезное условное число доступно и воспроизводимо; тот же объект не обходит запрет эмпирического/внешнего применения. Не удалять guards или labels ради PASS.

## CYC-01 / B03: не заказывать новый builder, когда он уже существует

**Исторический барьер:** готовый request или callable требовались извне.

**Фактическое изменение:** есть data-only builder, profile-bound inputs, model resolution и real controller call. [Builder](https://github.com/DenisKopylov/polisyos/blob/20d9009be21097bfbdc38a546a15cc60213b8ace/policy-engine/src/polisyos/runtime/quality/generation_cycle.py#L4830-L5170); [вызов](https://github.com/DenisKopylov/polisyos/blob/20d9009be21097bfbdc38a546a15cc60213b8ace/policy-engine/src/polisyos/runtime/quality/generation_cycle.py#L4270-L4475).

**Текущая оценка:** остаток нужно искать у постановки задачи и composition/discovery, а не в ещё одном DTO/framework. Наряду с ограниченной приёмкой текущего пути надо отдельно оценить новый кейс и actual request replay. Наличие пяти labels не означает готовые пять методов; один named profile не означает всю универсальность.

## Смежная граница: набор альтернатив не равен составной политике

Parent-joint diagnostic в текущем коде прямо сохраняет `source_candidate_relationship="alternatives"` и `composition_status="not_established"`. [Реализация](https://github.com/DenisKopylov/polisyos/blob/20d9009be21097bfbdc38a546a15cc60213b8ace/policy-engine/src/polisyos/runtime/http/services/control/generation_cycle.py#L1350-L1555).

**Текущая оценка:** сохранять это ограничение. Нельзя объявлять полноценное policy composition по одному успешному joint run или существованию parent-child edges. Нужны совместимость вмешательств, их ресурсы/порядок и предметное основание объединения; это передаётся соответствующим последующим задачам, не используется для блокировки любого малого N5.

## Как будут добавляться следующие решения

Старая рекомендация переоценивается только после чтения относящегося к ней текущего механизма. У непрочитанных 125 пакетов таких решений пока нет. Ни полезность нового подхода, ни красивое архитектурное название не подменяют различающую проверку на actual producer/consumer.
