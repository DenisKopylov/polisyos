# Рабочая установка: LLM и алгоритмический выбор

31 октября 2026 · дополнение пользователя к тому же аудиту, не утверждение о текущей реализации.

**Базовый исполнитель содержательного выбора — LLM:** формулирование конкурирующих гипотез, выбор модели, метода, горизонта, базы сравнения и существенных параметров для новой задачи. Если алгоритмический механизм для конкретного вопроса не хуже обеспечивает универсальность и масштабируемость либо делает это лучше, он предпочтителен. Пользователь обозначил это как общее рабочее размышление; реализация нового планировщика сейчас не поручена.

## Что меняется в критериях аудита

Отсутствие общего детерминированного алгоритма, самостоятельно изобретающего модель для любой задачи, не считается дефектом само по себе. Не следует по умолчанию назначать ручного эксперта либо новый универсальный optimizer на каждый смысловой выбор. Не требуется доказывать алгоритмическую оптимальность LLM-предложения до всякого условного расчёта.

Проверяемый технический остаток формулируется конкретно: может ли предложение выбранного исполнителя пройти существующий проверяемый путь — сохранить исходный вопрос, гипотезу и параметры; разрешить действительные данные и метод; исполнить именно выбранную спецификацию; вернуть результат и причину ограничения следующему шагу исследования. Наличие DTO само по себе не подтверждает эту цепочку. Назначение LLM исполнителем не доказывает её автоматического наличия, но снимает требование создать вторую универсальную алгоритмическую систему смыслового выбора.

Для CYC-04 различаются три операции: создание/ранжирование исследовательских предложений; определение исполнимости и следующей доступной операции; допуск расхода и учёт фактически исполненного. LLM может формировать первое и предлагать планы; детерминированная фильтрация подтверждённых ограничений, учёт и сохранение истории остаются у существующих владельцев. Это вывод для направления аудита, а не новая схема полномочий продукта.

## Как читать прежние отчёты

Фразы CYC-01, CYC-03 и ACQ-01 о том, «кто выбирает модель/метод/горизонт», теперь читаются с этой рабочей установкой. Их исторические тексты не переписаны. Прежнее отсутствие подтверждённого автоматического producer→consumer пути не превращено в реализацию только из-за принятого направления.

Не добавлены новые исходные B/LA IDs, продуктовый backlog или отдельная architecture-decision процедура. Продолжается проверка текущего кода по исходному порядку E02.
