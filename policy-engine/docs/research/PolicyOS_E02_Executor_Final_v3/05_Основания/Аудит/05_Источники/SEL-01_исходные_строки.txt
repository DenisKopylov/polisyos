1454: ## Поручение и минимальная приёмка
1455: 
1456: Проверять происхождение реально обнаруженного набора, а не запрещать cardinality=1. Применять обязательные свойства до top-k. Сохранять requested modalities даже при отсутствии поддерживающего метода.
1457: 
1458: **Различающие тесты и сохраняемое поведение.** Genuine singleton выбирается, фиктивный вне каталога — нет. Добавление non-value методов не прячет value-метод. Panel-запрос не становится пустым требованием при tabular-only каталоге; разрешённый adapter имеет реальный producer.
1459: 
1460: **Не считать исправлением.** Не добавлять фиктивный второй метод, не повышать top-k вместо ремонта порядка, не смягчать обязательные требования пересечением с каталогом.
1461: 
1462: **Цикл работы:** зафиксировать actual scope и нужный characterization; оформить equivalent move и намеренный behavior fix раздельно; выполнить указанные малые tests через I1; независимый reviewer проверяет actual owner; передать commit, path map и остатки. CLI/test selectors разрешаются по настоящему checkout до запуска, не выдумываются из названия находки.

1493: ## B34. Единственный корректно обнаруженный метод принимается за hardcode
1494: 
1495: *Источник карточки: C02-01. Унаследовано из полного C02/r01; 25 исторических локальных записей.*
1496: 
1497: **Источник:** C.Q01, C.Q02. **Свидетельство:** код; локальные контроли S1-1–S1-3. **Достижимость:** автоматический выбор при полном value-denominator из одного элемента.
1498: 
1499: В `MethodSelectionReceipt._verify_selection_trace()` стоит проверка:
1500: 
1501: ```python
1502: if self.selection_authority == "foundry_registry_advisor" and len(self.denominator) <= 1:
1503:     raise ValueError("value_method_selection_fixed_default")
1504: ```
1505: 
1506: Для явно запрошенного метода используется иной источник выбора — `requested_registry_method`, — на который это условие не распространяется. Поэтому одинаковый одиночный элемент может быть допустим для явного запроса, но недопустим для автоматического выбора. В локальном опыте эти две ветки расходятся именно по этому условию. Остальные предикаты receipt в опыте не выполнялись.
1507: 
1508: **Важное уточнение:** здесь denominator — весь обнаруженный набор методов с подтверждённым владельцем value-проекции, а не число подходящих вариантов после всех фильтров. Один подходящий метод среди большого denominator не обязательно вызывает этот отказ. Нынешняя численность полного value-набора в данном проходе не измерялась.
1509: 
1510: **Почему ограничение избыточно.** Кардинальность не устанавливает происхождение выбора. Честно обнаруженный singleton не становится hardcode; два фиктивно добавленных метода не доказывают честность процедуры. Так проверка заменяет нужное свойство косвенным признаком.
1511: 
1512: **Разумное расширение.** Разрешить singleton при доказанной связи с действительным каталогом, корректной применимости и честном полном составе рассмотренного набора. Сохранить обязательность source/contract/context bindings и запрет подменять полный denominator удобным подмножеством. Итог формулируется «единственный доступный в этой области», а не «лучший среди всех возможных методов».
1513: 
1514: **Проверка:** один реально зарегистрированный допустимый метод выбирается; тот же метод вне объявленного набора отвергается; скрытие других обязательных членов набора по-прежнему выявляется. Добавление фиктивного второго элемента не служит обходом проверки.
1515: 
1516: **Стоимость и граница:** очень небольшое условие, но смысл анти-hardcode проверки нужно заменить доказательством происхождения. Не повод ограничивать большую систему одним методом.

1525: ## B35. Top-k применяется раньше фильтра по обязательному типу результата
1526: 
1527: *Источник карточки: C02-02. Унаследовано из полного C02/r01; 25 исторических локальных записей.*
1528: 
1529: **Источник:** C.Q01–C.Q03. **Свидетельство:** межфункциональное чтение; искусственный упорядоченный набор S2-1/S2-2. **Достижимость:** `route_constraint=None` и методы других типов попадают в верх списка.
1530: 
1531: `_value_method_advisor_query` устанавливает `limit=max(1,min(8,len(value_entries)))`. В `advise_methods` ранжируется каталог, затем берётся верхняя часть `scored_entries[:limit]`. Уже после этого `select_value_method_for_problem` оставляет из рекомендаций только элементы value-denominator. Без route_constraint исключение всех non-value методов заранее не задано.
1532: 
1533: В контрольном наборе `[diagnostic.a, diagnostic.b, value.m1, value.m2]` при limit=2 текущий порядок даёт пустой список. Отбор value-методов до ограничения оставляет оба. Это не реальное ранжирование Foundry: порядок является заданным искусственным входом, демонстрирующим следствие композиции.
1534: 
1535: **Особенно существенное следствие:** расширение общего каталога может ухудшить доступ к существующим нужным методам. Новые методы других типов занимают короткий рекомендательный список; система сообщает отсутствие подходящего результата, хотя методы ниже доступны.
1536: 
1537: **Разумное расширение.** Обязательные свойства результата и применимость должны ограничивать множество до top-k. Альтернатива — ленивое продолжение чтения ранжированного списка до исчерпания допустимого бюджета, с явной неполнотой. Не решать это увеличением 8 до большого числа: дефект порядка останется.
1538: 
1539: **Имеющийся правильный шаблон:** `select_method_for_input_contract` получает eligible-множество, ранжирует только его с `limit=None`, затем выбирает. У ветки с route_constraint есть собственное предварительное исключение несовместимых методов; это важный контроль, а не повод считать все маршруты сломанными. [C.Q02]
1540: 
1541: **Проверка:** добавление новых non-value методов не скрывает подходящие value-методы; отсутствие всех подходящих методов остаётся настоящим отказом; журнал сохраняет причины исключений и область поиска. Ранговое предпочтение не создаёт доказательной силы.

1550: ## B36. Обязательное требование исчезает, если каталог не умеет его удовлетворить
1551: 
1552: *Источник карточки: C02-03. Унаследовано из полного C02/r01; 25 исторических локальных записей.*
1553: 
1554: **Источник:** C.Q03/C.Q04. **Свидетельство:** код; S3-1/S3-2. **Достижимость:** явно заданная `value_required_data_modalities` содержит модальность, которой нет среди value_entries.
1555: 
1556: В `_value_selection_criteria` выполняется пересечение requested modalities с объединением модальностей доступных методов. Потом `_rank_entries_with_scores` проверяет лишь это сокращённое множество.
1557: 
1558: Пример: требуется panel, каталог содержит только tabular. После пересечения обязательное множество пусто; проверка модальности не исключает tabular-метод. При добавлении любого panel-метода требование внезапно возвращается. Таким образом, одно и то же входное требование меняет силу от состава каталога.
1559: 
1560: **Это не доказательство уже опубликованного неверного причинного результата.** Рассмотрен этап выбора; downstream может остановиться, в частности нынешний N8 имеет собственный недостроенный положительный путь. Но отсроченный отказ хуже для диагностики: настоящая причина уже потеряна.
1561: 
1562: **Разумное расширение.** Сохранять обязательный запрос неизменным. Если его нельзя выполнить, возвращать точный пробел: нет подходящего метода, нет разрешённого преобразования или нужно уточнить само требование. Предпочтения можно смягчать; жёсткие требования нельзя молча переименовывать в предпочтения. Поддерживаемые aliases/совместимость следует разрешать явным типизированным преобразованием, не простым пересечением строк.
1563: 
1564: **Почему это расширяет цикл, хотя добавляет точность отказа.** Контроллер получает адресное действие для ремонта или перехода к допустимой альтернативе вместо более позднего непонятного падения. Обычный scalar/табличный результат не выдается за выполненную panel-задачу.
1565: 
1566: **Проверка:** запрос panel не превращается в пустой; подходящий метод проходит; несовместимый — нет; разрешённое преобразование имеет настоящего производителя, входы и проверяемый выход. Изменение каталога не переписывает исходный запрос.
