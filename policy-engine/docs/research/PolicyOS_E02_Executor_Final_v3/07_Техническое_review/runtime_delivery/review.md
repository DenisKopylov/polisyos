# Финальное техническое ревью E02: LANE-06 и LANE-12

**Срез:** 2026-11-01; immutable repository `20d9009be21097bfbdc38a546a15cc60213b8ace`. **26 пакетов**: 22 runtime/storage и 4 delivery/package. Это новое критическое ревью решений и доказательности, а не повтор ID/link QA. **Все продуктовые проверки: NOT_RUN.** Предложения ниже не реализованы и не означают допуск релиза.

## 1. Практический вывод

Основной технический выбор комплекта разумен: ремонтировать существующих владельцев, а не заменять работающие checkpoint/CAS/ledger/client контуры новым framework. Самые сильные места — разделение bytes/selected state/authority, exact successful frontier, сохранение useful partial, current request при reuse, отдельные Common/IR/DataForge migration profiles, реальный installed-origin harness. Эти различия имеют пользовательский смысл: продолжить расчёт после отказа, сохранить полезный результат, не повторить расход/действие, открыть прежний результат и поставить клиент без скрытой зависимости на checkout.

Однако **два предложенных ремонта неполны в самой механике**:

1. **RD-01:** EXE-01 исправляет `run_blocking_async`, но тот же blocking completion registration остаётся в `SharedExecutionHandle.result_async` и async thread-timeout bridge. Один исправленный тест не устанавливает capability всего shared owner.
2. **RD-02:** `json.dumps(query_name)` в JavaScript object literal не делает `"__proto__"` обычным data key. Такой параметр теряется. Optional `constructor`/`toString` могут случайно читать inherited значение.

Ещё четыре улучшения относятся преимущественно к **границе доказательства**, а не к объявлению новых найденных product failures:

- **RD-03:** callback fingerprint при регистрации не доказывает неизменный смысл live mutable closure; узкий `except ValueError` repair оставить, сильное обещание квалифицировать.
- **RD-04:** принудительный Linux `fork` требует проверки после настоящего JAX warm-up; JAX0.8.2 сам предупреждает о deadlock. Это конкретный риск, **не воспроизведённое зависание** и не приказ автоматически заменить всё на spawn.
- **RD-05:** direct `ParameterTransfer.pure_step` parity — хороший oracle проводки/reuse, но не независимый oracle численного prior mapping.
- **RD-06:** existing JS→Runtime bridge сейчас обрывается на fake200; Python отдельно проверяет сервис. Нужен обратный проход реального ответа через generated client.

Точные REQ/TEST replacements, code evidence, alternatives, preservation и uncertainty — в [findings.json](findings.json). Библиотечные решения и проверенные первоисточники — в [library_decisions.json](library_decisions.json). Coverage с хешами — в [coverage.json](coverage.json).

**Не требуется:** wholesale redesign всех26 пакетов, новый workflow engine, новый ledger issuer, новый canonicalization format, второй packaging checker, универсальный Python semantic prover или обязательный широкий CI для каждого маленького ремонта.

Например, `generation_cycle.py` содержит десятки тысяч строк; его full-product composition не доказана выбранными фрагментами.

Продукт не импортировался, не исполнялся и не изменялся. Нет installs, live providers, production stores, external mutations или credentials. Отказов разрешений не было. ## 3. Подробная оценка каждого пакета

Вердикты: **retain** — сохранить выбранное решение; **targeted revision** — адресно исправить формулировку/план; **bounded qualification** — локальный repair обоснован, широкий capability claim требует названного witness. Нигде не присваивается произвольный балл.

### 3.1 State, scheduling, resume

**STA-01 — retain.** Корень дефекта верно локализован: staged root/declared writes должны пройти protected membership invariant до публикации. В `state_merge.py:104–173` writes собираются, разрешаются и применяются в branch; проверка только отдельного setter недостаточна для whole-root operation. Сравнение множества ключей до/после у protected mappings дешевле полной deep serialization, и journal хранит same-value intent, который diff состояния потеряет. Не заменять журнал generic JSON patch без сохранения alias/order/delete/null/no-write. Хороший тест должен различать whole-root set с удалением protected key, same-value set, отсутствующий write и null; positive independent field остаётся. Мутант «копировать весь cached outcome snapshot» может давать верный простой результат, но уничтожает текущие unrelated fields; cold/warm tests должны использовать разные current bases. Отдельно operation-ID spend/effect owner, не повторная выдача authority из journal. Стоимость измерять в размере затронутого subtree/alias graph, не рекламировать O(1).

**STA-02 — targeted revision, RD-05.** Удалить stale early return и заново вызвать существующий numerical bridge с текущими backend/draws/seed — правильный ремонт. `resolve_parameters.py:253,419–443` показывает разные reuse/new paths и комплекс ready/interval fields, которые должны обновляться совместно. Same-path source bytes важнее pathname; уже заданный same-connection digest сохранить. Direct bridge parity хорошо обнаруживает stale branch, но ошибку самого bridge не обнаружит. Добавить независимый pre-sampling prior: actual DTO `value=2, std_error=.2`, CI отсутствует, multiplier3 ⇒ mean2/std.6; не требовать exact sample mean. Unsupported parameter, floor и backend fallback остаются явными. Causal consumer witness должен реально использовать эти priors, а не только найти ключ в state; отсутствие native backend блокирует этот claim, не известный resolver repair.

**EXE-01 — targeted revision, RD-01.** Private transport-only completion adapter оптимален: не второй pool, не arbitrary callback на loop, не новые worker на каждый callback. Но site-only fix оставляет публичный handle и retry sibling. `_SharedFuture.add_done_callback:223–242` → `run_callback_sync:301–351` синхронно ждёт bounded capacity; `result_async:143` и `retry.py:2491` используют его через wrap. Parameterized race должен охватить все actual shared-future awaiters. Сохранить distinction read-budget/run-budget и current-index publication fence: cache bytes после отмены могут существовать без admitted current entry. Heartbeat latency и scheduling fairness измерять отдельно от semantic correctness; underlying thread не объявлять убитым.

**EXE-02 — retain.** State-aware target identity лучше строковой нормализации всех numeric components. У dict `"0"` и `"00"` — разные ключи; у list оба могут адресовать index0. `async_executor.py:983–1037` сейчас сравнивает token prefixes, а actual reader `1217–1233` приводит list index к int. Предложенный finite shape traversal исправляет реальную aliasing ошибку, не требует общего scheduler replacement. При неизвестном shape fallback к tier правильнее небезопасной оптимизации; positive A→C до независимого B не даёт свести систему к always-tier. Нужны list aliases, dict distinct keys, parent/child overlap и explicit B→C join. Pairwise admission имеет квадратичную по node/path pairs стоимость; новый dependency-index оправдан только реальным большим workload. Speedup не выводится из одного counter.

**RES-01 — bounded qualification.** Code уже различает immutable origin fingerprint, residual plan и sufficient state (`checkpoint.py:2537–2593`); требование «сначала actual2-stop trace, code лишь при обнаруженном gap» технически дисциплинированно. `idempotency.py:864–924` memoizes exact successfully verified ref и переверифицирует после LRU eviction; cardinality refs не substitute обязательному state. Scan trace по строкам `926–979` остаётся O(trace size); tail optimization не дефект по умолчанию. Сильный контроль — changed functional request при том же FQN, duplicate refs вместо missing state, failed admission затем valid retry. Новый process/reader должен продолжить только residual и сравниваться с independent uninterrupted expected values; разрешённый full replay явно считает повторные вызовы. Grammar list/null ограничить actual consumer census, не arbitrary Python graph.

**RES-02 — retain.** Actual executor `async_executor.py:522–548` уже формирует ok-only frontier и одну tier publication после merge; checkpoint owner `1146–1203` пишет whole tier. Поэтому пакет преимущественно квалифицирует/сохраняет механизм, не заказывает новый. Crash witness должен остановить **реальную** запись между значимыми durable boundaries и читать свежим owner, а не просто выбросить Exception до mock save. Мутант «последовательно публиковать successful nodes» проходит uninterrupted run, но создаёт half-tier после crash. Сравнить frontier, merged state, cache refs, increment/spend once; fail_fast rollback не должен уничтожать immutable diagnostics и не должен повышать их до selected authority. Node-only hook support намеренно не расширяется.

**RES-03 — bounded qualification.** Правильная capability — пользователь получает точный полезный completed numerical result даже при позднем failure; не только status=partial. `AsyncChainExecutionError:104–128` и merge-before-raise `216–259` уже несут completed result/error/blocked IDs. Это нельзя считать доказательством same-leaf Runtime N5 projection: у каждого handoff нужен actual consumer. Хороший план DEC-RES-03-01 выбирает no-code, wiring или узкий typed extension после trace; не сразу новый partial framework. Distinguishing case: N5 сохранился, поздняя revision/независимый sibling отказали, новый reader отдаёт тот же value/ref, cause и pending branch; dependent normative route не получает success. Второй вариант меняет общий basis и инвалидирует только зависимую current authority, не исторические bytes независимого candidate.

### 3.2 Invocation, wire, durability

**RUN-01 — retain с координацией RD-01.** Закрывать только собственную `CORO_CREATED` coroutine после pre-submit refusal — корректный narrow lifecycle fix. Duck-typed `.close()` на чужом Task/Future или уже запущенной coroutine разрушил бы ownership. Один invocation deadline и contextvars должны сохраняться через sync/async/fallback. Мутант «timeout означает worker stopped» проходит возврат исключения, но поздно пишет protected state: нужен release noncooperative worker после timeout и отрицательный current-index/fence control. Уже bounded Common executor лучше переезда на AnyIO ради одного leak. Generic function-local typing сохранить; не делать его доказательством runtime behavior.

**RUN-02 — bounded qualification, RD-04.** EOF/exit/timely-completion/delivery-window precedence в пакете содержательно точен: смерть worker до срока не нужно выдавать за timeout, а неизвестное время смерти нельзя выдумывать. Pipe следует drain до join;64B и1MiB действительно различают backpressure. Но Linux branch явно выбирает fork (`retry.py:2514–2529`), и warm numerical parent не эквивалентен simple child. Добавить actual JAX warm-up и safe-start decision без forced rewrite. Linux descendants и Darwin spawn — отдельные именованные profiles. Process cleanup проверять actual PID/group, не mock terminate call; parent никогда не target. Watchdog нужен вне потенциально зависшего child/loop.

**RUN-03 — retain.** Fresh ordinary state каждой попытки и накопленный known failed spend — разные owners. `retry.py:4152–4160` CancelledError не делает `_merge_spend`, тогда как timeout/error branches делают; targeted repair justified. Arithmetic baseline5+known failed2=7 — полезный unit oracle, но durable authority требует real ledger receipt reconciliation. Unknown current attempt cost не равен0 и не право retry с новой UUID. Typed same-cause return/raise/IPC parity правильно привязана к actual producer, не substring message. Тест обязан включать cancel во время backoff и во время later attempt, no-double-merge, max_retries0, грязные ordinary writes отвергнуты; terminal partial не success.

**DUR-01 — retain; scale decision отдельно.** Stable separate lockfile, same-dir temp→fsync(file)→replace→fsync(dir) и repeat-event confirmation — правильный localFS алгоритм. `budget_ledger.py:1094` возвращает существующий receipt без подтверждения durability, тогда как `_confirm_compute_durability:1032–1041` существует: переиспользовать владельца, не stored dirty-bit в том же uncertain файле. `1516–1544` показывает full snapshot rewrite всех receipts; bounded ledger допустим, большой workload требует измерить O(N) per-event и O(N²) суммарный объём. SQLite — возможная поздняя оптимизация, не обязательная миграция. Restore из authentic stale backup не восстанавливает current spend без trusted reconciliation; positive restore test обязателен, чтобы не получить always-refuse recovery. Crash/process-kill evidence не power-loss attestation.

**DUR-02 — retain, positive reconciliation qualification обязательно.** Heartbeat typed unavailable должен ставить lost (`control_worker.py:203–235` сейчас не во всех ветках). Но local flag не сам fence: transactional owner/attempt/lease predicate и affected rows должны защищать status/progress/event/outbox целиком. Test oldA/newB требует настоящую DB и fresh transaction, все sibling writes и rollback; память-фейк обходит главное свойство. Содержательная free-grow способность — продолжить разрешённый остаток с тем же logical operation после reconciliation, а не лишь заблокировать A. Completed/remaining/ambiguous cases раздельны, внешний unreconciled effect остаётся unknown. PostgreSQL coverage только при declared support, не автоматически за каждую локальную правку.

**WIRE-01 — retain.** Semantic-depth fix нужен именно на tag wrappers: decode `_decode_wire_value:1022–1042` добавляет depth при tag dispatch, tag/model/mapping добавляет ещё; encoder/decoder могут считать разную глубину одного объекта. Исправить единый semantic counting, но не отменять physical parser ceiling. Exact Decimal, bytes, selected artifact refs, output-aware journal и legacyread действительно оправдывают custom closed tags поверх stdlib/orjson/Pydantic, не обычный JSON dump. Independent oracle — literal tag bytes/typed expected values, а не serialize→deserialize той же ошибочной пары. Нужно boundary±1 по каждому nested family и actual worker; deterministic codec error не добавляет physical retry. Wide payload измерять separately от depth; no new universal schema engine.

### 3.3 Artifacts, replay, migrations

**CAS-01 — bounded qualification.** Oneblob/multiple manifest views, immutable defaultA и точный selectedB — корректное переиспользование content-addressed storage. Content equality не tenantpermission; real initialized custody context принципиален. Fixed stripes — bounded lock-table, **не** O(1) totalstorage или zero contention. Тест должен совместить identicalblob/differentprovenance, competingwriters, failedownerindex publication, readonly no-create и fresh reader; отдельный corruption test не доказывает pending recovery. Recovery/quarantine owner и filesystem должны быть выбраны явно; при отсутствии их не притворяться production fault tolerance, но положительный admitted read не блокировать общим отказом.

**CAS-02 — retain.** `_publish_directory_generation:444–464` делает replace затем `rmtree(previous)`; чужой late member может быть уничтожен, даже если до этого inventory совпадал. Retain prior generation с передачей path и bounded retention лучше всё более сложного race-prone cleanup в transaction. Для tar temporary file до replace устраняет обнуление старого export на prepublication error. После replace/fsync error честный unknown/new-visible, не гарантированный rollbackA. Closedinventory и no-follow safeguards сохранить. Discriminating fault должен реально добавить/заменить foreign member между validation и cleanup; static extra-file fixture до проверки недостаточна. Diskcost retainedgeneration указать; не оставлять бесконечный silently growing archive.

**CAS-03 — retain.** Cancellation должна достигать scan/dedupe/StopIteration, а не только bounded worker submissions. `_signature_ops.py:128–143` проверяет stop вокруг next, но exhausted выставляется на StopIteration без повторной проверки. Важное различие: stopped census не complete; уже finished rows сохраняются, invalid/error/not-run различны. Actual crypto verifier и immutable snapshot обязательны; hashselfcheck не trust. Pending-window bound не O(1) total RAM: seen set/report остаются O(N), running work может закончиться после stop. Request-scope authorization loss нужно подать через actual caller owner; signal-only unit не устанавливает revocation. Positive fully completed report нужен против always-aborted implementation.

**REP-01 — bounded qualification.** Lazy root bindings непосредственно в Scientist плюс compatibility shim exact identities — разумный способ убрать unintended import fanout без разрушения ABI. Actual replay backend `backend.py:122–180` строит plan, проверяет incomplete и действительно вызывает Foundry/Scientist. Но compare hashes старого/new refs ещё не доказывает новый compute: instrumentation callable count и запрет cache-as-compute обязательны. Check-only=0compute, replay=actualcompute, resume=residualonly — три разных claims. Historical Runtime manifest1.0 не заменить Core manifest. CI-bounded stochastic tolerance не scientific validity; нужен отдельный domain oracle и объявленная environment mismatch semantics. Не требовать битового повторения agentic tokens там, где заявлен trace/audit replay.

**CAN-01 — retain.** Neutral mechanics с отдельными Core/IR tag/error/policy facades уже правильный reuse (`common/canonical.py:1–7,123–159`). Унификация допустима лишь на действительно одинаковой механике; raw legacy alias readability и current writer conformance — разные assertions. Default0.2 и enrolled bounded0.3 нельзя заменить общим более permissive writer ради зелёных tests. Старые bytes/hash IDs — независимые golden vectors; encode→decode parity обеих изменённых функций слабее. Named behavior-delta для двух expectations необходим, не «обновили snapshots». JCS/orjson — полезные building blocks, но не drop-in историческая семантика Decimal/bytes/None/float. Добавить resourceprofile boundary, не переименовать conversion в authority.

**MIG-01 — retain.** У shared writer `tools/lib/fs.py:80–130` tmp_path присваивается после write/flush/fsync; ошибка раньше оставляет созданный temp вне cleanup. Раннее запоминание пути исправляет text/bytes через один owner, без revival rootparser. Unit faults должны быть после реального temp creation, а не до него; existing output byte-identical и leftover census. Cleanup failure не скрывает исходное exception, exact residual path observable. Same-version CLI no-op всё равно должен пройти actual nested DTO validator; self-edge в migration registry для этого не нужен. Compatibility tuple/error identities сохранить; валидный Trinity scaffold — schema proof, не научный design result.

**MIG-02 — bounded qualification.** Actual path-only converter прочитан полностью165lines. `_source_root:20–38` сохраняет spelling root и CWD semantics; `_canonical_reference:57–101` требует agreement path/relative_path и real containment; `104–162` preflights entries до публикации. Это правильная bounded задача, не relocation/import arbitrary external artifacts. Мутант basename fallback проходит плоскую fixture, но выдаёт другой файл при samebasename nested roots: положительный nested writer→converter→fresh Runtime reader различает. Symlink escape, mixed valid/invalid list, `--to` refusal и exactbytes обязательны. Race mutable filesystem не превращать в обещание immutable scientific custody — пакет уже честно ограничен.

**MIG-04 — retain.** Fabric owns converter; Common owns mechanics. Actual converter переименовывает datasetName/rawHash лишь при отсутствии canonical поля, не выдумывает missing raw_hash/created_at. Это format conversion, не DTO/custody admission. Сохранение конфликтных aliases для отдельного отказа допустимо в таком профиле; не принуждать новый strict default без реального consumer. Tests: alias/canonical disagreement, missingfields, untouchedinput в Common profile, explicit registration, current DTO positive/negative. Случайный import Common не должен регистрировать весь Fabric; deprecated adapter finite lifecycle, не blanket deletion по календарю.

**MIG-05 — targeted qualification wording, RD-03; narrow fix retain.** Разделить чтение empty closure cell и `_stable_migration_value` вне broad except — точно соответствует наследованию MigrationCompatibilityError от ValueError. Fingerprint до registry mutation даёт clean failure; no repr/addresshash. Но dict/list/set encoding `base.py:508–558` — snapshot, fn остаётся live `594–650`, `1108` исполняет его позднее. Не обещать arbitrary semantic equivalence. Blanket rehash/freeze также неправилен: existing characterization callbacks меняют captured observer list (`test_mig_05.py:60–73`). Разделить registrationdescriptor и explicit semantic configuration для тех converters, где нужен reproducible contract. Common deepcopy/stamp, IR live nested/no-op identity и DataForge deterministic BFS не сливать: разные observable APIs, а не лишний код.

### 3.4 Distribution и public client

**DFK-01 — bounded qualification.** Три различных legacy surfaces требуют трёх finite retain/migrate/retire решений. ## 4. Выбор библиотек: что действительно лучше здесь

Полная сравнительная матрица, locked availability, price и revisit triggers — `library_decisions.json`. Ниже итоговые решения, а не список модных названий.

| Область | Рекомендуемый выбор | Когда оправдана альтернатива |
|---|---|---|
| Shared async completion | Существующий Common executor + один private transport adapter; `call_soon_threadsafe`, closedloop/cancel controls | AnyIO при отдельном общем concurrency переходе, не ради callback bug |
| Numerical process timeout | Квалифицировать warm parent и reuse closed worker wire | Spawn/forkserver после фактического launch/cleanup сравнения, не automatic global change |
| Durable budget receipts | Узкий fileledger durability acknowledgement fix | SQLite transactional rows после measured receipt/IO growth; preserve sameevent/restore semantics |
| Checkpoint/orchestration | Existing CASCheckpointHook/idempotency/fencing | LangGraph persistentcheckpointer/Temporal только под реальный новый operational scope |
| Wire/canon | Existing tags и profile primitive поверх pinned codecs | Новый versioned interop profile, если настоящий consumer требует JCS; исторические hashes не менять |
| CAS/signature | Existing artifact owner + cryptography | Новый storage profile для реальной multi-host задачи; библиотека подписи не issuer trust/currentness |
| Migration | Общий linear engine с различными profiles; DataForge BFS отдельно | Индекс adjacency после measured large registry, не универсальный framework |
| JS architecture | Уже owned TypeScript AST | Semantic dependency graph tooling лишь при расширении контракта beyond syntax |
| Client transport | Исправить existing narrow generator сейчас | Рассмотреть package-owned openapi-fetch + ABI adapter, когда реально нужны новые OpenAPI serialization families |
| Distribution | Existing Hatch/PEP517/Q2 owner, одно artifact-bound CP6 окно | Новый frontend не даёт installedorigin доказательства сам по себе |

Основания: Python документирует безопасный межпоточный handoff и closedloop failure; pinned AnyIO4.12.0 явно различает ожидание cancellation и оставленный running thread. Это поддерживает малый adapter, но не даёт права освободить физическую capacity раньше job. [Python asyncio](https://docs.python.org/3.14/library/asyncio-eventloop.html#asyncio.loop.call_soon_threadsafe), [AnyIO4.12 source](https://raw.githubusercontent.com/agronholm/anyio/4.12.0/src/anyio/to_thread.py).

Python3.14 изменил default start method, а pinned JAX0.8.2 предупреждает о fork многопоточного runtime. Это аргумент за bounded topology qualification, не доказанный benchmark преимущества spawn. [Python multiprocessing](https://docs.python.org/3.14/library/multiprocessing.html#contexts-and-start-methods), [JAX0.8.2 source](https://raw.githubusercontent.com/jax-ml/jax/jax-v0.8.2/jax/_src/xla_bridge.py).

SQLite WAL требует same-host coordination и явной sync policy. NORMAL/FULL отличаются durability; перенос fileledger — настоящая migration/restore работа, не бесплатная замена JSON. [SQLite WAL](https://www.sqlite.org/wal.html), [SQLite synchronous](https://www.sqlite.org/pragma.html#pragma_synchronous).

LangGraph различает checkpoint/store, RAM saver теряет данные при restart. Temporal replay имеет determinism/versioning constraints. Ни одно из этого автоматически не реализует PolicyOS selectedview, scientific provenance или external effect reconciliation; existing Temporal adapter даже отказывает parentRunContext без receipt route. [LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence), [Temporal workflow definition](https://docs.temporal.io/workflow-definition).

Pinned orjson3.11.5 имеет собственную physical nesting boundary1024 и держит GIL при decode. JCS задаёт другой JSON canonical profile; cryptography.verify принимает exact bytes/key, а не purpose admission. Поэтому сохранение существующих protocol owners технически оправдано. [orjson3.11.5](https://github.com/ijl/orjson/tree/3.11.5), [RFC8785](https://www.rfc-editor.org/info/rfc8785/), [cryptography46.0.4](https://cryptography.io/en/46.0.4/hazmat/primitives/asymmetric/ed25519/).

TypeScript AST позволяет syntax-only pass без typechecker. openapi-fetch предлагает typed paths и serialization hooks, но API и package dependency ownership отличаются от current named client. ECMAScript прямо различает computed и noncomputed __proto__. [TypeScript Compiler API](https://github.com/microsoft/TypeScript/wiki/Using-the-Compiler-API), [openapi-fetch API](https://openapi-ts.dev/openapi-fetch/api), [ECMAScript object initializer](https://tc39.es/ecma262/multipage/ecmascript-language-expressions.html#sec-object-initializer).

PyPA build frontend вызывает проектный backend, а не устанавливает истинность installed provenance. Это остаётся задачей Q2 witness, который нужно переиспользовать. [PyPA build](https://build.pypa.io/en/stable/).

## 6. LANE-12: capability и улучшенный bounded end-to-end план

### 6.1 Смысл lane

**Finite supported surface → owner/lifecycle decision → built artifact → noneditable installed consumer → generated client → настоящий Runtime request/response.** Это не «удалены старые файлы». Пользователь должен получить действующую поставку, читающую supported data и исполняющую public operations без checkout magic, stale raw files или dashboard runtime coupling.
