### FED-02 B139 — настоящий JOIN потребитель, а не collector unit

Каноническая проверка вызывается через `DataComposer.compose(strategy=JOIN, audit_level=SUMMARY)`, потом читает returned frame и sample, `get_last_merge_summary()` counters. Fixture даёт одинаковый join key и equal priority, но разные values/row/event IDs; прогоняется при cap=1 и cap=3 и в FULL/NONE. ### BERL — условный и маргинальный Shapley решают разные математические задачи

Нужная conditional coalition function — `v(S;x)=E[f(X) | X_S=x_S]`. Обычный KernelExplainer подставляет absent features из background dataset, что задаёт другую игру и не оценивает корреляционное `P(X_notS | X_S)` сам по себе ([официальное описание KernelExplainer](https://shap.readthedocs.io/en/stable/generated/shap.KernelExplainer.html)). Shapley attribution меняется с выбранной value/game definition ([Sundararajan & Najmi, PMLR 2020](https://proceedings.mlr.press/v119/sundararajan20b/)); методы зависимости требуют conditional model/sampling ([Aas et al., paper](https://arxiv.org/abs/1903.10464)). Это prediction attribution, не `do()`-каузальный эффект.

Различающий oracle: `X~N(0, [[1,.8],[.8,1]])`, `f(x)=x1`, `x=(1,1)`. Conditional coalition values `(0,1,.8,1)` дают Shapley `(.6,.4)`; marginal background game даёт `(1,0)`. При `rho=0` оба должны дать `(1,0)`. Выбранный reuse: law-bound exact linear-Gaussian sampler + finite-support weighted empirical conditional profile, которые опираются на один проверенный joint-law artifact owner из IR uncertainty/совместимый F SCM law, затем повторно используют существующий BERL coalition engine, persisted ExplanationBundle и оба реальных readback consumer. Law должен bind bytes/digest, variable order, population/cohort/time, support, model/schema epoch и verifier provenance; отсутствующая или mismatched law даёт typed unsupported без marginal fallback. Допуск Gaussian требует конечности, symmetric PSD, rank-aware pseudoinverse и отказа для наблюдения вне singular support без незаметного jitter. Конечная эмпирическая поддержка exact strata; smoothing/kNN — новая методика и не входит в этот minimum.

В G97 есть реальная P38-divergence: `service.py@97#L431-L434` связывает `kernel_shap_conditional` с тем же `KernelSHAPAdapter`, который в `shap_kernel.py@97#L46-L60` заменяет absent features фоновыми строками. В результате conditional request может сохранить `conditional_observational` в assumptions, но вычислить marginal/background function. Это не diagnostic-only. Немедленный защитный шаг — typed unsupported/diagnostic без marginal fallback; это mitigation, не функциональная closure. Capability остаётся `producer_missing` до law producer/artifact/verifier, `bridge_missing` до conditional draws и вызова engine, `verification_missing` до independent oracle, и `surface_missing` либо явно утверждённого `surface_out_of_scope` для объяснительного output. TreeExplainer API отдельно требует выбирать feature-dependence mode/background, но существующий локальный `shap_tree` наследует empirical coalition engine; это не отдельный exact tree backend ([официальный TreeExplainer API](https://shap.readthedocs.io/en/latest/generated/shap.TreeExplainer.html)).
