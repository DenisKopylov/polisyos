## Решения для каждого E bundle

Ниже для каждого пакета: фактическое расхождение, минимальная реализация с владельцем, функциональный независимый тест и точный focused selector. Fixture достаточен для чистой алгебры/детерминированной логики; source law, реальная история, полномочие или публичный статус требуют привязанного артефакта и настоящего consumer readback.

### Backtest

<a id="bundle-bkt-01"></a>

**BKT-01 — `B166, B169, B170`; критерий `bundles/BKT-01.md:49–105`.** Маска должна выбирать точную историю, horizon/тип прогноза — соответствовать target, `n_simulation_runs=K` должен приводить к K реальным предсказаниям. Сегодня mask adapter может расходиться с `HistoricalValidationPlan`, scalar может broadcast’иться на horizon, а флаг числа запусков — не вызывать повторные `_predict`. Продолжить canonical `scientist/methods/backtesting/orchestrator.py::{run,_run_single_scenario}`: привязать start/end/cadence/mask/version/origin/horizon/target и IDs фактически прочитанных строк; scalar разрешить только scalar target; каждый replicate реально исполнять со seed/ID/version либо отказаться называть его ансамблем. Тест: независимая ручная временная разбивка и точные consumed row IDs; отрицательные off-by-one, future leak, reorder/missing date, broadcast, один вызов при `K>1`, повтор одинаковых seed/content; CAS readback. `cd policy-engine && .venv/bin/python -m pytest -q tests/unit/scientist/methods/backtesting/test_backtesting.py tests/unit/remediation/test_bkt_02.py`. Владелец: Scientist backtesting; реальные данные нужны для конкретного history claim. Статус: partial, mask/replicate consumer verification отсутствует.

<a id="bundle-bkt-02"></a>

**BKT-02 — `B167, B168, B171`; `BKT-02.md:49–105`.** Aggregator не должен терять пропущенные outcomes из requested denominator, ставить оценку пустому набору или смешивать номинальный уровень с фактическим coverage. В `orchestrator.py::_aggregate`/`evaluator.py::evaluate` отдельно хранить requested/eligible/observed; пустой результат не trust-eligible; зафиксировать `micro` (pool rows) и `macro` (среднее сценариев) как разные estimands. Оракул — ручной numerator/denominator; перестановка партиций сохраняет micro, macro меняется только по заранее объявленному weighting; CAS readback не теряет confidence level. `cd policy-engine && .venv/bin/python -m pytest -q tests/unit/remediation/test_bkt_02.py tests/unit/scientist/methods/backtesting`. Статус: ограниченный candidate, finding closure нет; PCL обязан использовать тот же eligible set.

<a id="bundle-bkt-03"></a>

**BKT-03 — `B172, B173`; `BKT-03.md:46–82`.** Невычисленный inference для ненулевого residual не означает «bias нет». Принятый bounded путь сохраняет residual, точную недоступность, degraded/no-grade; all-zero отдельно. Разделить два независимых контроля: balanced predictions `[0.99,1,1.01]` against 1 дают residuals `[-0.01,0,0.01]`, `t=0`, `df=2`, `p=1`; отдельный unequal-error oracle `[0.5,1.5,2.5]` against population mean 0 имеет mean 1.5, `t=2.59807621135`, `df=2`, `p=0.1216899343463`. Сверить оба с настоящим `scipy.stats.ttest_1samp` и backend-unavailable path, `n<2`, constant offset и нулевым identity. Удаление reason/status должно ломать trust assertion при тех же метриках; CAS readback запрещает grade. Владелец `scientist/methods/backtesting/orchestrator.py::_detect_systematic_biases`. Приёмка G узкая, 6+6 adversarial/removal controls; native 150-test replay имел 4 composition failures неизвестного происхождения, P41 не позволяет списать их. `cd policy-engine && .venv/bin/python -m pytest -q tests/unit/remediation/test_bkt_03.py tests/unit/scientist/methods/backtesting tests/unit/remediation/test_bkt_02.py tests/unit/ir/mirror_contracts/test_backtest.py tests/unit/scientist/governance/test_backtest_matrix.py`. Findings partial; тест не доказывает независимость residual, effective N или multiple-testing correction.

<a id="bundle-bkt-04"></a>

**BKT-04 — `B174, B175`; `BKT-04.md:44–84`.** CV материализует splits до `max_folds`; `step_size<=0` не прогрессирует. Bootstrap unknown name раньше молча становился mean. Владелец Scientist backtesting: ограничить генерацию splits до выполнения, валидировать шаг до callback; сохранить имя встроенного mean/median в artifact. Python `__name__` и caller label пользовательского callable остаются `consumer_asserted`, не identity/provenance. Независимый перебор resample индексов для `[0,0,9]` даёт mean/median percentile oracle и JSON readback; CV spy подтверждает максимум заданных вызовов и ноль при неверном шаге; same-name callable — отрицательный контроль. `cd policy-engine && .venv/bin/python -m pytest -q tests/unit/scientist/methods/backtesting/test_cv.py tests/unit/scientist/methods/backtesting/test_bootstrap.py`. B175 code-only (сырые deciding outputs не были доступны), B174 partial; не полагаться на summary receipt как воспроизводимый вывод.

<a id="bundle-cal-02"></a>

**CAL-02 — `B179–B182`; `CAL-02.md:47–112`.** Не позволять shape broadcasting строить all-pairs loss, sample weights отменять target priority, `where` скрывать NaN reverse-gradient или даты другого target менять scale. Продолжить `foundry/calibration/loss.py::{pointwise_base_loss,reduce_weighted_loss}` и `calibrator.py::_compute_scale_local`: проверять оси до broadcast, нормализовать samples внутри target, priority применять после редукции, безопасно сформировать обе ветви до conditional, scale считать только по своему observed training support. Статус partial; fixture не заменяет источник measurement/model.

<a id="bundle-cal-03"></a>

**CAL-03 — `B183, B195`; `CAL-03.md:45–80`.** Отдельный span на каждый multi-start; finite numeric loss только для выбора; missing, singular, negative и ill-conditioned Hessian различать. Главный семантический риск: текущий calibrator минимизирует residual/prior penalty, а `hessian.py::compute_hessian` eigen-clips generic loss curvature, после чего отдаёт finite inverse как covariance/std. Выбранная функциональная граница: generic loss → только curvature diagnostic; likelihood-MLE → covariance только для заявленного likelihood и достаточных regularity/curvature условий; полный negative log posterior → только явно названный Laplace approximation. Сохранять raw spectrum/rank/threshold/dtype и причину exact vs FD; bad spectrum не чинить в публикуемый CI. Оракул Gaussian NLL `L=.5*((θ1−1)^2/4+(θ2−2)^2/9)` даёт MAP/MLE `(1,2)`, Hessian `diag(1/4,1/9)`, inverse `diag(4,9)`, std `(2,3)`; такой же Huber curvature не получает inferential covariance; saddle/flat/nonfinite — unavailable. Также два реальных span и finite minimum oracle. Пути `foundry/calibration/{multi_start,hessian,calibrator,identifiability}.py`; `cd policy-engine && .venv/bin/python -m pytest -q tests/unit/remediation/test_cal_03.py tests/unit/remediation/test_cal_04.py tests/unit/foundry/calibration/test_hessian.py tests/unit/foundry/calibration/test_calibrator.py`. Generic tests sufficient; нет утверждения об identifiability production-fit. Partial.

<a id="bundle-cal-04"></a>

**CAL-04 — `B184, B196, B203`; `CAL-04.md:45–105`.** Отчёт не должен трижды запускать модель, пропускать конечный optimizer iterate или переиспользовать Hessian при изменении weights/seed/dtype/numerical policy/model. В `foundry/calibration/calibrator.py` retain objective’s evaluated forward outputs, сравнивать только проверенные checkpoints (или один финальный вызов) и использовать эти же данные в report; кэшировать только при полном ключе `(parameters, target/sample weights, seed, numerical policy, model/plan version)`. Линейный closed-form objective + счетчик evaluator; независимо менять каждый компонент key, проверять cache miss; collision при удалённом поле должен провалить тест; CAS report связывает финальные параметры/seed/loss. `cd policy-engine && .venv/bin/python -m pytest -q tests/unit/remediation/test_cal_04.py tests/unit/foundry/calibration`. Partial; production dataset нужен только для качества конкретного fit.

**A-owned authority predicate:** trusted runtime composition выбирает in-process verifier и admitted source/design/rule profile независимо от любого E payload/ref/declared verifier ID. Этот verifier разрешает CAS bytes и независимо пересчитывает source, split/horizon, exact paired row IDs/counts, threshold, temporal roles и purpose. Сверенная candidate receipt — только вход/свидетельство, не доказательство issuer. A выпускает собственный verification result/provenance в фактической default projection; свежий read того же projection заново проверяет/пересчитывает основание, а не доверяет сохранённому `verified=True`. Не создавать криптографическую issuer registry/service; внешнее институциональное утверждение об issuer остаётся unsupported, если нет уже существующего совместимого typed contract. Валидный по hash/role/schema CAS с `credible=True`, но с unadmitted profile или leaky split должен fail на recompute; самодекларация даже с правильными полями не заменяет A verifier. Пока этот A verifier/result path не существует, authority — `not_established`, predictive candidate остаётся limited; closure конечна для одного admitted profile и названных recompute/readback tests, а не бессрочный production hold.

A verifier допускает verified evidence только для matching predictive-calibration purpose; causal-effect, treatment-assignment и policy-purpose authority остаётся denied.

Оракул: ETS-generated predictions с paired synthetic heldout outcomes, независимый ручной interval numerator/denominator и POST→persist→GET через настоящий default caller до S10 builder; matching-purpose predictive calibration принимается только после A-owned recompute, а неподходящая цель не получает полномочий.
