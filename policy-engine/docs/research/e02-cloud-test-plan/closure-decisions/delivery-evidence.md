Ошибок JSON, old-summary blob mismatches и прямых source-SHA binding misses — ноль. Ранее 13 source commits ошибочно классифицировались как unbound из-за неполного извлечения; полные JSON поля `production_sha`, `source_sha`, `implementation_sha`, `original_to_aggregate_implementation_commits` и др. дали точные binding + Git tree/diff witnesses для всех 13. Это исправление identity-учёта не приёмка поведения: локальный retained report `policy-engine/_build/e02-g-incoming/bdef-source-binding-reconciliation.json@sha256:36c37eff2e6910222ee3318f9c5441dcd952cce95a8439c26b14ac942f32a674` (не включён в Git; identity-проверку можно повторить по exact heads/blobs из `input-identity.json`) явно говорит `code_acceptance: not assessed`, `tests: not run`, `finding_or_science_closure: not assessed`.

Существенные интерпретации:

- B EXE receipt `exe-cold-seed.json@79abecd…` корректно pin-ит production `515054e7427467bf6e72fcfa22cc809c7cfe2c19` / tree `bad622f8…`. Aggregate candidate tree равен tree тестируемого source. Это устраняет предположение о клонировании несовпадающего production source, но не подтверждает сами tests.
- D transfer `transfer-workflow-4097.json@83b5b…` содержит верный `production_implementation_sha=830ddd…` и его tree. Указанные там `deciding_candidate_sha=4097a017…` и tree `c469ba35…` отсутствуют в frozen Git object store; этот исторический test decision нельзя независимо привязать к candidate. Продолжить с актуальных committed D code/test receipts; старый SHA искать только среди опубликованных объектов, не восстанавливая ephemeral workspace. Это не доказательство неправильного production SHA и не поведенческий FAIL.
- Ранние кажущиеся дополнительные F API/CAU candidates не являются отказом уже принятых slices: checkpoints 03/05 pin-ят API `0c709…` и CAU `c8e16…`; их accepted heads `baada…` и `6a6dd…` являются потомками кандидатов, а mechanism blobs совпадают с bounded admission. ## Недостающие outputs, proxy claims и следующие действия

1. **Сначала закрыть реальные consumer escapes.** B owner должен связать connector handle/cancellation/deadline и executor lifecycle с source-bound terminal settlement. C и B совместно должны воспроизвести cap=3→1 restart на настоящем CAS/CursorStore, затем либо допустить несовместимое состояние до poll/flush, либо вернуть typed refusal без потери данных. D должен заставить каждый transfer reader читать одну атомарную generation и отклонять устаревшие generation keys; RL/search должен принимать только точную typed version без bool/float alias.
2. **Восстановить действительные producers/bridges.** A — served ordinary request → owner-bound candidate context → persisted N5 → independent N8 readback, с declared unknown profile и без protected authority. E/A — закрыть FRC01 и фактический `generation_cycle`→S10 verifier/readback. Scientist `reconcile_causal_graph` ref-normalization consumer не назначен C-owned; возможный F writer — лишь proposal, G0 должен назначить owner. CAN adapter не закрывает общий raw-Core writer bypass. F — salt consumption в compiler→execution plan, а не только compile ABI.
3. **Не принять отказ за заявленную функцию.** CAL-05 отказывает на unsupported heterogeneous schedule; FRC ограничивает producer и CAS evidence, но не служит credible evaluator; GCM percentiles нельзя маркировать как estimator confidence intervals; `dowhy_available` не доказывает, что DoWhy backend исполнялся; RDD point-only результат не заменяет RBC и корректную variance correction. В F audit эти расхождения привязаны к конкретным producer/consumer paths; научные методы и supported assumptions требуют отдельного typed profile, а не позитивного marker.
4. **Сохранить настоящие skipped/UNRUN.** Broad freeze/replay и общий CI остаются не выполнены/красными согласно owner reports. Отсутствующий SALib — SKIP, отсутствующая production catalog DB — setup nonmeasurement, отсутствующие production history/data — `not_established`, а не PASS или продуктовый FAIL. После замораживания exact source выполнить один общий replay и отдельно повторить только downstream consumers, чьи upstream contract blobs изменились.
5. **Closure вести отдельно от code GO.** Перед статусным решением взять полный исходный критерий каждого ID, доказать producer→persisted artifact→bridge→consumer→surface, независимо пересчитать собственное deciding property и выполнить divergent removal/adversarial control. Применить P40: на второй escape одного класса расширить общий seam или объявить проверяемую ограниченную границу; не множить patch-пер-случай. Применить P41: красный owner gate остаётся `not_established` до exact-slice-base replay и полного input intersection.

Решающие code/closure predicate labels: completeness owner tables — `independently_reconciled`; проверенные локальные runtime properties каждого exact candidate — только настолько `recomputed`, насколько закреплены его deciding logs; identity receipt fields без Git/output witness — `consumer_asserted`; отсутствующие production data, object SHA и science owner rules — `not_established`. Ни красивый handoff, ни количество PASS, ни `closure_ids`, ни отсутствие ошибки JSON не меняют этот классификатор.
