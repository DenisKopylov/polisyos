## C — conditional explanations и embedding retrieval

### SHAP: библиотека не создаёт отсутствующий закон условного распределения

В `berl/adapters/shap_kernel.py@97c85fae2d4505ec8248540d98b9556296244208:L46-L59` coalition value строится заменой исключённых полей целыми `background_rows`; затем берётся среднее предсказание. Это вычисляет Shapley по эмпирической interventional/replacement игре, а не `E[f(X)|X_S=x_S]` для произвольных коррелированных признаков. `shap_tree.py@97c85fae2d4505ec8248540d98b9556296244208:L17-L62` сейчас является ясно помеченным точным empirical fallback, а не вызовом TreeSHAP. В отдельной F/DML интеграции `_econml_adapter.py@97c85fae2d4505ec8248540d98b9556296244208:L211-L275` действительно вызывает `shap.TreeExplainer` над моделью CATE и выдаёт среднее `abs(SHAP)` как feature importance; это характеристика конкретной fitted-модели, не causally identified effect attribution.

Официальный `TreeExplainer` поддерживает `interventional` с предоставленной background law и `tree_path_dependent` на статистике путей дерева; `auto` выбирает между ними. Документация объясняет зависимость feature-expectation от assumptions, но не обещает произвольный conditional sampler для любой зависимой выборки: [SHAP TreeExplainer](https://shap.readthedocs.io/en/latest/generated/shap.TreeExplainer.html). PyPI уже публикует stable SHAP 0.52.0 и стандартный CPython 3.14/macOS arm64 abi3 wheel; это решает packaging availability, но не семантическое расхождение и не доказывает runtime в PolicyOS: [SHAP release files](https://pypi.org/project/shap/).

**Свойство против реализации (P38).** Свойство conditional profile: коалиция использует content-bound `P(X_-S | X_S=x_S)` из объявленного закона. Реализация проверяет лишь background presence/shape и фактически вставляет наблюдаемые строки background. Контрпример: коррелированные Gaussian `X1,X2`, модель `f=X1+X2`; условное ожидание `X2|X1` меняется с `X1`, тогда как независимая замена `X2` маргинальными background значениями этого не делает. Поэтому не переключать поле policy на `conditional` лишь по строковому marker.

**Минимальная поддержка.** Сохранить текущий точно ограниченный `empirical_interventional` profile. Для conditional добавить один law-specific owner: сначала exact linear-Gaussian conditional expectation при content-bound `mu/Σ`, валидированной ковариации и конечном диапазоне; всё вне profile — typed `unavailable/assumption_not_established`. Тест использует hand-derived условное среднее и независимое перечисление маленькой игры, коррелированный negative, независимый-feature control и повреждённую/несимметричную covariance. SHAP может быть независимым TreeSHAP baseline только в его документированных assumptions, но не oracle общего conditional path.

Предлагаемые affected checks: `cd policy-engine && uv run --extra test pytest tests/unit/berl/mirror_contracts/test_shap_kernel.py -q` плюс новый behavioral test в `tests/unit/berl/` на коррелированном Gaussian. Настоящая TreeExplainer интеграция имеет отдельный selector после установки назначенного optional profile; текущий exact fallback не считается её запуском. Отдельный profile не добавлять в обязательное ядро ради случайного feature-importance output.

## E — SciPy, JAX and SALib can be reused; numeric contracts remain owner code

### DOE / sensitivity

`scientist/methods/doe/sampling.py@97c85fae2d4505ec8248540d98b9556296244208:L19-L60` is the canonical SALib sampler. It prefers `SALib.sample.sobol.sample`, passes `seed`, and only tries legacy `saltelli.sample` as a seedless fallback. `doe/analysis.py@97c85fae2d4505ec8248540d98b9556296244208:L87-L164` verifies Morris plan geometry, binds levels, passes a seeded analyzer and explicitly refuses seeded FAST while SALib 1.5.2 mutates the process-wide NumPy RNG. Keep those boundaries and refusals. Official SALib marks `saltelli.sample` deprecated since 1.4.6 and its Sobol-extension rows are intended for `SALib.analyze.sobol`; current `sobol.sample` exposes scramble/seed. [SALib sampling API](https://salib.readthedocs.io/en/latest/api/SALib.sample.html).

The divergence is the sibling `scientist/methods/autotune/sensitivity_bridge.py@97c85fae2d4505ec8248540d98b9556296244208:L63-L113`: it constructs a plan then independently imports Morris and deprecated Saltelli samplers and generates rows itself (without seed) before calling canonical analysis. This is duplicate sampling ownership (P27), not a reason to replace SALib. Route that bridge to `generate_sensitivity_samples(plan)` and leave analysis geometry checks at the canonical analyzer. Positive: known Ishigami/linear function with fixed seed, correct design dimensions, repeated same design and correct Morris trajectory order; independent analytic Sobol/Morris ranking. Negative: wrong Morris levels, rows from unrelated/seed-mismatched design, truncated/reordered Saltelli blocks, and test proving deprecated sampler path is no longer reached. Retain a typed refusal for seeded FAST until deterministic isolation proves no global RNG mutation.

Do not pretend Sobol balance for arbitrary row counts. SciPy `Sobol.random_base2(m)` gives `2**m` balance; `random(n)`, skipping or thinning loses that guarantee. This can be a bounded design profile rather than forcing huge 2^m runs: record design kind, actual N, scramble/seed and whether balance guarantee applies. Randomized replicate scrambles must be independent where used for error estimation. [SciPy Sobol](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.qmc.Sobol.html).

### Hessian and AD

`foundry/calibration/hessian.py@97c85fae2d4505ec8248540d98b9556296244208:L115-L160` computes `jax.hessian(loss_fn)`, falls back to finite differences, clips all eigenvalues below a floor, then inverts repaired curvature and exposes the result as `covariance`. JAX correctly differentiates the given function; it cannot establish that this arbitrary squared/Huber objective is a negative log-likelihood/posterior or that the evaluation point is an admissible optimum. `jax.hessian` documents a derivative of `fun`, not a covariance conversion: [JAX Hessian API](https://docs.jax.dev/en/latest/_autosummary/jax.hessian.html). Keep JAX autodiff for supported JAX-compatible objectives, and use SciPy/NumPy only for independent small linear algebra/quantile controls. Do not switch to SciPy Hessian/optimizer just to preserve the same unsupported inferential claim.

Minimal owner fix: label output as curvature diagnostic unless an objective-kind contract explicitly admits likelihood/posterior and stationary positive curvature. Reject/retain negative, singular, materially ill-conditioned and precision-limited directions; finite difference is a diagnostic comparison with step-size/convergence checks, not a silent path to accepted covariance. Independent check uses an analytic quadratic with known Hessian, saddle/flat negatives, and a non-likelihood Huber case that must remain `not_inferential_covariance`. Run through calibration consumer, not just a constructor. Selectors: `tests/unit/foundry/calibration/test_hessian.py`, `tests/unit/foundry/calibration/test_pure_executor_semantics.py`.

For mapped schedule predicates, the target behavior is a bounded per-row path implemented with `jax.lax.map` in the canonical calibration owner, not indefinite refusal as the only supported API. `vmap` over a `lax.cond` predicate converts it to `select`; it can execute/trace both branches. Current `apply_nodes` correctly rejects mapped schedule predicates and accepts either shared scalar schedules under `vmap` or explicit scalar calls under `lax.map`. The existing mixed-schedule `lax.map` proof is test-local; G97’s `run_pure_scan` and `runtime.step` consume scalar/common schedules, and a bounded vector wrapper for the real caller is not present. Add that owner wrapper with explicit aligned batch dimensions for states, per-row keys, and schedules, delegating each item to scalar `apply_nodes` via `lax.map`; route the real consumer that needs heterogeneous schedules through it. Keep the mapped-predicate refusal at `apply_nodes` as defense in depth; don't mark `supports_vmap` or weaken the refusal. Official JAX documents that `vmap(cond)` is converted to `select` and that `lax.map` maps with per-item control flow: [JAX lax.cond](https://docs.jax.dev/en/latest/_autosummary/jax.lax.cond.html), [JAX lax.map](https://docs.jax.dev/en/latest/_autosummary/jax.lax.map.html). The defining consumer oracle uses mixed active/inactive schedules and a counted numerical callback to prove zero inactive executions, checks active outputs/gradients and per-row PRNG advancement, and compares the mapped results to independently invoked scalar calls. Existing owner tests in `tests/unit/foundry/calibration/test_pure_executor_semantics.py` prove mechanism behavior, not a product caller; until that wrapper is wired, the vector consumer is `consumer_missing`.

### Covariance and Monte Carlo range
