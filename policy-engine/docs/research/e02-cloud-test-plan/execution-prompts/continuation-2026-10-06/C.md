# Продолжение E02: локальная группа C

Сначала полностью прочитай `AGENTS.md`, `policy-engine/CONTRIBUTING.md` и `policy-engine/docs/research/e02-cloud-test-plan/execution-prompts/HANDOFF.md`, прежде чем выполнять работу. Короткие E02-пути в этом поручении означают `policy-engine/docs/research/e02-cloud-test-plan/`; команды ниже выполняются от корня репозитория, кроме явно указанного subshell. Все необходимые решения находятся в tracked `closure-decisions/`, а локальные ignored outputs не являются входом облачной задачи.

Перед созданием любого checkout/worktree прочитай `policy-engine/tools/devx/workspace/README.md#worktree-admission`, выбери реальные точные branch и absolute worktree root, и выполни read-only `workspace doctor --worktree-admission create` с этими `--branch` и `--path`. Сохрани полный JSON; после создания проверь тот же pair через `resume`. Resume до создания допустим только для явно возобновлённой совпадающей lane. Не запускай команды с неразрешёнными placeholders и не prune-ь старые регистрации автоматически. Git — обязательный handoff для G; в другие пользовательские чаты не отправляй сообщения без прямой авторизации человека. После сохранения deciding outputs и полезных изменений переносите повторимые тестовые каталоги и использованные рабочие окружения только в Корзину. Корзину не очищайте; production data, код, полезную документацию и уникальные данные сохраняйте.

A–F работают только на собственных topic branches и не публикуют в `main`. G — единственный publisher интеграционной ветки. Будущая публикация в `main` требует отдельной явной авторизации пользователя для конкретной публикации; разрешение на уже опубликованный anchor не является постоянным.

Для admission назначь shell-переменным `E02_TOPIC_BRANCH` и `E02_WORKTREE_ROOT` выбранные реальные значения (второе — absolute path), затем выполни от корня репозитория:

```sh
(cd policy-engine && uv run --no-sync polisyos-tools workspace doctor --worktree-admission create --branch "${E02_TOPIC_BRANCH:?set actual branch}" --path "${E02_WORKTREE_ROOT:?set absolute worktree root}")
```

После создания checkout повтори ту же команду с `--worktree-admission resume` и той же парой. В облачной среде без штатной Корзины не удаляй данные навсегда: перечисли точные cleanup candidates в handoff.

Ты — локальный оркестратор C. Продолжай работу после публикации интеграции в main. Исполни полный собственный набор C до работающего producer → typed artifact → bridge → consumer и независимой проверки; для каждого finding вынеси отдельный verdict. Ещё один удобный bounded subset не завершает пакет.

## Выбранные discriminators

- **ING streaming.** Раздели B83 (86,400 секунд по persisted UTC ingestion time и точному source-owned event/version key в source/partition scope), B84 (retained operator state, вход до materialization и output refs) и B86 (row schema membership). Для B83 докажи a,b,c,a при cap=2 до/после restart, expiry и межисточниковую изоляцию независимым reference map. Entity ID, local hash и count-only eviction не заменяют ключ/TTL; missing key → typed unsupported, live-key overflow → durable bounded index/spill или refusal до eviction. Для B84 при restore на меньшем cap откажи до flush/write/cursor advance с сохранением predecessor либо используй настоящий staged spill reader; тестируй и pre-materialization cap. Это не RSS claim. B86 требует одинаковых membership/quarantine при batch sizes 1/2/8 для declared required/optional/missing/null/type/finite schema. Также доведи B79/B80/B81/B82/B85/B88 через реальный cursor → connector, per-source confirmed progress, failure/reopen/retry, window checkpoint/restart, все chunk ArtifactRefs и served replay из точного CAS ref.
- **CAN LA-021.** Bounded IR adapter уже принят, но raw Core put_bytes обходит канонический путь. Проведи полный caller census и закрой класс bypass единым canonical writer/strangle; не пиши адаптер по одному caller. Проверяй каждую живую Core/IR consumer цепь и adversarial raw-Core control.
- **BERL LA-034/036.** Целевая функция v(S;x)=E[f(X)|X_S=x_S]; KernelExplainer background replacement — другая marginal/interventional игра. Один content-bound/verifier-admitted law должен связать точные bytes, source/model/population/cohort/time, переменный порядок, schema/model epoch, support и provenance. E law допустим; F SCM только при точном совпадении nodes/population/schema/epoch. Переиспользуй coalition engine и оба readback: Runtime explanation_reliability и Scientist phase5_preflight. Gaussian oracle для rho=.8, f=x1, x=(1,1) даёт conditional Shapley (.6,.4), marginal (1,0); при rho=0 обе игры дают (1,0). Используй rank-aware pseudoinverse, symmetric PSD validation, singular-support refusal и не добавляй jitter. Второй профиль — weighted finite-support discrete law по точной страте и выровненным исходным строкам; unsupported без fallback.

  Нелинейную precision сертифицируй только для независимо доказанного structural bound f∈[a,b], admitted law и IID conditional draws. До запуска заморозь K coalitions, epsilon, delta, seed и draw cap; N=ceil((b-a)^2*log(2*K/delta)/(2*epsilon^2)). Для target Shapley error epsilon_phi используй epsilon=epsilon_phi/2. cap<N → precision_not_met с achieved error; не урезай N, не останавливайся по обычному repeated-peek CI. Unbounded f допускает только diagnostic fixed-N estimate/asymptotic MCSE, без precision_met. Сними law/bound admission, сохранив markers, как negative control.
- **FED B139.** Реальный DataComposer.compose(JOIN, SUMMARY), возвращённый frame/sample и get_last_merge_summary(); direct collector/UNION не подходят. Сверь cap=1/3 и FULL/NONE с независимым stdlib relational oracle, включая event identity, counters, seeded top-k и ties. Внешний Federation HTTP/export endpoint не требуется исходным критерием: surface_out_of_scope. Проверь остальные FED criteria в настоящих composer consumers.

## Работа и приёмка

Используй до 20 полезных прямых помощников, без субагентов у помощников. Раздели независимые writer families и read-only lanes; один writer на shared mechanism/test/lock/schema. Автор не рецензирует свой код. Не назначай шесть review на мелкую правку. Работай с G через Git receipts/commits, не через отправку сообщений в чужие чаты.

A/C/G делят локальный compute: одновременно только один тяжёлый numerical/full-data run и один numeric thread, пока фактические ресурсы не подтверждают запас. Лёгкие проверки, обзоры и bounded fixtures продолжай параллельно. Production data остаётся локально и read-only; используй только если criterion intrinsically data-dependent и fixtures не подходят. Недостающая DB/archive/backend — UNRUN/typed limitation с точным missing input, не PASS и не автоматически продуктовый дефект.

На каждом slice проверь точные candidate/base/tree, committed handoff, ancestry, полный diff включая tests/companions и canonical owner. Нужны реальный positive producer→artifact→bridge→consumer, независимый oracle, adversarial/removal control и affected importer/consumer checks. Назови divergence property/code (P38), классифицируй gate basis (P37). P41 exact-base replay нужен только для утверждения inherited red и полного input-denominator disjointness. Сначала commit implementation, затем отдельный handoff JSON, ссылающийся на implementation SHA/tree и сохраняющий commands, inputs, outputs, negative control, limitations и следующий owner. Проверяй branch attachment и remote readback.

Не запускай broad regression после каждого merge: повторяй только зависимые checks после изменения upstream contract; общий дорогой replay G выполнит после freeze integration SHA. Принимай код отдельно от finding closure. Финальная таблица перечисляет все C findings с criterion-backed verdict и deciding receipt, unavailable inputs, skipped backends и remaining verification.
