# Общие условия следующего продолжения A–F

Эта группа заданий заменяет прежние continuation prompts там, где они расходятся с исходным acceptance criterion. Исторические receipts сохраняют прежний source/profile и не становятся доказательством нового критерия. Цель продолжения — закончить доступные механизмы и их проверку; новый summary или рост числа PASS сам по себе задачу не завершает.

Полностью прочитай корневой `AGENTS.md`, `policy-engine/CONTRIBUTING.md`, `execution-prompts/HANDOFF.md`, failure/repair register, organization и свой closure-decisions pack. Перед использованием baseline запусти `import_results.py --check`, затем прочитай весь `results/verification.json`; после этого используй `query.py --unit <unit> --failures-only --limit 30` и точечные запросы. Полные первичные denominators — 127 bundles и 282 finding IDs. Лимит query, название PR и короткая подпись не назначают owner и не заменяют исходную карточку.

Документы опубликованы в `codex/e02-integration`, а не в `main`. В начале fetch `origin`, запиши точный fetched G SHA/tree и прочитай этот pack из него. Если файл отсутствует в своей ветке, его можно прочитать без переключения checkout:

```sh
git fetch origin codex/e02-integration
git show origin/codex/e02-integration:policy-engine/docs/research/e02-cloud-test-plan/execution-prompts/continuation-2026-10-07/README.md
```

Продолжай свою оригинальную topic history в существующем подходящем checkout. Проверь branch/path/status и workspace admission/resume до записи. При неожиданной ветке или HEAD не исправляй состояние reset, rebase или переключением. Если подходящего checkout нет, создай изолированную копию явно нужного topic через admission, сохранив существующую работу. Fetched G — опубликованная зависимость; его наличие не означает, что G уже принял весь твой carrier. Implementation candidate, проверенный runtime, receipt commit и transfer head имеют разные роли.

Для каждого ID сверяй полный исходный criterion, а затем разделяй остаток на mechanism, verification/oracle, missing input и semantic-owner decision. Дополнительный будущий product contract записывай отдельной задачей; он не меняет исходный критерий. Не требуй новую нормативную ратификацию для эквивалентного переноса существующего поведения. Не выдумывай authority, current-law evidence или данные, которых нет. Недостающий внешний вход имеет минимальный owner packet: кто поставляет, точный artifact/contract, producer и consumer, положительный и отрицательный сценарии, ожидаемые bytes/profile и причина отсутствия. Пока вход отсутствует, остальные готовые задачи продолжаются.

Используй до 20 полезных прямых помощников по реальной очереди, без детей. Разделяй canonical writers, tests/companions и независимых reviewers; автор не принимает собственный механизм. Helpers не пишут в integration. A владеет `generation_cycle.py` и HTTP `run_lifecycle.py`; C — `fabric/data_plane/streaming.py`. B/E передают им артефакт и сценарий. Четыре declared edges: `CYC-01→FRC-01`, `EMP-01→FRC-02`, `CYC-02→RES-03`, `NET-01→ING-02`; фактические CAS/UQ/graph/history impacts проверяются дополнительно по изменённому контракту.

B/D/E/F в облаке запускают готовые независимые проверки без искусственной общей квоты CPU/численных потоков/workers. A/C/G делят локальную тяжёлую очередь; лёгкие checks и review продолжаются. Сериализуй действительно общий mutable writer, DB, fixed port или scratch. Production data остаются локально read-only и нужны только там, где этого требует criterion. SIGKILL — фактическая незавершённость: причину устанавливай отдельно, не называй его ни PASS, ни доказанным OOM/product defect. Сохрани выполненные случаи и недовыполненный знаменатель, не сужай утверждение незаметно.

Сначала reuse-existing, затем extend/consolidate. Проверяй реальный runtime property, независимый oracle и adversarial/removal discriminator на immutable candidate с isolated inputs. На новые commits переносится только неизменившаяся часть review; delta и dependencies проверяются отдельно. Broad regression не повторяется после каждого merge: после всех source changes и независимых reviews — один freeze и дорогая wave. G отдельно выполнит общий integration replay и criterion-dependent local closeout.

Каждый готовый slice передаётся ordinary Git: original base/candidate/tree, полный code/test/mandatory companion footprint, canonical writer, consumer/surface, negative, полный deciding output, environment/input identity и limitations в committed `implementation-handoffs/<unit>/<slice>.json`. Implementation и receipt — отдельные commits. Большие raw dumps остаются ignored с path/hash; если deciding bytes не доступны приёмщику, укажи это и точный rerun. P41 inherited red требует replay на настоящем slice-base и полного zero-intersection input denominator; иначе `not_established`.

Завершающий отчёт покрывает все свои ID: выполненный код, результат каждого исходного критерия, рекомендации finding outcome, G acceptance отдельно, unavailable inputs, skipped backends и remaining verification. Ни metadata audit, ни один fixture, ни число PASS не закрывают всю capability. G остаётся единственным integration publisher. Разрешены собственные topic commits/push; `main`, force-push и переписывание истории не разрешены.

Сохраняй production, функциональный код, полезную документацию и уникальные inputs/deciding receipts. После их сохранения и проверки отсутствия активных пользователей переносить использованные воспроизводимые fixtures, source copies, environments и старые сессии только в штатную Корзину. Никогда её не очищай и не удаляй постоянно. Без native Trash в облаке — только точный список кандидатов. Контролируй свободное место до/после локального прогона; 25 GiB — ориентир раннего предупреждения, не запрет на полезную лёгкую работу.
