# Общие инструкции для параллельного исполнения E02

Эти инструкции обязательны вместе с конкретным role prompt. Работай по своему закончённому свойству, а не повторяй всю старую очередь A–F. Оригинальные unit/bundle/finding owners сохраняются; C01–C13/L01/L02 — execution roles. Formal closure и integration acceptance принадлежат G.

Проверь `pwd`, Git root, attached branch, HEAD/tree/status. Unexpected состояние не исправляй reset/rebase/switch; сохрани диагностику, продолжай доступную read-only работу.
2. Fetch `origin` и published `codex/e02-integration`. Прочти из Git этот каталог, `dispatch.json`, предыдущий `integration/connected-closeout-plan-2026-10-08/{inputs.json,tasks.json}` и только относящиеся к роли разделы decisions/delivery/inputs/source-selection. Не предполагай, что эти документы уже находятся в `main`. Если локальный checkout старый, сначала читай их через `git show origin/codex/e02-integration:<path>`.
3. Запиши exact fetched G/source/component SHA/tree и полный input closure. Исходный source из dispatch — старт для исследования, не автоматически совместимый или принятый G код. Carrier/root receipt отличается от source freeze. Existing paused matching lane можно продолжить с сохранением history; новую ветку/директорию выбирай по фактическому host inventory, не по примерному пути из чужого cloud receipt.
4. До commissioning нового branch/path выполни read-only workspace admission с **обоими точными selectors**. Команда и exit semantics находятся в `policy-engine/tools/devx/workspace/README.md#worktree-admission`: `uv run --no-sync polisyos-tools workspace doctor --worktree-admission create|resume --branch <chosen-branch> --path <actual-absolute-repo-root>`. Create — только новый pair; resume — существующий явно matching pair. Root сериализует создание и повторяет admission перед ним/после него. Receipt не reservation. При stale registration установи точную причину и варианты сохранения/recommissioning; не применяй prune/reset и не объявляй это product failure. Неполный admission ограничивает mutation этого pair, но не остальные read-only проверки/другие готовые роли.
5. Один production writer на path. До authoring перепиши declared lease в actual source/test/companion paths из выбранного candidate; source input SHA проверяй через Git. Shared contract, facade, lockfile и generated output не становятся твоими только из-за importer dependency. Подготовь requirement/patch своему canonical partner, а не конкурентную правку. G публикует composition/owner decisions и generated companions.

## Начало без искусственной очереди

У задач три фазы: independent preparation; authoring на зафиксированном собственном contract; composed acceptance на exact partner inputs. Уже сейчас выполняй полный source/diff review, fixture/oracle/discriminator, объявленный candidate-local baseline и свободную owned mechanism работу. Не жди окончания соседнего bundle. При missing semantic rule сначала реши свой конкретный вопрос с canonical owner и независимым discriminator; не выдумывай внешнюю law/authority. При unavailable factual input заверши generic mechanics/refusal, публикуй минимальный missing packet и продолжай другие свободные задачи роли.

После upstream delta перепроверь только её dependencies и affected consumers. Для composed verdict фиксируй все partner source/test/config/lock/companion blobs; старые PASS переносимы лишь для unchanged inputs. Carrier/doc-only commits не превращают UNRUN в PASS. Ни в одном consumer не повышай candidate/simulation/predictive result до empirical/causal/public authority по shape, имени, `.ok`, bool, source label или соседнему receipt.

## Делегирование и среда

- Если это **user-owned root/orchestrator**, используй полезные прямые helpers по actual queue до доступного лимита, не больше20. Одновременно занимай свободные механизм, oracle, negative, reviewer и receipt роли. Один уровень: helpers не делегируют и не создают детей.
- Если role prompt получен **как direct subagent assignment**, выполни свою роль сам; не создавай subagents. Write paths и ветку предоставляет root. Root не пишет поверх твоего lease.
- Code author не independent reviewer своего кода. Независимый reviewer читает exact immutable candidate/tree; testing получает isolated source/CAS/basetemp/ports. Один computed count или marker не заменяет behavioral property/removal.
- В cloud выполняй готовые проверки, включая тяжёлые, параллельно; не назначай искусственных CPU/process/test-worker quotas. Сериализуй только реальный общий mutable resource. Product workload admission, который проверяет B56, — свойство runtime, а не квота cloud оркестратора.
- В managed cloud сначала примени доступный environment-runtime skill/инструкции proxy, CA и credentials. Используй locked profile: app Python3.14; отдельный **Linux/Python3.12/DoWhy0.14** worker; optional GP `search_bo`; Node22 и `corepack pnpm` frozen workspace. Не отключай platform/authority guards ради PASS. Missing backend/runner до свойства означает UNRUN/ERROR с полной причиной, а не FAIL самого свойства.
- Для этой следующей организации пользователь явно выбрал размещение по compute/data: A/C fixture-based code authoring разрешено в cloud; это уточняет прежний default location в HANDOFF, но не меняет canonical logical writer. Production payload остаётся только локально read-only. Cloud использует portable fixtures/синтетические law, source/config profiles и non-secret receipts. Не проси выгрузить dataset, history corpus, embedding assets или confidential rows в cloud.

## Проверки и delivery

- Сначала исходный criterion/property и smallest distinguishing case; затем positive, boundary/adversarial и matched removal с сохранёнными markers. Если это second same-class escape — widen один canonical mechanism либо ограничь и выполни falsifier (P40); не начинай новую лестницу named-type patches.
- Во время authoring проверяй changed defining path и affected consumers, Ruff/type/architecture по blast radius. Широкий дорогой integration replay выполняет C13 один раз после **G source freeze и independent reviews**. Local authentic closeout — L02/G на том же source. Не запускай broad после каждого merge.
- Фиксируй actual wall/RSS/env и explicit measured timeout; disconnected/offline/signal9 с неизвестной причиной не приписывай коду. Сохраняй полный stdout/stderr/JUnit и deciding removal output; source manifests и generated runtime outputs раздельны.
- Законченные implementation commits, tests и mandatory companions сохраняй ранними clean boundaries; затем committed handoff JSON указывает exact implementation SHA/tree, base, branch, полный footprint, checks, oracle/negative, property/consumer/surface, limitations и следующий owner. Для каждого original unit — отдельный source-qualified leaf receipt, даже если один root координирует несколько units.
- Push только свою topic; original history append-only. Никаких reset/rebase/cherry-pick/squash/force/main push. G отдельно принимает и последовательно интегрирует оригинальные commits. Conflicts возвращай canonical owner. Remote head/tree/receipt readback обязателен. Если transport сломан — сохрани commits/patch/outputs и honest unavailable boundary; не добавляй CI/base64 workaround.
- Git — обязательный handoff channel. Не отправляй сообщения в чужие пользовательские чаты без явной человеческой авторизации. Root/orchestrator и helpers координируются в своей task tree; counterpart читает tracked packet через fetch.
- Source acceptance, measured property, proposed finding outcome и formal G closure сохраняй раздельно. Не объявляй весь пакет closed по ограниченному slice.

## Диск и завершение роли

Измеряй свободное место/рост scratch до и после тяжёлого исполнения. Reuse locked environments, не копируй tracked source или derived dumps в receipts. В macOS переноси лишь сохранённые/неактивные воспроизводимые outputs/envs в native Trash; никогда не очищай её и не удаляй permanently. В cloud без штатной Trash только перечисляй cleanup candidates. Уникальные changes/data и deciding evidence сохраняй.

Роль заканчивает самостоятельный slice с remote readback и exact evidence, named remaining boundary и minimum next input. Unavailable один input не прекращает другие готовые owned работы. Не выдавай отсутствие прежнего full-cohort повторения за incompleteness, если original defining criterion уже проверен; и не переопределяй criterion более лёгкой формулировкой.

Перед использованием result pack обязательно выполни `python3 policy-engine/docs/research/e02-cloud-test-plan/results/import_results.py --check`, после успеха прочти `verification.json`, затем query по original unit/finding. JSON reading не заменяет importer check. `execution-organization/README.md` и allocation задают logical owner; dispatch делит execution, не переименовывает finding owner.

Тестовые fixtures и mock допустимы в пределах исходного criterion (например B156 callback на реальном orchestrator/cache); независимым доказательством runtime эффекта считается именно actual exercised path. Не усиливай исходный criterion запретом допустимого mock и не ослабляй его mocked surrogate вместо native requirement.

S1 — координационная карточка, не глобальный all-of barrier. B31/B161/B214 публикуют отдельные decision-scoped receipts; dependent consumer освобождается по **своему** subject/refinement/query/purpose/child contract и immutable supplier, не ждёт остальные S1 решения. A N4 meaningful-child semantics устанавливает C10 по текущему DesignProblem/producer contract с relevant suppliers; B214 completion не блокирует N4. G фиксирует scoped release в input manifest.

В expanded режиме C01–C13, запущенный человеком как отдельный root, может иметь один уровень прямых helpers по COMMON. Тот же C-role, назначенный helper-ом ORCH, детей не создаёт. Эти режимы взаимоисключающие; helper scopes внутри standalone root дополнительно делятся по exact paths без второго writer общей роли.
