## Ownership and mode checks

The recommended arrangement is four coordinating cloud roots, two local roots and existing G. Their assignments are disjoint by function: ORCH01 routes runtime/CAS/money/pool-stream; ORCH02 routes Catalog/DFK-CAN/Legal; ORCH03 routes IR/graph/TMLE/calibration; ORCH04 routes A-served/Search/independent conformance. They coordinate parallel leases; they are not four serial writers.

The expanded C01–C13 mode is explicitly an alternative, not an addition: both README and `dispatch.json` mark the cloud modes mutually exclusive. Keep L01/L02 and G in either mode. The expanded roots do not create more capacity by themselves, and no cloud VM/process count is claimed. The live collaboration snapshot during review contained only direct `/root/<agent>` paths; no nested delegation descendants or active C01–C13 duplicates were present.

Isolation rules are adequate: ORCH roots may use one level of direct helpers; direct specialist assignments do not spawn children; shared paths and tests require one writer; if separate write-isolated checkouts are unavailable, helpers prepare patches for the single source writer. Reviewers use immutable candidates, code authors do not self-review, and G publishes integration/generated surfaces. The current prompt wording could be made clearer for expanded mode: say explicitly that standalone C01–C13 roots remain non-delegating specialist roots (or state their one-level helper policy). This removes any ambiguity between “standalone root” and COMMON’s root-versus-direct-subagent delegation rule. It does not affect the recommended ORCH mode or the current one-level tree.
