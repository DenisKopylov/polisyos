# B10/B11 discriminating A-side oracle draft

Use the existing `GenerationCycleController` and the existing canonical candidate/applicability, simulation, budget, and run-lifecycle owners. Do not add a parallel selector or make up a B authority rule. Keep this as a bounded fixture until the exact B66 producer candidate (or successor) is G-admitted.

For B10, arrange a high-proxy candidate whose actual owner-checked required input is absent and a lower-proxy candidate whose complete declared hard constraints are satisfied. Assert the eligibility owner classifies the first candidate before any VOI/top-k truncation, persists its typed rejection against the candidate/content identity, and still schedules the second. Read the persisted rejection and selected simulation from a fresh consumer, resolve the exact input/candidate bytes, and rerun the direct engine oracle against that identity. The independently computed result hash must match the persisted result. Negatives: stale `selected_candidate` cannot override recomputed infeasibility; preserve markers while removing the required input; alter the result bytes; make both candidates infeasible. The first three must refuse/flag mismatch, and the all-infeasible case must not invent a result or numeric zero.

For B11, after G admission, run the actual B producer through A's served run/job owner with an initialized durable ledger. Exercise three separate events: provider response with supplied `cost_usd` (`reported`, provider-supplied); response without it (`estimated`, never presented as a bill); cache hit (`reuse`, amount zero). Pair the original event and its acknowledgement at readback because the standalone B37 receipt contains the payload digest and amount but no explicit `cost_origin` field. Read BudgetState and the ledger before/after under one run/job identity. Retry the exact same event after an unknown acknowledgement and prove one receipt/revision/debit. Reusing that event ID with a changed amount/digest must refuse without a false charge. A sibling run/job must not inherit or suppress the original debit. With budget left, a permitted informative check runs despite low monetary proxy; after actual persisted spend exhausts the limit, the next resource-bearing operation is blocked before provider/simulation invocation.

Current CYC-04 controls already cover one grounding blocker followed by a simulated alternative, typed in-memory rejection history, an informative low-proxy advance, and a configured zero-available BudgetState refusal. They do not yet exercise the owner-complete feasibility set, persistence/fresh readback, actual provider event, or durable debit.
