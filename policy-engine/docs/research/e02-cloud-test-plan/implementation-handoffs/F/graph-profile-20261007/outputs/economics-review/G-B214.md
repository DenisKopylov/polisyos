## Decision: MGraph is not an explicit projection; the F boundary should refuse it

In product 519, `GraphType.MGRAPH` is a distinct IR contract, not an alias for ADMG. `build_mgraph` returns that type and stores typed missingness semantics under `metadata["mgraph"]`; `extract_mgraph_metadata` deliberately raises unless `graph.graph_type is GraphType.MGRAPH` (`ir/analytics/mgraph.py` lines 73–80, 124–143, 146–165, 297–311). Existing recovery, missing-data, and causal-identification consumers use this extractor, so the tag controls whether the semantic metadata is admissible.

The F graph-intake packet claims a finite profile of known contemporaneous directed/reverse/bidirected **ADMG** relations and says unsupported endpoint marks and nonzero lags refuse. It does not claim MGraph conversion. Yet product 519’s `_validate_static_admg` only checks lag and endpoint-mark pairs (`admg_ops.py` lines 47–87, 130–133); it does not inspect the graph type. `ReconcileCausalGraph.pure_step` calls that helper, then copies all input metadata and constructs output type as ADMG when any bidirected relation survives, otherwise DAG (`graph_reconciliation.py` lines 995–996, 1030–1062). The node’s reference resolver uses the same helper before the producer (`reconcile_causal_graph.py` lines 203–209). Therefore a valid `build_mgraph` whose edges fit that static mark/lag profile is admitted, its `mgraph` metadata is carried forward, and its output is DAG/ADMG; the concrete `extract_mgraph_metadata(output)` consumer then refuses because the discriminating type is gone. The current-content suite has no MGraph case; its exact candidate-647 native receipt is `79 passed, 1 warning` (pytest reported an unknown `cache_dir` config option), so that profile alone is not an MGraph witness. A separate exact-candidate native probe now confirms the leak: `native-MGraph/receipt.json`@`97cbc9aba2cd526966b12de34be1494a0477b01f1063fdc11c301d9fc2476bbc` and deciding `Mgraph-local/attempt2-confidence-annotated/probe-results.json`@`a8ae5414146c4b1f754dd97fa5e4a00f364f20d913b128eb6b28a7dad3b128a6` load exact 25cdea graph/node/IR blobs matching 519; a valid builder MGraph with a bidirected edge reaches producer output `admg`, node status `ok`, and fresh-CAS `extract_mgraph_metadata` fails with `ValueError` because `graph_type=ADMG`. DAG/ADMG controls are valid; attempt1 is explicitly inconclusive because the builder emitted no confidence and reconciliation filtered away the test edges. This review did not execute that probe.

That is not a legitimate explicit projection in this source. No declared conversion contract maps missingness/proxy semantics, no projection result marks the changed meaning, and the actual downstream extractor still requires the MGRAPH tag. A generic structural view may be useful, but it must be an explicit separately typed projection with a declared consumer contract; copying `mgraph` metadata onto a DAG/ADMG does not provide one.

**Smallest F action:** at the canonical `ReconcileCausalGraph` admission boundary, reject `GraphType.MGRAPH` with a stable typed unsupported-profile error before confidence filtering, cycle rewrites, or persistence. Keep the general shared ADMG helper’s scope local unless its owner chooses to make it the universal graph-type gate. Add a focused negative discriminator using a valid `build_mgraph` with a bidirected edge and nonempty missingness metadata through the real registered producer → node → CAS path: method/node refuses, no reconciled artifact is published, and the original MGraph still round-trips through `extract_mgraph_metadata`. Keep an ordinary ADMG with the same directed/bidirected shape as the positive control. If F instead intends to support MGraph, it must preserve GraphType.MGRAPH and prove missingness metadata and downstream consumer semantics end-to-end; simple ADMG/DAG relabeling is insufficient.

**Disposition:** this is a source-derived F-owned admission residual, in the same `P40` static-profile admission class already identified in the twelfth-wave F graph review, one level deeper than endpoint marks/lags. It is outside the *declared supported* finite profile, so it does not prove that the bounded endpoint property failed; it does mean the canonical boundary is not closed against a semantically distinct unsupported type. Keep the exact residual visible and do not claim MGraph support or fail-closed refusal until the focused fix/witness exists. No automatic block is inferred merely from the enum name.
