## Raw-profile witness and smallest strict mechanism

`raw_profile_probe.py` uses a temporary real FileSystemCAS. It removes raw `canon.max_depth`, then observes that `get_manifest_bytes()` still returns the missing key while typed `get_manifest()` materializes `128`; the current IR reader accepts the resulting artifact. The same probe writes raw `{"fraction":1.5}` with `forbid_floats=true`: current IR read returns a float without changing blob bytes, while re-encoding the decoded value with that profile raises `float forbidden in canonical JSON`. It also confirms that a Core-only `float_hex` tag is refused by the IR decoder under the same canon name/version, and profile-less history is refused with `unsupported_ir_canon_profile`.

This is the P38 divergence: the intended property would be “IR returns bytes that conform to a complete supported profile”; the current implementation validates the `CanonInfo` model presented by `get_manifest()` and parses JSON while using only `max_depth`. A raw sidecar missing `max_depth` and a numeric float under `forbid_floats=true` are concrete cases where that proxy stays green. The smallest capability that closes the byte/profile part is one IR-side intake that reads the exact selected sidecar bytes, validates required raw profile fields without defaults, decodes under the selected IR tag family, and re-encodes under the profile with exact byte equality before returning the value. It does not exist in the current IR consumer path. The raw carrier already exists in Core; the missing seam is IR protocol/adapter/reader integration.

The existing `FileSystemCAS.get_manifest_bytes(ArtifactID | ArtifactRef | str)` goes through `open_member(..., "manifest")`, which enforces the selected view and ownership boundary, validates manifest identity, and returns the original bytes from a verified stream. S3 and GCS also expose `get_manifest_bytes()` backed by their validated raw `_load_manifest()` result. Core's public `ArtifactStore` protocol does not declare the method, `CachingArtifactStore` has no public raw-byte method, and `CoreToIRArtifactStoreAdapter` exposes only the typed manifest. Current `get_json_artifact()` accepts an `ArtifactID`; current adapter methods normalize through `str(artifact_id)` to an `ArtifactID`, so a selected secondary `ArtifactRef` view is not preserved through this path. No Core API expansion is required for the existing filesystem/cloud carrier; adding a protocol or cache seam would need an explicit owner and lease.

The falsifier for any future strict implementation is: keep all profile markers unchanged, remove one raw `canon` field or substitute canonical-looking raw bytes containing `1.5` while `forbid_floats=true`, and require the read to fail before returning a value. The current reader fails that probe. The inverse control is the current shared Decimal fixture, which must still round-trip with byte identity. No production history census or deployed-caller census was run here.

## Raw conformance continuation (current candidate)

After root advanced the shared branch to `a76bbfaef5be8362c2393802c497866b79df4d9e`, the granted continuation implements the existing IR decoder/profile rule at the actual byte boundary. `get_json_artifact()` now requires exact `get_manifest_bytes()` output, parses the sidecar as raw JSON, rejects incomplete/malformed/ambiguous profiles before blob reads, strictly validates all declared `CanonInfo` fields, and keeps profile-less history refused. It then reads blob bytes through the same selector, decodes under the IR-only tag allowlist, re-encodes using all persisted formatting options, and returns a value only if the bytes are identical. No persisted field, version, or payload encoding changed.

The Core adapter preserves `ArtifactRef` selectors instead of reducing them through `str(artifact_id)`. `normalize_artifact_ref()` now retains a non-default profile selector, and the adapter passes that same view through raw sidecar and blob reads. `CachingArtifactStore.get_manifest_bytes()` forwards unchanged bytes from the owner that defines the default (remote for write-through, local otherwise); it does not reconstruct metadata from a typed cached model. The base Core `ArtifactStore` Protocol was not broadened because `get_manifest_bytes()` is an existing optional carrier capability; the IR read contract now requires it and the Core adapter fails if a store lacks it.

Fresh semantic probes now cover each `CanonInfo` field removed from a real FileSystemCAS sidecar. For each case the Core typed getter fills the field's model default, while the IR read refuses the raw omission before returning the value. Additional negatives refuse a malformed persisted `max_depth`, raw `1.5` under `forbid_floats=true`, and JSON whitespace that does not match the declared separators. The unchanged current Core producer's Decimal fixture remains byte-identical. A selected secondary view uses the same typed `ArtifactRef` for both raw manifest and blob requests; the normalized IR reference mapping also preserves that selector. The cache control proves raw sidecar bytes come from its durable owner rather than a typed/local reconstruction.

P40: this is the **same C06 class one level deeper**, not a new class. The first widening fixed the complete existing write-option set. This continuation widens the raw-profile/conformance branch from the two sampled divergences (default-filled missing `max_depth` and accepted numeric float) to a single strict raw-profile intake plus profile-driven byte round-trip and exact-view transport, rather than patching those cases individually. The falsifier now removes every raw profile key in turn, substitutes malformed profile data or a numeric float, and changes the selected view while keeping the content ID shared; all must refuse or follow the exact selector. No tag-family widening or history default is part of this repair.

P38 property: “the returned IR value came from bytes that reproduce under a complete supported declared IR canon profile.” The implementation now measures raw key completeness, strict field values, IR tag decoding, and exact decode/re-encode byte equality; the Core owner binds sidecar selection and blob bytes to its existing view/content checks. One bounded divergence remains: if `exclude_none=true` is declared but the decoded payload contains no null, bytes cannot show whether the original producer chose that option; likewise a `max_depth` value above the actual payload depth is unobservable. Therefore a pass means **reader-verified byte conformance to the persisted declaration**, not proof of the producer's original option choice or identity. `CanonInfo` remains manifest-declared, not cryptographically producer-attested. The independent producer-choice predicate remains `not_established` (P37); the raw completeness, selected-view binding, and byte equality predicates are recomputed by the owner/reader.

## Choices for G (no new persisted law selected here)

| Decision | Option A | Option B | Cost / migration boundary |
| --- | --- | --- | --- |
| Core and IR tag families under `polisyos.canon.json@0.2.0` | Keep reader-local tag allowlists and refuse unknown tags; treat the shared version as the existing mechanics/format label, not proof of equal tag capability. This preserves current behavior and matches LA-021's no-silent-widening boundary. | Add an explicit persisted tag-family/profile identity or separate versioned Core and IR profile identifiers. | B changes persisted metadata semantics and requires producer/readers, version ownership, old profile handling, and migration/reissue rules. Do not union Core tags into IR under the old identity. |
| Raw profile completeness and bytes | Retain the newly implemented strict IR raw-sidecar/byte-round-trip check under the current decoder/tag law. | G may direct a later compatibility mode for identified callers/history if the strict read rejects supported bytes. | The current repair changes no persisted law or bytes, but narrows previously accepted nonconforming/incomplete inputs. A caller/history census is still needed before broad rollout or any downgrade. Byte-only producer-choice limits are stated above. |
| Profile-less history | Keep current fail-closed refusal until evidence and an owner-qualified path exist. | Provide an explicit caller-selected legacy decoder mode whose result carries `reader_selected` provenance and a typed limitation. | B changes the read API/result contract. It must not write the caller's choice back as producer-attested metadata and cannot satisfy authority-grade consumers by itself. |
| Historical remediation | No automatic rewrite; retain refusal. | Source-qualified migration/reissue of an exact existing blob/view, preserving payload bytes and CAS ID while recording the authority and basis for its chosen profile. | Requires an appointed producer/history owner and verifiable source evidence; reader-materialized defaults are insufficient. |

Recommended interim disposition: enforce raw completeness and exact byte conformance in the current IR reader; retain the existing IR-only tag refusal and profile-less-history refusal; select no new persisted version/field. Do not describe the current sidecar `canon` as cryptographically attested: it is manifest-declared metadata. The reader selects its decoder settings from that declaration and proves only byte consistency; a signed/verified manifest could strengthen custody for a particular artifact, but this work establishes no deployed signing coverage.

For this reader check, P37 inputs are: CAS blob identity and exact sidecar/view binding are `recomputed` by the owning backend; raw profile-field completeness and canonical byte equality are `recomputed` by the reader; the historical producer's actual serializer choice and any missing `exclude_none` preimage are `not_established` unless an independent source supplies them. A future reader-selected legacy profile would be `consumer_asserted` and cannot carry an authority-grade decision.
