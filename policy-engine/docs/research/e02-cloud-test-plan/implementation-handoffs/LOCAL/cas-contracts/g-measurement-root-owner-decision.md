# G decision packet: MeasurementRoot owner identity and tenant-scoped runtime

**Status: owner decision pending; no production ownership policy selected.** This is a source-bound decision packet, not a G authority ruling or formal capability closure. It preserves the existing G system identity and strict readers while exposing the integration boundary for the owner to choose.

## Decision question

`MeasurementRootProducer` currently emits a system-owned MeasurementRoot (`tenant_id="policyos-system"`, `cell_id=None`, with the same identity in `same_input_closure`). A tenant-authenticated runtime worker can hold a tenant-A-scoped CAS. Which established contract, if any, permits that worker to produce or consume the system-owned root, and what verifiable fact distinguishes a legitimate system producer or neutral shared source from a tenant caller merely supplying a system label?

This decision separates three predicates: (1) who owns the source artifact, (2) who may emit a system-owned artifact, and (3) which tenant may consume a shared source. The current source names a system owner; that declaration is not, by itself, evidence of a system principal, producer permission, source ownership, or cross-tenant sharing permission. The candidate band may continue under declared unknown scope without silently substituting a concrete owner; protected use and published claims require the selected, verified contract.

## Complete source census and predicate classification

A complete AST walk of all 2,746 `src/polisyos/**/*.py` files found 7 `write_authority_artifact` call expressions: `runtime/http/access_audit.py:790`, `runtime/http/services/control/artifacts.py:576`, `runtime/http/services/human_decisions.py:1499,1802,2197`, `runtime/quality/data_forge_binding.py:639`, and `runtime/quality/workspace/loop.py:3304`. The same walk found 8 literal `policyos-system` occurrences, all in the producer and the three strict reader families listed above. No other runtime call site or literal was found by this census.

`write_authority_artifact` at `runtime/http/services/control/artifacts.py:168-210` accepts `tenant_id` and `cell_id` as caller-supplied values; it constructs `AuthorityArtifactIdentityContext` from those values (`:224-263`). `core/artifacts/backends/config.py:27-37,51-72` configures a backend/root and passes optional tenant/cell strings to `FileSystemCAS`; `FileSystemCAS.for_tenant` (`core/artifacts/store.py:798-810`) constructs a scoped view from strings. These contracts provide storage scoping and consistency, not an authenticated system-principal port or permission record. The writer's system-owner field is therefore **consumer/producer asserted** as an identity declaration; the predicate “this caller is authorized to emit as `policyos-system`” is **not established** by the available principal/permission interface. A matching manifest label is content-bound metadata, not independent proof of source authority or tenant sharing permission.

The actual tenant-A probe is the P38 divergent case: the property is whether an authenticated tenant workflow has an admissible owner path; the writer emits a hard-coded system identity and the scoped CAS checks that identity against tenant A, so it refuses before any write. Conversely, accepting a caller-provided system string would only satisfy the label comparison; it would not establish the principal/permission property. P37/P32 therefore remain live for any authority-grade choice: a source or permission fact must be resolved, content-bound to the selected source/profile, and independently reconciled or institutionally supplied; absence stays unknown.

## Prototype evidence and next checks

The actual tenant-A falsifier above is a minimal counterexample for a claim that the current producer can write its system-owned root through the active tenant store. The explicit production-intake test is a current positive candidate-only route through a real worker and fresh consumer. Neither selects G ownership policy.

Before selecting A, prototype only through a real existing authenticated system owner if one can be located; a test that constructs a store with `tenant_id="policyos-system"` is not a valid positive because it only repeats the caller's declaration. Before selecting B, prototype a tenant-owned root and run all three strict readers/replay paths, plus an old system-root compatibility fixture. Before selecting C, prototype a separate verified sharing artifact and make the current consumers recompute it from the selected CAS view. For each prototype, retain positive, wrong-owner, absent-fact, malformed-present, wrong-profile, fresh-process, and zero-side-effect results.

The selection must also name migration owner, existing v1/v2 treatment, reader rollout order, revocation/staleness behavior, and which authority/published claims stay blocked while ownership is unresolved. Preserve `generated_at`, `as_of_time`, source verification time, and current status semantics unless the owner explicitly changes those contracts. Do not create a new authority enum or silently reissue old roots.

Relevant repair patterns: P05 (authority boundary), P32 (resolve/content-bind/verify), P37 (classify the gate's own permission predicate), P38 (the current manifest-label/store-scope divergence), and P40 (resolve the owner class once across producer and all readers rather than patching one importer). For S0-K06, the safe candidate route may continue with declared limitation, while protected authority remains unestablished.
