## Admissible design options for G

**A — Extend the existing typed HTTP intake to the current method-owner raw parser.** Add a typed observational `ArtifactRef` selector to workflow intake and carry that immutable selected intent through the existing lifecycle into `ExperimentState`. The owner resolves the referenced local manifest/content and revalidates exact artifact ID, `ir.observational_data` kind, JSON media type, selected profile/content identity and the selected method before using the existing parser. Omission retains the existing skip/limited behavior. A present-but-null, malformed, wrong-kind/media, profileless (if G requires selected profile), or wrong-profile ref must receive a typed refusal before admission; no default source substitution. Explicitly label `schema: null` as an admitted legacy/unversioned input window and state its limit: runtime DTO parsing is not a versioned producer contract, provenance/custody, scientific identification, permission, or publication authority. This is the smallest reuse-first route **only if** G confirms that it adds no authority or scientific semantics and ratifies the legacy acceptance window and canonical source/method intent.

**B — Extend the existing versioned envelope for HTE.** Define and version a real HTE compatibility target, provide an actual owner producer and reader path, bind the selected method identity to that target, and migrate the R4 source/consumer with legacy transition and generated API/schema consequences. The current recorded-panel producer is not an HTE producer and cannot be relabeled. This offers an explicit input contract at the workflow boundary, but expands the source, producer, reader, schema and migration footprint; G must choose the HTE contract semantics instead of this packet guessing them.

**C — Route through the existing Ukraine/panel binder.** Reject as a universal answer. The current binder is selected for a purpose-specific `d2_panel_observational` contract and recorded-panel path; using it for generic HTE/TMLE would narrow the universal workflow around one domain and would not represent arbitrary policy input. Reuse may remain valid for its existing purpose-specific route.

**Recommendation.** Prefer A only if G accepts a candidate-band, explicitly legacy/unversioned raw input whose method-owner parser remains the sole decoder, with exact selected-CAS profile/content verification and fail-closed present-invalid behavior. Otherwise choose B and specify its HTE target/producer/migration contract before implementation. Do not use C as the generic path.
