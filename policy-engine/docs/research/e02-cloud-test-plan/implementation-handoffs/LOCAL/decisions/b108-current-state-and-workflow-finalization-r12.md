# B108 R12: source-current reports across terminal workflow finalization

Status: author candidate for independent review. `closure_ids` remains empty; only G may adjudicate findings, accept the source, and publish integration. No external law, issuer, permission, scientific adequacy, or deployment-currentness claim is made here.

## Whole property and implementation

The criterion is that a GovernanceReport or VerifiedPolicyReport used by a current decision consumer must be the exact output of a successful selected producer, and the producer's complete decision-relevant source projection must still match at read time. An artifact's presence, schema, output kind, run ID, node ID, source-basis label, or self-carried ref is not sufficient. Currentness is `current` only when the same live process can recompute the selected builtin producer identity and source basis; loss of that live owner results in `not_established`.

The source owner now pins the builtin node's import-time class, callable objects, callable code objects, spec descriptor/accessor code, component spec, and module bytes before any attempt is captured. The engine records that identity in the invocation basis. Admission recomputes the current selected implementation against the owner, the exact workflow invocation, the run's successful attempt and output edge, and CAS source snapshots. A same-component-ID subclass replacement and replacement of `execute.__code__` before a later capture both fail the identity path. This narrow identity does not attest dynamic validators, transitive imports, arbitrary plugins, deployment image, or a release signature.

Both workflow executors now persist the terminal-state transition as `scientist.workflow_state_finalization` schema `polisyos.scientist.orchestration.engine.WorkflowStateFinalization/1.0`. The typed receipt binds the workflow ID and selected workflow-spec artifact that the run actually consumed, the exact selected-profile state before and after finalization, and refs for the finalizer's report and optional research-DAG outputs. A reader validates the receipt schema and bytes, run input/output membership, workflow-spec identity, report schema/run/workflow identity, output-ref kinds and state slots, exact final state, and recomputed state diff. The mandatory workflow-report path must be present; optional finalizer changes are accepted only when represented by a matching output binding. It then uses the exact prior state as the comparison source. This is a content-bound transition, not a list of source-map keys to ignore.

RunGovernance and the verified-policy report builder are both registered producers with source-basis contracts that must equal their current `NodeSpec.state_reads`. Their conservative maps and direct fields are:

- RunGovernance: `run_id`, `execution_profile`, complete `inputs`, `artifacts_index`, `reports_index`, and `params` maps; direct policy projection refs `policy_output_bundle_ref`, `policy_brief_ref`, and `champion_policy_dossier_ref`; and the selected `verified_policy_report_ref`. Pass code gets plain mapping access to `artifacts_index` and `params`, so a finite list of currently known keys is not complete.
- Verified-policy report: `run_id`, `execution_profile`, the complete four maps above, and direct `policy_request_ref`, `policy_option_set_ref`, `source_verification_report_ref`, and `verified_policy_report_ref`. It can take the selected input refs from direct fields or map fallback; its existing report cache is reused only when the ref remains selected and the exact producer/source admission is current.

The `ExperimentState` schema declaration was read with an AST census: all 33 typed fields are classified below. This is a per-source-owner classification, not a claim that every generic state consumer reads every field. The complete maps bind all their contained keys and values. Direct top-level fields bound by these producer contracts are `run_id`, `execution_profile`, the four verified-policy refs above, and the three governance projection refs. The other 20 declared top-level fields—`schema_version`, `budgets`, `last_checkpoint_ref`, `observational_data_ref`, `execution_plan_ref`, `method_catalog_snapshot_ref`, `capability_manifest_ref`, `causal_capability_contract_ref`, `preflight_report_ref`, `evaluator_report_ref`, `iteration_state_ref`, `reproducibility_manifest_ref`, `control_job_id`, `causal_method_fqn`, `causal_method_params`, `critic_knowledge_base_ref`, `constitution_hash`, `legal_candidate_pack_ref`, `legal_source_pack_ref`, and `memory_index_ref`—are not direct reads of these selected report producers. An artifact-ref change exposed in a full map remains bound even when its similarly named top-level convenience field is not read by that producer.

The field denominator is the 33 typed annotations in `scientist/orchestration/engine/state.py::ExperimentState`. The source-owner set is RunGovernance, `project_policy_promotion_state`, `BuildVerifiedPolicyReportNode`, and the verified-report builder/currentness resolver; the runtime test also exercises the actual selected governance pass's full plain-map input. No all-repository `state.<name>` grep count is used as a field-use oracle because identically named attributes on unrelated types are not ExperimentState reads.

## Alternatives and migration

1. **Reuse the run owner outputs and source projection only.** Rejected as incomplete: the terminal workflow report and optional research DAG are appended after the node outcome snapshot, so complete map reads against the consumer-visible `WorkflowExecutionResult.state` would report a false stale result.
2. **Ignore terminal map keys such as `reports_index.workflow_report` or `artifacts_index.research_dag_ref`.** Rejected: a per-key filter cannot distinguish a real finalizer write from a later node/caller write to the same map and can admit a mutated source.
3. **Persist and recompute one terminal transition receipt.** Selected as a small extension to the existing run-owned CAS and executor finalization path. The exact workflow spec, prior/final states, and typed finalizer outputs are linked and compared; no arbitrary map key is exempted. The R12 prototype demonstrates both the true final state and a later source overwrite with the same engine finalizer outputs present.
4. **Narrow pass input through a declared, mediated dependency registry.** Deferred. Existing validators receive ordinary dictionaries, with no complete source-read registry or enforced accessor. If G wants to reduce revalidation costs later, introduce that owner contract first; unregistered/opaque passes must retain the complete maps.

Prior GovernanceReport schema-1/unbound bytes remain loadable but cannot be retroactively called current. Currentness requires a same-process producer identity and a supported source projection, so old attempts or a fresh process without the original live owner remain `not_established` for this decision use. VerifiedPolicyReport bytes remain loadable through their existing owner profile; an ownerless, stale, changed, removed, or malformed cache ref is cleared before the node rebuilds from selected inputs or returns `skip`. No historical artifact is rewritten. The internal transition receipt does not add a package-facade export.

## Evidence and falsifiers

The authored focused witnesses run a real `WorkflowExecutor` and use its final `WorkflowExecutionResult.state`, including `reports_index.workflow_report` and the optional final `artifacts_index.research_dag_ref`; currentness succeeds only after resolving the exact prior state via the receipt. Removing the transition output from the run owner or removing the selected workflow-spec input prevents currentness. A subsequent real node mutates the pass-consumed source value while preserving finalizer outputs; the report becomes stale. The selected governance plugin reads a formerly unlisted `params` field from the full map; changing only that field is stale. An owner-linked verified-policy report cache is reused without loading or rebuilding when sources are unchanged; changing its selected option-set source causes a fresh build from the changed artifact, and removing that source clears the cached report before `skip`.

The same-ID replacement and pre-capture code-object mutation controls reject a non-owner implementation. The actual async executor test also observes the terminal transition artifact emitted by the async finalizer. These are targeted source/currentness witnesses; the composed runtime wave, broad importer suite, and G acceptance remain pending. Existing `cache_dir` pytest warning and legacy `ValidationProfile` deprecation are tooling/documentation debt, not treated as product acceptance.

## P37/P38, remaining boundary, and G proposal

- The builtin identity and source projection are recomputed against engine-owned attempt refs, selected workflow-spec/profile, CAS payloads, current source, and output refs. The finalization receipt is accepted only after exact state equality and state-diff recomputation. These are in-process run-owner facts, not institutional facts.
- Dynamic `_RUNTIME_PIPELINE` pass code and transitive executable/plugin dependencies are not attested by this identity. A source-current report is not elevated to an external-law, issuer, permission, causal-calibration, or publication fact. Those remain independently required by their owning contracts.
- Consumer-visible source mutations are bound by complete pass-visible maps, including changed/removed/malformed selected refs. The false-positive boundary from comparing only node output to final workflow state is addressed by the exact transition, not by field names or self-attested provenance.

G can accept the conservative complete-map contract and same-process currentness claim, or require a separately scoped validated-pass dependency API before any source-map narrowing. Either choice leaves external facts and formal closure with their institutional owners. Proposed finding IDs are in the separate closeout proposal report; this packet adds no `closure_ids`.
