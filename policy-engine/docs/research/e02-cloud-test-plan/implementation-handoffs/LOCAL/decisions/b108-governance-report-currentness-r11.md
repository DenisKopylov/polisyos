# B108 R11: source-bound governance report currentness

Status: author candidate for independent review. `closure_ids` remains empty; this is a source proposal for G, not a formal closure. The report does not establish external law, an issuer, a protected owner receipt, or promotion permission.

R10 review showed that even after the current-state projection, a report reference in `reports_index` could outlive the invocation inputs that produced it. R11 uses the existing run-owned attempt chain and exact successful output edge, then recomputes the source projection before any decision consumer admits the report. A v2 binding identifies the exact run, attempt, workflow, input-state profile, node, component, and `governance-pass-context-v1` basis. The basis covers the full `run_id`, `execution_profile`, `inputs`, `artifacts_index`, `reports_index`, and `params` state maps that RunGovernance directly reads or makes available to selected validators. It is versioned in one constant used by the NodeSpec and resolver; the resolver refuses a binding with an unsupported basis or a NodeSpec that no longer matches that basis. Full maps are intentional: dynamic validator entry points receive mapping access and there is no source-owned complete per-pass dependency registry. This errs toward revalidation when any passed parameter or artifact reference changes.

The projected state is compared with the exact input snapshot, except paths overlapping RunGovernance writes are compared with the engine-recorded successful outcome snapshot. This preserves the report’s own output fields while making a later mutation to a consumed source stale. The top-level `iteration_state_ref` is not exposed to RunGovernance or its `PassContext`; the similarly named `params.iteration_state_ref` is exposed through the full `params` map and therefore invalidates currentness when it changes. The added controls prove both edges: an otherwise unlisted parameter consumed by a selected plugin changes the projection, while a top-level iteration reference alone does not. An unchanged selected-state control remains current.

Alternatives considered: (1) keep the finite per-key parameter list; rejected because an entry-point validator can read an omitted field while the declaration stays unchanged. (2) bind every field in the ExperimentState; rejected because RunGovernance does not pass or read all top-level engine fields, and unrelated runner metadata would force needless revalidation. (3) bind the exact full state maps supplied to the selected pass context plus the direct node maps; selected as the smallest conservative source basis available without changing the validator API or trusting an incomplete registry.

Migration and lifecycle: v1 GovernanceReport bytes remain readable through the owner profile and are returned as `not_established` for current decision use because they lack an invocation binding. v2 reports without a recognized source-basis identifier are likewise non-current. Historical report bytes are retained; current-state projection moves unsupported or stale report references into `reported_governance_report_history`, and downstream consumers receive no current verdict from them. A caller must rerun governance after any change in the selected source maps before asking a decision consumer to rely on a fresh report. This can add a full governance pass to workflows that mutate `params` or artifact/report maps between the original report and the decision step; that cost is preferable to preserving a verdict whose actual pass input may have changed.

The scope preserves current ABI exports and the G-only resource tree; the new invocation binding is exported through the existing governance facade. The engine owner proves which report bytes its successful invocation emitted. This does not fingerprint executable plugin code independently of the existing workflow/component version, and it does not prove scientific adequacy or external authority. Those remain explicit limitations for G rather than inferred facts.

Semantic controls are authored for exact source-basis matching, a selected validator consuming a previously unlisted parameter, removal of the full-map basis, unchanged currentness, stale selected-map mutation, and top-level iteration-ref isolation. These controls and the composed consumer paths are not yet run; native checks, a composed replay, and independent G review remain required.


## Narrow G choice: dependency completeness versus revalidation cost

The selected contract keeps the six full source maps as the complete basis for this runtime profile. `PassContext.state` is a plain mapping that exposes the full `params` and `artifacts_index` maps, and dynamically discovered validators have no required per-pass read declaration or mediated accessor. A finite list of known parameter keys is therefore incomplete by construction. The current owner is the RunGovernance node and its selected validation-pass pipeline; the source for admission is the exact input and successful output state recorded by the engine, compared against the current decision state. This is an internal source-currentness contract, not an external authority or law claim.

G can accept this conservative basis for E02 or request a later, separately scoped optimization. The safe optimization would first change the validator boundary so every source read uses a typed, enforced accessor and the selected pass identity/version has a complete dependency contract. Builtins could declare finite paths; third-party or opaque passes without that contract would continue to bind the complete context maps. A `dict` subclass or access tracer is not a sufficient substitute: native mapping operations such as `copy`, iteration, and C-level `get` can bypass Python overrides, and a pass can read through helpers or retain the mapping. No narrowed read set is implemented here.

Time semantics are state-based rather than TTL-based: the comparison binds the exact invocation input and recorded successful output against the state at the decision read. A later wall-clock time alone does not stale the report, while any changed pass-visible source map does. External evidence has its own time/currentness contract. The current effect is that any change to the supplied params, artifacts, inputs, or reports maps causes the old report to become stale until governance is run again. This can add a governance pass between evaluation and publication, including when an evaluator updates `params.iteration_state_ref`; that path is visible to validators through the full params map. The standalone top-level `iteration_state_ref` remains outside the projection because the node and its pass context do not receive or read it. Historical bytes and refs remain available as history, while consumers withhold a stale or unbound report from current decision use.

The concrete falsifier is in `tests/unit/scientist/governance/test_report_currentness.py`: a selected `strategic_response` pass reads `plugin_owned_policy_input`, a field outside the former finite key list. The engine-emitted report is current on the unchanged source and becomes stale after only that pass-visible value changes. The removal probe narrows the projection while retaining the pass read and shows that a declaration-only map would miss the mutation. The end-to-end source test is authored but remains UNRUN pending the composed review wave.

Migration stays additive: schema 1.0 reports remain loadable as historical records and are `not_established` for current use; schema 2.0 binds the engine attempt and the named source-basis version. Unsupported basis ids fail closed. The mechanism does not fingerprint arbitrary plugin executable bytes beyond the existing workflow/component identity. G may record that limitation or ask for a future registry/code-identity contract; it does not authorize an external issuer, scientific calibration, or promotion. Current proposal status is `review_pending`; formal closure remains G's decision.
