# B108 R6 selected source units and complete score operands

Status: implementation candidate for independent G review. No formal acceptance or closure is asserted. This is the same B108 source-score/admission class one level deeper under P40; R5 remains immutable and HOLD.

## Property and implementation boundary

A numeric objective is comparable only under the exact selected objective rule, all actual operands that rule consumes, and an exact unit identity for each measured operand. A declared score or run fingerprint cannot stand in for that evidence. The score producer and every score replay use the existing `_evaluate_configured_objective_source` owner; the same evaluator resolves aliases, null fallback, source units, and the existing formula. `ObjectiveScoreAssessment` schema 2 carries the matched source-unit bindings in its content digest. A measured rule with no selected unit, missing source unit, malformed source unit, or a unit mismatch is not score-available. A selected scalar rule that combines different unit identities is invalid because this contract has no conversion rule.

A transfer `RunFingerprint.units` map now binds each selected objective name to the one unit identity derived from its canonical `objective_rule_specs` entry. Empty, extra, missing, coerced, or mismatched entries fail before history write, index use, or fresh restoration. Persisted score assessments retain their unit evidence. Transfer history schema 5 emits the strict selected unit map; schema 3/4 and assessment schema 1 remain readable for diagnosis but their old self-carried numeric assessments cannot be upgraded to available under the new rule.

The policy-vector legacy scalar formula consumes both `feasible` and the complete ordered `blocking_reasons` list. Its source projection now requires those runtime fields, verifies `feasible == not blocking_reasons`, binds them into the source digest, and reconciles them with the vector before scalar, rank, frontier, selection, or persistence consumers can reuse the score. The producer emits the explicit feasibility field beside its blocker list. Missing either operand or mutating it while retaining channels/bootstrap invalidates the score.

## Reuse-first alternatives and migration

1. **Infer units from metric names, objective labels, or numeric values.** Rejected. It would make custom labels misleading, choose a fiscal convention without an owner, and treat a self-description as a measurement fact.
2. **Keep `RunFingerprint.units` equality-only and patch fiscal readers.** Rejected under P40. The same unbound unit can cross transfer registration, index metadata, artifact headers, and restoration; another local reader would reproduce the escape.
3. **Add a parallel measurement registry or score-authority service.** Rejected. Existing selected objective specs, `BaseObjective.expected_unit`, `SearchMethodRunProfile.unit`, `metric_units`, `ObjectiveScoreAssessment`, and transfer fingerprint already own the needed edges. The candidate extends their binding and uses the same evaluator rather than introducing a second formula.
4. **Extend the existing source binding with exact identity, with no conversion (candidate).** Each producer configuration names its expected unit; retained source reports `metric_units` for each selected measurement; replay compares exact strings. No dimensional algebra or conversion is claimed. Existing unit-aware MethodJob outputs keep their typed profile unit and now pass that same unit into the objective rule used for candidate history, fitting, acquisition, and fresh verification.

This adds optional `expected_unit` to existing configured scalar objective/optimizer constructors and tightens the semantics of transfer `units`. Existing code without a selected unit remains candidate-only/unavailable for measured score admission. Histories remain on disk, but legacy unitless rows are diagnostic and must be regenerated from a configured run before training or ranking. No bulk rewrite or backfill is proposed. The owner-facing public-surface inventory still requires its separate refresh/review.

## Unit and authority limits

Unit identity is an exact opaque string supplied by the selected rule and checked against the source. This candidate performs no conversion, guesses no currency or dimensional family, and treats empty or whitespace-altered values as malformed. An unknown unit remains an explicit limitation: callers may retain an exploratory candidate, but cannot feed its scalar into transfer reuse, configured GP training, ranking, or selection. A genuine zero with a matched selected/source unit remains available. A null fiscal alias remains an absence under the existing B108 fallback contract; a malformed present alias, contradictory aliases, incompatible units, or source-unit conflict remains invalid.

The unit string is not issuer authority, custody, calibration, causal validity, scientific adequacy, or production currentness. The vector's feasibility and blockers are runtime score operands, not external proof that a policy is safe or publishable. The public candidate result remains distinct from any protected/publication decision.

## Source and consumer path

Configured `BaseObjective` / scalar metric rule → `_objective_source_results` reconciles selected numeric aliases and exact `metric_units` → `_assessment_for_rule_spec` computes the existing selected formula once → schema-2 `ObjectiveScoreAssessment` records selected rule, actual source fields/values, and exact used unit bindings → `ObjectiveValue` / `Evaluation` and persisted schema-5 transfer row retain it → transfer registration, index binding, fresh restoration, scalar warm-start, MO coordinate admission, and Bayesian scalar-source replay recompute through the same owner before numeric training or comparison.

For policy vectors, `ObjectiveStack` emits vector feasibility/blockers → `_build_policy_simulation_results_impl` records feasibility, ordered blockers, channel values, and the currently empty unit map beside bootstrap context → `with_score_source_results` binds all scalar formula operands → scalar, ranking, and history consumers recheck the complete scalar basis. Each selected MO/frontier channel is separately recomputed from its actual channel value, selected expected unit, and emitted exact source unit; an unrelated scalar aggregate is not required. Missing unit provenance leaves numeric candidate values available for inspection but unavailable to comparison or training.

## Bounded policy-vector unit source limitation

The selected policy-vector transfer route and same-run MO/frontier axes now fail closed unless each selected channel carries an explicit expected unit and the emitted source binds the same exact unit under `metric_units.channel:<group>:<name>`. `ObjectiveChannelValue.expected_unit` is optional for compatibility; absence remains unscored. The vector scalar additionally requires every formula channel to have exact source-unit bindings with one identical unit identity, because the current scalar formula has no conversion or normalization contract. Unknown, malformed, missing, or mismatched unit data cannot produce an AVAILABLE coordinate.

The current source owner still cannot provide a qualifying unit. `ObjectiveStack` receives `PolicyEvaluationBundle.simulation_metrics` as a float map; Core `Metrics` stores `values` and `notes` without a unit map, and `load_simulation_metrics` converts artifact values to floats. `build_optimizer_objective_spec` therefore emits policy-vector channel rules with no selected unit. The runtime policy producer now emits an explicit empty `metric_units` map, so scalar scoring stays unavailable and selected MO/frontier channel gates remain limited. This is a confirmed producer-to-consumer gap, not an inference from a sampled channel.

The smallest closing capability is typed selected metric unit identity flowing from the actual metric/objective owner through the persisted metric artifact into `PolicyEvaluationBundle`, the selected channel rule, and the emitted simulation source. The current `MetricRegistry` permits `MetricSpec.unit_id`, but the `TrinityBundle` path does not carry that registry and the selected objective channel producer does not map its derived channels to registered metric IDs. No unit can be recovered honestly here.

Recommended G choice: keep unitless policy-vector axes candidate/display-only and unscored for same-run MO/frontier and cross-run transfer until the metric producer emits typed unit provenance; alternatively, G may approve a specific upstream source contract and migration. The discriminator is one selected channel with unchanged numeric value, direction, and all status markers but a removed, malformed, or mutated source unit: every same-run MO/frontier/transfer numeric admission must become unavailable. A positive route requires a selected unit and exact source unit on that axis, while an unrelated unitless sibling and unavailable scalar aggregate do not block that selected axis. No unitless or conversion exemption is inferred.

## Funnel score-limited continuation and completion

The same selected-score admission rule now governs the funnel and the SearchController bridge. At the generic orchestrator intake, each typed assessment is recomputed against the retained result source before its `is_promising`, numeric value, trace, VOI observation, or terminal action can be reused. An unavailable assessment is candidate-continuable only when its rule and source recompute to that unavailable state; an unestablished typed limitation may continue only with its declared limitation. An unbound numeric value is preserved as an explicitly diagnostic feedback field, cleared from the score coordinate, and converted to a typed not-established limitation. These routes never set score-backed `is_promising`, emit a numeric score, or permit training, rank/frontier admission, approval, promotion, or completion. A later stage may continue the candidate; if no stage can establish the selected basis, the route defers. Malformed or contradictory present values and invalid source bindings remain invalid and do not use the candidate continuation path. A stage with no score coordinate may still perform independent structural candidate work, but its compatibility projection does not represent score approval.

`FunnelOrchestrator.as_stage_a_callable` now returns the existing typed `EvaluationBundle`, whose `stage_a_passed` means continuation to the next evaluation stage, while `is_promising`, `score_status`, and `score_assessment` keep score admission separate. The `StageAEvaluator` contract accepts this result while retaining legacy tuple inputs for non-funnel callers. An unbound tuple cannot establish a score; the SearchController still recomputes its configured objective from Stage B source before any acceptance or training. Level 6 rechecks the prior selected assessment before consuming even a `complete` promotion payload. The compatibility projection preserves source-bound assessments and emits `DEFER` when the selected basis is not available, so an `APPROVE` verdict alone cannot finish the candidate.

The behavioral discriminator uses the real Level 3 producer, Level 4 adapter, funnel continuation, Stage A typed bridge, and Level 6 promotion consumer. Its negative controls keep an upstream `APPROVE`/`is_promising=True` assertion while the selected source unit is absent, and remove the typed assessment while leaving the numeric zero and approval markers. In both cases the selected score cannot be promoted; a downstream `complete` payload is deferred. Supplying the exact selected and source unit makes genuine zero available and allows the valid route. These runtime tests remain UNRUN pending the root's serialized runtime slot and independent review. The installed production policy runtime currently emits an empty `metric_units` map. General policy-runtime score routes therefore remain unscored until the metric/objective owner supplies exact unit identity through the source artifact; no unit is inferred from labels, values, or the synthetic fixture.

G should review the changed `FunnelOrchestrator.as_stage_a_callable` result contract and either accept the additive typed Stage A projection or require a versioned adapter for consumers that rely on tuple unpacking. Legacy tuple callables remain accepted by `SearchController`, but cannot carry a recomputable Stage A score. G should also name the upstream metric-unit owner before granting availability to the production default objective. These are narrow compatibility/source-owner decisions; implementation acceptance, source publication, and formal finding closure remain with G.
