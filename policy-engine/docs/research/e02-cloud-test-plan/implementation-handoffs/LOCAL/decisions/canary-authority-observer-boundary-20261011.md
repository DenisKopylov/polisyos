## Finding

The synthetic Pass1B record currently asserts runtime scope enforcement, non-overridable-blocker enforcement, and effective human oversight without observing those behaviors. It also assigns low rubber-stamp risk. The serious scorecard treats these values as sufficient after schema/profile validation. Stable-looking evidence/runtime references do not bind those values to an observed source record.

This is a P38 proxy gate / P32 trust-by-form gap, and P05/P04 matter because the unsupported assertions can make the authority/status record say `pass`. The four values are one failure class: an unobserved claim in a record producer, not four independent defects. Under P40, the repair must cover the entire record quantity and the consumer, not one field at a time.

## Reuse-first route

1. Reuse the existing Pass1B record and serious scorecard gate; do not add a second canary-only authority rule.
2. Extend its producer/bridge to carry source-owned evidence for each claim, bound to the exact run, tenant/cell, PDC, relevant input/decision, and event time. Derive read-scope status from an actual scoped read/denial observation; derive blocker preservation from the actual protected-gate/override path; do not infer either from a successful unrelated operation or a field name. Missing, malformed, foreign, or unmatched observations must stay unknown/limited and cannot emit Pass1B `pass` for these claims.
3. For oversight, reuse the existing `ReviewEffectivenessService.for_run` and `HumanDecisionService.read_record` path (`src/polisyos/runtime/http/services/review_effectiveness.py`, SHA256 `bbfacefb909db5802327923f26da489e03e424504ecdc8935195faf17d5b18d8`). It reconciles audit-trail authorization events to exact signed decision-record readback, detects malformed/duplicate/unmatched/incomplete joins, and computes the calibration report from those records. Its output is explicitly advisory; complete coverage still carries `review_time_not_established` and may downgrade a nominal threshold pass to warn. Treat it as review evidence, not as external authority or automatic closeout. `build_human_review_calibration_report` (`human_review.py`, SHA256 `35455aedf44782338ba5c6bfc61330f70baa3c7aad3218acc50e44affdffed14`) computes risk from review signals, but callers supplying arbitrary event mappings are not a source-bound observer. The NL pipeline context path around `nl_pipeline.py:8393` accepts context events, so it is not by itself the needed custody bridge.
4. Consolidate the derived evidence into the existing typed Pass1B record and have the current scorecard resolve/recompute the complete evidence relation. If the current schema cannot represent unknown or incomplete source evidence without converting it to pass/fail, make the smallest typed limitation/status extension; do not fabricate a signature, reviewer, law, or issuer.
