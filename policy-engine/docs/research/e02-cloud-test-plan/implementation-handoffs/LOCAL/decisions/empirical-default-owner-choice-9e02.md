# E02 empirical default owner choice (read-only, pin 9e02)

## Decision

The 9e02 default does not have an admissible empirical value/calibration chain to enable. Keep the current default refusal. There are useful, locally named owners and working candidate APIs, so this is not simply “waiting for external facts”: wiring and source-binding are incomplete, and the predictive-versus-causal purpose, threshold meaning, and downstream consumer are still semantic choices. Do not route predictive interval evidence to S10 causal authority.

The smallest safe next move is an explicit G decision with two separate lanes:

1. **Predictive-only lane:** decide whether held-out predictive interval coverage is a distinct candidate signal, name its consumer and effect, name the source of its pass threshold and time roles, and state when the evaluation corpus counts as credible. Then wire the existing ForecastOwner → CAS report → fresh ForecastBridge evidence path to a predictive-only consumer. Keep it limited/candidate until each required receipt resolves and recomputes.
2. **Causal-value lane:** remain blocked until one of the existing real treatment-assignment alternatives is selected and supplied by its institutional owner, then bind the assignment, outcome source, estimand, and unit through the actual ValueDataProfile → method report → ValueGateReceipt path. Forecast/ETS evidence is expressly ineligible for this lane.

A new generic “calibration” contract would not settle either lane. The threshold, current-law/scope, time, assignment, and consumer choices below have to be made before changing behavior.

## What the current default actually does

### Value, treatment assignment, and B31

`FoundryValuePort` stores the optional `artifact_store`, but its default gateway is constructed as `RealValueOwnerGateway(repo_root=..., cycle_substrate_context=...)` without passing that store or an empirical resolver (`runtime/quality/generation_cycle.py:4600–4631`). The actual call then resolves rows and method selection but blocks at `treatment_assignment_not_owner_derived` (`:4975–4998`) before a causal result or downstream S10 record can be produced. The default constructors are in the normal generation and recursive/reentry paths; their source references are recorded in the raw callsite receipt.

The blocker is explicit. `acquisition_planner.py` enumerates two owner-derived routes: a real owner rollout-assignment source, or a certified SKG identity bridge. Simulated intervention assignments and candidate-provided assignment fields do not stand in for either. The relevant test negatives in `tests/unit/runtime/quality/test_value_gate.py` reject those substitutions.

Some useful subject inputs exist locally. `ValueDataProfile` carries the outcome, rows, declared measurement `unit_id`, period, values, hashes/counts, and `treatment_assignment_status="owner_assignment_unresolved"` (`generation_cycle.py:1175–1213`, loader around `:9925–9940` and `:10152–10263`). `DesignProblem`/intervention contracts also carry request-side estimand, targeting, and policy fields. These fields do not establish a producer-owned relation from an actual treatment assignment to the outcome rows or bind that relation to the causal report. `NativeValueEstimandBinding` is caller-constructible, not a registered assignment/estimand owner.

`CausalEffectReport` carries estimator, estimate, CI, diagnostics, and generic metadata, but no resolved subject/unit/source binding. `ValueOuterSet` can represent statistical bounds separately from identification bounds. `_value_outer_set_from_foundry_result` preserves that distinction in a helper, but AST/source scan finds no product callsite; its coordinate uses method identity rather than a source-bound estimand/unit. `ValueGateReceipt` does not carry the method report, uncertainty envelope, or a joined subject/unit reference. Thus B31’s numerical representation is available, while the actual chain needed to say “this interval belongs to this same source-bound estimand and unit” is not.

The property and implementation currently diverge (P38): the property is *native CI and identification set remain separate for the same joined estimand/unit*; the default path tests whether treatment assignment is owner-derived and blocks before that property can be consumed. The helper’s point/CI shape is not the property. No false positive value publication was demonstrated; current refusal is the honest result.

### Law/scope, temporal roles, and threshold

These owner inputs are not wholly absent as names, but their actual source relationships are not resolved by the empirical owner path:

- **Law/scope:** `InterventionSpec.lex_provision_ref` is a request-side string described as a legal provision/lex artifact (`ir/governance/policy_spec.py:93–97`). A typed string field is not a current-law source, version, or freshness receipt. `ForecastOwner` accepts model/policy references, but the owner only resolves their CAS manifests and does not parse/verify that the model snapshot matches the observed `DataSnapshotRef`. No current-law role producer is in the scanned default chain. A named reference exists; source custody/currentness does not.
- **Treatment assignment:** no default owner is registered. The two explicit candidate authorities are rollout assignment and a certified SKG identity bridge. Neither is emitted/bound in this path. This is a genuine missing owner input for causal value, not an internal field that can safely be guessed.
- **Time:** `ForecastTemporalRoles` validates timezone awareness, distinctness, and order, and `ForecastOwnerRequest` accepts/persists the roles. This proves request consistency, not that the times describe the source. `DataSnapshot` has no typed observation time axis. `ModelSpec.TimeSemantics` and policy schedules are local typed inputs, but `ForecastOwner` does not resolve them against the observed source; schedule steps are not calendar/observation-time evidence. The role fields are available as caller inputs; the source-derived role owner is not wired.
- **Threshold:** the bridge requires a numeric `calibration_threshold` and content-addressed ref, then resolves and compares the persisted threshold to the evidence (`forecast_bridge.py:230–317`, `:827–897`, `:1424–1440`). A local `CalibrationRuleArtifact` supplies `nominal_coverage`; ForecastOwner uses it for interval construction/evaluation. That is a candidate nominal target, not yet an agreed minimum pass-rate rule. Separately, the S11 summary helper defaults to `.75`, the generated S11 manifest contains `.5`, and `layer2_floor_governance.toml` names the S11 metric/owner/artifact/revision rule without a numeric value. S11’s metric is per-axis predictive calibration, not this report’s held-out interval hit rate. A local threshold-like API/value exists; there is no unambiguous compatible threshold owner for this gate.

### Predictive producer and bridge

A useful predictive-only prototype already exists. `ForecastOwnerRequest` takes a CAS-bound `DataSnapshotRef`, train/holdout positions, target metric, versioned calibration rule, caller time roles, and optional model/policy inputs (`scientist/methods/backtesting/forecast_owner.py:120–239`). `ForecastOwner` makes actual predictions, evaluates actual holdout outcomes, and persists a `BacktestReport` with the split, method, rule and supplied temporal roles (`:505–649`, `:718–799`). Its suitability label is a finite-sample screen, not an institutional calibration-authority decision (`:934–945`).

`forecast_bridge.py` supplies an existing typed eight-role protocol: `scope_binding`, `calibration_threshold`, `observed_outcome`, `prediction`, `evaluation_design`, `credible_evaluation`, `source_lineage`, and `method_lineage` (`:85–126`). It resolves references, checks role edges/payload identity, checks temporal binding to the report, recomputes coverage, and fresh-loads persisted evidence (`:827–897`, `:1256–1301`). This is reusable infrastructure. But the source scan finds profile declarations only: no product source emits the role artifacts. `run_forecast_owner()` has no product caller; `produce_forecast_inputs()` has no callers; `_build_real_s10_forecast_inputs()` is called only from an uncalled gateway method; the evidence persistence and load functions likewise have no default callsites. The actual default route is therefore not “a resolver set to None” alone; producer, receipt emission, orchestration, and predictive consumer are absent from its composition.

The existing real-owner test is a useful positive/negative discriminator. `tests/unit/remediation/test_frc_02_empirical_bridge.py` runs a real ForecastOwner on actual train/holdout rows, persists and freshly loads the report, and recomputes hit rate. Same forecasts/intervals with changed holdout outcomes change the measured coverage/suitability. It also demonstrates that without context the evidence is `predictive_only`, `context_bound=False`, `usable_for_calibration=False`, and persistence refuses without changing CAS. `test_frc_02_s10.py` creates role artifacts with a test helper; it does not demonstrate production role owners. These tests were read at the pinned source; not rerun for this read-only refresh.

Finally, `EmpiricalCalibrationEvidence` explicitly disallows use for `s10_authority` and `causal_effect_authority` (`forecast_bridge.py:43–57`). The current finite-estimator S10 route yields denominator 0, `floor_passed=False`, and a blocked forecast tier (`generation_cycle.py:11141–11180`). This is the correct boundary: predictive hit-rate evidence can support only a predictive claim after an owner/consumer decision; it cannot be promoted to causal calibration.

## G choice before implementation

The code supports a small candidate prototype, but a default capability cannot be safely wired until these choices are resolved:

1. **Purpose and consumer:** Is FRC a predictive-only held-out interval-coverage signal, with an explicitly named predictive consumer and bounded effect, or is someone seeking causal-effect calibration? The latter requires a distinct real effect-calibration owner/corpus and treatment-assignment relation. Existing ETS/ForecastOwner evidence is prohibited for S10 causal use.
2. **Threshold relation:** Does the acceptance floor mean nominal coverage, minimum observed hit rate, an uncertainty-adjusted tolerance, or another versioned rule? `nominal_coverage`, `ForecastOwner.empirical_suitability`, bridge `calibration_threshold`, and the S11 per-axis threshold are different mechanisms today. Do not map one to another by field name or default. The selected value must resolve from the exact threshold artifact the consumer uses.
3. **Time source:** Which owner derives observation/valid time, prediction time, policy-effective time, and calibration window from the input source and rule? Either add a typed source time-axis receipt or define and verify a precise mapping from a content-bound `ModelSpec.TimeSemantics` plus observed-source timestamps. A caller-provided `ForecastTemporalRoles` object alone is insufficient.
4. **Scope/current law:** Does the predictive evaluation bind to a particular policy/legal context? If so, name the lex owner and freshness/version receipt that resolves `lex_provision_ref`; a string is not enough. If not, explicitly keep law scope out of this predictive evidence claim.
5. **Causal assignment:** For EMP-01, choose the real rollout-assignment owner or certified SKG identity bridge and specify the exact typed receipt and row-level source join. Until one exists, causal value remains refused.
6. **Role ownership and admission:** For each of the eight existing bridge roles, name the producer and which fields are recomputed from the actual ForecastOwner output versus supplied by a distinct institutional source. In particular, `credible_evaluation` cannot be a role artifact that simply repeats a request’s claim.

These are substantive semantics, not missing plumbing only. The current bridge can be reused after the choices; it cannot select them itself.

## Narrow candidate, proof, and falsifier

Link the exact report, `DataSnapshotRef`, model/policy refs where verified, split, predictions, outcomes, method, rule and source hashes.

- Add a separately named predictive consumer only after G selects its target/status effect. S11 is a possible existing surface to assess, not a compatible mapping until its per-axis metric and threshold are explicitly related. Do not wire this into the causal `RealValueOwnerGateway`/S10 route.
- Minimal tests: reuse `test_frc_02_empirical_bridge.py` for actual producer/source/outcome sensitivity; add end-to-end CAS role receipts → fresh resolver → selected predictive consumer; add refusal for missing/wrong threshold, time source, model/data snapshot mismatch, empty holdout, and forged “credible” role. The consumer should change its predictive grade when same intervals face different actual outcomes and refuse on stale/mismatched refs. Include the explicit test that resulting evidence never makes S10 causal calibration pass.

- Persist the profile/report/uncertainty as typed CAS refs and carry the complete refs into `ValueGateReceipt`; use the existing `ValueOuterSet` statistical-bound channel without synthesizing any width or conflating identification and native CI.
- Minimal integration test: real source rows with a zero-width identified point and native CI `[1,10]` stay separate for the same source-derived estimand/unit; change the unit, assignment artifact, source bytes, or method-report ref and require the join to fail. Test the real default/refusal path before the owner evidence exists. Existing `test_emp_01.py` helper is not enough.

Potential source/test surfaces to lease after G: `scientist/methods/backtesting/forecast_owner.py`, `calibration/forecast_bridge.py`, a named predictive consumer path (new dedicated module unless G proves an existing axis is semantically compatible), `runtime/quality/generation_cycle.py` only for the source-owned causal route, `tests/unit/remediation/test_frc_02_empirical_bridge.py`, `tests/unit/remediation/test_frc_02_s10.py`, and `tests/unit/runtime/quality/test_value_gate.py`. Add a new mirrored integration test for the full default bridge. New public surface/export/docs are required only if the chosen consumer is public; they cannot substitute for an owner and consumer decision.

## P40 classification and residual

This is the **same producer-to-consumer evidence-binding class one level deeper**, not a new defect class: earlier helper/prototype work proves local numerical/context behavior; the current review shows the actual default composition still has no owner-derived assignment and no ForecastOwner→role receipt→predictive consumer call chain. Widening a helper or adding per-role declarations would not close the property.

Bounded residual for this pin: causal value remains blocked because assignment authority is unresolved and no same-source assignment/subject/unit/report join exists. Predictive evaluation can be computed for a caller-selected split, but no source-owner role receipts, resolved compatible threshold/time/credibility context, or selected default predictive consumer exists. The exact original fixed-date/optimistic-pass subcase is absent from current source. The smallest capability to close the predictive residual is the G-selected role-owner → fresh ForecastBridge → predictive consumer route; it is not in the current product call graph. The smallest capability to close B31 is a real owner-derived assignment receipt plus source-bound row join carried into the native-CI consumer; it is not in the current default graph.

The falsifiers are ready: (a) the real holdout outcome-change test must alter the *consuming* predictive grade while identical predictions/intervals remain unchanged; (b) replacing a role/threshold/time/source ref with a forged, stale or incompatible artifact must fail at fresh resolution; (c) an empty denominator must stay ineligible; (d) predictive evidence must not raise S10 causal status; (e) changing subject/unit/assignment/source while retaining the same numerical CI must break B31 admission. Until those pass through the actual selected consumer, labels remain `implemented_but_not_orchestrated` for the predictive prototype and `absent/unallocated` for the causal assignment owner, with `not_established` for any missing authority predicate.
