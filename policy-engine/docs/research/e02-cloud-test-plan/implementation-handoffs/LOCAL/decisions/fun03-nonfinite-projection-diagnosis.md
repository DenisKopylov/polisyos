## Existing semantics and reuse

`StageResult.objective_value` is a required `float` (`stages.py:22-38`), and `FunnelStageResult` inherits that field (`funnel/types.py:274-310`). There is no stage-local objective status. `FunnelEvaluationStatus` is only the aggregate `not_evaluated | partial | evaluated` (`funnel/types.py:26`); `_evaluation_status()` derives it from whether stages ran and whether the funnel is terminal (`funnel/orchestrator.py:1260-1267`). It cannot distinguish an attempted workflow that failed from a computed value. The empty-result path deliberately uses `+inf` with `funnel_evaluation_status="not_evaluated"` (`orchestrator.py:1243-1257`), and existing tests preserve that sentinel (`tests/unit/remediation/test_fun_02.py:100-117`). L3 also returns `+inf` on an engine error, with a typed `workflow_error` failure card (`funnel/level3_medium.py:94-103`).

No current carrier is a semantic substitute for objective availability. `UncertaintyEnvelope.unknown()` means every uncertainty dimension was unassessed and sets each level to `1.0` (`scientist/methods/search/uncertainty.py:28-86`); it does not say whether a score was computed. `TypedFailureCard` can preserve a failure reason but not the state of the objective value. `ParetoViewAssessment.non_finite_coordinate_ids_by_candidate_hash` is scoped to a declared Pareto view and a candidate denominator, not stage-result serialization (`scientist/methods/search/contracts.py:76-154`). Reuse those existing failure details and empty-stage status as inputs, but add an explicit stage-local evaluation status or equivalent typed projection; do not overload uncertainty.

Keep the internal `+inf` rank sentinel and the finite-state journal rejection. The smallest routine repair is to carry a producer-assigned stage status and encode non-finite values at the serialization boundary, preserving both the meaning and exact sentinel. A candidate version of the projection could keep finite values as numbers and add a versioned status field; for non-finite values it would expose a null numeric slot plus a typed `positive_infinity` sentinel and a status such as `workflow_error`, `not_evaluated`, or `invalid_numeric_output`. Those labels are a proposed runtime projection, not a ratified public DTO. Preserve the existing feedback/error detail. Do not infer `workflow_error` solely from `+inf`, because the empty-stage path also uses it.

The projection must cover the whole serialized graph—trace, stage results, feedback, failure-card payloads, and any nested numeric metadata—not just the top-level objective. For arbitrary non-finite leaves without a producer-owned status, return a typed serialization refusal or an explicit invalid-output status with the exact location/value kind; do not silently sanitize. Keep `state_branching` unchanged. A new public or persisted state shape needs an explicit version/compatibility decision because external readers of `ExperimentState.params` are not covered by the local source census.

- Exercise the same projection against L3 failure, an evaluator returning each non-finite numeric kind, and a non-finite leaf nested in feedback/metadata. Every JSON leaf must be finite or an explicit typed tag/refusal; no nested non-finite value may reach state mutation.
- Negative guard: direct attachment of nested `+inf`, `-inf`, and `NaN` must continue to raise the state-branching finite-graph error. A finite objective must round-trip numerically unchanged.

The current source has multiple producers of the same sentinel—`ExpensiveStage` failure, L3 failure, and empty/no-stage result—and duplicates objective values into trace and stage-result projections. The smallest falsifier is the control set above run through the actual outcome serializer and state attachment.
