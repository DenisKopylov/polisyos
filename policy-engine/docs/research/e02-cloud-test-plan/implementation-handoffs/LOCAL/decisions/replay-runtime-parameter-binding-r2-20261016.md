# Replay runtime-parameter binding — G decision packet R2

**Status:** a bounded identity-comparison proposal, not G acceptance or a closure. The R1 independent review is `GO_BOUNDED` for the actual A/B consumer mismatch and exact-ref comparison primitive; it is `HOLD` for source-origin proof and a version-only ban on v1.0. This R2 corrects both boundaries.

## G decisions requested

1. **Origin evidence:** require a durable record tied to the original run’s real selection/intake or producer transition before treating a parameter-path binding as source evidence. A serialized `ArtifactRef`, selected-profile hash, manifest read, producer label, or `origin` enum inside the new bundle is not that record by itself.
2. **Legacy handling:** decide eligibility from the actual consumed-input set and its existing typed provenance, not from `schema_version` alone. Preserve v1.0 archive/snapshot behavior. A v1.0 route with no consumed params-ref dependencies, or with all actually consumed refs already completely covered by existing typed owner/input refs and edges, need not invent a missing params binding. If a route consumes a params fallback without an original source record, semantic replay is `not_established`/typed incomplete for that route.
3. **Contract scope:** decide whether the existing run/execution artifacts can be extended to capture the required source-to-path link, or whether a versioned replay-basis receipt must be added. The 37-route source-derived inventory is the current denominator; the whole route has not been dynamically executed.

No new authority, issuer, time, legal, causal, calibration, or current-world facts are implied by a successful identity join. Keep artifact-snapshot integrity distinct from executed semantic replay and promotion.

## Why origin is a separate property

R1 is `decision-r1.md` (`sha256: 15fbfb18954fbf9afa3629588121bd15474ea6df1dfd3f887ba38dc7afcda064`). Its independent review is `independent-review-r1/review.md` (`sha256: c2f379e77c672e5ee591cf9f45172317b225f34ebc2f4cfbecdb34920f4d146f`). The review reran the real candidate A/B consumer witness and confirmed that the selected-profile mismatch is real at `_resolve_candidate`: the bundle's candidate A and same-byte/same-id candidate B have different manifest profiles, both payload checks pass, and the consumer selects B when the params alias is B. The deciding output is `.../independent-review-r1/candidate-alias-current-rebind.stdout.txt` (`sha256: 8f63b4e18c48bd071cfefbece8e3c44c71c54c7aaa8ad375ba850f0727635102`). That proves a consumer/owner identity divergence, not a full-workflow grade or promotion false-green.

R1’s prototype asserted that its API prevented bindings being created from the raw snapshot. That assertion was false. It supplied a default `origin="producer_typed"` and allowed arbitrary caller-provided refs and manifest edges. The independent counterexample parses B from the snapshot, uses B’s current manifest inputs, labels the binding producer-typed, and the check accepts it. Exact output: `.../independent-review-r1/raw-only-binding-origin-falsifier.stdout.txt` (`sha256: 66bec4461a3d800b3055e1ed17dc5ce230d7d39f61f82eebbc35544ab25ec955`), with `raw_snapshot_parsed_into_binding=ACCEPTED` and `baseline_A_vs_binding_B=True`. The guard checked that the snapshot agreed with the *supplied* binding. It did not establish how the original run selected B.

The corrected R5 scratch prototype is `typed_path_binding_prototype_r5.py` (`sha256: e0cbfd2825010ab608372b7453ef131a5f87497ae7aba5de37fa3ad02e9e4167`) with output `prototype-r5.stdout.txt` (`sha256: 1a0edda2755ff539709fcd155f3ddd899f73fbd3360285eb8aa23caaad9f99b9`). It removes the `binding_for` factory, the default origin/producer strings, and any semantic-admission result. It tests only the narrower primitive against a separately supplied expected ref: snapshot A versus controlled A is `IDENTITY_AND_SELECTED_VIEW_CONSISTENT_ONLY`; snapshot B versus controlled A refuses on full identity mismatch; nested welfare and list-item B-versus-A substitutions also refuse. The old falsifier is reproduced honestly: raw B compared to itself passes identity/current-manifest consistency, while both `raw_snapshot_self_source_provenance` and `semantic_admission_from_raw_snapshot_self_binding` remain `NOT_ESTABLISHED`. It records that an `ArtifactRef` instance alone does not prove original selection and that this prototype has no original workflow-selection receipt. The script uses temporary CAS data and is a comparison primitive only, not a production source receipt or trust boundary.

The identity primitive can establish that a named snapshot value matches an independently obtained selected ref, its selected manifest profile and physical bytes, and the supplied lineage edges. It cannot establish that the independent ref came from the original run. A receipt that merely repeats an `ArtifactRef` or says `producer_typed` has the same weakness. Actual source evidence must be tied to the original intake/execution record and its exact ref/path/role; the persisted receipt itself must be content-bound through the existing producer/run mechanism. If that source cannot be resolved, the honest result is `not_established`, even if identity and bytes are self-consistent.

## Conditional version and grade boundary

Do not say “all v1.0 is banned.” A route-specific resolver first needs the actual consumed-ref set and source precedence. If no runtime-param ref is consumed, or the existing typed bundle fields/inputs/edges already bind every selected input used by that route, preserve the existing snapshot/archive behavior subject to its existing grade gate. If a params alias/fallback is consumed but its original source selection was not recorded, mark semantic replay `not_established` for that route; do not infer a blanket schema rule or default to the currently visible manifest. New versions should encode captured path/source evidence only after G chooses the source contract.

The two existing focused grade-gate tests passed (R1 review cites `current-grade-gate-tests.stdout.txt`, SHA `cb33dbba2d0a223612129c405f06f48fef9ae54eff1eaef74733b2c6a19ae849`): a selected artifact-snapshot report can be `passed=True`, while JudgeStack blocks `artifact_snapshot` in `bounds` and `estimation` with `replay_verification_unmeasured`. The inspected code does not establish a universal block for every `proof_only` path. Therefore preserve that grade distinction, do not claim a current promotion failure or false-green, and keep the full-workflow semantic grade/promotion question `UNRUN / NOT_ESTABLISHED` until an actual frozen replay demonstrates it.

**Recommended root decision:** choose the evidence source first, not the `origin` field. Reuse typed state/owner refs and actual node execution outputs wherever a durable record binds them to the original invocation and JSON pointer. Where that bridge does not exist, either approve a versioned run-capture receipt or retain a typed `not_established` limitation. Make legacy eligibility conditional on the actual consumed basis. No G choice is inferred here.

**Next check before code:** identify, with exact owner/source hashes, whether a current durable run record can join (i) workflow id + invocation/node id, (ii) exact selected ArtifactRef, (iii) the params JSON Pointer/consumer role and actual source precedence, and (iv) the selected manifest/input edges. Probe the real candidate A/B consumer with a source receipt from that mechanism, plus a forged/raw self-binding control that must stay `not_established`. If there is no existing source record, root decides a narrow receipt design and leases all producer, workflow-state, bundle, consumer and test paths as one mechanism. Then rebind the 37-route denominator and run a source-frozen composed replay. Do not run the expensive full workflow before source scope and receipt ownership are settled.
