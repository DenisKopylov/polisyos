# V6 candidate-only recursive child source: G decision packet

## Decision requested

P40 bucket: **SAME_CLASS_DEEPER**. V6 still concerns the same whole property: an actual root producer yields meaningful children, one successful child simulation is persisted before a later sibling fails, and an independent fresh reader retains both the successful observation and typed failure. The current root source reaches the historical L2 confidence guard before producing child candidates. This packet offers two ways to proceed, but the second changes the capability to an explicitly candidate-only exploration path; it does not silently satisfy the original V6 exit.

G should choose one of these semantics before implementation:

1. **A — keep the original exit and wait for an acceptable current L2 source.** The existing full N4 producer and child derivation remain the route. The historical confidence snapshot stays withheld. The external custody owner supplies a genuinely acceptable current source through the existing SKG owner; then a fresh complete producer → child graph → CAS artifacts → sibling failure → independent reader run decides V6.
2. **B — approve a new, additive candidate-only recursive child source.** This would let a typed N4 proposal generate *exploration subproblems* from the root's already declared candidate lever set while retaining `historical_l2_confidence_withheld`, `grounding_status=not_established`, and `publication_authority=false`. It must never be cast to `GenerationUnderAResult`, and it cannot claim full grounding, currentness, N9 admission, or the original production-strength V6 result.

Until G chooses B and its input-to-child semantics are implemented and tested, the V6 producer and fresh-reader exit remains `verification_missing`. No current typed root proposal artifact or candidate child source was produced from the retained V6 run. The current run persisted `GenerationUnderAResult.status="generation_unavailable"`, zero candidates, and zero LLM calls because prewarm returned on the missing credal reference; the direct owner probe identifies the historical L2 confidence refusal in [the V6 diagnosis note](v6-actual-derived-lineage-diagnosis.md). The proposed B capability is currently `absent/unallocated`; it has no artifact, bridge, reader, or semantic integration test.

## Concrete B proposal for G

If G accepts this distinct candidate-band semantic, add a **new artifact family**, provisionally `policyos.runtime.quality.n4_candidate_child_source.v1`, with a new artifact kind. Do not mutate V1/V2/V3 schemas, widen the meaning of `GenerationUnderAResult`, or claim the candidate child projection is an atom-binding or grounding result.

The proposed producer input is the *current, typed* `N4CandidateProposalSource` from the existing three-organ N4 proposal route, persisted with its actual run/job/tenant/cell and exact root problem/context/profile source refs. The producer must not take a raw LLM response directly, nor use a recording fixture as current source authority. It recomputes the proposal and root problem hashes, then maps proposed intervention members only to already declared root candidate levers. The narrow reuse-first option is to call the existing `_link_candidate_scenario_intervention` for each exact typed intervention, take its registry-derived `LinkedIntervention.writes_slots`, and compare the exact operator/write-slot tuple against the root's declared lever set using the same semantic grouping rule as `derive_n4_candidate_child_problems`. This helper is a single-intervention linker, not a proposal-to-child producer; it does not currently emit a child source or accept an arbitrary candidate proposal as an authoritative child set. The current direct recording parse is invalid under today's strict Trinity enum values, and the current formalizer/healing route has not been run on that recording, so this reuse path is a concrete implementation option, not a demonstrated positive witness. Unregistered, malformed, ambiguous, and unmappable proposals stay in a typed `unresolved` collection; they do not create children. The new producer reuses the Core `DesignProblem` value and existing proposal/member types, but records a distinct source-intervention identity rather than pretending it has the existing generated atom's `source_atom_ref`.

The envelope should bind the exact root proposal source ref/version, root problem ref, root context-job ref, job/run/tenant/cell scope, projection rule ref/version, and production time. Each child row should carry the recomputed child problem ref, exact proposal-intervention content ref, exact subset of declared `candidate_lever_space` members, and the independently selected child `profile_selection_ref`. After derivation, the existing context/profile owner must admit each child under its own `cycle_job_profile_selection_ref(child_problem)`; the root profile cannot be silently reused. A missing or unresolvable child profile leaves that child `candidate_limited` and stops it before N4/N5. A child that reaches the existing candidate-scenario port still yields only `candidate_unverified`/`candidate_limited` N4 scenario source V1/V2/V3, not a generated full result.

The envelope should preserve the root typed K_ref limitation and confidence vintage when the actual K_ref owner supplied them, and require `credal_reference_payload=None` plus `l2_confidence_forwarded=False`. Candidate children have `grounding_status="not_established"`, `currentness_status="not_established"`, `publication_authority=false`, `n9_status="not_admitted"`, and no N6/N9 promotion authority. Do not call the candidate child “generated” or a full `GenerationUnderAResult`. If the candidate-only N5 route is authorized, its simulation result remains a candidate scenario and cannot be promoted to causal effect evidence.

The new reader would resolve and content-check the root proposal, projection envelope, each child problem, and the corresponding selected child source within the original job scope. The existing fresh run-details consumer can project the candidate-only lineage alongside the successful N5 result and the later sibling failure, with the status and limitation visible. A corrupt child ref must withhold that observation while retaining the independent failure checkpoint. A consumer that does not understand the new artifact kind must return a typed limitation; it must never reinterpret it as a generated root or silently show an empty success.

## Status, authority, migration, and time impacts

- **Status composition:** the root remains `candidate_limited` when K_ref withholds L2. Child rows are `candidate_limited` until their own source/profile admission; a successfully bound candidate stays `candidate_unverified`. Unresolved siblings remain typed blockers/limitations. A successful sibling's N5 observation and the later failure are both visible, but neither closes grounding or currentness.
- **Authority:** preserve P05/P15. LLM output remains candidate-only; no generated-result cast, inferred NCM authority, root-to-child profile reuse, confidence forwarding, causal claim, or publication. Candidate proposal model confidence is ignored for these gates. Only a separately admitted producer can ground a candidate.
- **Time and provenance:** retain recorded prompt/response and source refs, root/child job and run scope, persisted-at time, profile/context refs, and the proposal projection rule version. Do not reinterpret the original recording date, scenario date, or K_ref vintage as currentness or as child effect time.
- **Compatibility/migration:** this is additive and versioned. Historical candidate-source V1/V2/V3 bytes remain readable under their existing rules; there is no backfill and no migration of a V3 record into the new root-child schema. New source kind and reader are opt-in only after G choice. Existing consumers that encounter it must expose a typed unsupported/limited state.
- **Capability labels before implementation:** B has `contract_only` only after G ratifies the schema; today it is `absent/unallocated`. After contract acceptance, missing items are `producer_missing`, `artifact_missing`, `bridge_missing`, `consumer_missing`, `verification_missing`, `surface_missing`, and `semantic_test_missing` until each is actually built. A source-only prototype is not capability evidence.

## Required acceptance and negative controls if B is chosen

1. Run the real current N4 proposal path using a source-bound stored recording through the current formalizer, and retain the exact typed proposal and K_ref refusal. Do not edit the raw response or seed the historical L2 registry. If the current formalizer cannot emit a typed proposal, report `generation_unavailable`/typed limitation and stop.
2. Prove at least two semantically distinct declared-lever children from that typed proposal, each with recomputed child problem identity and separate owner-selected profile/context refs. The off-slice guarantee, unknown alias, malformed intervention, duplicate intervention identity, and source-hash mutation must not emit a child.
3. Persist the candidate-child envelope and child source(s) in the same actual job scope. Keep L2 payload null/forwarding false, candidate statuses, currentness not established, and publication false through N5 and fresh GET.
4. Let one selected child complete real N5 persistence, then make a later sibling fail through the ordinary producer. A fresh parsed GET must preserve the first child's exact source/context/input/profile/simulation refs and the exact second failure. Corrupting the successful source or N5 blob must hide the observation with a typed limitation while retaining the failure checkpoint.
5. Remove the proposal-to-child content-binding mechanism while keeping all IDs/status/hash-marker fields. The test must go red. Cross-job/context/profile refs and wrong `DesignProblem` bindings must also refuse before N5.

If G does not approve the candidate-only semantic, retain option A as the only V6 route and keep V6 held until the custody owner supplies the current L2 input. The current historical confidence withholding remains in force either way.

## Pattern pass

Existing anti-pattern risks are P01/P02 (proposal contract without producer/artifact/bridge/fresh consumer), P05/P15 (LLM proposal or scenario projection laundering into authority), P07/P08 (historical source and time-role replay), P31/P32/P33 (per-intervention or form-only admission), P37/P38 (self-declared target as gate predicate), and P40 (repairing the root result, then a child mapping, then a profile, one layer at a time). The desired B pattern is one versioned source-bound candidate-child projection, one canonical resolver for proposal member → declared lever subset, independently admitted child profiles, and one fresh consumer that carries limitations. The existing source-bound prototype demonstrates the immediate discriminator but is intentionally not a passing child artifact. Acceptance is the real multi-child sibling-failure replay and mutation controls above; no G closure or V6 closure is implied by this packet.

No product source or tests were changed, no test or fit was run, and no Git command was run.
