## Capability states

The code paths are not equivalent to a claim of complete production capability. Authorization and OPA are wired through server-resolved identity, action dependency, middleware, and audit/OPA consumers. The action-permission denial path emits a denial receipt; the run-ownership mismatch path returns a typed 403 but currently has no matching denial audit, so that branch is `surface_missing`. Production approval's scorecard input is a persisted CAS consumer bound before policy evaluation. Governed projections have a typed HTTP surface and replay controls; the dynamic projection route carries no tenant selector, so cross-tenant scope for that route is `not_established` here.

Human decision gate readback explicitly returns `producer_missing` when its optional producer is absent and records that limitation in the access audit. Acquisition action is bridged to the durable worker and CAS action head; the replay witness is intended to verify terminal-head reuse, and its corrected fixture lifecycle awaits the root-owned rerun. The acquisition surface projection composes owner-source records, while the execution route is conditional: absent production authority/execution/readiness remains `producer_missing`, the semantic epoch remains `not_established`, and world growth remains `no_growth`. The existing production integration tests exercise the configured execution path. These are runtime states, not labels inferred from the presence of test files.
