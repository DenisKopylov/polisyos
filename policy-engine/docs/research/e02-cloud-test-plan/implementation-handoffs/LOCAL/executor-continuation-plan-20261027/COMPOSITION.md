This procedure continues the existing author lineage. ## Intake contract

The root coordinator is the sole canonical local writer and Git index/HEAD/ref publisher. Local assistants prepare confined regular postimages/patches or read-only oracles; they do not share a Git mutation lease. Independent cloud tasks edit their own task source only. Each small receipt binds actual base and final commit/tree (or exact final source and patch identity when uncommitted), task/environment, source and input identity, per-file pre/post hashes, full mechanism/companion footprint, commands actually executed, profile/backend and separate `PASS`, `FAIL`, `ERROR`, `SKIP` and `UNRUN` results. Record the positive, adversarial and removal property, original metadata separately from runtime observations, and each accessible evidence locator/hash. A returned commit alone is not source acceptance.

### Evidence and delivery admission

- **A — deliver:** useful implementation, regression/oracle and mandatory companions, useful documentation, and evidence G requires. Retrieve the actual bytes. A patch or task diff must include new files as well as modified ones.
- **B — give a recipe:** material reproducible from Git, an exact command and an input already available to the coordinator. Bind all identities; a known command does not make inaccessible input reproducible.
- **C — exclude:** duplicate/noisy output and unnecessary debug, source or payload dumps.
- **D — retain with a justified exception:** nonreproducible deciding witnesses. Keep the necessary complete output and establish coordinator access. Generate compact output at source and use lossless gzip when useful; moderate receipts/logs can use the real Git or cloud diff or an applicable patch. Do not hand off giant recovery, checkout, environment, dependency, fixture, CAS or DB archives.

The delivery property is that the local coordinator actually receives the required bytes and recomputes their SHA-256. A cloud ignored-path locator and digest measures only the producer's assertion of existence: for example, a destroyed task VM can leave that assertion intact while its bytes are inaccessible. Thus the predicate is `recomputed` only after local retrieval and hash comparison; until then availability is `not_established`, not `AVAILABLE`. Prefer proving a suitable transport before expensive proof. If a large channel has not been proven, identify the unavailable witness and its exact bounded rerun on the relevant source, backend/profile and available inputs; do not automatically repeat all cloud computation. C01's early useful code/new-test/receipt/output delivery probes the small channel, without delaying unrelated authoring.

Admit a return in this order:

1. Retrieve and hash actual task report and required deciding evidence, then inspect source diff at exact commit/tree. Check the result did not rely on unavailable RAW, private local data, a changed pytest profile or fabricated authority. Check its initial base against the dispatched prompt; a moving branch name is insufficient. If required bytes cannot be obtained, retain the bounded result as `not_established` and its exact rerun, not a verified delivery.
2. Enumerate mechanism **and** importer/config/build/test/public/API/UI/schema/generated/lock/release companions. Compare actual canonical local preimages. Existing patch applicability, constructor validity or static GO does not admit the property.
3. Assign an independent reviewer different from the author. Review the precise source/diff and original occurrence, actual producer→artifact→bridge→fresh-consumer effect, adversarial oracle and removal control. Require a named proxy-divergence example. Bucket findings as new class or same class deeper before repair (P40).
4. Compose disjoint source under one canonical writer. For overlap, refresh the proposal on the actual composed source under a new identity and review only its delta; do not overwrite newer work or port a hidden second implementation to old G. Use ordinary append-only commits and the existing G composition procedure. No reset/rebase/cherry-pick/decorative merge or history rewrite.
5. After composition run the affected defining property, importers and consumers at that exact source/profile/input. A cloud receipt remains a receipt for its source; it does not silently become a PASS for the local composition. Reuse unchanged earlier numerical proof only after source/input/backend/consumer qualification and explicit unaffected scope.
6. Keep implementation and evidence/receipt commits separate. Publish only the author topic, then independently read back remote commit/tree and changed bytes. If transport fails, preserve useful commits/diff and available outputs, state `transport_blocked`, and name the missing bytes and exact next rerun; do not introduce upload workflows or encoded blobs into the repo.

## Frozen verification and closeout

Freeze source → complete all source reviews → batch blocking deltas → freeze selected inputs/profiles/backends → run the expensive composed wave once. Reviewer cosmetic changes after freeze are recorded debt unless they change a load-bearing property. A new blocking source delta invalidates only its affected proof footprint; it does not trigger numerical reruns merely because HEAD advanced.

The wave covers changed modules/importers, recomputing validators and corrupt-field drift refusal, Ruff, architecture guardrails, runtime contracts, canonical generated consumers, ordinary parsed HTTP/client/browser where required, native optional profiles, source wheel/rebuilt-sdist/archive consumers and actual local data-dependent proofs. The exact complete commands/selected nodes come from each task's admitted record and source; a nonexistent proposed selector is created/reviewed before it is counted. Full backend verification/CI parity are reserved for closeout. Failed installation/backend/profile admission records ERROR/SKIP/UNRUN and an exact next action, not a product failure or green check.
