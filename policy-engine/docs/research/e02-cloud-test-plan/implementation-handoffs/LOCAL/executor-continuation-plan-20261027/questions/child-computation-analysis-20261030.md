## Authority choice and alternatives

The exact neutral G question is in [the question](child-computation-question-20261030.md).

- Reuse-only branching/snapshot/merge cannot appoint broader child rights. Active
  grants survive snapshots; merge applies declared journals and branches under the
  existing grant. Private completion detachment is not a consumer release API.
- Conditional recommendation: extend the existing canonical engine/registry/
  invocation/journal/merge ownership with a **new separately issued and admitted
  child-computation capability**, keeping the parent view and four paths intact.
  Registration identifies a child contract; it does not authorize the new rights.
- Alternative: a **new explicit parent composition grant**, independently derived
  from authorized registered child contents/implementations, plus separately
  enforced four-path projection. This requires a selected migration decision and
  does not justify silently enlarging the current NodeSpec.
- If an existing ratified rule already chooses either form, G must cite its finding,
  appointed owner and scope. Selected engine/custody documents inspected here do
  not supply a proven complete workspace issuer or read/effect boundary.
- Reconstructing an unguarded model, clearing journals, invoking a private detacher,
  broadly adding params/artifacts rights, bypassing the search node, or manually
  persisting result/CGF/calibration/authority fields is rejected.

This is one load-bearing computation/authority composition class, not a path-by-path
write-list repair. The minimal extension stays inside the existing engine; it does
not appoint a new sovereign workflow, registry, policy, CAS or publication subsystem.

## Proposed issuer and admission, conditional on a selected rule

A separately appointed issuer owns which parent/component may receive which bounded
child computation rights. A registered composition is necessary evidence, not that
appointment. The engine port must resolve actual issuer appointment/policy/rule
version from its owner and independently reconcile the active admission generation,
expiry/revocation status and current parent run/job/attempt/tenant/cell. A caller
cannot appoint it by supplying a NodeSpec, Protocol-shaped object, LLM result, file
path, marker, receipt or a list of child names.

The issuer binds the exact selected-profile parent invocation/input/WorkflowSpec,
registered composition content/digest and complete ordered membership. Actual child
component IDs, NodeSpec content and **live registered implementations** must be
content-bound to that source and independently reconciled at consumption; a correct
name with a replaced implementation is insufficient. Missing issuer/source proof,
ambiguous ownership, substituted profile/content, stale/revoked admission or changed
member/implementation set refuses before child work. Reconcile the same admission
before every child and final publication; freeze its exact rule/generation and
membership in the evidence. No claim of atomic exclusion of arbitrary external
writers follows from periodic checks; protected publication needs the canonical
transaction/lease custody that actually covers its commit.

The following predicates are separate, with current evidence honestly classified:

- Parent invocation/run/attempt and selected input source: independently_reconciled
  only when the existing run owner resolves and content-binds them; otherwise
  not_established.
- Issuer appointment, new computation grant and freshness/revocation owner:
  not_established in this prototype. No broader child right is currently granted.
- Complete immutable composition and actual child implementations: recomputed from
  the appointed owner's source and independently_reconciled with the registry/live
  implementation; caller-declared lists alone are consumer_asserted and refuse.
- Enforced read/input basis and side-effect envelope: not_established for a workspace
  today. Existing `state_reads` is advisory, not a hard privacy boundary.
- Child settlement/journal/merge and four-path projection: recomputed from actual
  operations and independently_reconciled against the admitted source/lease; field
  presence and an outcome's self-attestation are insufficient.

Consumer_asserted, institutionally supplied without independent reconciliation, or
not_established predicates cannot carry a protected authority/settlement gate.
Until the missing owners exist, no successful settled-workspace receipt is issued.
A typed refusal/limitation may preserve candidate work only in the specific plane G
permits; it cannot claim a protected read/effect boundary or authority publication.

## Input, effect and lifecycle custody

The new owner must enforce a restricted input/read mechanism, not merely compare
advisory read lists. It supplies only the admitted input projection and explicitly
owned candidate refs, refusing undeclared reads and cross-tenant/profile substitution.
A new field of rights does not silently extend current stores, ports, authority
writers, network/data access or effect scope.

A private Python state graph is not a side-effect boundary. The selected contract
must appoint an independently controlled effect envelope for CAS writes and generated
references, RunContext/run manifests, other ports, tenant effects and public/export
bytes. Specify which writes are staged, when candidate bytes may become visible,
which are reversible, and which effects are refused because they cannot be contained.
The existing Stage-B save/restore of a few manifest fields is not complete custody.
A child result/ref/journal cannot authorize an external/public/authority effect.
Parent publication independently resolves the complete permitted output/ref set and
checks the same current admission and lease at the actual publication boundary.

Each child executes under its own authorized registered scope. The workspace owner
settles its genuine journal and applies only verified operations through the common
merge owner. A later sibling is independently admitted; it cannot broaden the prior
child's narrowed view. No mutable alias may affect the parent, sibling or a completed
child. Parent publication uses its still guarded original four paths only. Partial,
failed, cancelled, rejected and unadmitted work retains its honest terminal state;
rejected input cannot mint a success/settled receipt. Currentness and scientific or
institutional authority remain governed by their original owners.

Nested work shares the parent's remaining resource/deadline/cancellation authority,
not a renewed budget. Retry, closure, cancellation, lease loss, cache/replay and
remote return must bind the same issuer generation, implementation and selected
basis; late writes/effects and handle reuse after settlement/revocation refuse.
Sync, async and remote parity is a requirement to demonstrate, not a property of
this interface sketch. Process-crash/irreversible external-effect guarantees must
be explicit supported mechanisms or bounded refusals, never implied rollback.

## Minimum positive, negative and removal controls

1. A cheap genuine registered two-child composition with disjoint private writes,
   actual journal settlement/merge, unchanged parent/sibling, only four published
   paths and properly bound candidate refs. Equivalent actual sync/async/remote and
   replay entries must exercise the same contract where supported.
2. Refuse missing/forged issuer, stale/revoked admission, wrong parent/tenant/attempt,
   substituted selected profile, absent or replaced composition/child implementation,
   changed ordered member set, and a consumer-supplied wider NodeSpec despite intact
   identity/receipt markers. No rejected input yields a settled receipt.
3. Refuse an undeclared/secret read, unauthorized CAS/RunContext/port effect, cross-
   tenant artifact or public/export byte emission, parent/sibling alias mutation,
   late effect after cancellation/settlement/revocation, and reused handles. Preserve
   failed/incomplete status and the exact absence of publication/effects.
4. Remove issuer/source binding while keeping names/markers: the forged/replaced
   child must become a counterexample. Remove the read gate: a secret read must
   escape and fail the unchanged negative. Remove the effect/publication gate:
   an actual side effect/public byte must escape. Remove closure enforcement:
   the late-effect negative must distinguish it. These are substantive runtime
   falsifiers, not scanner/field-presence checks or permission from a pyi shape.
5. Rerun all three exact R102 comparison selectors with actual planner success/output
   and every existing target policy, cold receipt, audit, adversarial and removal
   assertion retained. Genuine remaining causal/calibration/evaluation refusal is a
   bounded input/capability signal, never reason to fabricate evidence or claim an
   admissible recommendation.
