Treat custom claims= as low-level compiler utility only; never label its status="pass" artifact as an admitted candidate. Preserve the current blocked typed output and zero-candidate adapter input for unmatched custom input. Document the scope and leave the public schema unchanged. This matches current source capability and adds no new legal criteria.

**B. Extend the existing compiler artifact/input handshake.** Reuse the current LegalAuthorityRequirementArtifact producer; add an owner-controlled persisted source-input basis (or an equivalent owner API) that retains and resolves the original claim/facet/obligation inputs, target_context, governed fallback configuration, run/rule version, source provenance, and exact request/query identity. The top-level GL producer accepts that typed basis and derives the requirement artifact and matching search ledgers from the same source IDs; consumers recompute the entire basis-to-artifact/binding projection before adapter calls. This option needs G approval for who owns/supplies the custom basis and how it is versioned; implementation must reuse the existing compiler and query owner.

The current artifact stores compiled output and claim refs, not its original arbitrary input payload; no source resolver is established for those refs, and the high-level bundle is fixed to canonical defaults. Confirmed absence is the LegalAuthorityRequirementArtifact model and the GL builder signatures above, plus the executable R5 custom-input refusal control.
