## Caller, identity, and bounded residual

The cache key binds model and request fields including prompt/system/user/messages, temperature, seed, response format, stable metadata, and extra parameters. Ordinary scope adds tenant, cell, and actor. Snapshot reuse recomputes the content hash; the live decision is checked against issuer, epoch, actor, tenant, scope, purpose, model, request digest, and evidence. `metadata.cacheable=False` bypasses caching for an intentional independent call. Maintained tests cover same-wrapper four-way single-flight, seed/tenant distinctions, intentional bypass, follower cancellation, owner error/deadline cleanup and retry, exact reuse-origin events, and unknown-cost preservation. The r3 scratch witness separately isolates actor/ref/version axes; those isolated variants are not yet maintained regression cases.

The author’s one-call census is for `run_provider_preflight`, not the entire gateway-factory surface. I independently scanned all **2,754** product `*.py` files, counted source mentions, and parsed every candidate file. The corrected census finds **10** bound/qualified `create_traced_gateway_client` call sites and **2** direct `CachingLLMClient` constructor sites, with zero parse errors. Receipt: `gateway-factory-caller-census-r2.json`, SHA-256 `6876c47ac9a877cf9c425997b14928eccd7ba2f5ccef42525397fa0432cf0087`. The first draft census missed a public-facade import from `polisyos.scientist`; r2 includes it and is authoritative.

The shared factory creates a fresh in-memory cache for each constructed client. The separate preflight completion map stores only completed client/reference entries; a cold miss constructs a new wrapper. The sole `run_provider_preflight` production call site is `ControlPlaneService.launch_nl_run`: it creates a fresh run and job ID, binds them into the producer scope/key, then calls preflight once. Thus two distinct runs must remain distinct settlement intents. The selected ordinary route does not admit a second same-binding preflight caller. Other source callers do not establish an equivalent cross-client same-key workload; the parallel model-variant route deduplicates model names and has distinct model identities, and the parallel source-bundle verifier uses temperature 0.1, which bypasses the cache. These are source-bound findings, not production frequency measurements.

**P40 classification is `SAME_CLASS_DEEPER`, not a new class.** The known deeper boundary is two direct, concurrent, same-binding helper calls that each cold-miss the completed-entry map and create separate `CachingLLMClient` instances; the instance-local `_inflight` maps cannot join across them. This is the original B68 residual at lines 1745–1746 (“inter-client sharing” and production frequency unverified), not evidence that independent runs should coalesce. The author names the smallest future capability: a shared in-flight registry keyed by the complete admitted request, current authorization/scope, and durable run-event identity, with owner/deadline/error cleanup. No such registry exists or is warranted by the selected current caller. If a future real caller admits this shape, falsify it with one origin plus N equal usable results after fresh-ledger reopen, then separately exercise follower cancellation and owner failure/deadline.

The property is one producer for equivalent, admissible requests on the same wrapper; current `_inflight` ownership is per instance. The concrete divergence is same-binding equivalent requests through multiple cold client instances. Keep that as an explicit bounded limitation. Do not widen to a global/cross-run map: it would risk collapsing distinct run bindings, actors, evidence versions, or intentional repeats.
