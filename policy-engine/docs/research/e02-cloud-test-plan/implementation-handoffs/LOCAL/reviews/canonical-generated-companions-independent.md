## Findings at the earlier artifact checkpoint (superseded for current bytes where noted)

**Blocking contract divergence — GateRequest schema 1.2.** `GateRequest._require_selected_replay_refs_for_current_schema` rejects a 1.2 request whose `context.selected_replay_refs` is absent or null. The committed `schemas/snapshots/ir/gate_request.schema.json` only constrains `schema_version` to a version-shaped string and leaves `selected_replay_refs` optional in the nested `GateContext`; it has no conditional for 1.2. A payload with schema version 1.2 and no selected refs is rejected by the Pydantic runtime model but accepted by `jsonschema.validate` against the published snapshot. The same payload with version 1.1 remains readable by Pydantic, as intended. The full discriminator is retained at `reviews/raw/canonical-generated-companions-independent/gate-schema-divergence.stdout.txt`.

This is P38: the public schema is the stand-in for the runtime property and agrees on ordinary payload shape, but misses the exact schema-version boundary the property guards. The ABI snapshot checker passes despite the divergence because its generated model schema does not encode this `model_validator`. A complete fix must make the generated/published schema require a present, non-null `selected_replay_refs` for version 1.2 while retaining the 1.1 read shape, and add a behavioral schema test proving both sides. No implementation change was made in this read-only review.

**Same P38 class, one level deeper — field-specific WorkflowRunRequest admission is broader in OpenAPI than at runtime.** `production_case_intake_ref` is correctly optional and nullable, and the generated OpenAPI and both generated TypeScript surfaces agree on `ArtifactRef-Input | string | null`. The runtime DTO further rejects typed refs except `kind == "gy.loop.proof.root"` and `media_type == "application/json"`. The generated `ArtifactRef-Input` schema leaves both properties as unrestricted strings. A payload with a valid-looking SHA-256 artifact ID, `kind: "some.other.kind"`, and `media_type: "text/plain"` passes OpenAPI validation and fails `WorkflowRunRequest.model_validate`. The discriminator output is retained at `reviews/raw/canonical-generated-companions-independent/workflow-ref-schema-divergence.stdout.txt`.

This is not generated-client drift: the client and dashboard accurately reproduce the broad OpenAPI type. It is a runtime/schema admission mismatch. P40 classification: the second finding is the same schema-versus-runtime contract class at the field-specific narrowing layer. Closing only the GateRequest conditional would leave this divergent case. Either the source-derived OpenAPI contract needs to express this field's accepted artifact kind/media type, or the narrower runtime rule must be recorded as a bounded documented residual; a second local patch alone is not closure.

## Historical follow-up: pre-v2 Core source and TypeScript projection (superseded above)

The current `src/polisyos/core/contracts/control.py` bytes (SHA-256 `a9f30eea895fff8afb715f254b232711e405408a53fc96de3be5c512492df47c`) now attach an `allOf` `if`/`then` condition to `WorkflowRunRequest.production_case_intake_ref`. At this read the OpenAPI artifact has not yet been regenerated: `schemas/runtime_api_v1.openapi.json` (SHA-256 `b431712cea11280f1a404b84fb97d55c1665bc9105fc4c7bd001008dc6ab941c`) still shows only the broad union. The earlier OpenAPI/runtime discriminator remains accurate for that checked-in artifact, but it is not a measurement of the new source condition.

I fed the exact Pydantic-emitted field schema into the repository's actual `generate-openapi-types.mjs` pipeline, with only the local `$defs/ArtifactRef` pointer rewritten to the equivalent OpenAPI component reference. The installed pipeline is `openapi-typescript 7.13.0` plus TypeScript `5.9.3`. It emitted `production_case_intake_ref?: unknown | components["schemas"]["ArtifactRef-Input"] | string | null`; the `unknown` arm makes the generated type accept arbitrary values. A strict TypeScript probe supplied a valid typed ref, the legacy string and null arms, plus wrong-kind and wrong-media typed objects. Both `@ts-expect-error` directives were unused (tsc exit 2), proving the generated consumer type admits both invalid objects.

A counterfactual OpenAPI shape preserved the same optional `ArtifactRef | string | null` union while wrapping only the typed-ref arm in `allOf: [$ref ArtifactRef, {type: object, properties: kind/media const, required: [kind, media_type]}]`. The actual generator emitted a TypeScript intersection with literal `kind` and `media_type`; the same valid, legacy-string, null, wrong-kind and wrong-media probe passed strict tsc (exit 0). This is a real behavioral discriminator, not a keyword-presence check. The straightforward inner `Annotated[ArtifactRef, Field(json_schema_extra={properties, required})]` alternative was also tested: Pydantic emits those constraints as `$ref` siblings, which this generator omits. Adding `allOf` as a sibling of `$ref` has the same loss. The source fix therefore needs to produce the wrapper `allOf` shape (or change the generator to preserve `$ref` sibling constraints and prove that path); merely moving `Field` extras onto the inner annotation does not close the TS consumer gap.

P40 classification: this is the same P38 contract-to-consumer class one level deeper, now demonstrated at the generated TypeScript consumer. Close the class across source schema, regenerated OpenAPI and both generated TS surfaces, with runtime/JSON Schema and TS positive/negative tests. Do not treat the Pydantic schema addition alone as closure. Full commands, raw stdout, exact models and hashes are in `reviews/raw/canonical-generated-companions-independent/typescript-if-then-probe/`.
