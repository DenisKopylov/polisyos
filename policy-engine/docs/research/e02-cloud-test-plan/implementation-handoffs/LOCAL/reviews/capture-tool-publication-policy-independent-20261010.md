It is also distinct from source identity, which binds the executable bytes and worktree to the freeze.

The hunk changes only the ignore predicate in `verify_branch_and_freeze`: `git check-ignore --quiet -- <path>` becomes `git check-ignore --no-index --quiet -- <path>`, and the refusal diagnostic now says the path falls outside configured ignore policy. The old command uses the index, so a tool path that is both tracked (for publication) and covered by an ignore rule is reported as not ignored. `--no-index` evaluates the configured path policy independently of tracking; return code 0 admits that predicate, while every nonzero result still fails closed. This is the correct distinction for a published/tracked capture wrapper that remains at an ignored path.

The change does not relax the frozen-source check. `verify_branch_and_freeze` still requires attached `HEAD == supplied commit`, matching commit/HEAD/supplied tree, then calls `inspect_live_identity`. A tracked wrapper with changed bytes therefore still fails the clean-tree and/or pinned-hash predicate. The ignore check only resolves the status-vs-policy mismatch; it does not grant source identity.
