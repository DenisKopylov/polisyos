## Property review

The proposed classifier admits only a pytest status derived from exit code 1 plus parsed JUnit FAIL/ERROR cases; unknown and non-1 exits, invalid JUnit, launch errors, timeouts, and non-pytest failures do not qualify. `captured_pytest_failure_continuation` additionally checks command receipt identity, frozen commit/tree, plan/input/raw-source manifest hashes, wrapper/plugin identities before and after, selected-runtime-profile validity, matching fresh output roots, complete pre-receipt and final output inventories, stdout/stderr/JUnit hashes in both inventories, nonempty reconciled testcase counts with no skips, a matching FAIL/ERROR disposition, passing module-origin evidence, and required child-stream inventory. The CLI flag is opt-in; without it a failure stops. With it, only eligible pytest failures continue. Completed failures remain in `failed_command_ids`, all unexecuted commands stay `UNRUN`, completed-with-failures is distinct, and the process returns nonzero.

The profile check is weaker than that complete eligibility predicate implies. The wrapper obtains `versions = validate_product_python_profile(package_versions(python_path), ...)` once before the queue (`raw/composed_mac_capture.py:3640–3642`), passes that same value into each `run_one`, and serializes it into each receipt (`:2933`). The continuation predicate checks only that the stored profile says `status == "read"` and `prefix_matches_product_venv is True`; it has no post-command profile field or comparison. `inspect_live_identity` covers the repository/source manifest and capture tools, not installed product-venv distributions. Therefore a pytest failure can modify the selected venv’s installed-distribution profile while leaving Git/source/tool identity, output inventories, module origins, exit code, and JUnit valid; the continuation predicate still admits the next command using the stale pre-queue profile.

P40 bucket: **SAME_CLASS_DEEPER**, a missing integrity check within continuation eligibility. The smallest falsifier is a synthetic first pytest command that changes the selected product-venv package inventory and exits 1 with a complete ordinary failing JUnit report while leaving the repository and capture tools unchanged. Under the requested rule, the second marker command must remain `UNRUN`. Close this at the mechanism level by recording a fresh selected-venv profile after each command and requiring it to match the queue-pinned profile before continuation; unavailable, malformed, or changed profile must refuse continuation. Keep the existing source/tool/output identity controls.

The proposal’s two-command positive oracle and source-identity/output-inventory negative oracles are well targeted, but they are instructions only; this patch contains no executable oracle and none was run. Add the profile-drift negative case to that oracle. After applying any repair, the required static/review evidence still needs the synthetic ordinary failure to continue to a successful marker while the final result remains nonzero, plus default-stop, identity-drift, incomplete-inventory, profile-drift, unsupported/collection, unknown-exit, and signal stop controls. This review does not establish runtime behavior or authorize the 19+11 queue.

Two execution-isolation conditions remain. First, `load_wrapper()` imports the canonical wrapper with `spec.loader.exec_module` while leaving `sys.dont_write_bytecode` at its ambient value. Second, the synthetic pytest command sets `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` but does not override inherited `PYTEST_PLUGINS` or `PYTEST_ADDOPTS`. The wrapper copies `os.environ`; `run_one` preserves an inherited explicit `PYTEST_PLUGINS` list and appends its origin plugin. Pytest’s disable-autoload flag does not suppress explicitly named plugins, and `PYTEST_ADDOPTS` can alter invocation. For the claimed no-product-import/no-port isolation, pin `PYTEST_PLUGINS` to empty in the planned environment (the wrapper will add its own origin plugin), pin `PYTEST_ADDOPTS` to empty, or launch with those ambient variables unset and record that environment.
