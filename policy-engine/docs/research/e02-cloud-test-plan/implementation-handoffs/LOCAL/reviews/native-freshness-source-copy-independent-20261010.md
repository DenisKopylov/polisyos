# Independent review: native freshness source copy

## Verdict

**Partial; blocked for a full-source-isolation claim.** The proposal is tightly scoped to the isolated-copy mechanism and its mirrored test; it does not change scientific behavior or delete files. Its tracked/missing-path and special-file handling is materially safer than the current `copytree` path. The remaining issue is that the selected copy set is not yet proven equal to the four generators' effective read set. One concrete OpenAPI read can be redirected outside the copy by inherited environment, and the trust-posture compiler walks a filesystem-defined Python source set while the copier selects Git-visible files. The tests are proposed only; this review ran no tests, generator, native wave, or Git command.

## P40 classification

**SAME_CLASS_DEEPER:** the property is complete isolation of the source inputs used by each generated-artifact family. This is a deeper source-boundary escape from the same class, not a new defect class. Widen the input boundary once to cover file selection, symlink ancestry, and environment-selected source roots, or record a bounded residual with its falsifier. Do not add one more exclusion alias per discovered cache.

## Material findings

1. **High — the OpenAPI generator can read a source root outside the copy.** The current `_isolated_probe_environment` in `tools/devx/architecture/guardrails.py@5d30de37ed02c5e346458e62e00b2772e7ba0eed501cf8282f72d3058bf9b4f6` begins from `os.environ.copy()` and removes a fixed set of UV/virtual-environment variables; it does not clear or rebind `POLISYOS_GOVERNED_ARTIFACT_ROOT`. `openapi_contract.py@d0223be603ecdde252a96ded5970f2fedfecf3099401a3a8608bb70fd27b1e3c` reads that variable in `_confidence_ledger_risk_spend_example`, which is registered as the success example for `get_confidence_ledger_risk_spend_projection`. `augment_runtime_openapi` calls that example when the operation has no existing example. The route in `routes/governed_projections.py@a59d18b809d7b073e423dee7045c94569752f112f8df600d497fd5fe74787541` declares the response model and operation ID without a fixed example. If the inherited variable points at the original checkout or another repository root, the isolated generator can consume governed artifacts from outside its copied source and still emit an OpenAPI result. Whether the variable was set during the historical red is **not established**; the bypass exists in the current code. The narrow fix is to set this family input to the isolated root and prove that a deliberately different external root cannot affect the output.

2. **High — the trust-posture generator's source denominator differs from the copy denominator.** `trust_claim_posture_sources.py@75ae37a1facb5dccdfd72437dea96cff26c460e5bda79186b46c3977b6fcf656` says `walk_source_files` walks every Python file under `repo_root/src` and implements that with `source_root.rglob("*.py")`. The proposed `_isolated_probe_copy_inventory` instead uses `iter_repository_files` plus `git ls-files --others --exclude-standard`. A user/global-ignored, untracked `.py` under `src` is therefore part of the live compiler's filesystem walk but absent from the copy. The compiler can produce a self-consistent output from the smaller set without reporting that omission. The repository `.gitignore` inspected here ignores bytecode and residue under `src`, but not ordinary `.py`; no actual ignored source file was established, and this review was explicitly barred from Git queries. Thus this is a confirmed selector divergence with a current-hit status of **not established**, not a claim that such a file is present. The new test force-adds its `LOCAL/raw` Python-independent fixture with `git add -f`; it proves tracked ignored files survive the selector, not that an ignored untracked required input is admitted or causes `UNRUN`. Align the copied Python-source set with `walk_source_files` (or make the canonical compiler consume the same explicit source manifest), then falsify with an ignored untracked `.py` whose recognized posture metadata changes the output.

3. **Medium — symlink containment is incomplete and its omission is not a typed unrun.** The proposal checks a final-component symlink with `resolve_admitted_path`, but regular-file paths are `lstat`ed and copied without resolving their parent chain. A tracked `pkg/module.py` beneath a replaced symlinked parent can therefore be read from outside the admitted root while appearing as a regular file. Separately, an unsafe or dangling **untracked** symlink is counted as `external_symlink` and silently skipped; if a family needs that visible path, the code can continue without proving the input is irrelevant. The patch tests assert the intentionally linked `node_modules` path and a missing tracked schema, but add no internal, external, dangling, or symlinked-parent control. Validate the parent of every selected path before copying, and make any omitted visible symlink that may be a family input resolve to a typed `UNRUN` unless a consumer-derived inventory proves it is not used.

## Four-family input review

The generic selector includes all **tracked** and **nonignored untracked** files under the supplied product root, except recognized local-artifact roots; it does not add an explicit `raw` path exclusion or per-family source aliases. Tracked paths under excluded roots fail closed. Untracked ignored paths are omitted by `--exclude-standard`, including the repository's `docs/research/**/raw/` rule. Therefore the test's force-added `LOCAL/raw` file is a tracked-input control; the statement “no blanket raw skip” is true for the copier's explicit path rules, but not for ignored, untracked raw files. The actual family read-set review below is enough to identify current concerns, but not to claim a complete runtime census without the frozen four-family run.

The patch also has two honest limits: its `selection_manifest_sha256` binds path/size/mode/link text, not file bytes; and the disk preflight sums selected regular-file sizes only, not the private `uv` environment or later generator scratch. The handoff labels disk size as a lower bound and requires later provisioning to fail as `UNRUN`, so it does not claim full-wave capacity. The manifest must not be cited as proof of copied content identity.

The source-set policy itself is unresolved across owners: the guardrail snapshot intentionally uses the Git-visible set, while the canonical trust-posture walker documents and implements a complete filesystem `src/**/*.py` walk. If G/source owners intend Git-visible files to define posture source, the canonical walker must be changed and tested to that same set; if filesystem semantics remain authoritative, the copier must preserve that read set and not silently omit ignored files. This review does not choose a new source rule or claim a current ignored Python file exists. The minimum falsifier is an ignored, untracked `src` module containing a valid recognized posture declaration: compare the canonical live walk with the copy and require the copy to include it or return `UNRUN`.

## Proposal tests and scope

The patch changes exactly `tools/devx/architecture/guardrails.py` and `tests/repo_quality/tools/test_architecture_phase3.py`. The added child generator reads a copied schema, config, and raw fixture and shows its output changes when the copied schema changes; the missing tracked schema and insufficient-space cases assert `UNRUN` before destination creation or execution. These are useful mechanism controls. They do not run the four real families or prove their complete read sets. There are no controls for inherited external source roots, ignored untracked runtime source, parent-symlink escape, unsafe untracked symlink omission, or copy-byte integrity.

No source, tests, generated artifacts, or Git history were changed. The proposal patch itself was not applied, and no test, copy, generator, or native command was run in this review.
