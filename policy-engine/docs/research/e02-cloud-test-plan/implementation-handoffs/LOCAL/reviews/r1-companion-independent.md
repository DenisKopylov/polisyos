- The generic `test_workflow_timeout_raises` used a test-only `test.slow` node. Its timed macOS admission was refused, so the node returned as a failed outcome and the test's expected outer `WorkflowTimeoutError` did not occur.
- The journal-replay worker and the two Decimal codec cases requested timed nested workers for custom IDs absent from the closed spawn allowlist; all were refused with `timeout_worker_node_not_supported` before reaching their asserted behavior.

The proposed replacement exercises a real saved-source `ResolveParametersNode` and an async checkpoint hook. The fixture retains the SKG value `1.25`, replaces the live source with `9.75`, and the hook reads the produced parameter bundle before it blocks. It then checks the node has completed, the selected value is `1.25`, cancellation reaches the hook, and the workflow timeout reports `execution_state=unknown` / `publication_operation=checkpoint`. In the current executor path, `_cache_deadline` combines the workflow deadline with invocation timing and `_execute_node` passes the remaining budget into `execute_with_retry_async`; therefore the sync ResolveParameters node in this async workflow is executed through the timed worker path even though `_workflow("async")` leaves the invocation timeout unset. The existing parameterized `mode="timed"` SKG selector test separately asserts the Darwin spawn route, child cleanup, selected-view value, and live-source divergence.

The new refusal row adds a well-formed, non-allowlisted custom component ID and requires its typed `timeout_worker_node_not_supported` refusal before process creation, thread fallback, node-body marker, or CAS changes. This complements the existing missing-canonical-node and unsupported-context controls; it does not imply that arbitrary custom IDs are admitted. The worker-wire and Decimal transport tests use `timeout_s=None` for Darwin custom nodes while retaining Linux `timeout_s=2.0`; their assertions preserve branch merge behavior, both codecs, and the platform-specific process ancestry (direct execution in the outer worker on Darwin, nested timed fork worker on Linux).

The patch's evidence boundary is appropriately limited. The new deadline witness proves cancellation of an async checkpoint after a real node has completed and its CAS output has been read. It does not establish hard cancellation for blocking synchronous callbacks or native/backend I/O. Nor does it prove that every admitted slow node produces a top-level workflow-timeout error: the current node executor may convert a node timeout into a failed node outcome before the outer workflow wait expires. These broader deadline semantics remain unclosed, as the companion note states. The new callback test does not itself assert the spawned PID; the separate timed selector case covers that mechanism, while the current source path ties this workflow deadline to the node budget.

P40 bucket: **SAME_CLASS_DEEPER**, the timeout-spawn admission class applied to real SKG workflow/checkpoint behavior and unsupported-input negatives. The patch preserves the closed allowlist rather than weakening it. No codec behavior is removed; the Mac path changes only from unsupported nested timed custom-worker admission to the existing untimed wire, while Linux's timed fork route remains.

No test result is claimed for this patch. The later focused/full wave remains necessary, including the timed selector positive, the new async checkpoint deadline case, all three unsupported-input refusals, the worker-wire branch test, and both real-worker codec cases.
