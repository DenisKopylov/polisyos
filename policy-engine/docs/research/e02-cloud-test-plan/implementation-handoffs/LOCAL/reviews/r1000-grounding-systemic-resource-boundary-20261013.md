## Current source path and quantity

`build_credal_reference` deliberately retains the full selected L2, all L3 query families, loaded L6 bundle, and WMR slots in `essential_edges`, then derives component versions and a hash over that set (`credal_reference.py:568–612`). CG1 consumes that full mapping.

`GroundingRelationEngine` already has the right per-engine reuse boundary for the FTS object and the atom tuple (`grounding_relation.py:350–369`). On the first nonempty search it lazily builds `_DuckDbReferenceFtsIndex`. That builder creates four Python lists for **every** essential edge, serializes completion and provenance into search text, materializes a Pandas DataFrame, registers it with DuckDB, copies it into a table, and creates a full-text index (`grounding_relation.py:880–943, 2046–2059`). The query then returns at most 80 lexical hits (`:888–918`), but that limit does not bound the full index construction or the subsequent candidate scan. The run's stack at the SQL query is consistent with this full-corpus path; it does not apportion CPU or memory among DataFrame materialization, DuckDB table/index creation, or other work.

After FTS search, `reference_atoms` derives the complete operator/compatible-writable-slot universe from the reference and caches it once for scoring (`grounding_relation.py:363–369, 946–1037`). Retrieval scores every cached atom (`:511–537`). There is a second full construction per proposal: `_proposal_verdict` calls `_known_space_coverage_claim`, which computes `atom_universe_count` with a fresh `_reference_atoms_from_cg0(reference)` rather than reusing the engine's tuple (`:403, 1528–1542, 1677–1727`). In this candidate-generation path, `Q` successful proposal certificates therefore cause one cached atom construction plus `Q` additional throwaway full constructions; `Q` is the number of interventions in the bundle. The selected test describes an unchanged three-proposal capture, but R998 did not record the runtime bundle count or per-proposal timing, so that fixture description is not reported as a measured dynamic count.

## P38 measurement gap inside the same class

The FTS wrapper sets `indexed_edge_count = len(reference.essential_edges)` in its constructor, before any DuckDB table is built (`grounding_relation.py:883–886`). `_certificate_for_parsed` later reports that field, and `_known_space_coverage_claim` declares `coverage_sufficient` when it equals the source mapping length (`:408–414, 1715–1727`). It never reads the actual table's row count or verifies its document keys. A concrete divergent case is an empty or token-empty query: `search()` returns before `_build()` (`:891–900`), but the prefilled count can still make `coverage_sufficient` true when base candidates exist. That is a P38 proxy: the property is “the complete reference corpus is indexed,” while the current predicate tests “the source edge count was copied into a field.” This case was not the cause of R998—the captured stack shows R998 did execute SQL—but it should be closed when the index builder is next changed. The current builder's explicit loop does append one row per edge; no missing-row runtime case was observed.

## Smallest class-wide direction and falsifier

Extend the existing `GroundingRelationEngine` owner rather than introducing a global cache or another N4 gate. Keep the complete K_ref and exact CG1 candidate behavior. Make one per-engine full-basis retrieval state the source for the actual indexed document count, the cached atom tuple, and each proposal's coverage summary. A bounded-batch DuckDB loader is a plausible prototype to remove the full Python list/DataFrame/table duplication while retaining every edge; it is a hypothesis, not a measured fix. Reusing `len(self.reference_atoms)` for the coverage summary is the direct reuse-first correction for the repeated atom reconstruction.

The prototype must prove the property behaviorally on the same selected full basis and every original proposal: exact source edge-key/document set and actual table row count; exact ordered `(edge_key, score)` FTS results; exact candidate atom IDs/order, reasons, scores, CG1 certificate hash and coverage fields; then identical N4 dispositions, selected child profiles, and fresh-GET projection. Include an omitted-row counterfactual while keeping the source-length marker intact; the completeness predicate must turn false. Capture `E`, `A`, row count, `Q`, per-stage time, and RSS at the existing owner boundaries. Do not reduce the source basis, cap the atom universe, lower the lexical limit, change ordering/scoring, or infer authority from CG1: its certificate remains `shadow_only` and `no_bind_admit_promote` (`grounding_relation.py:438–475`).
