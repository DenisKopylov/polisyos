## Findings

**R1276 pointer refusal — addressed at the cause.** The retained failing case shows a real `ClaimAdjudicationRuntime` call over a persisted champion/evaluation fixture. A mismatched evaluation pointer correctly blocked, but the blocker exposed Pydantic’s multi-line `ValidationError` text instead of `claim_adjudication_promotion_basis_pointer_mismatch`. The patch introduces a private typed refusal and unwraps it only when Pydantic reports exactly one error whose context contains that exact exception type. Both actual source parse boundaries are covered: `_ClaimChampionEnvelope.model_validate` and the legacy `_PromotionBasis.model_validate_json` in `claim_adjudication_verifier.py`. Ordinary or mixed validation errors remain `ValidationError`; this is class/type matching, not string-prefix matching. The three production call sites of `read_claim_promotion_predecessor` are the registry read, promotion path, and verifier replay; each uses the same normalized helper. The patch does not turn a refusal into admission or change the status/authority gate.

The renamed runtime test now states the actual property: the false-guardrail evaluation is not the evaluation committed by the pointer/basis, so it is refused before the client is invoked. It retains the persisted fixture, asserts `blocked`, exact reason, and zero client calls. The fixture’s signed evidence is controlled test evidence, not an external evaluator appointment or production-grounding claim. The added legacy-sidecar test exercises the second parse boundary and asserts the stable domain code.

**Autotune protocol facade — addressed by completing the actual protocol.** `core/artifacts/protocol.py` defines the synchronous `ArtifactStore` surface (`has`, byte/manifest reads, byte/JSON writes with `return_selected_profile`, `verify`, and ID enumeration) separately from optional `RawManifestBytesReader.get_raw_manifest_bytes`. The old test proxy implemented only two methods, so it was not an `ArtifactStore`; strict Core loading was right to refuse it. The candidate’s base facade implements the complete base interface, and the derived facade adds the optional raw reader by delegating to the actual `FileSystemCAS`. The positive case persists with a selected profile and loads through `persist_mutation_artifact` → `load_model_artifact` → Core’s strict reader. The negative case retains the selected-profile ref, confirms persistence and `has`, then expects the exact `canon_profile_raw_manifest_unavailable` refusal when only the optional reader is absent. It adds no profile fallback or reader-side reconstruction.

The common Core JSON test suite already supplies the shared-loader adversarial controls with selected refs retained: present-but-malformed profile, incomplete/unsupported raw profile, wrong typed payload shape, selected byte drift, and selected-view preservation. Those tests exercise the same `load_core_json_artifact` boundary used by Autotune (`models.py` `load_json_artifact`/`load_model_artifact`). Thus the new proxy test covers complete protocol presence/absence, while malformed/fake declarations are checked at the common owner boundary rather than by a second Autotune-specific loader imitation.

## Pattern and coverage assessment

This follows P32 (resolve and verify, never trust presence), P38 (the old test label implied a guardrail decision although the real failing condition was pointer mismatch), and P40. The refusal normalization is a **new class**; the candidate widens it across both extant parsers in one helper. The protocol-proxy finding is **same class, one level deeper**; the proposal widens the facade to the complete base protocol plus the separately optional reader instead of adding another assertion to the incomplete proxy. This is not a status or authority change.

The property path now has a representative persisted-input/runtime refusal test, a direct legacy-sidecar parsing test, and protocol-backed persistence/fresh-load and missing-reader refusal cases. Existing Core tests supply malformed and altered profile controls. The proposed code is intentionally private and reuses the existing Core reader contract.
