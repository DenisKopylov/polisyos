## Blocking R3 oracle gap

The patch correctly recognizes that `manifest_profile_sha256 is not None` was a P38 proxy: the recorded producer emitted one explicitly profiled selected view and six legitimate default (`None`) views. The new `_resolve_authority_envelope` checks the selected CAS bytes and identity, kind/media/schema, expected tenant/cell/run, manifest governance classification, non-null producer/closure, and the envelope-to-manifest producer and closure fields. It loops over all actual producer refs and does not blanket-reject a profileless default.

However, this is not yet the full authority-envelope binding claimed by the handoff. It never checks `EvidenceAuthorityEnvelope.owner` or the envelope's `governance` fields against the actual producer contract (`owner="team-runtime"` and the values returned by `_runtime_quality_governance_metadata()`), even though it checks only the CAS manifest's classification. It also compares closure job IDs only between the envelope and manifest, not with the observed job (`no-control-job` in the retained readback), and it does not reconcile `manifest.inputs` with the closure's `evidence_input_refs`. These omissions let two matching but wrong envelope/manifest values pass the new oracle. Add those source-backed checks and a remove-property-keep-markers negative before treating it as a complete content/scope/governance/issuer test; do not introduce a new issuer or authority rule.

There is a second schema-control issue in the special `default_ref` probe: the fixture creates a profileless view by changing the schema version to `1.0.0.sibling`, then passes that value as `expected_schema_version`. That proves a selected-view read can return the fixture's alternate manifest, but it is not a contract-valid `runtime_quality.evidence_authority_envelope` view. Keep the selector probe within the actual `1.0.0` schema contract, or clearly separate it as a raw CAS selector test that does not admit the fixture view as an authority envelope. The six actual default refs do run through the expected `1.0.0` checks; this finding is about the extra synthetic control, not a reason to restore the old non-null-profile assertion.

P40 classification for R3: **same class, deeper**. The class is exact selected-view binding; after the explicit-profile case, default `None` is the next selector form. The patch widens over all seven actual refs, but the authority predicate needs the additional source-bound checks above. The minimal falsifier is a correctly selected, content-identical view whose envelope owner/governance or closure job/input membership is changed while the manifest remains self-consistent; the oracle must reject it.

## V3 assessment

The V3 companion repair is structurally sound against the recorded gap. The original fixture persisted the compiled artifact without `tenant_context`, and the route refused it before calling `_candidate_acquisition_history_projection`; the readback shows the actual owner-bound admission scope and two matching terminal heads, generations 1 and 2. The fixture change derives `ArtifactTenantContextInfo` only from an established `admission.scope` while inside `control._install_execution_scope`, and `_put_json_artifact_ref` records that owner. It does not derive identity from the request or alter the route's production guard.

The proposed fresh GET assertions widen the history expectation from one row to the observed full two-generation set: generation 1 retains the `quarantined_no_growth` terminal receipt and no reentry/candidate fields; generation 2 retains the actual successful reentry/source assertions. The existing unauthenticated GET 401 control remains unchanged. The typed history model fixes `currentness_status="not_established"`, `authority_purpose="candidate_observation_only"`, and `publication_authority=False` for both rows, and its validator rejects reentry fields on the quarantined row.

P40 classification for V3: **same class, deeper**. The class is completeness of the persisted history projection. The first observed failure stopped before the reader because the fixture omitted established scope; the next boundary exposed that the test asserted only the successful generation while two source-backed heads existed. The patch widens to the complete matching head set instead of changing the reader or weakening admission. The retained observer evidence supports the inputs to this oracle, but the unapplied patch still needs focused execution before its output can be claimed.
