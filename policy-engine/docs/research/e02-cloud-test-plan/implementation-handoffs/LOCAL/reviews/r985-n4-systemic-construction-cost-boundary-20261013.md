## Engineering decision

Keep the full L2/L3/L6/WMR basis and current authority semantics. No new contract or G choice is justified by this evidence. The smallest next discriminator is one fresh, uninstrumented execution of the exact original test with a **300-second owned-child wall budget and the same hard 3-GiB RSS ceiling**. Preserve the original selected profile/source and all candidate, child, worker, persisted-artifact, and fresh-GET assertions. Retain full stdout, stderr, JUnit, PID/RSS samples, exact source frame, and input hashes. Do not treat the 60-second cutoff as a semantic test result.

If stage attribution is needed, run a separate payload-free diagnostic around existing owner boundaries and capture L2/L3/L6/WMR durations and edge counts, L3 fetched-row counts, valid-manifest scope count/duration, component total/registration count, peak RSS, build count, and fresh-GET completion. Do not install a global registry cache, drop L3 rows, cap routes, or bypass edge hashing. Any later optimization must preserve exact edge keys, statuses, provenance, content hashes, aggregate reference hash, and served GET output. If the replay reaches the 3-GiB guard, stop and profile allocation before changing the ceiling.

An older R904 run used frame R896 and a three-selector command; it was operator-interrupted after 190.7 seconds at a measured 14.7-GiB footprint while the target actual POST/worker path had begun, also without a completed consumer receipt or OOM attribution. That is a reason to keep the current 3-GiB guard, not a prediction of current R957 memory: R904 used older source and a different test composition.
