## Verdict: GO for the requested focused rerun

The removed check compares every parsed compiled run to the v1 constant even though the canonical `CompiledRecursiveGenerationCycleRun` contract admits the four Literal versions v1–v4. Its `_verify_bindings` validator requires the exact version implied by the typed payload: ordinary run v1, partial v2/v3, and v4 when producer events or scoped N4 evidence/profile projection is present. Thus the deleted comparison is a stale proxy that rejects valid v4 output; accepting only `model_validate`’s typed result preserves the real version/shape gate. Unknown v5 is outside the Literal and is rejected. The changed unit test mutates a valid v1 payload only to v5 and calls `model_validate`, so the failure is behavior-based rather than marker-based.

There is no separate malformed-v5 assertion through `AcquisitionRouteLoop.resolve_current_route` in the reviewed patch: the v5 negative is at the canonical typed parser, while the existing served-acquisition route test supplies the real route/reader positive. The production path calls that same `model_validate` and maps its `ValueError` to `compiled_run_invalid`; this makes the parser negative relevant, though not a direct assertion of the wrapper error code. If the review bar requires the wrapper mapping itself, add a light persisted malformed-v5 resolver negative; this is a bounded test-strengthening opportunity, not evidence that the patch widens accepted versions.

The guarded integration fixture change is correctly placed at the producer construction boundary. It supplies `FileSystemCAS(...).for_tenant(tenant_id, cell_id)` to `_build_control_service` before the workflow writes, then wraps that same explicit owner view with `guard_runtime_cas`. This replaces the previous helper monkeypatch/ambient wrapper that left newly produced artifacts unclaimed. The second test addition reads the produced passport through a distinct explicitly foreign-tenant CAS view and expects `ArtifactOwnershipError`; this is an actual CAS read refusal, not a synthetic ownership assertion. The test already runs inside the source tenant scope and uses the actual growth passport ref.

The captured pre-patch 22-case run is reproducible evidence for the two relevant failures: the actual served route fails with `compiled_run_schema_mismatch`, and the guarded world-growth test fails verifying its own passport because the owner index says `unowned`. The report was 20 passed / 2 failed, exit 1, 92.66s; no tests were rerun for this read-only review.
