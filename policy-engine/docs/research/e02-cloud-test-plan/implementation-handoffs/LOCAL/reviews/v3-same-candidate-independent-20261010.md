## Verdict

**GO for root-owned application and focused verification.** The patch reuses the canonical N4 source loader and active-epoch verifier, keeps the existing action authorization and `quarantined_no_growth` outcome, and does not turn the no-growth result into publication/currentness authority.

## Same-candidate lineage

The new route branch is limited to equal candidate IDs, then recomputes the complete `candidate_scenario_semantic_identity_hash` for each loaded V3 record and requires equality of those full hashes, stable subject, selected profile, and candidate ID. It also requires distinct occurrence and world-model hashes and binds the new record's typed origin ref to the previously selected N4 source (or its existing root origin). The source repository already validates V3's content hash, candidate-ID prefix, nested exact V2/context view, current tenant/cell/job/run, recursive origin, and recomputed semantic identity. The branch therefore closes the truncated-ID boundary from the actual source records instead of treating ID equality as semantic proof.

The served fixture now exercises the real same-candidate producer path twice, reads both records through the canonical repository, checks the changed occurrence/world-model and preserved origin lineage, and verifies the result through the authenticated fresh GET. The profile, subject, and model probes derive candidate identity from changed typed source components. The test also retains the ordinary changed-candidate path and uses the actual `AcquisitionOverlayReentryReceipt` for the old candidate value. These checks do not grant the candidate currentness or publication authority; the returned history remains `currentness_status="not_established"`, `authority_purpose="candidate_observation_only"`, and `publication_authority=false`.

## Measured no-growth path

The new branch is admitted only when the same configured selection has a persisted positive growth receipt and original attempt. Under the existing admission lock it revalidates the growth through `_verified_growth`, re-reads and reconciles the attempt for the closure's tenant/cell/run/source job, checks selection/binding/evidence-ref/passport agreement, and verifies the evidence refs. It then calls the existing `_finish_admission` with the current owner snapshot as `before`; a positive delta refuses, while a zero result is followed by a second projection whose complete typed snapshots must equal `before`. The strict receipt validator independently requires equal snapshots and recomputes the literal zero delta. The service takes the existing quarantine terminal path, which does not call reentry; this branch also does not reserve a new live attempt or invoke the N4/N5 producer. The test's new request has a distinct idempotency key/job and fresh allow/decision, while the third generation's actual provider-call list remains empty. Its GET preserves all pre-existing candidate fields and generations and adds only the quarantined action row.

The zero-delta count is not the sole content predicate. `_verified_growth` and `_finish_admission` both use `resolve_activated_semantic_epoch_admission`, which re-resolves the persisted passport and source evidence, replays the native qualification, validates the active owner rows, reconstructs the expected observations, and compares the physical member denominator. Existing `tests/integration/core_runtime/test_acquisition_world_growth_chain.py::test_revised_cycle_basis_survives_served_native_admission_and_reentry` mutates an observation value while preserving the owner markers/member key and count; the real resolver refuses with `active_epoch_observation_content_mismatch`. Thus a same-cardinality, different-content substitution is rejected by the reused source-backed verifier rather than admitted by the no-growth snapshots. The no-growth test exercises that verifier on the positive route, while the existing negative pins its same-cardinality content check.

The persisted artifact keeps the prior admitted evidence refs and exact before/after membership projection and is reconciled to the owner scope. The consumer-visible terminal remains quarantine; no new law, permission, status, or authority predicate is introduced. P40 is **SAME_CLASS_DEEPER**: this widens the existing native-admission revalidation contour from the first positive growth to a later ID/time-only action. The implementation handles the route generically rather than special-casing action generation 3.

## Bounded test note

Adding `no_growth_manifest.artifact_schema.version == "1.0"` would pin that manifest contract. This is a small verification refinement, not a source blocker. The patch-only proposal has no post-application test result; the complete served integration command and focused owner controls remain required before claiming verification or closure. The separately registered historical `withhold_external` source remains outside this result.

## Independent delta review: initial source seeding and cached no-growth

Reviewed the patch-only artifact `LOCAL/raw/v3-initial-source-seeding.patch` (SHA-256 `d38997ad0fd7edcf55efb45de7aaed31e4c089aa5243fc6bcb2a874a6a07cc38`) against its decision note `LOCAL/decisions/v3-initial-source-seeding.md`. **Verdict: NO-GO pending one test-fixture basis correction.** The source-seeding path is substantially stronger than the prior synthetic `persist_wdi_route` setup: the proposed test does POST `/api/v1/control/runs/nl`, dispatches the accepted job through the real control worker, reads the selected N5 input and N4 source from CAS using `GenerationSourceRepository`, and checks root origin, selected profile, stable subject, candidate identity, and context refs. The no-growth update reads the typed receipt/attempt and compares before/after membership, attempt and re-entry pointers/bytes, and external transport calls. Those checks are directionally consistent with the existing measured-admission verifier and preserve the prior authority/currentness limits.

The blocker is that the POST does not supply the problem used to construct the selected profile. `n4_contract._design_problem(recording)` for this recording has an industrial-MSME employment-retention prompt. The proposed `controlled_fiscal_problem` changes the problem statement, domain, jurisdiction/time, objective, outcome, and allowed lever/target, but the POST still sends `recorded_problem.nl_provenance.raw_request` inherited from that original employment-retention problem. `run_real_compiler` calls the original compiler with deterministic span support; the controlled gateway returns the already-transformed `recorded_problem` as its canned `emit_design_problem` answer. The equality assertion between `cycle_job_profile_selection_ref(compiled)` and the profile therefore proves that the compiler accepted that canned object and that profile lookup used the same object. It does not establish that the submitted request is a genuine basis for the transformed tax-rate profile/problem. The runtime compiler merges the request into provenance, but this response's other fields are not recomputed from that request.

This is a fixture fidelity issue, not evidence that the production route bypasses validation or that the resulting candidate has authority. The existing positive comparator in `tests/integration/runtime_quality/test_configured_candidate_simulation_served.py` builds the profile from `_current_compiler_problem(recording)` and submits that same problem's raw request; the proposed fiscal transformation breaks that correspondence. Align the controlled request/provenance and any constraint `source_text` with the controlled fiscal problem before profile construction, or construct the profile from the actual compiler result for a request that states those semantics. Keep the candidate-only limitation and real route/worker checks intact; do not resolve the mismatch by treating the prebuilt profile-selection equality as source support.

The cached no-growth assertions are a useful direct owner-port witness: the production branch re-verifies the existing growth/attempt under the admission lock, recomputes the owner membership, persists a strict zero-delta receipt, and returns without running a fresh acquisition; the test checks stable attempt/re-entry state and no transport increase. This test does not itself count N4/N5 producer invocations or perform a fresh HTTP read of the no-growth receipt, so its evidence should remain scoped to the owner-port/CAS zero-delta path. The served initial-source route supplies the separate HTTP/N4/N5 selected-view witness once the request/profile basis is aligned. This remains P40 SAME_CLASS_DEEPER; it widens the existing producer/consumer path rather than adding a per-ID exception.
