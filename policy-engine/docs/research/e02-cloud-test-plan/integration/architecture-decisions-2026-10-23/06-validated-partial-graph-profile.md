# Selected bounded partial-graph method for PAG/R4

This is the concrete producer design required by [PAG](03-pag-scope-and-legal-relation.md) and [R4](04-conditional-transport-diagnostic.md). It authorizes implementation, not a claim that the current code has this capability. No graph jobs were run in this architecture review.

## Reuse and precise gap

At question commit `f12fb9895a4009ce77828554f4c5c18d83e6ec15`:

- `transport_engine.py::solve_transportability` and `transport_check.py` reject direct scalar PAG/CPDAG admission before the legacy sampler. Preserve this gate.
- `transport_check.py::_orientation_options_from_pag_edge` turns some non-directed endpoints into alternative directed edges; acyclicity is the principal candidate filter. It loses compelled/latent semantics. This producer is unsuitable even if its output is relabelled heuristic.
- `pag_completion.py` has R1–R3 orientation and local `validate_pag` checks. These are reusable primitives subject to conformance checks, not a full PAG equivalence/member verifier. Empty violations are not proof of a valid complete PAG or class membership.
- `id_engine/core.py::_pag_id_algorithm` calls static ADMG validation before and after its orientation pass. Its name is not proof of an implemented complete PAG-ID algorithm.
- `CausalGraphModel` supports `DAG`, `CPDAG`, `PAG`, `MGRAPH`, `ADMG`; `MGRAPH` denotes missingness, not MAG. The existing causal-discovery integration already uses causal-learn. Reuse that optional dependency through the method/backend owner instead of introducing a separate graph platform.

## Preferred first profile

Implement a versioned **finite no-selection PAG member sensitivity** profile in the existing causal method owner. Its domain is a complete observational PAG with the declared no-sample-selection model assumption; latent confounding is allowed. Input scientific adequacy and real-world truth are still conditional. Unknown real-world selection may be represented as an explicit hypothetical no-selection assumption, never as an established fact. Do not silently choose this profile for an arbitrary graph.

CPDAG input is outside this PAG profile, with an explicit unsupported disposition; a future CPDAG→DAG profile needs its own DAG-equivalence validator. Supported endpoint patterns are directed, bidirected, circle-arrow and circle-circle (including reversed endpoint order). Tail-tail/selection-encoded patterns, background-knowledge-refined noncanonical PAGs, RFCI-specific incomplete semantics, and graph regimes the validator cannot interpret return profile-specific unsupported. This is a governed algorithm domain, not an enumeration of policy domains or allowed variables. New graph profiles reuse this interface with their own semantic law and version.

1. **Freeze actual input.** Resolve the owned graph representation, selected profile, node identities, endpoint meanings, query, source/target contexts and transport selection diagram. Separate population transport S-nodes from sample-selection variables in ancestral graphs. Refuse collisions, inconsistent endpoints or unsupported graph semantics before computation.
2. **Generate bounded proposals.** Enumerate or deterministically propose assignments only to circle endpoints, preserving all fixed tails/arrowheads and adjacencies. Stream proposals; do not allocate the Cartesian product. Use admitted limits for attempts, nodes/edges, elapsed work and retained identities. Reject tail-tail outcomes in this no-selection profile. A stable traversal or explicit seed determines the finite selected family, not a probability measure. More efficient generators can later use the same validated-member interface.
3. **Check ancestral/maximal meaning.** Reject directed cycles and directed paths incompatible with arrowhead ancestry; preserve bidirected confounding. Check maximality through the appropriate inducing-path criterion. A no-selection MAG that satisfies these conditions can be encoded losslessly as the existing ADMG; do not coerce a general selection MAG into ADMG. Distinguish a valid member that the downstream scalar method cannot handle from an invalid member.
4. **Establish membership, not just local validity.** Expand each bidirected edge into a separate namespaced latent common parent whose identity cannot collide with any observed or generated node with arrows into its endpoints, retaining all original directed edges and observed node identity. This is a computational representation for the separation oracle, not a newly inferred real latent variable. Reconstruct the complete observational PAG of that latent DAG with a pinned, validated exact d-separation/complete-orientation backend. Require equality of observed node identities, skeleton and endpoint marks against the selected input PAG. Compare semantic graph structure, not list order or serializer bytes. A partial/incomplete computation cannot yield membership. If a background-knowledge-refined graph does not equal its observational PAG, refuse this profile rather than weaken equality.
5. **Run the existing resolved-graph method.** For each admitted member construct a resolved `SelectionDiagram` whose `base_graph` is that member, preserving the frozen population-transport S-nodes and source/target contexts, and binding the same query. Do not pass the original PAG diagram into the scalar solver, drop S-nodes, or manufacture verified legal S-nodes from absent legal input. Invoke the existing DAG/ADMG transport/identification owner on that resolved diagram. Its capability contract must support that graph/query domain; a generic `auto` shortcut or presence of an estimand string is not proof of identification. Retain the actual solver disposition/proof/limitations. A member with unsupported solver domain is visible in evaluation accounting; do not discard it and inflate the fraction.
6. **Persist the finite family result.** Bind generator, validator and solver versions; original and member graph identities; per-member dispositions and query/contexts. Small identities/summary live in the nested R4 diagnostic, large traces use existing CAS/InputRef lineage. Report only sensitivity over this named family. No claim that it exhausts the PAG class, represents a random sample, or identifies an effect in every model.

The preferred reconstruction adapter is causal-learn's `DAG2PAG` utility, using its exact separation oracle; its official [documentation](https://causal-learn.readthedocs.io/en/latest/utilities_index/Graph%20operations/DAG2PAG.html) describes the DAG/latent conversion. The [upstream implementation](https://github.com/py-why/causal-learn/blob/1e5a2470210cd6c7ccfacebf096b4b3cb29c2d0e/causallearn/utils/DAG2PAG.py) shows the separation/orientation approach. The question lock pins `causal-learn==0.1.4.4` under the optional causal-discovery dependency; its tagged implementation expects latent **Node objects**, despite documentation calling them indexes. Pass the exact graph Node objects, use an empty selection-node list for this profile, and normalize returned observed identities/endpoints independent of iteration order. A same-shaped integer list is not an acceptable adapter. These links justify a reuse candidate, not installed-backend availability or the correctness of a particular version. The tag was read as source; the installed wheel was not executed or inspected here. Bind the actual lock/version/source and verify its node/endpoint API and complete-rule behavior before admitting it. Do not silently use moving upstream `main` or upgrade the lock to fit an assumed API. A later conformant backend revision may be admitted through the same adapter/profile record and independent conformance evidence; the shared dispatch does not hardcode this package version as the only possible future oracle. If the existing optional backend is unavailable, other lanes and resolved-DAG diagnostics continue; this particular PAG positive remains UNRUN until its declared backend works.

[pcalg's `pag2magAM`](https://people.math.ethz.ch/~buhlmann/teaching/pcalg.pdf) documents a no-selection member construction via arrowhead augmentation and chordal components. Use it as an independent reference or later generator adapter, not a new mandatory R runtime. The finite native generator plus a separate membership oracle is preferred initially because it exposes every admitted hypothesis and avoids claiming that sampling itself preserves equivalence. A complete PAG-native transport algorithm remains an extension, not a prerequisite for this bounded result.

## Resource behavior and backend admission

The reconstruction oracle may enumerate exponentially many conditioning sets. Preflight its worst-case work from the **actual graph size and selected algorithm**, obtain the existing resource permit, and enforce a bounded per-member/process deadline using existing supervised execution. No universal hardcoded node count or newly invented scheduler. Resource policies supply measured limits; the method supplies work estimates and truthful termination. Budget checks occur during generation and between membership/solver calls. If an uninterruptible backend cannot be bounded in-process, use the existing worker isolation or refuse that execution profile. No unbounded library call on a request/GET thread.

Cache completed membership checks by original graph semantic identity, candidate identity, no-selection/profile assumptions and validator/backend revision. Cache no timeout as a negative mathematical fact. Stream members, deduplicate canonical semantic identities with a bounded set, and stop with an explicit partial/budget outcome. Do not rerun discovery/statistical fitting to verify a generated member: the oracle is structural, with no production dataset needed.

Before enabling the backend, an independent conformance suite must cover latent expansion, node permutation, endpoint translation, discriminating paths, ancestral and maximality failures. Compare against independently specified small graph/separation cases and, where available, pcalg or another admitted independent implementation. The same generator's self-reported success is not the oracle. Library version strings and hashes bind an implementation; they do not establish its semantic correctness. Record unsupported domain and backend availability separately from product failures.

## Required positive and falsifiers

- A complete two-observed-node `X o-o Y` PAG is a minimal seed. With only population-transport `S_X → X`, an available source observational joint and the needed support/positivity, its three no-selection MAG members have distinct conditional identification formulas: `X → Y` gives `P_s(Y | X=x)`; `Y → X` and `X ↔ Y` give `P_s(Y)`. In the latter two, intervening on X changes no ancestor/equation of Y; the X-only mechanism shift does not change Y's marginal. All three are individually identified; the bidirected-only case is **not a hedge**. This is a formula-sensitivity witness, not a status-variation test: fraction one cannot supply a common PAG-wide identifying formula. Derive these expectations independently of the runtime solver and preserve their stated assumptions. Add a nontrivial latent/confounded graph with a compelled mark, independent positive/negative identification expectations and an oracle-derived complete PAG. The two-node case alone is not sufficient to validate the generic algorithm.
- A separate known DAG/ADMG positive proves R4's candidate production/persistence/consumer path independently of this optional profile. It does not count as PAG completion proof.
- Permute node/edge order; preserve semantics and result. Change a compelled arrowhead, remove a bidirected edge or introduce an ancestral/maximality violation while retaining labels; the member must be rejected or the query result must differ as mathematically required.
- Include a discriminating-path case that local acyclicity and R1–R3 alone get wrong. Remove the membership validator while retaining fields/markers: the negative must detect the escape. Replace the real solver with a constant result: the independent query discriminator must fail.
- Zero valid members after a bounded search means `not_established`/budget outcome, not that the PAG has no members. Invalid source evidence and exhausted search are different dispositions. Generation complete for a chosen finite policy still does not imply exhaustive whole-class coverage.
- Exercise request → existing permit → generator → validator → actual solver → CAS result/report → fresh consumer. The nested value is useful while outer legal refusal remains unchanged. Independent legal-positive or production model claims remain unavailable.
