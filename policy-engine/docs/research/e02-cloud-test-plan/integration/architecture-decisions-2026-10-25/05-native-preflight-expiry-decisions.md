## N1. Dynamic imports: review, который переживает regeneration

**Факт.** Header `architecture/imports/dynamic.toml` имеет `review_expires=2026-08-04`; полный parsed registry содержит 249 pattern rows. В `tools/quality/validation/decomposition_preflight.py::render_dynamic_imports_toml` жёстко записаны прежние `reviewed_at` и `review_expires`. `validate_dynamic_imports` уже отличает три внешних review fields от остальных canonical values. Простая правка TOML будет потеряна при следующем render. Inventory/target shape сами по себе не доказывают допустимость dynamic edge.

**Выбранный механизм.** Extend существующий renderer: generation of discovered rows и owner-supplied review metadata — отдельные inputs одного процесса. Сохранить валидные review fields при roundtrip; не выставлять текущую дату автоматически. Если metadata нет/она malformed, не синтезировать действующий review. Source inventory остаётся производным, решение reviewer — внешним к генератору. Не создавать ещё один loader или waiver registry.

Содержательный review сверяет полный actual edge set, concrete targets и существующие extension-point contracts, origin/provider binding и ABI. Canonical evidence — один обычный tracked review/handoff с exact source/config/dependency denominator, inventory identity, проверенными edge families, actual deciding outputs и limitations. Review valid для **проверенной семантики и dependency closure**: новые/изменённые edges требуют delta review даже до даты expiry; docs-only commit не обнуляет unchanged source review. Header может сохранять прежний формат: связь с receipt через существующий ADR/review path, явно указанная в handoff. Если автоматический consumer должен проверять эту связь, расширять тот же contract/validator атомарно; существующий metadata-only preflight не объявлять автоматическим verifier содержания review.

Не замораживать 249 как вечный список и не превращать runtime plugin discovery в запрет новых поставщиков. Новая реализация существующего entrypoint допускается по его действующему provider/ABI/origin contract; новый loader или способ обхода boundary требует owner review. `architecture/extension_points.toml` с `contract_only`/report-only частями не повышается до implemented от изменения даты.

**Acceptance:** renderer roundtrip сохраняет externally supplied metadata; отсутствие metadata не даёт fresh review; повторная генерация не возвращает старую дату; source/registry drift обнаруживается existing verifier; при выбранном executable entrypoint новый допустимый provider проходит, wrong ABI/target-origin не проходит. Для чисто декларативных extension points runtime positive остаётся `UNRUN`/`contract_only`, а не изобретается. Не исполнять произвольные полученные из интернета modules для такого теста. Generated inventory, renderer, validator и его existing tests — обязательные companions.

**Остаток:** фактический повторный review и evidence ещё нужны; дата будущего review выбирается owner по действующей cadence/риску после него. Эта записка не выполнила ни review всех runtime providers, ни их admission.

## N2. Operational coverage: библиотеки, исполняющие сервисы и security

**19 записей** = четыре package exceptions (`common`, `berl`, `ddm`, `calibration`) + по пять component rows в `architecture/component_observability.toml`, `ops/components/index.toml`, `architecture/runbook_coverage.toml`. Все expire 2026-08-01. `security` присутствует в трёх последних таблицах, без соответствующей package exception. Не считать эти зеркала независимыми remediation tasks.

У `common` уже есть `[slo_runbook].status="covered_by_dependents"`; остальные регистры сохраняют exception. Текущий `tools/ops_runners/release/check_operability_release_gates.py` допускает в index только `present/exception`, а проверка present YAML смотрит строки `objectives:`/`runbook:`. Поэтому просто поставить новый status или пустой `objectives: []` — неправильное решение: меняется declaration, а не измеряемое свойство (P37/P38).

**Выбор:** использовать user-visible operation как единицу SLO. Для helper/library без самостоятельного serving boundary — **проверяемое `covered_by_dependents`**, расширяя существующие Ops contracts/checker. Для actual standalone execution — собственный конкретный SLI/SLO с instrumentation и runbook. Не назначать каждой библиотеке 99.9% или произвольную latency. User journey/SLI должны отражать потребляемый результат; это соответствует [Google SRE: implementing SLOs](https://sre.google/workbook/implementing-slos/).

| Component | Предпочтительная relation, которую исполнитель должен подтвердить | Не смешивать |
| --- | --- | --- |
| common | Shared helper operation → consuming service/workflow SLI; зависимости/миграции сохраняют свои runbooks | Отсутствие собственного сервера и отсутствие влияния на надёжность |
| berl | Evaluation/support operation → фактически исполняющий Scientist/Runtime contour | Contract/unit checks и operational observation |
| ddm | Detector execution/delivery → actual monitoring host и его delivery/latency/error surface | Качество drift detector, доставка сигнала и downstream governance effect |
| calibration | Calibration computation → исполняющий Foundry/Scientist contour | Численная/эмпирическая достаточность calibration и доступность вычисления |
| security | Availability/latency security operation → actual enforcement host SLI; security correctness → hard invariant checks | Error budget инфраструктуры и «бюджет допустимых» cross-tenant/auth/signature нарушений |

Package semantic owner и operations owner могут различаться: например calibration package — `team-scientist`, Ops — `team-foundry`; BERL/DDM Ops — `team-architecture`. Сохранить обе роли, назначить одного writer для общего формата и одного для каждого component binding. Не выравнивать названия команд ради красивой таблицы.

**Минимальный реализуемый контракт.** Canonical operational binding хранить в существующем `ops/components/index.toml` рядом с component; другие registry projections ссылаются на него, а не владеют независимыми копиями relations. Для `covered_by_dependents` обязательны непустые records, содержащие: scoped operation, execution/deployment profile, consuming component, exact objective reference, instrumentation/denominator definition reference, runbook/action reference и verification receipt reference. Использовать существующую grammar refs там, где она есть; новые fields — additive в этом Ops contract с обновлением всех readers. Это внутренний operability contract, не новый product status. Не держать вторую глобальную ontology операций.

Checker должен resolve + content-bind refs, сопоставлять их с current source/profile и проверять покрытие фактических operations данного scope; названия и наличие файлов недостаточны. Relations могут быть many-to-many. Цепочка покрытия обязана завершаться реальным измеряемым objective; цикл `A covered by B covered by A` не является покрытием. Не требовать полного production roster для проверки библиотечного интерфейса; но непроверенный deployment нельзя обозначать observed. Каждый deployed profile/operation учитывается или явно остаётся uncovered, а не исчезает при фильтрации.

SLI definition фиксирует eligible population, success/error condition, window, units и missing/zero-traffic behavior. No traffic/missing telemetry → нет наблюдаемой оценки, не 100% success. Definition validity, instrumentation verification и production observation — разные результаты. Offline controlled witness может доказать получение/учёт сбоя в consuming contour, не настоящее production SLO attainment. Security invariants не ослабляются при exhaustion/error budget. Не убирать alert/runbook/trace obligations из-за отсутствия standalone SLO.

**Acceptance и companions.** Обновить вместе index, component observability, runbook coverage, четыре package records, affected `ops/components/<component>/{slo.yaml,runtime-contract.toml}`, реальные alerts/runbooks и existing validators/tests. Проверять parsed objective, exact profile/ref/units и результат instrumentation, а не YAML substrings. Negatives: оставить markers, удалить objective; wrong host/profile; circular coverage; missing referenced objective; dropped eligible failures; absent telemetry; попытка списать security нарушение в availability budget. Positive — реальный ограниченный failure-to-observation маршрут и fresh consumer. Новая неизвестная status value не должна обходить checks. Нельзя удалить 19 records раньше появления соответствующей принятой relation/собственного SLO.

Если actual mapping не найден, исполнитель сначала ищет реальных consumers и строит недостающую instrumentation в existing host. Только после этого фиксирует конкретный `bridge_missing`/`verification_missing` или требующий внешнего deployment input остаток. Blanket renewal и «нужны все production data» не являются выбранным путём.

## N3–N4. Ruff: совместимость вместо blanket ignores

**N3 (2 records):** `fabric-ruff-ratchet` в package TOML и `fabric-ruff-package-ratchet` в static override registry описывают одну причину. Выполнить [Fabric reflection R2](01-fabric-runtime-annotations.md), затем проверить **весь effective production ignore set** из `architecture/tooling/ruff/per-file-ignores/50-fabric.toml`: не только TC001/TC003. Retained output говорит о 14 Fabric diagnostics на том run; не предполагает, что каждый сегодняшний suppressed code действительно нужен. Нужные runtime imports — локальный semantic rationale, обычные ошибки — исправление, не перенос blanket ignore в десятки скрытых copies.

**N4 (1 record):** IR production glob находится в **`architecture/tooling/ruff/per-file-ignores/10-tests-ir.toml`**, несмотря на название файла; `80-runtime-core-ir.toml` не его замена. Исходный набор suppressions: `ANN401, TC001, TC003, E501, SIM102`. 168 IR diagnostics из старого retained run — проверенный исторический input, не current baseline.

Для IR runtime types сначала различить Pydantic/KernelModel fields, registered schema/reflection contracts и обычный static-only code. Использовать уже настроенные реальные runtime-evaluated base classes там, где pinned Ruff их корректно учитывает; остальные действительные reflection obligations — узкие rationale-bearing ignores. Нельзя двигать imports в TYPE_CHECKING, не проверив model rebuild, forward refs, schema/serialization и потребляющие owners. Нельзя менять transport/scientific semantics, nullability или ранее выбранные G решения ради lint. `ANN401` исправлять truthful typed boundary (существующий DTO/JSON-value/Protocol), а не фиктивным типом, скрывающим допустимые значения.

**Приёмка обоих:** active pinned config, exact complete candidate path denominator, semantic positives/negatives, constructor/model/fresh importer checks по blast radius, suppression visibility и generator drift. Полное снятие blanket ratchet не означает запрет обоснованных локальных lint suppressions. DevX удаляет obsolete override records и Fabric package mirror только когда effective config и actual evidence показывают устранение именно blanket долга; partial progress сохраняет точно названный residual. Generated `ruff.generated.toml`/workspace root и test pins — один writer. Не переоткрывать решение по семи N818 identities: сохранить уже выбранные identities и scoped policy, не возвращать blanket N818 ignore. [Ruff suppression](https://docs.astral.sh/ruff/linter/#error-suppression).

Сначала source-bound run с effective suppression removed в isolated candidate; классифицировать ошибки contracts/generics/overloads/optional dependencies. Typed adapters, настоящее narrowing и верные signatures предпочтительны. `cast`, `Any`, фиктивные stubs и `follow_imports=skip` не substitute для недостающего свойства. Если конкретный external typing defect не устраним в owner, допустим узкий code/line exception с проверенным runtime contract и отдельным остатком; не выдавать его за полную strict typing.

Приёмка: штатный generated mypy config/profile, affected consumer calls и meaningful generic/nullability negatives, regeneration `--check`, absence нового broad suppression. Версии stubs фиксировать; online mypy guidance не означает обновить project toolchain. [Mypy: existing code](https://mypy.readthedocs.io/en/stable/existing_code.html), [import handling](https://mypy.readthedocs.io/en/stable/running_mypy.html#missing-imports). Canonical/generated configs и `static_analysis_overrides.toml` меняются согласованно. G здесь не запускал mypy и не знает текущего числа его actual errors.

## N7–N8. Naming: разные понятия не объединяются по слову

**N7 `discovery`:** backlog ссылается на `core/discovery`, `foundry/discovery`, `scientist/discovery`. На source первые три tracked Core files обслуживают plugin discovery; два последних directories отсутствуют, causal discovery находится в иных canonical paths, включая `scientist/methods/discovery`. **Выбрать `scoped_ok`**, сохранить Core primitive и causal method owners, убрать stale locations/rename obligation после current complete relevant path/import census. Новый shared-name record нужен только если actual collision требует его по существующему registry, а не для отсутствующих путей. Без доказанного дублирования механизма не вводить consolidation.

**N8 `runtime`:** `foundry/runtime` содержит шесть tracked Python files execution utilities (fingerprint, numeric, NaN guards, profiles, traces); `scientist/runtime` из backlog отсутствует. Existing `shared_name runtime` разрешает Data Forge и top-level Runtime, но disambiguation требует прежнего rename для Foundry. **Выбрать `scoped_ok` и добавить реальный Foundry bounded context в существующее shared-name решение**, согласованно обновив disambiguation/backlog/package docs. Top-level lifecycle/HTTP owner не поглощает Foundry numeric execution helpers.

Обе задачи — одно изменение canonical name registry writer, два независимых semantic arguments. Qualified imports, настоящие dependency boundaries, публичные facades и consumers сохраняются. Проверки: complete current collision inventory, существующий name/boundary checker, imports использованных публичных путей; negative с неправомерным cross-package private import не должен стать допустимым от `scoped_ok`. Нельзя снять backlog только потому, что папка исчезла: проверить replacements/потребителей и отсутствие оставшихся неоднозначных routes. Если actual candidate отличается, переносить relation, не слепо вчерашнюю path list. Косметическое mass rename и новые compatibility wrappers сейчас не нужны.

## 3. Порядок исполнения, честные остатки и free-grow

Независимы N1, общий N2 contract, Fabric и IR cleanup, N7/N8 research. N3/N5 имеют пересекающиеся Fabric owners, N4/N6 — IR: объединить edits в owner lane или сериализовать только пересекающиеся файлы. N2 component bindings можно готовить параллельно после выбора общего формата; нельзя поручать пяти авторам переписывать один index/checker. Generated configs, name registry и общий native preflight — один writer каждый. Shared rules не означают общий дорогой barrier до каждого маленького slice; global replay остаётся после принятого source freeze.

Сначала coherent implementation + review, затем affected checks, потом один native preflight по собранному candidate. Здесь описана **будущая** проверка, не разрешён её запуск в текущем документационном исследовании. Evidence отдельно показывает code acceptance, metadata expiry, underlying runtime property, profile limitations и finding adjudication. Успех 27 remediation records не закрывает E02 и не снимает non-expiry diagnostics.

При moving source повторить bounded census по actual native selectors; не редактировать исторические receipts. Истечение новой даты или новый registry branch добавляет obligation по семантике checker, а не по фиксированному лимиту 27. Future shim renewal нельзя подтверждать одними непустыми owner/ADR fields; sunset из свободного notes с выбором максимальной даты не должен стать authority для новой миграции. Это ограничения существующих metadata guards, не новые доказанные expired rows: при затрагивании соответствующей family перейти к однозначному typed field/связанному review через existing owner и migration, без построения второго governance engine.

**Pattern pass:** P01/P02/P03 — operation → producer/instrumentation → artifact → consuming SLO/audit; P05/P37 — review/SLO status не authority по наличию поля; P07/P08 — source и review dates различаются; P10/P29/P32/P38 — семантические negatives против marker-only checks; P27/P31 — canonical owners и projections; P35 — полный pinned denominator; P39/P40 — companions не выталкиваются в искусственные квоты; P41 — никаких inherited-red claims. До реализации выбранных новых bridges/checks честные labels — `bridge_missing`/`verification_missing`/`semantic_test_missing` в конкретном scope; существующие рабочие возможности не объявляются отсутствующими.
