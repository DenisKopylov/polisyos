## Остаточные математика и границы

**B110 — идентичность осей исправлена на уровне типизированной координаты, но finding остаётся limited.** Текущая `_canonical_coordinate_id` связывает metric, split, unit state/value и direction; `definition_version` входит в хэш для v2, schema запрещает смешивать v1/v2 и требует version на каждой v2-координате. Тест owner suite делает JSON roundtrip, различает selection/holdout и отказывает при смене definition версии; независимый oracle также меняет unit/direction/split/schema marker при сохранении старого ID и получает отказ. Значения и reference keyed по coordinate ID, поэтому display labels не несут осевую идентичность. Но `definition_version` всё ещё producer-декларация, не content-bound ссылка на фактическую спецификацию измерителя/источник метрики; реальный producer, evaluator, units и их полномочия не установлены. Независимый Fraction-suite не даёт positive v2 definition-version witness. Считать B110 полностью закрытым нельзя.

**B111 — положительный underflow не исправлен; это уже известный P40 class, не новый класс.** Для 2D adapter складывает `(x-ref_x)*(y-previous_y)`, а затем проверяет только `math.isfinite(value)`. При конечных `x=y=1e-200`, reference `(0,0)`, обе ширины положительны, математический объём `1e-400 > 0`, но binary64 произведение — `0.0`; код всё равно возвращает `available/recomputed/exact_2d`. Это не настоящий нулевой объём: такие коробки отсекаются до ветки вычисления, а ноль должен означать пустую геометрию. Существующие Fraction tests используют малые целые; `1–4D` owner suite проверяет обычные известные значения, но не этот край. Тот же риск относится к внутренней арифметике BoTorch 3D/4D. Минимальная защита для заявленного float64 профиля: если после строгого отбора есть хотя бы один contributing box, а результат равен нулю, вернуть typed unavailable (либо доказать ненулевую representability/scaled calculation); добавить позитивный underflow falsifier. Не требуется вводить arbitrary precision: точный результат, не представимый в профиле, должен быть limited/unavailable, не ложным нулём.

**Производный reference overflow также остался.** В `_reference_configuration` исправлена потеря/ошибка на невалидном исходном значении (включая huge int, bool и неправильную длину). Но `_update_ref_point` затем без проверки считает `configured_offset * (best - worst).abs()` и `worst - offset`. Конечные принятые цели около `-1.7e308` и `+1.7e308` могут дать бесконечный spread и `-inf` reference. В `compute_hypervolume_assessed` общий adapter впоследствии вернёт unavailable на неfinite reference, поэтому он не обязан ложно выдавать ноль. В `suggest`/batch path производная точка сначала идёт непосредственно в EHVI; широкая обработка исключений возвращает `random_fallback` и логирует ошибку, не оставляя типизированную причину overflow в исходе оптимизации. 14-case oracle проверяет невалидный configured reference/offset, но не overflow, полученный арифметикой над конечными целями, и не `suggest`/EHVI. Минимальное закрытие: проверять derived tensor сразу после арифметики, не передавать Inf в BoTorch и сохранять численную причину в фактическом fallback/assessment; испытать оба настоящих consumer-пути конечным экстремальным входом.

3D независимый oracle обнаруживает bbox-подмену, 4D owner suite содержит лишь специальную известную конфигурацию с дополнительной шириной 1 и ожиданием 16. Это подтверждает прохождение backend-пути для одного 4D значения, но не общий независимый 4D oracle. Для 4D оставлять ограничение профиля; не повышать его до универсальной геометрической гарантии.

## Решение для G

Учитывать математические receipts как **PASS для покрытого профиля**, отдельно от closure: owner сам маркирует B109/B110/B111 `limited`, ни finding этим review не закрыт. Положительный underflow и arithmetic-derived reference overflow — остающиеся пункты той же численной representability/intake группы P40. Для нового exact source до принятия достаточно точечного прогона affected Pareto/MO consumer tests после helper move и двух названных semantic falsifiers; это не основание повторять broad regression. В этом review тесты/окружение не запускались и исходники, refs и checkout не менялись. Pattern pass: P29/P33/P37/P38/P40 — независимые значения и marker-preserving отрицательный пример есть; producer authority и граница float64 всё ещё ограничивают claim.
