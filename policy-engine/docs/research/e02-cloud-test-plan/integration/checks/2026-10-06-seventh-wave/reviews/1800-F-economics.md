# F economics source cross-check: C training bridge compatibility

## Decision

**GO** for the bounded LA-004 conclusion that the native fiscal/labor kernels and Economics-plugin transitions are different model profiles and must remain separately identified. The frozen F source compares matched and deliberately divergent regimes; C's adapter calls the real Economics plugin mechanisms and does not replace them with the native PatchMap kernels. This does not establish equivalence of the adapter's training profile to either complete profile.

**HOLD** the cross-slice claim that C's supported Economics training path is compatible with F's new strict hard-Gini input law for all admitted profiles. The composition has a concrete generated-negative-wealth case and no combined F+C runtime witness. This is a new cross-slice edge, not a basis to restore the old Gini formula, clamp wealth, or redefine LA-004/LA-035.

## New combined-source boundary

F changes canonical `compute_gini_hard` to call `_admit_gini_population`, which binds `eqx.error_if` to reject negative or nonfinite active values (`distributions.py@4128879c`, lines 437–462). EconomicState's `_compute_distributions` always computes hard Gini for active wealth and income, and `update_aggregates` always refreshes it (`plugins/economics/state.py@4128879c`, lines 178–221). CompositeExecutor runs its configured mechanisms and then invokes `update_aggregates` (`plugins/composite.py@976212bb`, lines 178–212).

C's training admission (`training_adapter.py@976212bb`, lines 311–365) checks domain/profile shape, mechanism names, state/plugin types and interactions; it does not check the metric's value domain. Its actual projection calls `_compute_distributions` (`training_adapter.py@976212bb`, lines 186–230). The plugin's actual tax transition subtracts progressive tax from household wealth without a floor (`economics/mechanisms.py@976212bb`, lines 29–49). Thus a typed, `validate()==True` pre-tax state can enter the profile with positive wealth and later produce active negative wealth; the strict F Gini check then refuses during the composite refresh. Since C translates only `TrainingBridgeError` to `bridge_pending`, this Gini refusal is not shown by the source to become that typed status. The transition must retain its fiscal meaning; do not repair this by inventing a wealth floor.

A deterministic minimal mechanism fixture is: `EconomicState.empty(n_agents=10, max_agents=10, seed=7)`, then all active, `wealth=1`, `income=20_000`, `employed=True`, `wage=20_000`, `skill_level=1`, `consumption=0`, default policy (`tax_rate=.25`, `transfer_rate=.1`), followed by `update_aggregates()` to refresh the positive before-state. `validate()` is true for that state. After a zero-separation/zero-growth LaborMarket transition, income remains 20,000. Default progressive brackets debit 2,500 from wealth; default transfer adds 2,000 from mean income (means-tested factor clips to 1 after the tax debit), leaving `wealth=-499` before savings/aggregate refresh. This proves the producer/consumer arithmetic from source. It is **not** a run of C's default stochastic labor object or full trainer; the C bridge's default labor transition needs one exact-key combined runtime probe before describing the observed outcome. C's adapter also excludes the plugin Consumption mechanism, so the fixture must retain that training-profile distinction.

The smallest deciding continuation is one isolated combined-source probe on the immutable C source plus F Gini source: start from a refreshed positive typed state; run the actual adapter/composite transition with an exact seeded actor/key and a nonnegative before-step; make tax push at least one active household negative; capture whether execution refuses before any trained result/artifact and whether the public caller returns a truthful typed limitation or leaks an untyped runtime error. If the strict Gini metric is mandatory in this profile, admission/refusal must be explicit and artifact publication must not occur. If training remains supported when Gini is unavailable, that needs an existing typed unavailable representation/consumer path; no such path is established by these receipts. Do not modify either economic law to make the probe pass.

## Keep the original findings separate

- **LA-004:** F's corrected interpretation is the two-model comparison above. It is not a Gini normalization or welfare decision. C's training bridge is a third, explicitly adapted consumer path; do not call it a replacement for either model.
- **LA-003:** F's new native replay test establishes the registered baseline producer/spec/compiler/CAS path on tested inputs. F's own handoff leaves the finding limited; it does not demonstrate the proposed relocation. C does not move or rewrite the baseline kernel.
- **LA-035:** F characterizes the legacy normalized-income/budget function and preserves its aliases, but leaves the finding held because a named optimizer/caller and intent are not established. C trains through `EconomicReward`/CRRA, not that loss. C's trainer result cannot close LA-035 or ratify a new norm.

No test, environment, source, ref, checkout, or tracked file was changed or run in this review. The historical receipts were inspected at their pinned source commits; neither C's `a452` passing run nor F's `412` run covers the combined strict-Gini training case above.
