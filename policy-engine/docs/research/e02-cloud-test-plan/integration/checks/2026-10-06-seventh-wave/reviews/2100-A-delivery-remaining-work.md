## Приёмка по capability и pattern pass

Для каждой строки проверять только исходный criterion: contract/input → canonical producer → persisted typed artifact → A bridge → названный consumer/fresh reader → negative/semantic witness. Статус отмечать точной capability label из AGENTS (`producer_missing`, `bridge_missing`, `consumer_missing`, `verification_missing`, `surface_missing`, `absent/unallocated` и т.д.); synthetic positive не заменяет served path. Для L6 digest, owner signature, scope, temporal roles и default-registry completeness фиксировать отдельно, является ли deciding predicate `recomputed`, `independently_reconciled`, `consumer_asserted`, `institutionally_supplied` или `not_established`; последние три не дают positive authority.

Учитывать паттерны P01/P02 (полная цепь и bridge), P05/P09 (authority/currentness и owned refusal), P10/P14 (семантическое доказательство и независимая evidence lineage), P27 (canonical owner вместо parallel writer), P29/P32/P33 (реальный resolve/content-bind/readback, свойство вместо marker и adversarial variants), P31 (единый chokepoint для класса), P35 (полный знаменатель 13/34/35 из pinned JSON), P37/P38 (кто поставил deciding predicate и где gate может расходиться со свойством), P40 (повтор одного escape — widening или declared limit, не бесконечные локальные patch), P41 (точный slice base + пересечение полного input set до ярлыка inherited).
