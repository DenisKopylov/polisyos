# Новая конфигурация команд

Рекомендуется шесть функциональных потоков с короткой общей очередью property slices; G остаётся единственным integration publisher. Потоки — роли и boundaries, не новые sovereign подсистемы. Прежние A–F остаются provenance/criterion owners в ledger; эта карта не переписывает их историю.

Не нужно заново создавать шесть больших orchestrator queues по 35–60 findings. Одновременно активны несколько готовых task cards из §03; каждый owner получает конкретный exact source, decision, consumer и exit. Если прежний specialist ещё занят подходящим slice, сохраняется его checkout и source history — новая организация не требует новых полных copies.

## Writer leases

Lease — запись в tracked task/handoff, а не новая service. Она содержит canonical paths, candidate/base, changed contracts, companions, named consumers, reviewer и conflict owner. Один механизм не дробится по коммитам ради artificial path cap; обязательные tests/docs/generated companions именуются отдельно от mechanism count (P39).

Особенно:

- `core/artifacts/{store,ownership,manifest}` и budget/settlement — R canonical owners; D/F/C возвращают requirements/companion commits, не правят их параллельно.
- `fabric/data_plane/streaming.py` — I/C; B меняет свой pool/witness и сообщает exact requirement.
- `runtime/http/services/control/{generation_cycle,run_lifecycle}` и `runtime/quality/generation_cycle.py` — V/A, как записано в `execution-organization/allocation.json#/cross_unit_single_publishers`: A — sole writer, B/E — suppliers. E владеет forecast/calibration producers и предлагает S10 adapter delta; перед приёмкой этот delta согласуется и публикуется canonical A owner. Автор уже существующей правки не получает ownership по факту её написания. Передача lease требует tracked решения до следующего authoring.
- IR uncertainty/Profile2 — S/E; graph exports/SCM — S/F. E/F README/facade intent согласуется canonical owner, generated inventory принадлежит G.
- Catalog checkpoint/basis и Legal generation/query readers — I respective owners, не общий root carrier C.
- Search/service/funnel/Node — V/D; поступивший R CAS/budget contract фиксируется source inputs, а не silent latest.
- OpenAPI/generated schemas/public inventory/reference — Q/G canonical generators. Node/dashboard consumers — отдельный frontend writer после frozen contract.

Task activation уточняет эти boundaries до конкретных paths, base/candidate/tree и input blobs. Для R3 раздельные leases: B `core/llm/settlement.py`, `scientist/orchestration/engine/{budget_ledger,budget_middleware}.py` и relevant gateway/enforcer; A его control/lifecycle consumer; D `scientist/methods/search/funnel/{orchestrator,types}.py` и `scientist/nodes/builtins/decide/run_policy_blueprint_runtime.py`. Перечисление existing path не требует менять его, если contract уже достаточен.

Для V2 N4 producer — `runtime/quality/design_generation.py`; A control adapter и `run_lifecycle.py` persistence/readback получают отдельные leases. Для I4 Legal — `data_forge/domains/legal/batch/embedder.py`, `data_forge/domains/legal/embedding_projection.py`, `lex/knowledge/{search,store}.py`; serving adapters дополнительно именуются из selected caller diff. Catalog owner отдельно фиксирует свои basis/registry/HTTP paths. Без такой записи разрешены read-only design/fixture preparation, но не overlapping authoring.

F владеет своими именованными GRF/CAU/FIT method и export paths, а не всеми graph producers системы. `reconcile_causal_graph.py` и иные workflow producers получают конкретный owner handshake перед graph-to-policy-gate task; одинаковая форма графа не передаёт global graph ownership F. Proposed новый route остаётся proposed, пока supplier и consumer не приняли typed artifact/purpose contract.

## Работа reviewers и помощников

G масштабирует прямых helpers от нуля до двадцати по фактической очереди. Для двух-трёх сложных slices полезны независимые identity/ancestry, ownership/diff, runtime, oracle/negative, consumer/surface и deciding-output reviewers. Для мелкого companion достаточно одного focussed review; шесть reviews на каждый README не нужны. Helpers не пишут integration/source и не создают детей. Test runner получает isolated exact candidate и отдельный CAS/basetemp/resource slot.

Review всегда immutable SHA/tree. После первого полного review проверяются только changed delta/dependencies/evidence; unchanged body не перечитывается ради новой даты. Code author может объяснить intent и дать receipts, но не выдать independent GO самому себе. Отдельный skeptical reviewer проверяет scope: не сужен ли исходный criterion, и не добавлен ли лишний production/authority барьер к bounded механике.

## Контроль незавершённой работы

В начале каждый task фиксирует вопрос, который его результат изменит. После второй same-class находки действует P40: widen общий mechanism либо сформулировать bounded residual и выполнить falsifier; следующие примеры той же residual не создают новых rounds. Task без доступного supplier/input заканчивает bounded mechanical work, публикует точный missing packet и освобождает execution slot. Он не запускает снова весь исходный bundle.

При конфликте integration G возвращает correction canonical owner. Accepted upstream commits добавляются последовательно ordinary append-only merge; новый checkpoint публикуется только `codex/e02-integration`. Foreign human chats не получают автоматических сообщений; owners читают tracked tasks через fetch. Эти документы являются handoff, не implicit authorization отправить prompts в чужие чаты.

## Compute и место

Сериализовать contended local A/C/G CPU-heavy run, shared mutable DuckDB/CAS, fixed port, browser и generated artifact. Read-only source reviews, lint/type и независимые isolated logic scopes могут работать параллельно. Облачным B/D/E/F не назначаются искусственные квоты.

Профили runners именуются отдельно: app Python3.14, locked Linux/Python3.12/DoWhy0.14 worker, optional GP stack, Node22/frozen pnpm, installed wheel/sdist. Mac refusal не даёт результата Linux consumer. Failed cloud executor заменяется подходящим controlled runner; source fetch уже не блокирует prepared B.

Лёгкий disk check перед/после тяжёлого run, warning около25GiB. Reuse environments по lock/profile, отдельный небольшой scratch/CAS; не копировать tracked trees/raw data в receipts. После byte-bound preservation и проверки отсутствия active users воспроизводимый export/env/generated fixture переносится только в native Trash. Trash никогда не очищает G; same-volume move сам по себе не освобождает физические blocks. Полезные unmerged changes сначала compact commit/ref/patch+receipt для будущего решения. Production data и уникальные inputs не являются cleanup candidates.
