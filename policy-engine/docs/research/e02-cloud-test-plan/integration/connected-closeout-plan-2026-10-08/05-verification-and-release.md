# Приёмка и исполнение проверок

## Не добавлять к исходному criterion чужую задачу

Для каждой из 291 occurrences G читает exact original criterion и сравнивает с actual source-qualified receipt. Mock/injected path допустим, когда он действительно упражняет свойство criterion; он недостаточен, когда criterion требует configured producer, persistence, authentic source или installed consumer. Например, D B156 требует исполнения independent-control callback/cache/history поведения, а не statistical independence или production persisted history. B109 finite Pareto helper не становится production optimizer task; B117 исключает production concurrency. Не создавать новые blockers из более сильного product aspiration.

Обратная ошибка также запрещена: source review, DTO constructor, marker count, соседний PASS, helper serialization или один manually injected artifact не закрывают требуемый producer/bridge/consumer. Property, то, что код фактически проверяет, и один distinguishing case должны совпасть. Для каждой remaining occurrence результат — закрываемый exact criterion, bounded limitation, concrete defect, unrun profile или missing owner fact. Только G принимает finding-level решение.

B11 full criterion дополнительно требует публично назвать proxy/inspection value heuristic, сохранить picked/deferred reason и не присвоить publishability. Его controller positive и exhausted-budget negative не дают автоматически этот surface. В очередь Q2 идёт именно такая projection check; B66 invoice/provider truth к B11 не добавляется.

## Протокол slice

1. Fetch точный topic/PR и candidate/tree; прочитать committed handoff. Проверить base/candidate ancestry, inputs, canonical writer и полный code/test/companion footprint. Branch-wide diff не задаёт ownership. Prepared B1e/a0 — реальные fetched commits; новая official topic publication всё ещё отдельный шаг.
2. Сопоставить receipt с точными implementation/test/config/lock/input blobs и origins. Current A8b не получает старый ab93 результат автоматически; F852 не получает exact519 sdist результат автоматически. Doc-only tail переносит runtime proof только при input equality.
3. Независимый reviewer читает immutable source. Runner получает изолированный candidate и compute slot. Источник не становится mutable от рабочего CAS: tracked input manifest и runtime output manifest раздельны.
4. Выполнить deciding positive, independent oracle, boundary negative и matched property-removal с сохранёнными markers. При unavailable data/tool/platform сохранить raw output и semantic UNRUN до достижения свойства; assertion failure на самом свойстве сохраняется FAIL.
5. При changed upstream contract выполнить только affected consumers из §03/footprint. Остальной ранее reviewed package переносится по equality. Повторное full review всего unit не является default.
6. G принимает code slice отдельно от finding. Conflicts возвращаются canonical owners. Accepted original commits добавляются ordinary append-only merges; generated companions делает G canonical generator.

Нельзя переименовать runtime setup failure в положительный product verdict. Но raw harness `ERROR_SOURCE_AFTER`, вызванный output CAS/empty lock рядом с export при неизменных input/origin bytes, также не стирает actual assertions. Сохраняются оба факта и separate output custody; исправляется runner manifest boundary, source property не подменяется return code.

## Global reds и freeze

Одна queue global gates содержит command, exact slice base, candidate, environment/input denominator, changed-path intersection, deciding output, owner и disposition. «Inherited» разрешено только после exact pre-slice base replay + нулевого intersection. Без этого P41 `not_established`. Конкретная generated drift исправляется generator owner; unexplained scanner -9 не становится архитектурным исключением.

Порядок завершения: accepted source DAG и owner corrections → delta consumer checks → canonical regeneration/public consumers → все independent reviews → **source freeze** → один required expensive broad replay → named local read-only data-dependent closeout → original finding adjudication. После freeze cosmetic finding записывается debt; blocking findings батчируются, меняют freeze и инвалидируют только зависимое evidence. Это не цикл broad run после каждого merge.

Required global gates остаются release blockers до успешной проверки или явного применимого scope decision; данный план не разрешает bypass hook/guard или main publication. Unavailable optional backends и factual inputs перечисляются отдельно. Нельзя назвать whole E02 complete, пока required original criteria held/unrun.

## Хранение evidence и диска

Полный deciding stdout/stderr/JUnit и removal output сохраняются. Tracked receipt ссылается на source `path@sha`, а не копирует tracked source или обе стороны diff. Большие raw outputs — ignored `raw/`, связаны path/hash; компактный deciding receipt содержит необходимый verdict и ограничения. Не хранить рядом несколько derived representations одного source artifact.

Checkouts/envs после source preservation, proof/output readback и отсутствия active users можно переносить в native Trash. Нельзя очищать Trash или удалять permanently; Trash move не считается физически reclaimed space. Research pack не требует новых full environments/archives. Полезный unmerged код/doc/data сохраняется компактно для отдельного owner решения, воспроизводимые fixtures не превращаются в вечный archive.
