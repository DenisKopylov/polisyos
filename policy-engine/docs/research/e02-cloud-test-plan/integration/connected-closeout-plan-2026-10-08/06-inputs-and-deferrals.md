# Минимальные входы, решения и deferred capability

Input packet — конкретный источник, scope и потребляющий boundary. Это не просьба «дать production data» и не universal permission для проекта. Сперва проверить latest owner packet/API; старые null-owner и historical demands могли быть уже исправлены. Generic mechanics и negative controls продолжаются без external authority; protected positive/production claim остаётся ограниченным.

## Что не является новым внешним input blocker

- B59 и B87 — исполняемые mechanism/lifecycle задачи. Physical handle/session/pool generation являются inputs теста, не institutional authority.
- B61 retained-SKG replay — source review prepared candidate находит capture path и настоящий query/reader; exact-candidate runtime/removal UNRUN. Старый live freshness121PASS не доказывает replay; заменить/убрать live file и прочитать retained bytes в fresh process можно маленькой DuckDB fixture. Новый issuer law для этой replay property не требуется. Authenticity/output-dependency claims отдельно limited.
- B68 same-key singleflight/cancel/error и B66 local accounting — runtime properties. B67 permission scope отделён от них; не задерживать проверку одной из-за отсутствия другой.
- D B109 Pareto, B110/B111 coordinates, B117 local registry/pointer, B156 control invocation, B163 tracker restore имеют собственные ограниченные критерии. B156 сохраняет четыре проверяемых условия: same effective request reuses; changed input version вызывает новое исполнение без stale score; independent control реально вызывает callback; ordinary-attempt history/state не мутирует. Mocked callback допустим при реальном orchestrator/cache path. Общий product evaluator/default/production history не добавляется как универсальный blocker к их evidence.
- D16 owner packets включают adjacent API/context/quantity/ordinary-owner work. Существование packet не расширяет автоматически D criterion; §05 задаёт original-scope adjudication.
- E B201/B202 semantic appointment/choices уже tracked. Новые schemas/ABI/public companions и adoption — engineering/verification, а не повторная ratification.
- F LA-035 unchanged historical relocation не требует нового welfare/optimizer intent. Изменение формулы/ranking — отдельное решение. LA-017 report migration не утверждает current-law validity.
- Missing Hatchling, unsupported host, absent optional Torch/DoWhy backend, scanner incomplete и installed layer UNRUN — tooling/profile/verification. Их не переименовывать owner decisions или product FAIL без deciding assertion.
- LA-033 default resume требует truthful absent `pii_scan_results` и optional-read adapter через authentic7/23 checkpoint; отсутствие scan не clean. Это код/contract/caller task, а не blanket PII corpus census.

## Ограничения, которые допустимо держать без нового round

Intrinsic mathematical assumptions; unsupported PAG/temporal/fuzzy/cluster profile; unknown external/computed caller; unavailable genuine historical asset; отсутствующий institutional permission/law. В каждом случае сохранить точный affected criterion, measured profile, способ refusal/limited projection и минимальное условие открытия. Нельзя превращать bounded limitation в full closure либо считать сам факт ограничения новым неисправным методом.

For current-world authority PolicyOS owns свой honest intake/reaction/expiry/reissue, а не sovereign external act. Если external source ещё не назначен, назвать `absent/unallocated`; если DTO есть без producer — `producer_missing`; если нет path consumer — `bridge_missing`/`consumer_missing`; unavailable check — `verification_missing`; absent actual surface — `surface_missing` или явно `surface_out_of_scope`. Не заменять все причины одним словом held.

При новом факте открывается только его named consumer/property task. При новом counterexample внутри already-declared same class он учитывается в residual по P40; новый mechanism только при доказанном расширении quantity. Freeze/closeout документации не закрывает global E02 и не приостанавливает integrator continuation.
