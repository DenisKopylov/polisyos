## Narrow semantic decision required

Before the system may publish a scalar claim from an unresolved graph, G must specify what “valid completion” means by graph type, and what the returned status denotes. The current enum values `conservative`, `optimistic`, and `probabilistic` do not supply those semantics. The minimal alternatives are:

| Option | Claim meaning | Reuse-first implementation route | Cost and migration |
| --- | --- | --- | --- |
| **Selected-extension conditional** | A result is conditional on one explicitly selected and validated extension; it does not assert invariance over other extensions. | Reuse `CausalGraphModelRef`, the existing artifact store/CAS, and static DAG/ADMG ID. Extend the typed request/result to bind the source partial-graph digest, selected extension ref, selection algorithm/version, provenance/time, and an explicit conditional status/assumption. Fresh consumers must preserve that condition. | Lowest initial cost. Existing scalar `identified` consumers must not silently treat the result as unconditional; old sampled artifacts need a versioned diagnostic interpretation. An extension selector is not itself authority to assert the graph. |
| **Invariant across all admissible extensions** | Return a scalar identified result only if every admissible completion yields the same query result/proof under the chosen equivalence rule. | Reuse R1–R3 and static ID only where already fully resolved. Extend with a sound, graph-type-specific complete algorithm or a certified query-specific invariance test; do not treat random samples as completeness. | Higher algorithmic cost and potentially exponential enumeration. Migration makes non-invariant queries `contested`/`limited` or `unsupported`, with a counterexample witness. Needs a precise extension-set definition; PAG may not be reduced to DAG enumeration. |
| **Set or bounds over extensions** | Preserve all admissible result formulas or an identified effect set/bounds, including differing answers. | Reuse static ID per certified extension; extend the typed result and consumer to carry extension provenance and complete set/bound semantics. A truncated enumeration can only produce a declared partial candidate set. | New result contract and consumer behavior. Scalar callers must accept set-valued/partial results or abstain. Exact set completeness and resource-limit status require a contract. |
| **Probability over extensions** | A probability-weighted claim over a defined distribution on valid extensions, not a sample fraction masquerading as identification. | Reuse sampling only after an owner-supplied, content-bound distribution and a sampler whose support/weights match the declared extension space; return Monte Carlo uncertainty and candidate-grade provenance separately from identification. | Requires a named source/owner, distribution version, time and authority scope, plus calibration/coverage tests. No such prior or authority input was found in the examined source. Do not invent one. |

**Recommended interim behavior:** unresolved partial-graph input must retain its marks and return a typed limitation/refusal unless the caller supplies a separately typed, validated selected extension. Treat the existing sample ratio as candidate diagnostics only; it cannot produce an unqualified `identified` result. Reject malformed policy values rather than converting them to an absent/default choice. This is a conservative engineering proposal, not a new external causal law. G still decides the enduring result semantics and whether any probability-weighted route is in scope.

Reuse-first order is: (1) keep current safe normalization, R1–R3 and static ID for their bounded contracts; (2) wire a typed selected graph artifact where the claim is explicitly conditional; (3) extend the result/consumer only for G-selected set/invariance semantics; (4) build a new completion/inference algorithm only if the chosen property cannot be implemented by existing components. Do not create another generic causal facade.

## Acceptance discriminator and residual

Any chosen path must be tested on the real producer → persisted graph artifact → bridge → transport/ID consumer → fresh result reader. The minimum semantic suite should contain: known reverse edge; bidirected edge; unresolved circle-circle with two completions and different estimands; a graph with multiple admissible completions and equal estimands; directed-cycle rejection; candidate extension bound exhaustion; malformed policy; profile/hash mismatch for a selected extension; and a removal control that deletes the extension-set validation while leaving policy/result markers intact. For the invariant option, a positive scalar is accepted only when the implementation can establish complete-set agreement. For conditional semantics, the same output must carry a resolvable selected-extension ref and preserve the conditional label through the receiver. For a probability option, test support and weights against the declared finite distribution before any empirical calibration claim.
