The boundary test does not exercise the ordinary NL worker producer. It runs the real controller first, then submits an accepted fixture `POST /api/v1/control/runs/nl` and manually dispatches a lease callback that persists that already-created run through Core's compiled-recursive writer. After a fresh app/context, it resolves the Core attempt manifest and CAS bytes through the service. The HTTP `GET /api/v1/artifacts/{id}/content` is deliberately refused with 409 `authority_surface_signal_missing`; a foreign tenant gets 403 `artifact_tenant_mismatch`. Those are useful adversarial controls for content custody and refusal. They are not a positive public inspection response, and the test never calls HTTP `GET /api/v1/runs/{run_id}`. That route can project a `RecursiveCycleCheckpoint`, but its DTO contains progress/frontier/authority fields rather than the B11 candidate's VOI estimate. This review does not claim a complete inventory of every possible surface.

There is no cost projection or spend oracle in this test: the cap is a scheduler fixture and estimated step cost is not charged or reconciled. The B11 criterion's “not publish as measured monetary VOI/probability” is not contradicted because the tested content route refuses; the positive display-label behavior remains unverified. Actual cost owner/ledger evidence remains a distinct question (do not treat this B11 test as B66 settlement evidence).

B27's original criterion still requires a valid revised context, an allowed second default N4/N5 path, and original/revised history persisted through the shared owner-backed path. Those are unrun. The guard is a bounded safe stop, not a closure of that criterion.
