# B148: bounded criterion vs. broader tenant policy

**Decision: HOLD formal B148 acceptance only pending exact-candidate verification, and narrow its reason.** The overlay's reason, “cross-tenant/first-for-tenant ownership law absent,” is too broad as a prerequisite. B148 contains a concrete tenant/cell-preservation requirement; the existing ownership index and import lease can enforce that bounded rule. The candidate deliberately requires a scoped import's manifest to bind the same explicit tenant/cell, even for an unclaimed target. That behavior is stated in the public release fragment and package README. Neither the original criterion nor this audit establishes a required unbound-manifest-to-scoped-store positive route. The broader public policy for authorized cross-tenant sharing remains a separate held semantic extension. No new registry, public transfer law, or fixture-hash authority is required for the bounded finding.

## What the original criterion does and does not require

The B148 source requires an import to stage and verify before publication, retain the prior valid artifact on bad/truncated/conflicting/concurrent publication, check conflicting metadata against the existing owner, and preserve existing tenant/cell isolation. It says to validate signatures and ownership **where mandatory**. The CAS-02 bundle requires bad import to leave the old readable blob/manifest intact and a correct import to remain usable. The text does not require an external cross-tenant sharing policy or a new first-owner subsystem for every unclaimed/non-authority cache.

The overlay's broad rationale should not erase the real bounded ownership clause either. At baseline `1980768`, the complete CAS-01/02/03 output in `cas-current-put-evidence/base-native.txt@0bf788ac2e57533b08be9172d64c19705a3af30d` was 48 PASS / 4 FAIL. Two failures directly violated the bounded tenant clause: `test_import_enforces_existing_tenant_ownership` admitted an import over tenant A's existing claim, and `test_import_rejects_a_selected_view_bound_to_another_tenant` accepted a manifest explicitly bound to tenant A in tenant B's store. The other two were stale fault-injection seams for generation publication. These are concrete failures, not merely absent public policy.

## Candidate evidence and the remaining distinction

The B-W02 admission slice in `cas-current-admission.json@0bf788ac2e57533b08be9172d64c19705a3af30d` adds a common `_admit_import_members` gate before staging and rechecks at publication. It uses existing per-artifact leases and `ArtifactOwnershipIndex`; a claimed artifact is accepted only as an already-owned, exact byte/view/signature no-op. Explicit tenant/cell mismatch refuses. Its source-bound run at `129ace949fe452959c965134fb37cffc4f8b4c94` exercised 121 cases: 120 PASS / 1 FAIL; the 34 admission cases passed, and matched removal produced 19 expected failures after removing admission while keeping marker/report code. This supports a real bounded mechanism and discriminator, not a cross-tenant public-law decision.

The one predecessor failure used an unbound manifest for a same-owner exact-view positive in a tenant-scoped store. The candidate contract intentionally requires a scoped import—including an unclaimed target—to carry the exact manifest tenant/cell binding. Commit `5494f7d056ddc251107f416299db76400a96efce` changes that positive fixture to include `tenant_context=tenant-exact-view`. In isolation, changing a fixture would not validate behavior; here it supplies the contract-conforming positive that the declared public behavior requires, and is not evidence of weakening by itself. At exact candidate `0bf788a`, `test_import_admission_noop.py` also contains the discriminating controls: bound same-owner exact no-op; unbound claimed and unclaimed refusal before staging or claim with receiver snapshot unchanged; foreign tenant/cell refusal; and refusal of changed manifest/signature views on an existing claim. Those are source tests at the pinned candidate, not execution receipts for it.

The release fragment `2026-10-06-e02-b-cas-bound-import.toml@0bf788ac2e57533b08be9172d64c19705a3af30d` classifies scoped bound-import admission as a public-stable behavior change and calls for matching bound source manifests; the package README states the same migration. It also explicitly says this does not ratify a public cross-tenant transfer policy. A general unbound-to-scoped positive is not required by B148. If a maintained A/C consumer is shown to depend on that route, that is a concrete compatibility/migration issue to resolve; the predecessor test alone does not establish such a caller requirement.

The candidate contains the required bounded mechanism and the source-level positive/negative witnesses. However, the positive fixture changed after the 120/121 predecessor receipt, and no exact-current-candidate run of the changed positive plus affected import consumers is established here. Keep formal B148 at `verification_missing` until that bounded exact-candidate check is retained; do not recast the predecessor failure as a missing owner-law decision or as proof that an unbound positive must be restored.
