## Finding dispositions

### B61 — cache-freshness accepted; historical replayability limited

The precise remaining original-scope question is whether prior source bytes remain resolvable for the promised replay horizon. Issuer authenticity, scientific row-to-output causality, K_ref custody, and deployed production-data behavior are broader claims and are not inferred from this code or receipt. If the bounded original closes without historical replay, B61's mechanical path is ready for acceptance; otherwise hold only the replayability subclaim until the retained-byte/run-retention predicate is demonstrated. Do not request a generic owner packet or institutional ratification.

**B-owned work now:** preserve the V11 executor and source-composition delta when integrating the older 0bf topic; keep the existing real `SKGQuery` connection and full-digest checks; add/retain only an exact snapshot-retrieval or immutable-run replay witness if the original B61 replayability sentence stays in scope. Do not rerun the 121-case wave merely to revisit the issuer/K_ref extension.

### B67 — optional evidence-reuse profile; no global approval prerequisite

The original B67 calls this a constrained efficiency extension after ordinary end-to-end passage, explicitly not a gate before the first result. It requires exact frozen bytes/ref/version, model and request parameters plus current access/use permission on each reuse; live/unpinned URLs, tool calls, streaming, and independent repeats remain outside the optimization.

At 0bf the code has a typed `CacheReuseRequest` and `CacheReuseDecision` bound to actual actor, tenant, scope, purpose, model, parameter digest, evidence ref/version/hash; it recomputes the snapshot byte hash, requires immutable bytes, and rechecks the authorizer before cached emission/publication. An absent or invalid authorizer yields a miss/provider call. The exact source census shows the factory parameter is optional and production call sites do not supply a concrete authorizer. That is a missing deployment bridge only for deployments that choose to serve frozen-evidence cache hits; it is not a reason to prevent cold provider work or add a new sovereign approval subsystem.

The local `_UnitDeploymentOwner`/CAS fixtures are test authorities, not production authorities. The same-source run passed the basic exact-packet, changed-material, revoked-fixture-permission, and live-URL discriminators; the stronger real-CAS actor/epoch/revocation tests errored in setup and remain unverified. Canonical ledger status remains `partial` because there is no accepted B67-specific receipt, despite Appendix C's bundle-level `closed_bounded` label. Do not auto-close it or silently convert a fixture grant into deployment authority.

**B-owned work now:** keep the authorizer optional but fail-closed; continue code, docs, and exact-candidate tests using the typed interface. If a real deployment wants this optimization, its existing access/use owner must be appointed and wired through the factory; the packet must state permission epoch/revocation and independent-repeat policy. If none is appointed, document this surface as disabled/out of scope and retain the ordinary provider route.

### B68 — bounded in-process optimization, not a new service

The original B68 is conditional cost reduction, not a cache-integrity defect: same already-admissible requests may share one provider task; different seed/instructions/snapshot/access/tenant/goal, independent repeats, and non-idempotent actions may not. It expressly disclaims distributed locks and unmeasured production frequency.

At 0bf, `CachingLLMClient` keeps an in-process `_inflight` map keyed by the full request/cache identity; it shields the producer from follower cancellation, keeps a task-owned deadline, and removes the entry in `finally`. The source-equivalent 6fa9 receipt passed the core four-identical / one-provider, seed+tenant separation, follower-cancellation, and failed-owner cleanup tests. This supports that bounded local property on the same production/test blobs, not cross-process exactly-once, production frequency, or the stronger deadline/actual-owner end-to-end cases whose setup failed. The canonical finding remains `partial`; the exact 0bf 62/17 run did not execute this selector.

**B-owned work now:** continue the small per-client singleflight only behind the existing cache-eligibility/admission boundary; retain permission decision and accounting scope in the key; do not create a distributed coordinator. The exact current-candidate witness should cover the four listed controls plus owner-deadline/error cleanup and show a fresh provider call after cleanup. `cacheable=False` is an existing bypass for intentional independent repeats; no claim should imply that temperature zero alone proves experiments are interchangeable.
