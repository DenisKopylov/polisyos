## Property and source assessment

The intended property is: an active producer may mutate only the live model-graph paths granted by `state_writes`; rejected attempts leave branch/base/journal and external completion effects unchanged, while settled output becomes normally editable by later consumers.

The source has a credible finite-graph design. `branch_state` walks the state graph and checks model admission before its copy/isolation work (`state_branching.py:222–261`). `_ordinary_model_type` statically compares mutation/copy/construction hooks and rejects private/extra state (`1110–1147`). Tracked model writes authorize current live paths, validate candidate attachments, run Pydantic assignment, then reconcile the actual stored field value before journaling (`1012–1042`). Parent/root ownership lets aliases resolve to their current live paths; new model children are checked before attachment. Detached copies retain the original grant, and `_completed_producer_state` deep-copies settled output into a non-enforcing consumer view while leaving the provider-held view guarded (`283–312`, `1051–1104`).

The new independent oracle is a meaningful design improvement: it uses real sequential/async executor routes, filesystem CAS, completion callbacks, cache reopen/merge, live aliases, shallow copies, list-owned children, validating assignment, and root deletion. It asserts public state/journal/effect outcomes rather than private wrapper markers. It is not yet execution evidence. ## Concrete blockers and bounded limitations

1. **Validated assignment can mutate an ungranted sibling.** The d18 isolated runtime probe exercised exact source blob `b15855c…`: with only `params.holder.count` granted, an admitted `validate_assignment=True` model's after-validator changed sibling `tag` from `stable` to `changed-by-validator`; the branch changed, base stayed unchanged, and the journal recorded only `params.holder.count`. This is a direct counterexample to the broad live-graph write-scope property. Receipt: `R/incoming-20261007-1311/B-model-local/report.md` and `receipt.json`, `direct_probe.validator_sibling`. Ordinary pure field normalization is handled by reading/reconciling the post-validation stored value, and the new oracle covers that positive case; the source does not distinguish pure validators from side-effecting validators at admission.

   **P40: same class, one level deeper** — this is another escape in producer live-graph write-scope enforcement, not a new class. The README acknowledges arbitrary validator side effects are outside its sandbox claim, but runtime admission still accepts such models; the release fragment does not state that precise boundary. Do not add another per-validator patch or demand a universal Python sandbox. Either widen the finite graph mechanism to detect and reject/restore out-of-grant model-field deltas caused during assignment, or make this model profile's admissibility boundary explicit and enforceable; otherwise retain a declared bounded residual and narrow the release claim. The smallest closure capability is validation that is isolated from the live graph or a graph-wide before/after delta check with rollback; external side effects remain outside the sandbox claim.

2. **Worker wire rejects the newly tracked artifact-reference subtype.** In the actual worker consumer, `_encode_wire_value` accepts only the canonical allowlisted model type (`runner/serialization.py:244–250`). `serialize_outcome` normalizes the state field to `ExperimentState` (`585–603`) but leaves `NodeOutcome.artifacts` intact. A tracked `ArtifactRef` in that list has the dynamic `_JournaledArtifactRef` type and is rejected as `Unsupported model on runner wire`. The d18 native wave observed five worker-contour failures at this real producer → worker serializer edge. Fix at the canonical B producer/wire owner by serializing a canonical `ArtifactRef` while preserving its full selected manifest identity; do not broadly allow arbitrary dynamic subclasses.

3. **Async hook refusal escapes the typed workflow result.** Both executors call `branch_state` before the node-execution `try` that maps failures to a `NodeOutcome(status="fail")` (`executor.py:1356–1367`; `async_executor.py:1665–1669`, catches at `1869–1909`). Sequential tests expect `TypeError`, but async tests expect a structured failed result. The same-source d18 wave observed all nine async unsupported-hook cases propagate instead of returning that result. Keep scope admission fail-closed and before producer invocation, but translate its refusal at the public async execution boundary (or explicitly change the contract and tests if propagation is intended).

4. **Constructor-hook preflight has a side-effect counterexample.** The d18 test for an unsupported custom `__new__` expected no hook call after its baseline; sequential admission called it once more before refusal (`test_producer_scope_reconciliation.py:499–582`). Thus static hook preflight is not yet evidence that every unsupported constructor path is side-effect-free. The exact source cause was not established here; do not speculate or widen this into a universal constructor sandbox. Preserve this failing selector while the owner resolves the path.

5. **Completion/copy/alias positives are useful but not a blanket claim.** The author test explicitly holds the producer's old view, mutates the returned completed view, and confirms the held view remains guarded (`test_producer_scope_reconciliation.py:259–275`). The independent oracle exercises actual alias, shallow-copy, new-child, cache-reopen and physical completion paths. The d18 wave's worker failures occur before this boundary, so they do not falsify the completion-copy result for sequential/async; they do mean completion has not been demonstrated through the worker contour on this source.
