## LA-037: P38 и роль compatibility alias

Исходная карточка LA-037@1980768, строки 2156–2170, прямо говорит: «Две обёртки не являются двумя layout-алгоритмами»; если стабильный внешний Foundry contract нужен, нужен «один осознанный facade с прямыми явными bindings, а не обязательная цепочка двух». Там же отдельно сказано, что закрытие последнего поддерживаемого public facade требует собственного lifecycle-решения. Это не требование удалить любой второй import path.

Наблюдаемая реализация совпадает с этим bounded смыслом:
- polisyos.ir.kernel.slots — единственный владелец builder/types; TrinityCompiler импортирует builder оттуда напрямую (trinity_compiler.py:33).
- foundry/methods/layout.py объявлен compatibility facade и ограничивает имена через __all__ (layout.py:1–17).
- foundry/methods/compiler/layout.py объявлен compatibility re-export; он также связывает те же пять объектов непосредственно с IR owner (compiler/layout.py:1–9).
- Tests test_foundry_layout_facade_binds_ir_owner_without_compiler_hop и test_both_layout_addresses_preserve_all_ir_object_identities (test_layout.py:55–87) проверяют desired direct ownership and identities. Первый проверяет, что подмена module attribute у intermediate alias не перенаправляет primary Foundry facade: это подтверждает отсутствие двух-hop authority, а не несовместимое поведение потребителей.
- Stable IR package root документирует __all__ как API contract, а неэкспортируемые helpers как internal (ir/__init__.py:1–10); KERNEL_FACADE_EXPORTS публикует registry types, но не эти layout builders. Политика public surface объявляет не перечисленные пути internal (contract.toml:1–5; public-surface.md:11–17); Foundry stable list содержит root/api/compile/execute/uncertainty, но не два nested layout modules (public-surface.md:2293–2312). Значит, здесь не установлено два равноправных public-stable API.
- Ограниченный документный долг конкретен: docs/reference/foundry/state.md:35,87 всё ещё ссылается на foundry.methods.compiler.layout; architecture/shims.toml:1–8 требует owner/target/sunset для active shim entries, но ни один layout адрес там не зарегистрирован. Это несогласованность документации/lifecycle списка, не source/property failure LA-037.

P38 разбор: property — first-party compiler использует IR owner, а сохранённые compatibility адреса возвращают те же object identities без второго layout implementation; implementation — прямые импорты обоих модулей из ir.kernel.slots; divergent consumer case для этого bounded property в receipts не найден. Простое количество module paths не является фальсификатором. Самый маленький follow-up: либо обновить state docs так, чтобы они отличали IR owner и внутренний Foundry compatibility alias, либо зарегистрировать compiler/layout как конкретный alias с owner/target/sunset. Если alias позже будет сниматься, сначала обновить этот autodoc/user reference и оставить уже имеющиеся обе import/identity проверки. Новая approval bar или внешний полный client census не следует из LA-037.
