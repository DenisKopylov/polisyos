## Исправления scope до следующего шага

- B109 исходно проверяет математическую корректность ускоренного Pareto-компаратора: сравнить с прямым all-pairs определением для 1–4D, направлений, перестановок, равенств и разных records с одинаковыми координатами. Default A frontier provider / run-tenant-cell export — отдельная served capability и не дополнительное условие исходного B109.
- B111 — неизвестные/non-finite метрики не должны становиться сравнимым числом или победителем; проверять missing/invalid/nonfinite state, честную полноту и доступность quantity. Положительная геометрическая volume, потерянная float64 underflow до нуля, — отдельный bounded новый class, без придуманного ID и без закрытия B111. Derived-reference overflow — отдельный negative control.
- B100 — исходное свойство об одном и том же объявленном распределении и преобразовании параметров в sampler и analyzer, с round-trip/fingerprint и поддержанным RNG. Наличие `analysis_ref`, D workflow или подсчёт DOE cases сами по себе не закрывают этот закон.
- B120 остаётся upstream decoder fail: JSON wire token `±1e-1000` теряет ненулевое значение до D admission при обычном `json.loads`; нужно сохранить raw numeric lexeme/точное значение и проверить настоящий response-text path с контролями 0, 0.0 и обычной конечной суммой. Это не тот же class, что геометрический underflow hypervolume.

## Следующее решение

Продолжение D должно закрыть каждое выполнимое исходное свойство по exact candidate, без подмены criterion дополнительными owner-decision запросами и без притворного заполнения отсутствующих inputs. Кодовый slice, runtime check и finding closure — три отдельных статуса. Формальные finding-переходы делает G после независимых receipts и owner evidence. Production-dependent checks выполняются локально, на read-only data и exact frozen candidate только там, где criterion требует реальные входы; ни весь production dataset, ни его перенос в cloud не нужны. Финальную широкую wave проводить один раз после source freeze/reviews; перед ней — только changed-property и affected-consumer checks.

Аудит read-only: тесты/окружения/ref не менялись; новый текстовый материал сохраняется только в ignored `_build`.
