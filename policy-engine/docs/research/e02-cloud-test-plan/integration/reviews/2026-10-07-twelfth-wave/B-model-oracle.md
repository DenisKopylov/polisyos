## Acceptance blocker: validator can change an ungranted sibling

**P38 property:** a grant for `params.holder.count` must not publish an effect changing `params.holder.tag`. **What the implementation measures:** `_TrackedModelMixin.__setattr__` validates `count`, reads and wraps only `count`, then records only the `count` path. `_ordinary_model_type` checks a fixed list of low-level methods but does not reject or inspect Pydantic `@model_validator` / `@field_validator` functions.

A concrete adversarial discriminator is an admitted model with `validate_assignment=True` and an after-model validator that, while `count` is assigned, updates `tag` via `object.__setattr__` (or direct model-field storage). The validator is not among the admission checks; successful validation can leave `tag` changed while the wrapper records only `count`. The existing validation test uses `validate_assignment=True` but no custom validator, so it does not distinguish this case. This is a **source-derived counterexample candidate, not an executed FAIL**: the review had no local test slot, so the runtime result is `not_established`. Because validation is explicitly exercised by the candidate, silently treating validator-bearing models as excluded is not supported by the current test/receipt.

This is the same P40 class as the prior alias escape—an actual model-graph effect outside the declared write grant—one level deeper through assignment validation, not a new class. Do not add a one-off patch for one validator. The owner must either (a) widen the mechanism to reconcile/authorize the complete post-validation field delta before admitting the mutation, or (b) declare validator-bearing models outside the finite profile and reject them during preflight. The smallest falsifier is one real executor/CAS case granting only `count`, where validation tries to alter `tag`; assert either fail-before-effect with unchanged state/journal or complete correctly authorized and journaled deltas.
