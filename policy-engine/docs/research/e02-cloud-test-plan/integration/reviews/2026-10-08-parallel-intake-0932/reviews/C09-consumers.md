## Required consumer rechecks

1. **Calibration evidence bridge — substantive propagation gap.** `calibration/forecast_bridge.py:1040-1118` recomputes observed hits and reconciles requested, available, evaluated, and availability fields, but does not inspect scenario `metadata.interval_admission` or the C09 degraded reason. A coherent partial roster (for example, one valid pair and one missing pair) passes those reconciliation checks: availability is correctly 1/2, while the observed-pair pass rate can still meet the context threshold. There is no blocker for `availability < 1` in `_OBSERVATION_BLOCKERS` (`:156-174`), so `produce_empirical_calibration_evidence` can set `usable_for_calibration=True` (`:441-454`). The S10 runtime consumer maps usable + floor-passed evidence to `calibration_status=pass` / `forecast_tier=observable_calibrated` (`runtime/quality/generation_cycle.py:10809-10842`). Recheck this narrow path before claiming limited interval admission governs calibration: either make limited admission prevent calibration usability, or preserve the partial scope/denominator as typed evidence and have each consumer apply an explicit policy. Do not gate on generic `report.degraded` alone: the FRC-02 path deliberately marks predictive-only bridge-pending reports degraded even with complete intervals.
2. **Backtest matrix / leaderboard — independent scoring path.** `BacktestMatrixRunner` records the scenario degradation but still makes each kind `status="ok"` and scores any non-null `coverage_probability` (`scientist/governance/backtest_matrix.py:176-219, 289-306`). It aggregates those scores into `BacktestMatrixResult.composite_score` and only puts `report_degraded`/`report_trust_eligible` in result metadata (`:222-265`). `CalibrationLeaderboard` consumes the matrix composite as `backtest_matrix_score` (`calibration_leaderboard.py:116-149`). Thus a limited evaluated-pairs-only coverage value can still improve a separate governance score while the public TrustScorer grade is null. Add a focused regression/review deciding whether to exclude partial coverage from this score or carry its limitation into the matrix/leaderboard status; preserve point-error scoring if that remains admissible.
3. **Decision packet projection.** Existing output carries a degraded marker and null trust profile, which is sound for the historical grade. If `overall_coverage_probability` remains exposed for a limited report, consider projecting requested/evaluated/available counts or explicit scope alongside it, or suppressing that coverage value; currently `enrichment.py` exposes the conditional value without those qualifiers. This is a projection clarity issue, not a reason to change the report schema preemptively.
4. **ETS forecast owner.** FRC-02 constructs intervals from strict held-out evaluation and computes its support/limited label from complete, equal-length holdout pairs (`backtesting/forecast_owner.py:715-767, 832-842, 929-940`). It fresh-loads the CAS report and separately checks predictive-only trust ineligibility (`:887-927`). This current producer route is not the partial-roster source; a full repeat of its suite is unnecessary. A targeted assertion is only needed if the producer is later allowed to emit incomplete interval vectors.

## Constructor coercion boundary

There is a real, explicitly documented boundary: `HistoricalValidationPlan.prediction_intervals` is `dict[str, list[tuple[float, float]]]` under non-strict Pydantic config (`backtesting/plan.py:56-80`), so plan construction may coerce numeric strings and booleans before `_read_interval` sees them. The candidate README expressly scopes rejection of strings/booleans to the direct evaluator API and says plan float coercion remains. Therefore this is not an undisclosed break in the current promise; if raw plan inputs must reject those values, tighten the plan contract and add a test through plan construction/orchestration rather than relying on the evaluator helper test.
