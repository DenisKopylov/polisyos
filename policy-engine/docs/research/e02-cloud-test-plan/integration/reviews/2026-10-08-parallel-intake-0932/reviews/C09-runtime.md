## Admission core: property exercised correctly on the named path

`backtesting/evaluator.py::_read_interval` (candidate lines 14–27) requires list/tuple length 2, rejects bool and non-`numbers.Real`, converts only finite values, and refuses reversed pairs instead of swapping. The evaluator (lines 69–233) keeps the expected `y_true` cell roster as the denominator when a nonempty interval map is requested; it records absent cells, extra times/metrics, bad intervals, and point-unavailable cells as limitations. `coverage_probability` remains hits / evaluated pairs and is explicitly labeled `evaluated_pairs_only` when limited. A fake `metadata.interval_admission` is overwritten on interval requests and removed for point-only evaluation.

On the standard `BacktestOrchestrator._run_single_scenario` path (candidate lines 285–335), a recomputed limited result adds `interval_admission_limited`; `_aggregate` then sets the persisted report degraded and `trust_eligible=False`. The CAS load returns the stored scenario metadata. The test file exercises reversed/oversized/scalar/bool/string/nonfinite intervals, partial and foreign axes, caller metadata, point-only, changed observations, and the persisted standard report. This is sound for that evaluator→orchestrator→report path.

The raw `HistoricalValidationPlan` float-tuple coercion is unchanged and the handoff states the boundary: strict type rejection is only at the post-validation evaluator API. That is a declared scope limit, not evidence that upstream string/bool payloads are rejected. B172/B173 themselves remain unclosed: their original criteria concern constant nonzero residuals and truthful Student-t/unavailable-inference reporting, not interval-pair admission; the handoff correctly says their implementation was carried unchanged and issues no closure.

## Actual current escape: the promotion score ignores the report’s trust status

`governance/backtest_matrix.py` calls the protected `_run_single_scenario` and preserves `report_trust_eligible`/`report_degraded` in its metadata (lines 176–202, 222–265). But `_score_backtest_scenarios` (289–303) still scores `coverage_probability` from evaluated pairs and emits a `BacktestKindResult.score` without consulting interval admission or report trust. `BacktestMatrixRunner` averages those scores into `composite_score` (244–258). `CalibrationValidationRunner.run` passes that result directly into `CalibrationLeaderboard.build_entry` (calibration_validation.py:215–249). The leaderboard consumes the composite score (calibration_leaderboard.py:116–120) and makes `eligible_for_promotion` depend on governance approval, adversarial pass, and absence of missing-score gaps only (145–149); it never checks `report_trust_eligible` or `report_degraded`.

Concrete divergence, derivable from this code: provide a valid three-cell point series and only one valid interval pair. The report is correctly `limited`, degraded, and non-trust-eligible; its conditional pair coverage can still be 1.0. The matrix score remains present (and can be high on accurate point errors), so it creates no missing-score gap. With the other required slots present, approved governance, and adversarial pass, the leaderboard can set `eligible_for_promotion=True`. Even fully invalid intervals leave point-error components available to score. The intended property is “limited interval evidence cannot carry a promotion score as fully admitted”; the implementation checks/uses a finite conditional numeric score and carries trust status as metadata, but the promotion gate ignores that status. This is an actual wired path through calibration validation, not a hypothetical future consumer. The defining interval tests do not cover this matrix/leaderboard consumer.

## Same-class sibling example and P40 disposition

The exported temporal API is another concrete sibling (no in-repository non-test caller was found, so current production reachability is not established). `evaluate_temporal_trajectory` calls the evaluator, computes band coverage from `coverage_probability or 0.0`, and tests `min_band_coverage` against that conditional value (`temporal.py:104–170`). It then merges caller `metadata` last (`218–237`), which can overwrite the evaluator’s recomputed `interval_admission`. `build_temporal_backtest_report` returns the standard report with defaults `degraded=False` and `trust_eligible=True` (`388–421`). It illustrates the same class: admission limitation/status can be bypassed in a sibling projection. The public package exports these functions.

P40 bucket: **same interval-admission/status-propagation class, one level below the report gate**, not a new pair-parsing class and not a hypothetical generic future. The handoff’s bucket names one pair intake plus one report limitation consumer; this review found the promotion consumer escape. This is the second finding of that class. Stop adding per-call-site exceptions: widen one invariant across score/promotion projections (or explicitly scope a typed diagnostic-only score that cannot satisfy promotion). A capability already exists to close it—the matrix carries report trust status and the leaderboard owns promotion eligibility—so declaring this residual bounded because no capability exists would be false. Treat the temporal path as a same-class worked example, not another repair round. P38 divergence is the numeric score being used where the property is admissible evidence for promotion.
