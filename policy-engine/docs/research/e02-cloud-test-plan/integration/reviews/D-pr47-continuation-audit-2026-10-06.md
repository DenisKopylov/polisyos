## Решения, которые меняют продолжение

**B111: неверное количество/availability.** `scientist/methods/autotune/pareto.py` для >2 objectives перемножает диапазоны bounding box вместо объёма объединения dominated boxes. Maximizing front `(2,0,0), (0,2,0), (0,0,2)` относительно `(0,0,0)` даёт кодом 8, геометрически 0. Точная 1D/2D часть сохраняется. Предпочтение — один адаптер к уже имеющемуся BoTorch partitioning с явными direction/reference и точным supported profile; при недоступном backend/неподдерживаемом профиле typed unavailable. Отдельный `MultiObjectiveStrategy.compute_hypervolume()` тоже возвращает ложный numeric zero при отсутствии backend. Исправление должно сохранить assessment/reason через registry, stopping и exporter; иначе quantity исправлена, consumer всё ещё неверен. [BoTorch API](https://botorch.readthedocs.io/en/stable/utils.html) предоставляет partitioning/hypervolume; фактические параметры сверить с pinned installed version. Для произвольной размерности не обещать дешёвую точную геометрию.

**B110 отдельно: coordinate/round-trip identity.** Сохранять metric+split+direction/version/unit или typed ordered coordinates через frontier, reference, serialization и `is_dominated`; display-label меняется без изменения relation, different splits не схлопываются. Это отдельный original criterion, не hypervolume численность.

**B120: raw-cost класс на следующей границе.** `json.loads(raw_text)` может превратить JSON number `1e-1000` в `0.0` до guard. Текущие строковые/Decimal tests подменяют `_post_json` словарём. Следующий discriminator обязан пройти response-text decoder. Сохранить lexeme/Decimal на едином intake; стандартный [`parse_float`](https://docs.python.org/3/library/json.html) допускает это без новой библиотеки. Реальный zero остаётся zero; invalid-present/nonzero-underflow не становятся бесплатным событием. Это P40 same class deeper, не ещё один dict-only patch.

**B/D общий ledger.** D schema 1.0 (`resource_events`, `settle_resource`) несовместим с уже принятым B 1.1 (`spend_receipts`, `settle_spend`, unknown-ack reconciliation). Не переносить старый D shared ledger поверх G. B canonical owner готовит additive typed resource/reservation extension единого durable event index; D портирует свои consumers. Номер successor schema назначает owner. Event identity, scope, distinct budget keys, physical request, amount/unit/source, reserve/settle/retry и reopened projection нужны вместе. Unknown ack сохраняет pending reservation и тот же event ID; это не zero и не разрешение повторного списания. Marker/class/module cache provenance и caller evaluation text не appoint authority.

**B106: score basis ещё расходится.** Новая L5 partial/unknown correction реально присутствует и имеет 57 PASS bounded consumer evidence; её не переоткрывать. Но отсутствующий violation threshold всё ещё может дать score 1/robust, а blueprint пересчитывает score по числу grouped issues: 1 high issue на 32 scenarios превращает 31/32 в 0. Сохранить producer scenario denominator до grouping/top-k; без typed threshold unavailable, без sampling law только observed fraction. E проверяет реальный downstream DOE, D сохраняет ownership stress semantics.

**Search/transfer/service.** Остались MO `10**400` → uncaught OverflowError, NN `_warm_data` без checkpoint restore, future-created lessons принимаемые в past-as-of, и optional Torch/HNSW collection в профилях без extras. GP/CAS positive уже есть; обычный `SearchConfig.transfer_manager` ещё не гарантирует wired bridge. Champion primitive admission/local races полезны, но не served SearchService restore/factory/cutover/rollback. LA-014/015 открыты по конкретной consumer работе, а не по абстрактному отсутствию production data.

**B164: отрицательный контроль не positive permit.** FUN-03 показывает нулевые effects при legacy bool/callback и два FAIL после удаления guard. Реальные issuer/current verifier/revoke-serialized writer и valid typed positive отсутствуют (`bridge_missing`, UNRUN). Назначение существующего permission owner — отдельное решение; D не выдаёт себе authority. Отзыв после preflight при bool=true должен запретить commit, valid current permit — ровно один effect.
