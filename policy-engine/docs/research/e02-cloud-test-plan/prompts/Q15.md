## 2. Измерь каждую ячейку

Создай уникальный run directory `_build/e02-pilots/Q15/<run-id>/`. Cell key: job + source SHA + полный repo-relative path + attempt ID. Не дели DuckDB, mutable artifact store, фиксированный порт или owner scratch между независимыми процессами.

Используй существующий `tools.quality.testing.run_timed_suite` из целевой ревизии. Его `--cwd` и `--receipt-output` относительны к `policy-engine`, а не к Git root. Путь из manifest начинается с `policy-engine/`; для pytest убери именно этот префикс.

Шаблон команды одной ячейки, cwd = policy-engine; переменные E02_TEST/E02_CELL/E02_OUT заполняет твой цикл:

```sh
/usr/bin/time -v -o "$E02_OUT/wrapper-resource.txt" \
  .venv/bin/python -m tools.quality.testing.run_timed_suite \
  --lane "e02-pilot-Q15:$E02_CELL" --cwd . \
  --capture-pytest-workload \
  --receipt-output "$E02_OUT/execution.jsonl" -- \
  /usr/bin/time -v -o "$E02_OUT/pytest-resource.txt" \
  .venv/bin/python -m pytest -c pytest.ini "$E02_TEST" \
  --junitxml="$E02_OUT/junit.xml" --durations=0 \
  --basetemp="$E02_OUT/tmp" \
  -o "cache_dir=$E02_OUT/pytest-cache" \
  --benchmark-storage="file://$E02_OUT/benchmarks"
```

Сохрани полный stdout/stderr команды в raw/run.log; в чат его не печатай. Не прерывай цикл из-за первого ненулевого exit code. Не используй tee так, чтобы потерять exit code. Не вводи короткий немеренный timeout: если приходится прервать зависший/слишком долгий запуск из-за бюджета среды, запиши elapsed и решение, пометь TIMEOUT/harness_limit; это не продуктовый FAIL, остаток явно UNRUN. При внешнем kill финальный bound receipt может отсутствовать: сохрани supervisor event и logs, укажи execution_receipt_incomplete.

Перед первой ячейкой проверь GNU time на коротком независимом Python subprocess с известным exit code и чтением полей elapsed/user/sys/max RSS. Зафиксируй единицы RSS (GNU time: KiB) и границу измерения. Внешний GNU time измеряет wrapper; его RSS/CPU не выдавай за pytest. Для pytest используй вложенный GNU time непосредственно перед `.venv/bin/python -m pytest`, как в шаблоне. Это per-command RSS, не суммарный VM peak RAM; две вложенные метрики не складывай. Отсутствие/ошибка resource adapter — отдельный harness blocker; не выдавай Mac RSS за Linux RSS. Краткий setup probe не является тестовой ячейкой.
