# INT-R2 — Claim-Evidence Ledger

## 1. Method

The package's three-column F01–F40 table is not accepted as its own evidence. Each exact
`confirmed` row was traced to the baseline, the package argument, or the external-practice ledger.
The audit dispositions below are evidentiary dispositions, not a new W4-K05 standing vocabulary:

- `supported` — the cited artifact directly supports the bounded proposition;
- `supported_narrowly` — support exists after preserving a stated domain/scope limit;
- `split_required` — the positive local observation is supported but an attached repo-wide zero or
  universal conclusion is not;
- `not_supported_as_cited` — the cited coordinate does not contain the claimed evidence;
- `not_established` — the package did not execute the denominator needed for the claim.

The complete audit denominator in §2 is the **23 findings whose cell is exactly `confirmed`**, as
supplied and verified in the commission. Six mixed cells are audited separately in §3. This audit did
not recompute the package's classification distribution.

### 2.2 T3 result

The baseline does not support all 23 exact `confirmed` findings at the same strength.

- F01 fails at its cited coordinate.
- F05, F07, F11 and F32 attach repository-wide absence claims to sampled local evidence. Their local
  positives survive; their zero/absence component does not.

  column makes them look equivalent to direct repository measurements.

This is a material standing problem, not a refutation of the union. The amendment can close it by
repairing one anchor, splitting four findings, and moving scope/basis text into governed columns.

## 4. External-Transfer Claims

The source ledger does considerably better than a citation list. Every S01–S22 row binds one named
source to a proposition, a source class, an explicit non-effect and a holder label. That structure
makes the **transfer identity** reconstructable.

The remaining problem is source replay:

| Transfer family | Strongest durable coordinates | Weak coordinates | Audit consequence |
| --- | --- | --- | --- |
| relation / estimand | JCGM identifier, JMLR paper, FDA/ICH named guidance | live IARC news/landing page | Retain transfer; pin the actual Preamble/guidance version and section. |
| mandate / normative / write | statute, W3C recommendations | regulator/guidance pages that can change in place | Add retrieved version/date and stable section locator or preserved content digest. |
| human decision / assurance | PCAOB standard identifier | generic “current standards,” overview/news and live professional-guidance pages | Name the exact standard edition/paragraph supporting each transfer. |
| capacity | GAO report number and DOI papers | live Treasury and framework pages | Pin edition/publication date and the precise claim-bearing section. |

Thus T6 has a split result:

- a repository-only auditor can identify **which of the 22 sources maps to which transfer**;
- that auditor cannot reconstruct the **exact content/version** of every mutable source from the
  repository alone.

This is a material reproducibility gap, not evidence that the transfers are false.

## 7. Standing Reconciliation

The package's aggregate three-axis statement remains defensible:

```yaml
research_standing: accepted_narrow_scope
capability_standing: absent/unallocated
gate_standing: NO_GO
```

The audit does not replace those values. It finds that the **per-finding register cannot currently
justify all of its strongest tokens** because kind, transfer class and consequence are absent, one
anchor is wrong, and several repo-wide zeros were not enumerated.

Required reconciliation:

1. use only exact registered standing tokens in the standing column;
2. add `kind`, `evidence_refs`, `source_or_transfer_class`, `holder_label`, `consequence` and
   `non_effect` columns;
3. repair F01;
4. split or downgrade F05, F07, F11 and F32;
5. scope F20 and identify F25 as a design rule;
6. keep the aggregate package standing separate from every audit verdict and capability label.
