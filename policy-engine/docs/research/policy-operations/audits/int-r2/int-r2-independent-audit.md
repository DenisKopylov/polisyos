# INT-R2 — Independent Audit

## 1. Scope And Method

The audit read all five stage-1 files before writing substantive findings:

1. `int-r2-gap-acquisition-cases.md`;
2. `int-r2/repo-baseline-and-source-ledger.md`;
3. `int-r2/operational-closure-and-fixtures.md`;
4. `int-r2/integration-handoff-and-finding-register.md`;
5. `int-r2/external-primary-source-ledger.md`.

The seven audit skeletons were the only files written before that read, as required by the delivery
contract.

The audit branch was created from the exact package head. Connector comparison establishes:

- package head is the audit branch's merge base;
- the initial audit branch was one commit ahead and zero behind the package;
- the initial delta contained exactly the seven audit skeletons;
- no package file was modified.

The audit attacked the nine named threats, sampled every exact `confirmed` finding through a complete
23-row reconciliation, checked all 28 union-type pairs, walked all twelve proposed ceiling dimensions,
audited all eight terminal pairs, inspected all 22 external-source rows and ran the required
orientation-error pass.

The package is uneven. Its measurement-holder discipline and refusal of a supplied zero are exemplary.
Its finding register, field-level gate construction and benchmark falsifiability are materially weaker.
The strong parts receive commendations but do not offset the defects.

## 2. Verdict

# `GO_WITH_REVISIONS`

The package has a defensible research core:

- the eight commissioned acquisition objects are genuinely non-substitutable;
- same-stream row growth is correctly barred from closing relation, estimand and mandate cases when
  the required object remains absent;
- re-entry returns to the demanding owner rather than auto-closing;
- `deeper_terminal` is correctly defined as stronger admitted negative knowledge rather than effort;
- external institutions remain external;
- aggregate standing is honestly `accepted_narrow_scope / absent-unallocated / NO_GO`.

Nine material defects prevent a clean `GO`. None requires withdrawing the union or contradicts a
ratified kernel. The defects can be repaired by an amendment that strengthens the register, evidence
anchors, classifier, ceiling checkability, benchmark oracles and terminal coverage.

A `NO_GO` would require a structural defect revision cannot repair — for example, collapsed union
types, a data-count closure rule, or an unavoidable authority-minting premise. The audit found none.

## 5. Commendations

The four commendations are not generic praise.

1. **C001 — holder-aware measurement.** The package does not merely state `15` and `3`; it records the
   measure, denominator, executing/supplying party, P37 class and consequence.
2. **C002 — orientation resistance.** It refuses a zero supplied by the commissioner even though
   accepting it would have made the narrative cleaner.
3. **C003 — real discrimination.** The union is not eight renamed rows. Relation versus target,
   legality versus sanction versus write authority, capacity versus permission, and decision versus
   assurance each yield different producers, proofs and ceilings.
4. **C004 — transfer non-effect.** The source ledger says what a practice supports and what it does not;
   it never claims that mature law, trials or audit practice creates a PolicyOS capability.

These strengths explain the `GO_WITH_REVISIONS` rather than `NO_GO` verdict. They do not reduce the
severity of F001–F009.
