# INT-R2 — Orientation Error Ledger

## 1. Method

The stage-1 prompt is treated as `institutionally_supplied`, not as authority over repository state.
The audit checked its claims against the package pin, the N13a census, the GY plan, the CG5 module
boundary and resolvable Atlas planning material.

Orientation dispositions in this ledger are descriptive audit results, not W4-K05 research-standing
values:

- `accurate` — the pinned owner artifact supports the statement;
- `accurate_with_scope` — the core fact is supported after narrowing an overbroad implication;
- `erroneous` — the orientation states more than the pinned evidence supports;
- `not_established` — the claimed object/status could not be independently resolved at the pin.

## 5. Draft Consumer Row

The orientation states that an in-flight slice drafted a non-closure row named
`gap_acquisition_case_union`, quoting its reason and saying the row was not yet registered because the
slice had not merged.

Audit observations at the package pin:

- exact-key connector code search did not resolve `gap_acquisition_case_union`;
- exact quoted wording did not resolve;
- fuzzy search returned related Atlas/DS9 plans and registers, including a plan whose frontmatter says
  `implementation_receipts_complete_unmerged`, but not the exact row;
- code search is an index and therefore establishes neither a repository zero nor a positive;
- the package supplies no immutable branch/ref/path for the drafted row.

Disposition: **`not_established` for this auditor**. The orientation may be factually correct about an
unmerged line, but neither stage 1 nor stage 2 can independently reconstruct it from the pinned
repository. The package uses it only as demand evidence, which is safe; it should label that demand
`institutionally_supplied` at every citation.

This is AUD-F012 (`minor`). It changes no union semantics or capability standing.

## 7. Result

The orientation ledger contains:

- three consequential orientation errors: the supplied zero, structural overclassification of the
  capstones, and owner-appointment language;
- one unresolved supplied object: the drafted consumer row;
- accurate orientation on the 15 residuals, three route records, N13b exclusion and missing-plane
  problem.

The stage-1 package caught and corrected the two most dangerous authority errors: it refused the zero
and refused to appoint an owner. The remaining repair is to holder-label the consumer-row claim and to
avoid calling `not_a_data_gap` a completed structural classification.
