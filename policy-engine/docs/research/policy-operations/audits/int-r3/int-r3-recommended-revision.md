## Finding-by-finding closure conditions

### `RR-01` — baseline, negative census and owner seam

Closes `INT-R3-AUD-F001`, `INT-R3-AUD-F002`, and `INT-R3-AUD-F012` when all of the following hold:

1. Re-read every baseline source at a named pinned commit.
2. Remove or correct the nonexistent `TrustPostureContent` coordinate.
3. Replace the inaccurate `TimeSemanticsLabel` contract description with the actual inputs and
   rendered clocks at the pin.
4. For every repository-wide absence claim, provide an executable complete-tree walk with:
   - pin;
   - path and file-type denominators;
   - exact query/property;
   - positive controls;
   - negative controls;
   - executing party;
   - result and predicate-provenance label.
5. Where such a walk is not executed, downgrade the zero to `not_established`; do not substitute a
   search index or named-path sample.
6. Reconcile the Atlas statement “DS6 owns the instrument” with the package’s owner map. Record one of:
   - valid live owner allocation;
   - stale/closed owner requiring reallocation;
   - superseded allocation with the superseding owner;
   - explicit unresolved conflict.
7. Recompute `capability_standing` after that adjudication. Do not infer implementation from ownership
   and do not infer unallocation from missing runtime code.

**Acceptance signal:** the corrected baseline has no unresolved false coordinate; every asserted zero
has a complete receipt or reads `not_established`; and owner/capability standing agree with the active
plan at the same pin.

### `RR-02` — durable evidence and earned transfer

Closes `INT-R3-AUD-F003` and `INT-R3-AUD-F004` when:

1. Every `EXT-01`–`EXT-16` row links to one or more durable source entries.
2. Every source entry carries a stable URL/DOI/report identifier, title, author/issuer, date, source
   type, and page/table/section/result locator where applicable.
3. The exact survey or extract relied upon is committed or content-digested so a later auditor can
   resolve the same evidence without conversational citation tokens.
4. Each external quantitative result remains attached to its original population, task, instrument and
   denominator.
5. `F005` gains a target bridge naming:
   - the PolicyOS operator population candidate;
   - the actual surface/workflow;
   - the time-pressure/interruption condition;
   - the shared mechanism;
   - one case where the mechanism would not transfer.
6. `F007` distinguishes:
   - deterministic all-must-pass composition;
   - governance minimum over ordinal states;
   - probabilistic conjunction;
   - intervention-allocation tasks.
   It states which evidence supports which hypothesis and withdraws any implication not shared by the
   target composition.

**Acceptance signal:** a repository-only reader can start at a package claim, resolve the exact primary
source and reconstruct the transfer argument without using the five uncommitted conversation reports.

### `RR-04` — bounded escape band

Closes `INT-R3-AUD-F006` when the protocol preregisters:

1. the item flow `authored → semantic_verified → scenario_verified → adjudicated → accessible_parity
   → scored/contestable/invalid`;
2. per-construct and per-modality counts at every transition;
3. a minimum scored-coverage floor for every mandatory construct and declared accessibility condition,
   or an explicit governance owner for setting that floor;
4. a maximum contestable/invalid absorption rule or a fail-closed equivalent;
5. a rule that suppresses the aggregate primary score when a mandatory stratum falls below coverage;
6. separate reporting of contestable and invalid items with reason codes;
7. no forced consensus: set-valued `A_i*` and genuine `contestable` status remain available.

**Acceptance signal:** the hardest construct or modality cannot disappear from the headline result
without turning the result into a typed non-result.


1. the first target operator role/population and recruitment frame;

3. ethics/consent determination route;
