## T1 — Absorbed-Scope Discharge

### T1.1 Standard applied

An absorbed task is discharged only when its independent research questions are answered to the same
standard as the host task:

```text
question
→ evidence and disagreement
→ bounded conclusion
→ operational consequence
→ counterexample/failure mode
→ fixture/falsifier
→ unresolved residue
```

A section pointer, artifact field or “mandatory condition” is coverage, not discharge.

### T1.2 OPS-R7 inside INT-R4

The backlog defines OPS-R7 as causal validity under sequential policy adaptations: versioned
treatment, interference and stopping rules. The package adds delayed/censored harm and promotion
because they are inseparable from that question.

|---|---|---|---|
| Is the estimand tied to a version, version distribution or dynamic rule? | INT-R4 §3.4 gives one paragraph; §4.2 and §7.1 require version/rule fields. | `partly_discharged` | No decision rule chooses among the three estimands. |
| Does version assignment depend on prior outcomes or risk? | Named as endogenous and non-inheriting in §3.4. | `cited_not_discharged` | No sequential-exchangeability, randomization, positivity or g-method requirement. |
| How is treatment history/carryover represented? | Exposure history is required. | `cited_not_discharged` | No carryover estimand, washout, lag structure or failure test. |
| How is interference represented? | One paragraph and exposure-map fields; local displacement is named. | `partly_discharged` | No rule for misspecified or endogenous exposure maps; no direct/indirect/total estimand selection. |

**Conclusion:** OPS-R7 is covered but not discharged. This is `AUD-F01`, severity `material`.

## T2 — Residual Absorption And Discriminating Power

### T2.1 What can be established

The package correctly says 8/24 is stress composition, not prevalence. Neither the package nor its
surveys supports a numerical estimate of the proportion of realistic movements that will be
unresolved. The only defensible proportion is:

```yaml
realistic_unresolved_prevalence: not_established
```

### T2.2 Why the residual may be large

The supplied evidence gives four reasons:

1. epidemic and official-statistics movements often have several simultaneous data-generating
   mechanisms (`S3:132-181`);
2. SRE root-cause practice is multi-label and does not offer a universal elimination order
   (`S3:183-227`);
3. Microsoft SRM cases can contain a real behavioral treatment effect and a behavior-induced
   observation/filtering effect in the same path (`S3:229-287`);
4. without an independent sensor, randomized variation, valid proxy or structural restriction, latent
   outcome and observation process are nonidentified (`S1:256-268`).

This is not evidence that unresolved is bad. It is evidence that a safe classifier needs to abstain.
The audit issue is operational absorption: the six substantive classes have no demonstrated coverage.

### T2.3 Degenerate implementation

Consider classifier `D0`:

```text
for every valid MovementComparison:
    primary_class = diagnosis_unresolved
    name all six alternatives
    request independent evidence
    never update posterior or world
```

`D0` obtains:

- zero unsafe posterior updates;
- zero unsafe world writes;
- zero self-confirmation escapes;
- zero version laundering;
- perfect adherence to the unresolved freeze.

Unless acceptance also enforces useful selective coverage on independent cases, `D0` can satisfy the
non-compensable safety criteria and most narrative fixtures. The two positive `prediction_error`
controls prevent a literal all-unresolved implementation on the authored corpus, but they do not show
coverage on realistic holdouts or new domains.

### T2.4 Required performance object

The missing evaluation object is a selective-classification profile:

```text
coverage(c)       = P(primary_class != unresolved | consequence class c)
selective_risk(c) = P(wrong substantive class | resolved, c)
false_resolution  = P(resolved | oracle says nonidentified)
false_abstention  = P(unresolved | oracle supports unique class)
```

It must also report:

- class-specific precision/recall;
- blocking-contributor recall;
- unresolved reason and missing-discriminator distribution;
- coverage by domain and consequence severity;
- risk–coverage curve;
- comparison against `D0` and simple trust-invariant quarantine baselines.

No universal minimum coverage should be invented before domain evidence. The audit requires the
profile and holdout, not a fabricated threshold.

**Conclusion:** six classes retain conceptual distinctions but empirical discriminating power is
`not_established`. `AUD-F03` is `material`.

## T3 — Admission Precedence

### T3.1 Two different orders

The package’s sequence can mean either:

1. **validity-gate order** — which conditions must be established before a residual may be interpreted;
2. **causal precedence** — which supported cause becomes primary when several causes coexist.

The evidence strongly supports the first. It does not establish the second globally.

### T3.2 Observation-first

Observation-process invariance before substantive inference is conservative in the correct direction:

- epidemic investigation checks ascertainment, definitions and pseudoepidemic explanations before
  interpreting incidence;
- Microsoft quarantines SRM-affected inference before ship analysis;
- official statistics separates revision/definition breaks from world movement;
- the O3 negative specifically requires an observation-ancestry firewall.

Therefore step 1 is defensible as an admission gate.

### T3.3 Behavioral co-occurrence divergent case

Use the Microsoft-shaped path:

```text
policy variant
→ genuine increase in engagement                  [behavior → latent/user outcome]
→ bot filter excludes highly engaged treatment users [behavior → observation/inclusion]
→ observed metric appears negative
```

Both `behavioral_response` and `observation_process_change` are supported. Under package §4.5,
observation becomes primary unless an independent channel identifies the latent behavioral effect.
That is safe for posterior admission. It is not enough for operations: the behavior lane still needs
review even when the current causal estimate is quarantined.

The package records `contributing_classes`, but no invariant says every contributor must open its
corresponding action lane. A consumer that routes only on `primary_class` can therefore mask a
behavioral response.

### T3.4 Steps 2–4

No cross-domain argument establishes that intervention/version should always precede context, or
context always precede behavior. Examples exist in both directions:

- a behavior change can cause delivery divergence;
- context can trigger behavior;
- a planned version can be introduced because context changed;
- interference can be mediated by behavioral substitution.

These may be useful elimination heuristics, but the package assigns them semantic routing weight.

### T3.5 Repair

The safe formalization is:

```text
admission_gate_order:
  identity/maturity
  observation validity
  treatment identity
  context/exposure adequacy
  behavioral-path identification
  model compatibility

routing_disposition:
  one primary disposition for the requested operation
  zero or more mandatory contributor lanes
```

The primary is not “the cause that wins”; it is “the disposition that controls this requested
operation.” Every supported contributor carries an obligation, owner/route and closure state. A
blocking contributor remains blocking regardless of primary.

**Conclusion:** the order is partly argued and conservative for learning, but under-specified as
causal routing. `AUD-F04` is `material`.

## T4 — GY-O1 Rider Loosening

### T4.1 Exact logical comparison

GY-O1 states:

```text
before any posterior update:
    type delta
    only prediction_error may update effect posterior
```

INT-R4 states:

```text
prediction_error may enter discrepancy update
expected_variation may enter separately predeclared routine likelihood/calibration schedule
```

Let `U(x)` mean “class x may cause a change to the effect posterior.” The rider is:

```text
∀x, U(x) → x = prediction_error
```

The package adds:

```text
U(expected_variation)
```

That is a contradiction unless the new operation is not an “effect posterior update” in the rider’s
meaning. The package does not establish that semantic distinction; it asks the architect to decide it.
Calling the change non-contradictory before that decision reverses the required routing discipline.

### T4.2 Why the scientific intuition is not enough

Bayesian inference normally assimilates model-compatible observations. That general fact does not
settle this closed-loop system. The very threat is that policy-produced observations can be highly
compatible with the model and still be epistemically circular. Repeated compatible rows may:

- shrink the posterior interval;
- move an effect mean slightly over time;
- increase edge confidence;
- make later publication/promotion easier;
- ratchet a performatively stable but causally invalid model.

Predeclaration does not provide independence. It only proves the schedule existed before the row.

### T4.3 Minimum safe amendment if the architect accepts it

A valid amendment would need all of the following:

1. explicit update target whitelist—e.g. observation-noise calibration distinct from causal effect;
2. sealed pre-deployment schedule and stopping rule;
3. no schedule adaptation after observing compatibility;
4. the same observation-ancestry, treatment-version, context/interference and maturity gates as O1;
5. independent or experimentally justified outcome channel for any causal posterior change;
6. cumulative confidence-gain cap and audit of interval shrinkage;
7. new claim/version identity when the update changes a signed causal statement;
8. a negative fixture in which self-produced compatible data attempts to increase confidence;
9. explicit GY-plan amendment or architect ruling.

Until then, the current written rider governs and `expected_variation` cannot update the effect
posterior.

**Conclusion:** first-order contradiction, not mere scope clarification. It is material rather than
blocking for this research package because no capability exists, the gate remains `NO_GO`, and the
conflict is repairable before consolidation. `AUD-F05` is `material`.

## T6 — Coordinate Independence

### T6.1 Factorization versus orthogonality

A system can use four axes without allowing every tuple. The package and supplied survey use
“orthogonal” or “independent” language but do not define whether it means:

- different semantic questions; or
- unconstrained Cartesian reachability.

The first is true. The second is false.

### T6.2 Counterexamples

#### Counterexample 1 — material reissue constrains claim status

Fix:

```text
E3 diagnosed_mechanism
X2 narrowed
V2 patched_or_reissued
```

If the patch materially changes treatment identity, `C0 confirmatory_intact` is unavailable unless a
separate equivalence/pooling claim passes. `V` constrains `C`.

#### Counterexample 2 — confirmed unacceptable state constrains claim

Fix:

```text
E4 confirmed_unacceptable
X4 terminated
V3 redesigned
```

A claim asserting the terminated version remains acceptable cannot stay `C0`. At minimum it is under
review, exploratory-only for a new version, or withdrawn. `E/X/V` constrain `C`.

#### Counterexample 3 — rollback constrains restart

Fix:

```text
V4 rolled_back
X0 full
C0 confirmatory_intact
```

Without a separate restart probe and authority record, full exposure is illegal. `V` constrains `X`
and the allowed transition history.

#### Counterexample 4 — claim withdrawal need not force intervention termination

A claim may be withdrawn for measurement invalidity while an external institution continues a
protective intervention under a different legal basis. This proves the axes are not a ladder, but it
does not restore orthogonality; it shows conditional rather than deterministic coupling.

### T6.3 Required formal object

The package needs:

```text
State = (E, X, V, C)
Invariant(State, history, contract, authority) -> bool
AllowedTransition(State_old, event, evidence, authority) -> State_new | refusal
```

The invariant enumerates forbidden tuples and required co-transitions. It also names cases in which
multiple next states remain lawful and human authority chooses among them.

**Conclusion:** the coordinate system is useful but its orthogonality claim is false in the
operational sense. `AUD-F06` is `material`.

## T7 — Fixture Falsifiability

### T7.1 Definition used

A fixture can fail only when it supplies:

```text
immutable input packet
independent expected outcome or oracle
assertion at the actual consumer
mutation that violates one property while retaining adjacent markers
```

A family name plus required output is a specification example, not yet a fixture.

### T7.2 Diagnosis corpus

The package supplies arithmetic, family names, packet fields and metrics. It does not supply:

- twenty-four case IDs;
- concrete prediction/observation/evidence packets;
- sealed primary/contributor expectations;
- independent adjudicator/oracle provenance;
- per-case mutation;
- machine evaluator.

The corpus therefore cannot presently fail against an implementation.

### T7.3 O3 conjunction

Required outputs are independently falsifiable in principle:

| Output | Independent wrong implementation | Required assertion |
|---|---|---|
| `diagnosis = observation_process_change` | Emits unresolved or behavioral while all observation-only evidence is retained. | Class assertion. |
| `observation_ancestry = self_confirmation_observation_only` | Correct diagnosis, but ancestry marked independent because sensor name differs. | Provenance/path assertion. |
| `effect_update_allowed = false` | Correct labels, posterior consumer still commits. | Posterior-consumer assertion. |
| `world_edge_write_allowed = false` | Posterior frozen, direct world writer commits edge. | World-writer assertion. |
| permanent quarantine | Both writes blocked now, generic reprocess later admits same confirmation claim. | Lifecycle/reprocess assertion. |

The package’s sentence “removing the prohibition while retaining markers must fail” does not split
these five mutations. It especially fails to prove permanence across generic reprocessing.

### T7.4 Response scenarios

The twenty response scenarios are similarly uninstantiated. To fail a wrong response model, paired
cases must hold the threshold movement constant while changing one load-bearing property:

- authority present versus absent;
- matured versus immature outcome;
- high versus low waiting harm;
- rollback control available versus state irrecoverable;
- same version versus material new version;
- first event versus duplicate retry;
- alert disappearance versus independent restart probe.

No such packet pairs are delivered.

**Conclusion:** properties are conceptually falsifiable; delivered artifacts are not executable
fixtures. `AUD-F07` and `AUD-F08` are `material`.

## T9 — Rare Standing Assignments

### T9.1 `refuted`

OPS-F06 says a universal linear ladder is not supported. The supplied survey does more than fail to
find one: it provides incompatible domain objects and transition logics. Clinical trials govern
statistical error and participant exposure; aviation governs unsafe-operation permission; nuclear
systems govern an engineering envelope; software governs blast radius; sunset governs time. A single
universal ordered ladder loses distinctions. The universal claim is therefore refuted.

The row could say “the universal-ladder proposition is refuted” rather than “not supported,” but its
standing is substantively correct.

### T9.2 `blocked`

INT-F17 and OPS-F14 name:

- missing item: competent institutional signer/override authority;
- effect: update/reissue/rollback/termination gates remain `NO_GO`;
- unblocker: appointment or preauthorization evidence from the relevant institution.

A universal research package cannot name the concrete ministry, DSMB, regulator or product authority
without a domain instance. The actor class is adequately specified.

**Conclusion:** rare standings correctly assigned. `AUD-F15` and `AUD-F16` are commendations.

### A12 — One-vocabulary necessity

The package’s own S13 crosswalk proves two vocabularies can coexist when they answer different
questions:

```text
SMDV-1: why may this movement inform the predictive mechanism?
S13: which accountable component/destination receives an admitted divergence?
```

The evidence supports:

- no contradictory source diagnosis for the same operation;
- no mapping that widens update eligibility;
- one versioned crosswalk with complete unresolved handling.

It does not establish:

- one owner for all cause taxonomies;
- identical terminal classes for learning and operations;
- kill-on-fork even when a tested total map exists.

**Conclusion:** semantic unity is sound; representational monopoly is overclaimed. `AUD-F10`, `minor`.

### A13 — Positive correction to the supplied orientation

The stage-1 “only truly greenfield” claim is false. S13 already has typed attribution, learning
proposal and anti-learning firewalls. The package’s narrower proposition survives because the fields
are caller/fixture-supplied and the validator checks consistency rather than deriving a movement cause.

This correction is exact and materially improves architecture. `AUD-F12` is a commendation.
