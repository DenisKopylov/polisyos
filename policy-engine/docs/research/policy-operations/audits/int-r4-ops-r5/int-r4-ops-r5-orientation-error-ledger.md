## Supplied Orientation Boundary

This ledger distinguishes four outcomes:

- `confirmed_error` — the supplied orientation asserted a fact contradicted by the pinned repository;
- `overstatement` — the orientation named a defensible concern but gave it more scope or necessity than
  the evidence establishes;
- `accurate` — the repository/source evidence supports the orientation at its stated scope;
- `not_orientation_error` — the stage-1 premise was accurate, but the research package later departed
  from it.

An orientation error matters because it can preallocate ownership, define false greenfield scope, force
one ontology, or make a later correction look like a research failure. The package deserves credit
when it corrects the architect rather than conforming to a false premise.

## Confirmed Orientation Errors

### `OR-01` — “the only truly greenfield zone”

**Orientation statement:** the deployed-learning area was the only truly greenfield zone in the
register/plan.

**Repository evidence:**

- `DivergenceAttributionClass` already defines eight typed post-deploy attribution destinations;
- `DivergenceRecord` carries class/status, evidence refs, learning eligibility, authority and closure;
- `LearningUpdateProposal` already wraps an attribution-gated learning proposal and A-before-B barrier;
- canonical S13 fixtures supply class/status and exercise several anti-learning constraints;
- DDM, monitoring, continuous governance, value carriers and Fabric branches are also real fragments.

**Disposition:** `confirmed_error`.

**Corrected statement:**

> The exact evidence-derived `MovementComparison → source diagnosis → update/response routing →
> admitted consumer` chain is greenfield/absent, while substantial adjacent types, detectors, storage,
> accountability and lifecycle fragments already exist.

**Package response:** excellent. INT-R4 §2.2 explicitly narrows the claim rather than pretending the
orientation was correct. This is `AUD-F12`, a commendation.

### `OR-02` — “one vocabulary approached from two directions” as representational necessity

**Orientation statement:** the pair has one vocabulary approached from two directions and cannot
tolerate two diagnosis vocabularies.

**Evidence:** the tasks do need consistent source semantics for update eligibility. They do not ask
only one question, and the repository already has multiple legitimate vocabularies:

- SMDV source diagnosis;
- S13 destination/component attribution;
- DDM signal/event types;
- OPS action families;
- E/X/V/C response coordinates;
- public validity statuses.

A versioned total crosswalk can preserve semantics without identical terminal classes or ownership.

**Disposition:** `overstatement` with material architectural pressure, recorded as minor package
finding `AUD-F10` because the package itself preserves S13 and action distinctions.

**Corrected statement:**

> The pair requires one governed source-diagnosis semantics, or a total tested crosswalk that cannot
> widen learning/action authority. Purpose-specific destination and action vocabularies may coexist.

## Overstatements And Forced Convergences

### `OR-03` — greenfield wording inside GY Phase 6

GY Phase 6 says “one genuinely greenfield zone” and immediately qualifies that posterior,
calibration, drift, FDR and decision-feedback primitives are reusable. The headline is therefore
stronger than the body. The package correctly treated the body as the architectural truth.

**Disposition:** same confirmed baseline error as `OR-01`; no separate finding.

### `OR-04` — cause class as necessarily single

The stage-1 framing emphasized one typed cause class before update. External evidence shows that
mature regimes frequently retain multiple contributors and sometimes cannot identify a unique
decomposition. One primary **routing disposition** can be useful, but the orientation risks implying
one physical cause.

**Disposition:** `overstatement`.

**Package response:** partially corrected through `contributing_classes` and unresolved fallback, but
then reintroduced design weight through the fixed precedence. This contributes to `AUD-F03` and
`AUD-F04`.

### `OR-05` — joint pair implies equal ontology scope

The binding relationship is real: one movement can feed operational response and effect learning.
That does not make the two authority thresholds equal. Protective containment can act on a signal or
unresolved concern under preauthorization; causal learning needs much stronger identification. A
single classifier cannot by itself carry both decisions.

**Disposition:** `overstatement` if read as one decision gate; accurate if read only as a shared input.

**Package response:** good. It separates protection from learning and earns `AUD-F18`.
