# INT-R5 Recommended Revision

## 1. Scope

This artifact specifies what would close each non-commendation finding. It is not a rewritten package,
a production design, an implementation authorization or an owner appointment.

The revision is bounded to nine findings:

```text
7 material
2 minor
```

It must preserve:

- the five-file package's research-only standing;
- `research_standing: accepted_narrow_scope` unless revision evidence refutes the model;
- `capability_standing: absent/unallocated`;
- `gate_standing: NO_GO`;
- PAO-R4 as a separate owner;
- external institutions as producers/adjudicators of their own acts;
- candidate/demo availability under typed negative institutional standing;
- immutable historical certificates and append-only correction/cure events.

The revision must not implement the capability, edit source, appoint missing holders, register final
wire vocabulary or infer a `GO` gate from an audit verdict.

## 4. Finding Closure Criteria

### 4.1 Closure of `INT-R5-A-001`

Required text property:

```text
The revised proposition permits authority_at_check == authority_at_use in unchanged histories,
while proving that t0 evidence alone cannot determine t1 authority across all admissible histories.
```

Falsifier:

```text
If the revision still entails actual inequality in every mutable regime, the finding remains open.
```

### 4.2 Closure of `INT-R5-A-002`

Required repository-comparison property:

```text
acquisition_pa2_ds9_bridge = missing
```

or, if repository state has changed before revision, the reviser must pin and inspect the new route and
prove the actual call edge. Research prose cannot anticipate a future bridge and call it current.

Falsifier:

```text
Remove the human-decision route/service from the repository comparison. If the acquisition verdict
still says the effect is PA2/DS9-protected, the claim is adjacency-based and the finding remains open.
```

### 4.3 Closure of `INT-R5-A-003`

Required denominator record:

```yaml
pin: exact commit
executor: named revision pass
entry_roots: exact routes/contracts
closure_rule: executable, documented
path_denominator: exact count and paths
file_type_denominator: exact count by type
producer_bridge_consumer_partition: complete
positive_controls:
  - known security owner reached
  - known event/artifact owner reached
  - human-decision route reached
  - acquisition effect service reached
```

Falsifier:

```text
Add or rename a direct import/call owner without changing task vocabulary. The closure must discover
it automatically; otherwise it is still a task-term sample.
```

### 4.4 Closure of `INT-R5-A-004`

The revised producer table must answer, for each decisive field:

```text
who produces the semantic fact?
who verifies issuer and content?
which provenance label does the gate use?
can the requester choose or alter it?
what exact mismatch test fails closed?
```

Minimum negatives:

- requester backdates `decision_time` into an otherwise valid interval;
- requester changes `effect_class` from irreversible to reversible;
- requester chooses a less restrictive revalidation mode;
- requester selects a jurisdiction profile favourable to the action;
- canonical bytes remain valid in every mutation.

All must refuse despite valid canonical hashes.

### 4.5 Closure of `INT-R5-A-005`

A reader with only the revised branch must be able to:

1. identify all five exact survey artifacts;
2. verify their bytes or durable archive identities;
3. locate the source passage supporting every load-bearing transferred rule;
4. distinguish survey synthesis from primary source;
5. see jurisdiction, effective/retrieval date and stated limitation.

A bibliography without claim anchors is an improvement but does not fully close the finding.

### 4.6 Closure of `INT-R5-A-006`

Required identity properties:

- every reason code is namespaced and versioned, or explicitly marked non-binding and forbidden from
  fixture oracle equality;
- local result union remains family-native;
- one owner defines the projection crosswalk to the system status lattice;
- collision scan covers existing refusal/blocker IDs;
- reason mapping never upgrades `not_established` into a positive.

Falsifier:

```text
Introduce an existing semantically equivalent code from another family. If the revised package cannot
say whether the two IDs are aliases, siblings or distinct predicates, the finding remains open.
```

### 4.7 Closure of `INT-R5-A-007`

Required formula:

```text
EffectAuthority(E, t_e) :=
    INT-R5 certificate/currentness predicates
    ∩ DS20 operation/resource/step-up predicates
    ∩ (PAO-R4 receipt if individual_case_or_pointwise_recoverable(E))
```

Required two-direction negative:

1. valid authority certificate + missing/failed PAO-R4 → no individual effect;
2. valid PAO-R4 receipt + missing/failed authority certificate → no effect.

The package must keep the two owners separate and name the component that evaluates the conjunction.

### 4.8 Closure of `INT-R5-A-008`

Required cure output:

```yaml
cure_effect:
  kind: prospective | relation_back | saved_act | limited | unresolved
  legally_effective_from: timestamp | event | unresolved
  affects_original_legal_effect: yes | no | qualified | unresolved
  historical_certificate_mutated: false
```

A relation-back profile must be representable without changing the original `authority_at_decision`
receipt.

### 4.9 Closure of `INT-R5-A-009`

Required corrected orientation ledger:

```yaml

  - GY-PA2
  - DS9
unclosed_named_consumer:
  - DS14

  - DS20 action-permission vocabulary
```

The labels may differ, but the relationship classes and arithmetic must remain separate.

## 5. Verdict-Lift Conditions

### 5.1 Lift from `GO_WITH_REVISIONS` to `GO`

A later conformance pass may issue `GO` only when:

- all seven material and two minor findings are explicitly dispositioned;
- every revision appears in the package files, not only in a revision ledger;
- severity arithmetic remains row-based and closes;
- the corrected acquisition topology is rechecked at the revision pin;
- the complete denominator is independently rerun;
- source-manifest anchors resolve;
- producer walk covers every decisive field;
- PAO-R4 two-direction negatives are specified;
- no commendation property is lost.

### 5.2 Conditions that would require `NO_GO`

A revision should receive `NO_GO` if it attempts to close findings by:

- treating acquisition adjacency as a live call edge;
- retaining a universal inequality under a renamed heading;
- keeping the ten-file sample while calling it complete;
- allowing requester-selected time/effect/profile values to become decisive through hashing alone;
- asserting branch-replayable external evidence without preserving source identities;
- registering a second global status lattice or leaving duplicate bare refusal codes;
- absorbing PAO-R4 or removing its individual-case protection;
- denying jurisdictional relation-back as a universal rule;
- upgrading capability standing or gate standing because research text improved.

### 5.3 What revision cannot accomplish

Even a conforming revision does not:

- implement `DecisionAuthorityGraph` or `DelegationValidityCertificate`;
- appoint institutional holders or adjudicators;
- create a production route or database contract;
- make the capability `contract_only` or `implemented`;
- open the first-public-signature gate;
- authorize individual decisions;
- resolve every jurisdiction-specific legal question.

The correct post-revision terminal remains an accepted research package with an absent/unallocated
capability and a closed publication/action gate until separate implementation and institutional work
exists.
