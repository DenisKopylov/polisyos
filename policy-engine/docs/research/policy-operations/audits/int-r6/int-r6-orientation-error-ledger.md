# INT-R6 Orientation-Error Ledger

## Enumeration And Counting Method

This ledger distinguishes an orientation error—looking at the wrong object, direction, holder, denominator or evidence class—from an ordinary substantive disagreement.

Rules applied:

1. every repository read is pinned to package SHA `5e47c868c2c1d4d66fa11fcddcc972dbb55e95d3`, unless the row explicitly says `b612b21272c732d53cfde8569846cfb7a0c73f5a`;
2. a set count comes from a complete tree/contents population with `truncated=false`, not code search;
3. finding count means 30 table rows in the consolidated register, not occurrences of `F-` elsewhere;
4. package file count means the eight final package blobs, not the two removed historical files;
5. connector observations are never formatted as terminal output;
6. architecture representability and repository capability are different objects.

## Corrections And Preventive Rules

- A replacement file inherits no standing from its predecessor merely by name; compare claims and evidence rows.
- Duplicate standing blocks are a population. Fixing one member does not fix the set.
- `truncated=false` is recorded with every tree population used as denominator.
- Code search is navigation only, including positives; exact file reads establish the cited coordinate.
- A finite adversarial suite has asymmetric force: one failure refutes, zero failures do not prove universality.
- “Works in the model” is written as model standing; “works in the repository” requires the full capability chain.
- Owner routing requires an accountable holder, not a discipline noun.
- An audit residual remains unresolved; it is not filled with an architect-supplied number.
- Every Stage 3 correction must change the reader-facing package artifact that carries the defect, not only a revision ledger.
