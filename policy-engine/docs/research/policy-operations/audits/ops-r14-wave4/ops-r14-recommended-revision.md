# OPS-R14 recommended revision register

## 1. Execution rule

This register describes changes to the research artifacts only. It does not authorize runtime work,
appoint an owner, choose a vendor or wire, or open the first-public gate. Each revision is complete
only when the amended branch is read back and the stated evidence is independently reproduced.

## 2. Required for standing

### R1 — separate research standing from operational capability/gate standing

**Defect.** `standing: NO_GO` and the final unqualified `NO_GO` collapse a technically coherent
research result into the repository's inability to claim or operate it.

**Required change.** In all eight artifacts, retain one bounded research-result standing
(`accepted_narrow_scope` or `GO_WITH_REVISIONS` are consistent with the delivered substance) and add
separate exact negative propositions for:

- present custody-grade capability claim;
- `DurablyVerifiableAt` positive from repository evidence; and
- first-live-public-signature gate.

The three operational propositions remain `NO_GO`/closed. Equivalent non-schema prose is acceptable.

**Execution evidence.** A complete eight-file search shows no unqualified task-level `standing:
NO_GO`; every executive/final decision states that candidate work and separately authorized building
remain allowed while capability and gate claims remain forbidden. Independent review confirms no
positive operational inference was introduced.

### R2 — narrow and register the acceptance-evidence finding

**Defect.** The report describes the baseline as accepting a runbook as “DR closeout evidence.” The
baseline passes documentation/posture/tabletop checks but does not expressly claim custody-grade DR
passage.

**Required change.** Restate the repository finding as an evidence-taxonomy defect: acceptance does
not distinguish document presence, tabletop, exercised restore and custody-grade drill. Give it a
stable local finding ID, affected baseline paths and an exact closure signal.

**Execution evidence.** The primary, orientation and drill artifacts use the narrowed wording; the
finding says closure requires either a non-green separate exercise row or a linked DE-01–DE-10 event
package. No sentence claims the existing acceptance artifact asserted RPO/RTO or PV-K01 passage.

### R3 — add a prospective watched-event timeliness/reconciliation proposition

**Defect.** WD-12 prevents timer failure from extending authority, but a watcher outage can still make
the first visible symptom a runtime refusal. That closes safety but not the commission's scheduled-
event falsifier.

**Required change.** Add one prose-only checkable requirement: for every watched right, an approaching-
expiry/due event or explicit missed-event incident must be durably present by the lead-time/expiry
boundary, and a census must reconcile rights against delivered events. State inputs, verdict and
failure consequence. Do not create a schema or new status lattice.

**Execution evidence.** WD-05/WD-12 and F-13 distinguish:

1. authority safety at use time; and
2. prospective scheduling objective.

A fixture with watcher outage returns safe refusal **and** a failed scheduling/reconciliation
predicate; a delivered event before the boundary passes it.

### R4 — extend disaster coverage for scoped succession and attacked premises

**Defect.** F-10 covers globally unresolved successor conflict, not a lawful partial split. The suite
also assumes independent governance, honest time and one canonical interpretation.

**Required change.** Add semantic fixtures equivalent to audit AF-01–AF-04:

- lawful disjoint successor scopes with disputed overlap;
- multiple stores sharing one compromised administration/root;
- authenticated/monotonic-time rollback across expiry; and
- parser/canonicalization differential after preservation migration.

Amend F-10 or cross-reference the scoped split. Each fixture must retain Given/When/Then, invariant,
detection and exact outcome.

**Execution evidence.** The fixture denominator increases by four; a static completeness check lists
every fixture; each new case has one exact non-amplifying expected result; a later independent review
can locate no blanket pass/fail over the lawful split.

### R5 — use only canonical capability labels and qualify GY-N12's contract level

**Defect.** “implemented as documentation artifacts only” is not a repository capability label.
`contract_only` for GY-N12 can also be read as a runtime type/schema claim when the evidence is a
normative plan task.

**Required change.** Replace the custom label with plain factual prose: “the five documents are
present and substantive; the recovery capability is absent/unallocated.” State GY-N12 as
“project-level semantic/plan `contract_only`; runtime capability absent/undelivered.” Preserve all
other prerequisite reasoning.

**Execution evidence.** Complete search of the eight artifacts shows every bold/inline maturity label
belongs to the repository vocabulary or is explicitly identified as non-label prose. GY-N12 has both
contract layer and runtime layer stated.

### R6 — mark procurement survival/audit/exit propositions as contract-specific inference

**Defect.** The synthesis can be read as if FAR 4.805 or Procurement Act s.98 universally makes audit
rights, exit duties and survival clauses outlive service.

**Required change.** State that the statutes/rules support durable procurement records and decision
chronology. Separately label audit rights, exit duties and survival clauses as instrument-specific
possibilities whose existence/scope must be proved from the admitted contract, statute or agreement.

**Execution evidence.** External ledger and primary synthesis contain the inference label and no
universal proposition. The contract watched-dependency row continues to require exact term/option/
notice/survival evidence.

## 3. Improvements and re-verification

### R7 — complete and retain the full byte-level source census

**Defect.** Exact high-cardinality matching-line and occurrence totals remain unestablished because the
connected interface could not walk raw bytes.

**Required change.** At the pin, run a script over every regular file under `policy-engine/src` and
report, for each of the eight literals, all-file and Python-only denominators, matching files, matching
lines, occurrences and exact path list.

**Execution evidence.** Commit or retain the script/output digests outside the research if repository
policy permits, and amend the orientation ledger with the reproduced totals. A second independent run
matches exactly. Do not use code-search candidate counts as the result.

### R8 — replace indirect external citation anchors

**Defect.** Rule 37(e) points to a general U.S. Courts rules page; FCD-1 points to a FEMA catalogue;
the cited ICO guidance path is not the clearest current live section-77 anchor.

**Required change.** Use exact document/section/PDF or permanent publication records and retain access
and currentness metadata.

**Execution evidence.** Every revised URL resolves to the exact cited instrument; source text or
metadata contains the cited identifier; the transfer conclusion remains unchanged.

### R9 — qualify “local intent cannot complete renewal”

**Defect.** The phrase can exclude a competent unilateral option exercise authorized by the existing
instrument.

**Required change.** Use “local intent alone cannot establish renewal”; state that a locally performed
unilateral exercise passes only where the instrument grants it and all scope/time/competence
conditions are proved.

**Execution evidence.** Family and contract sections carry the qualification; continued service,
payment or desire still cannot manufacture renewal.

### R10 — add anti-substitution evidence to the disconnected drill

**Defect.** “real intended paths” is not fully protected against a permissive test-only canonicalizer,
verifier, reducer or profile.

**Required change.** DE-04/DE-05 should require content identities/digests for production-target
components/configuration and one negative test showing a test-only stub or alternate permissive
profile cannot satisfy the drill.

**Execution evidence.** A drill package can prove which executable/profile ran; replacing the real
component with a stub while retaining marker strings makes the drill fail.

### R11 — cite the complete PAO-R36 F11 closure, not RP-10 alone

**Defect.** RP-10 states the central rule but depends on ordering, latest-head, fan-out and drill
clauses elsewhere.

**Required change.** In seam summaries, cite RP-10 with RC-01, RC-07, F-04, F-09 and DE-07.

**Execution evidence.** Every claim that OPS-R14 closes PAO-R36 F11 names the complete set and remains
bounded to semantic specification, not implementation.

## 4. Standing after revision

Executing R1–R6 would support a bounded positive research standing while preserving all operational
negative gates. R7–R11 improve reproducibility and auditability. None of the revisions can establish
that the repository has implemented or drilled the capability; that requires separate authorization,
institutional commitments, implementation, and retained execution evidence.
