# OPS-R15 Metric and Oracle Audit


## Executive result

The report defines `36` unique metrics. None is computable end to end from the supplied artifact because no runner, fixture manifest, receipt schema or executable oracle exists. Correctness metrics are salvageable as conjunctive properties after denominators and independent oracles are frozen. Five numeric thresholds and the RPO/RTO-derived timing criteria are unsupported and must not be Stage-0 kills.

The report names seven oracle families in §4.17 but uses 98 distinct calendar oracle-label strings and provides no registry mapping. Eight replay checkpoint rows are prose, not machine-visible input sets.

| Public record | Expected public state and material limitations for controlled surfaces | Exact states not canonical; controlled surface population absent | Benchmark invents publication lattice and can ignore omitted surfaces | Define predicates (currentness, visible limitation, successor link, as-of parity), enumerate surfaces, map via PAO-R36/Atlas owner | `cross_task_dependency_unresolved` |

## Calendar oracle-label normalization

The 98 strings in the calendar's `Oracle` column are not definitions. Create a registry where every label resolves to:

```yaml
oracle_id: stable id
family: semantic | rebuild | replay | authority | public | human | fault
artifact_ref: immutable content address
authored_by: independent role
committed_at: before implementation access
input_population_ref: immutable manifest
accepted_outcomes: predicate or finite set
ambiguity_policy: contested | unresolved | set-valued
challenge_and_supersession_ref: optional
```

No metric may consume an unresolved label string directly.

## Threshold conclusions

- Preserve zero tolerance only for closed, observable safety populations and only as conjunctions.
- Demote reuse, recompute efficiency and aggregate DR numbers to diagnostics.
- Do not average a critical semantic failure into an overall pass.
- Report uncertainty for sampled/generalized claims; the 117 fixed rows support only fixed-scenario conformance.
- Freeze denominators and allowed exclusions before first execution; any correction creates a new benchmark version with comparability notes.
