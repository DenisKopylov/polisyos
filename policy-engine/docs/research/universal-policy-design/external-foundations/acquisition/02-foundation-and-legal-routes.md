# Получение по содержанию основания; юридический маршрут

Часть [проекта](../12-acquisition-storage-and-deployment.md). Таблица покрывает полный текущий массив из 26 записей [families.json](../families.json). Это навигация исследования, не предел универсальности, обязательный checklist для каждого task или production dispatcher. Native owners — reuse targets, не утверждение о существовании сквозного producer для каждой строки.

## 2. Не пропустить основания, которые нельзя скачать

Внешний provider может дать файл, API ответ, действующий акт или доступ к среде исполнения. Есть основания, которые **ещё должны возникнуть**: новое наблюдение, эксперимент, экспертное суждение, решение уполномоченного органа, согласие, консультация. PolicyOS формирует минимально необходимый запрос/исследовательский дизайн, проверяет возможность existing route и получает receipt. Сама система не превращается в администратора программы, survey operator, суд или орган согласования.

План запроса должен назвать issuer/operator, предмет, scope, срок, допустимый канал, ожидаемый evidence и возможную альтернативу. Если authoritative answer отсутствует, выполнить доступную часть: исследовать legal basis, подготовить dossier, использовать permitted candidate assumptions/sensitivity, найти альтернативное достаточное основание. Не возвращаться с одним «нужен input», но и не создавать substitute внешнего акта. Реальная отправка сообщения/заявки требует соответствующего полномочия; нынешняя документационная работа ничего не отправляет.

## 3. Право: предварительная библиотека и runtime

**Предварительно:** source profiles издателей/юрисдикций, официальные identifiers, допустимый transport, языки, classes of acts, release/update path, rights и известные gaps. Подготовить bounded корпус для реальных потребностей и связи amendments/corrigenda/repeals; не обещать полноту мировой правовой базы. Нормы, нормы вычисления, implementation guidance, case law и policy commentary различаются по роли.

**Во время task:** сформировать LegalAuthorityRequirement с jurisdiction, lever, issuer/subject, purpose и legal `as_of`; сначала разрешить exact existing version. При gap — поиск official metadata → original publication/selected language/representation → capture → DataForge parse/structure/temporal relations → versioned legal generation → Lex selection/applicability → verifier-backed provision-to-use relation. При смене source проверить affected uses, сохраняя историческую оценку. LLM может предложить clause/mapping/translation, не удостоверить legal relation.

Конкретные starting channels:

- **ЕС:** Cellar metadata/content interfaces и официальная документация harvesting; exact CELEX/ELI/work/expression/representation selection. Search index и update feed помогают discovery, original act и изменение требуют exact retrieval. Authentication/quotas/coverage проверяются для выбранного interface; general search не bulk export. [Cellar data](https://op.europa.eu/en/web/cellar/cellar-data), [developer documentation](https://op.europa.eu/en/web/cellar/documentation).
- **Authentic publication:** использовать проверяемый electronic Official Journal и подпись/печать там, где данный выпуск и режим это предусматривают. Consolidated text полезен для чтения, но EUR-Lex прямо отличает его от актов с legal effect. Поэтому хранить связь view→original/amendments; не приписывать consolidated view самостоятельную authority. [Authenticity/CheckLex](https://eur-lex.europa.eu/content/help/oj/authenticity-eOJ.html?locale=en), [consolidated texts](https://eur-lex.europa.eu/collection/eu-law/consleg.html?locale=en).
- **Украина:** exact act ID и official detail/history/publication references на [портале Верховной Рады](https://zakon.rada.gov.ua/laws/main/index), затем официальный источник издателя/выпуска при необходимости. В исследованном пакете не установлен общий документированный API; это ограничение исследования, не утверждение об отсутствии API вообще. Не угадывать JSON endpoint. Permitted page/export/manual intake остаются отдельными маршрутами; authentication/anti-bot failure не доказательство отсутствия закона.
- **Другие страны/суды:** registered official gazette/register/case-law source; ELI/ECLI/Akoma Ntoso поддерживают идентификацию/структуру там, где publisher их использует. Сам формат не проверяет competence, legal force или faithful transformation. Добавление юрисдикции поддержанного класса — source profile; новые applicability semantics требуют Lex owner extension.

Root web read в этом раунде получил JS challenge на нескольких EUR-Lex help pages и HTTP403 на selected Rada act; Cellar documentation читалась. Official search results подтвердили различие e-OJ/consolidated texts. Эти transport ограничения записаны, не обходились и не выданы за успешную product acquisition. Перед реализацией необходимо выполнить реальный permitted source handshake, а не ссылаться на успех браузера исследователя.

## 4. Юридические время, содержание и проверка

Сохранять native time roles отдельно: adoption/signature; publication; entry into force; provision-specific application interval; transition/suspension/repeal/annulment; consolidation cut; observed/fetched/verified times; evaluation `as_of`. Нельзя вывести начало действия любой нормы из download date или единого национального default. Future-effective amendment не меняет historical result раньше своего boundary. Retrospective rule/event сохраняет source time и более позднее время нашего знания/действия; историю нельзя задним числом делать «всегда известной».

**Юридический trigger определяется правилом данного акта, а не наличием публикации.** Например, Article 297(2) TFEU связывает действие решений с указанными адресатами с уведомлением этих адресатов; authentic publication сама по себе не заменяет этот факт. [Официальный текст Article 297](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=celex%3A12016E297). Lex relation должна связать exact act/provision, применимое trigger rule, recipient/scope и проверяемое событие notification/service либо другой предусмотренный правилом commencement/condition. Если необходимое событие не установлено, соответствующее current-effect суждение остаётся `not_established`; система может исследовать условные ветви. Не вводить единую дату для всех адресатов или обязанность получать notification для актов, где она не требуется. Public act не делает private delivery receipt публичным.

Это обобщённая source→rule→event→use связь в существующих Legal/Lex owners, не новый closed enum всех правовых событий. Acquisition planner получает недостающее событие от допустимого issuer/custodian либо сохраняет явный gap; агент не заменяет его download timestamp. Негатив: опубликованный акт с неустановленным уведомлением, а также уведомление другого акта/адресата, не дают нужного effect. Подтверждённое уведомление меняет оценку в надлежащем scope и времени, сохраняя время нашего знания. Проба проектная, UNRUN. Официальный search read вернул текст Article 297; прямой ELI read в этом исследовании встретил JS challenge.

Article/annex/footnote/language expression имеют значение. Parsed date/span — проверяемое извлечение; спорная interpretation и norm→lever applicability — отдельный semantic decision. Authentic signature доказывает определённый origin/integrity claim, не законность проекта политики. Техническая валидация XML/ELI и citation existence — недостаточный proxy. Legal owner @C уже отказывает при missing source-relation verification; acquisition не должен снимать этот отказ просто потому, что теперь появился URL.

На authority gate classify каждое решающее predicate: content/span recomputed; issuer/issue binding verified/reconciled по принятому правилу; правовая применимость проверена нужным owner; source completeness `not_established`, пока нет соответствующего scoped доказательства. Bare institution-supplied field не повышается в verified predicate. Одновременно не требуется «второе учреждение, заново принимающее закон»: проверяется подлинность/компетенция/применимость оригинального акта, а не создаётся новый акт системой.

Если права на текст, перевод, commentary или remote LLM submission различаются, отдельные permissions идут за конкретными representations. Public law не делает private policy query публичным. В библиотеке допустимы общие permitted law bytes и отдельные private task mappings/assessments.

## 5. Один design task, несколько acquisition путей

Для программы помощи с отоплением заранее могут быть подготовлены official price releases, dwelling/geography dictionaries, income definitions, legal corpus и методы распределительной оценки. Runtime выясняет конкретный population/time/lever и получает missing inputs: текущий tariff vintage, local capacity, применимую редакцию нормы, custodian aggregate по домохозяйствам, сведения об implementation/take-up и mandate о целях.

Gini/Atkinson/energy-poverty branches используют согласованные, явно разные estimands и conventions; результат сравнивается как sensitivity, а не как три независимых доказательства. Недоступные microdata не заменяются invented household rows. Remote authorized aggregate может закрыть одну задачу, оставив невозможным heterogeneity analysis. Найденное исследование из другой страны не автоматически calibrates местную модель; transport assumptions отдельны.

После run сохраняются permitted source versions, reusable derived slices/method bindings и исследовательские alternatives; private source/mandate mappings остаются scoped. Следующий run сначала проверяет reusable basis, затем получает только действительный gap. Изменение закона или source coverage вызывает owner reaction, а не перезапись прошлой рекомендации.

Pattern pass: P05/P08/P10/P14/P15/P20/P25/P32/P35/P37/P38. Acceptance: substantive source relation и различия между альтернативами доходят до fresh consumer; внешний акт не фабрикуется; changed legal-time boundary изменяет только надлежащую оценку. Runtime UNRUN.
