# Первичные прецеденты и пределы переноса

Исследование для [повторного review](06-delivery-and-review.md), доступ 2026-10-21. Это выборка подходящих инженерных механизмов, не сравнительный benchmark и не утверждение, что существует одна «лучшая SOTA платформа». Читались названные разделы первичных спецификаций/документации и papers; сайты целиком не архивировались. Live URL не является immutable execution input. Выбор runtime dependency впоследствии требует exact released version и проверки фактических возможностей deployment.

Факты об источниках ниже кратки и ограничены разделами. Колонка «перенос» — **инженерный вывод PolicyOS**, а не требование автора источника и не доказательство работающей capability. Отдельные карточки `sources.json`/`grounds.json` этой волной не добавлялись: эти ссылки обслуживают review механизмов, не подменяют содержательные основания политики.

|---|---|---|

Ни checkpoint, ни event-time watermark не доказывают completeness внешнего корпуса или PolicyOS admission. |
| [Apache Iceberg Table Specification](https://iceberg.apache.org/spec/), Optimistic Concurrency / Table Metadata / Schema Evolution; live page | Metadata replacement проверяет исходную версию; immutable snapshots/manifests описывают выбранные файлы. Страница включает несколько format versions; она не закреплена за версией из navigation banner. |
| [PostgreSQL 16 §13.2](https://www.postgresql.org/docs/16/transaction-iso.html), Serializable isolation | Serializable execution соответствует некоторому последовательному порядку committed transactions; predicate locking отслеживает writes, которые повлияли бы на прочитанный набор. DB isolation помогает только внутри participating transaction; не обеспечивает полноту внешнего поиска и не запрещает будущие изменения. |

Token не даёт права сам по себе; механизм зависит от cooperating consistent store, не замораживает внешний мир и не отменяет уже раскрытые bytes. |

Требуются receiver outcome/inbox и recovery; публикация сообщения не равна admission/ack/remote effect. |
| [Temporal Event History](https://docs.temporal.io/encyclopedia/event-history) и [Worker Versioning](https://docs.temporal.io/production-deployment/worker-deployments/worker-versioning), live docs, Event History / Choosing a Versioning Behavior | Durable history позволяет replay execution state. | [Delta Lake feature compatibility](https://docs.delta.io/versioning/), live docs, Read protocol / Write protocol / Table features | Reader и writer requirements различаются; granular features определяют поддержку, не только aggregate version. | Directional operation/feature negotiation через существующих owners. Lineage описывает процесс, не устанавливает warrant или independence. |

Это сознательное ограничение PolicyOS, не дефект Arrow. |
| [W3C PROV-CONSTRAINTS](https://www.w3.org/TR/2013/REC-prov-constraints-20130430/), Recommendation 2013-04-30, §1.2 / §6 / §7 | Validity модели означает согласованность истории entities/activities и ограничений, а не общее логическое значение «validity». | Reuse provenance; отдельно проверять отношение proposition→basis→use. | [NIST SP 800-88 Rev.2](https://csrc.nist.gov/pubs/sp/800/88/r2/final), September 2025, abstract; [публикация](https://doi.org/10.6028/NIST.SP.800-88r2), выбранные §§3–4 в rights review | Sanitization рассматривает недоступность target data для заданного уровня усилий; метод и verification зависят от носителя/условий. | Заявлять exact backend/scope outcome, отдельно учитывать plaintext/key/backup copies. Это не универсальный legal-erasure verdict и не evidence об активной конфигурации PolicyOS. |
| [AWS S3 Object Lock considerations](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock-managing.html), live docs, Lifecycle / Delete markers | Delete marker не удаляет protected version; lifecycle expiration не удаляет locked version. | Разделить hidden/inaccessible/retained/deleted. | [lakeFS Data Retention](https://docs.lakefs.io/data-retention/), live docs, How they fit together | GC освобождает storage лишь без live reference и после relevant branch retention. | Root-aware retirement вместо sampled inactivity/refcount. ## Сравнение архитектурных вариантов

| Вариант | Почему недостаточен сам по себе | Выбор для PolicyOS |
|---|---|---|
| Lakehouse как единое основание | Решает версии файлов/таблиц, но не legal/scientific relation и актуальный use | Использовать pattern immutable roots в существующем CAS; новый storage engine только по реальному capacity need |
| Stream engine как custody | Хорошо поддерживает state/checkpoints; не знает полномочие, значение negative claim и public signature | Capture/frontier — вход native custody owner; snapshot/CDC guarantee остаётся source-specific |
| Workflow engine как вся lifecycle | Recovery state не равен evidence history, method validity или закрытому внешнему эффекту | Короткие attempts поверх owner duties; SQL first, engine adapter по measurements |
| Provenance/lineage graph как truth graph | Граф знает входы и трансформации; не доказывает entailment/applicability/independence | Owner-local assertion/assessment/use; shared edges связывают, не повышают authority |
| Universal deny/current/complete bit | Смешивает external observation, local receipt, use, factual truth и public projection | Native scoped outcomes + ratified status composition и PV vector |
| Один plugin ABI для любого будущего смысла | Непроверенный meaning превращается в исполнимую configuration | Data/config growth внутри уже поддержанного contract; новые transport/semantics — локальные reviewed extensions |

Системы решают разные части проблемы. Рекомендация не «установить все»: переносить проверяемый invariant в уже имеющегося владельца, измерять реальные пределы и сохранять явно неустановленные гарантии. Источник прецедента не даёт PolicyOS institutional authority и не заменяет будущий negative/removal witness.

Pattern pass: P07/P08 — versions/time; P10/P14 — lineage не adequacy; P13/P27 — не строить stack ради названий; P29/P37/P38 — конкретная гарантия вместо feature marker; P35/P36 — версии, scope и точные источники. Runtime/production verification не выполнялась.
