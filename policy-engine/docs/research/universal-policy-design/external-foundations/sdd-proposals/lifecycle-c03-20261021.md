## 1. Зачем и где

Цель — не дать прочитать «free grow» как обещание произвольной новой семантики без кода, а общий lifecycle — как обязательный pipeline/DTO для каждого источника. Второй риск — требовать внешний independent verifier для любого rebuild, хотя S0-K14 разрешает consistency checks тем же кодом.

## 2. Предлагаемый точный текст

Ниже draft текста для approval. Если одобрен, заголовок и строка standing заменяются на запись фактического принятия и ссылку на decision record; до этого блок **не копировать** в authoritative directory как adopted.

```markdown
## Proposed reading clarification — external-foundation lifecycle (C03)

Proposed only. This block is not adopted and changes no existing authority.

**C03 — free growth through supported contracts.** New external-foundation
instances should be addable as data or configuration when their required
transport, artifact, semantic and use behavior is already supported. A new
version of content does not by itself require new code. A materially new
behavior requires a local owner extension and a real producer-to-consumer
path; configuration alone cannot establish it. Demonstrate growth with a
second source of the supported class, including change, recovery and the
actual consumer, rather than only an unchanged central dispatcher.

A lifecycle diagram maps applicable owner handoffs. It creates no universal
persisted DTO, temporal envelope, status lattice, mandatory stage sequence
or duty to publish every resource. Native owners preserve meaning, time,
permission and claim reaction. Missing external grounds constrain the
dependent protected action or claim; declared candidate analysis remains
available within actual access rights.

Verification establishes its named predicate and scope. Under S0-K14,
same-code reconstruction establishes consistency, not method correctness
or scientific validity; a claim of independent validation needs the
corresponding independence evidence. Public projections retain the
separate PV-K01 dimensions, historical/current distinction and existing
disclosure limits. No new permission, currentness promise or public
verification Boolean follows from lifecycle completion.
```

## 3. Основания, варианты и стоимость

Это **уточнение чтения**, а не изменение signature boundary. Основания: S0-K03/K06/K09/K14; CTM §§2–6; identity §9; PV-K01–PV-K09; ранее принятые SDD-B01/C01/C02 и ADR-0179. Весь North Star не становится ratified целиком из-за этой вставки.

| Вариант | Disposition |
|---|---|
| Ничего не добавлять в SDD; оставить implementation research | Допустимо. Уже принятых правил достаточно; нет blocking architecture question |
| Добавить один C03 в existing owner document | Рекомендуется как краткое устойчивое разъяснение free-grow; требует вашего согласования |
| Новый governing lifecycle SDD, registry/ontology/status envelope | Отклонён: дублирует owners и создаёт governance gravity без доказанного нового требования |

Цена: implementation acceptance должен проверять реальный второй источник и change/recovery, а не только registries. Новые semantics требуют местного исследования и consumer verification. Нельзя обещать нулевые правки кода для любого будущего protocol; нельзя превращать каждый новый dataset, law version или profile instance в архитектурную комиссию.

## 4. Impact, остатки и пересмотр

- **Status/authority:** без новых enums/гейтов/authority slots; candidate band и protected-action boundary неизменны.
- **Time/replay:** CTM и sparse native records сохраняются. Никакого нового значения `current` или универсального timeless token.
- **Owners/schema:** не назначает нового owner, shared ABI, storage vendor, schema/table или workflow engine.
- **Public surface:** только ссылка на существующие PV semantics; разрешение публикации, disclosure guarantee и implementation readiness не выдаются.
- **History/migration:** append-only разъяснение; исторические claims/bytes не переписываются, runtime migration определяется выбранным owner slice.
- **Остатки:** capture/enrollment/rights/restore/long-duty/semantic-use bridges и behavioral witnesses всё ещё требуют реализации. Source-independent truth, universal legal interpretation и all-copy erasure не заявлены.
- **Revisit:** same-class additions требуют central rewrites; unknown optional metadata блокирует exploration; same-code consistency представлена как independent validation; lifecycle success становится public `Verified`; universal DTO поглощает native meaning.
