## Red-first prediction and owner design

The census's declared-but-unproduced `causal_report_ref` counterexample will
still receive the current executable `PlaybookStep` from `_step_from_invocation`.
Its existing semantic verifier will report `output_not_preserved`; the admission
consumer currently ignores it. This is the named
`gy-verifier-built-but-not-consulted-at-the-admission-seam` class, not a new search
for a defect.

Static workflow descriptions become explicitly unadmitted candidates. The
existing adapter owner performs formal applicability and one actual candidate
execution, verifies full declared-output preservation, and persists/readbacks
the actual candidate payload through the existing CAS owner. This permits reuse
of the registered `runtime_to_cas` preservation boundary honestly; a `gy://`
in-memory hash is not renamed as a CAS artifact. The source projection is frozen
before adaptation and the target comes from emitted bytes/manifests. Empty or
self-declared evidence cannot establish preservation. No output is exempted
because the real node produces it conditionally.

Only successful conformance can admit an executable step. The loop consumes
that same checked execution and cannot reconstruct an unchecked adapter as an
alternate path. Failed smoke remains visible as a typed attempted terminal and
cannot carry output authority. Existing Phase-2 proof ownership supplies the
recomputed admission evidence and C1-specific StrangleReceipt; the closed Lex
strangle is not rewritten. Adapter/playbook and proof interpretation changes
receive explicit epochs.

P01/P05/P27/P28/P29/P32/P35/P37/P38/P40 apply. Root owns playbook admission and
loop consumption; a bounded agent owns adapter/CAS preservation and its tests;
proof work and independent review run against those explicit boundaries. Shared
canonical artifacts and registry updates remain serialized. No task status is
promoted from a marker or a selected-test total.

## Engineering checkpoint

The predicted admission failure reproduced: the original constructor returned
an executable `PlaybookStep` for the nonproducing census node. Candidate discovery
now returns `CandidatePlaybookStep`. The admission owner resolves the current
node once, compares its complete typed spec and adapter contract to selection,
and calls semantic conformance on the actual input. Successful admission reuses
that one checked execution. Refusal publishes no Operation invocation, ledger
event or candidate envelope to the loop, and does not reach Foundry consumption.

Conformance verifies real CAS bytes and manifest lineage, the existing
`runtime_to_cas` preservation predicate, derived applicability and every declared
output. It persists actual applicability/conformance receipts and compares
readback to the producer payload. Caller state is isolated. Adapter operation,
adapter rule and playbook epochs move to v2; the recomputing C1 proof packet moves
from v2 to v3, with a C1-specific default-fence StrangleReceipt. The separately
closed Lex receipt is not changed.

The independent review found a deeper instance of the same typed boundary class:
removing `artifact_id` made a malformed reference look like ordinary data, so it
escaped reference traversal. This was a real error in the first repair, not a
new task. State and outcome are now reconstructed through the base-owned schema
and their actual subtype before extracting fields. The complete declared
input/output × identity-removal/scalar witness is refused, and removing that
typed validation reopens its admissions. No output name or malformed case was
exempted. The review then confirmed the actual mutating-nonproducer loop path
refuses without changing caller state or invoking Foundry.

A late review supplied another concrete discriminator in the already-required
signature binding: a node changed only `state_writes` after selection's reread
but before the smoke's initial snapshot. Its operation contract stayed equal;
the smoke passed under a different complete NodeSpec. The first consumer
accepted that report, although the proof instrument rejected it later. The
consumer and admitted-step contract now require the returned full NodeSpec and
contract hashes to equal the selected candidate before admission. The measured
report is preserved unchanged; successful smoke under the wrong signature
produces a typed admission refusal. This closes the measured boundary quantity
instead of adding a node-specific condition.

The loop-removal launcher restores only `WorkspaceLoop.run_intent` from lane
base `43580c80b`, in memory, while current tracked source and adapter markers

The canonical request was extracted from the actual Phase-2 producer, with a
