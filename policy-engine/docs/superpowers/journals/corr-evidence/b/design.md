# CORR-B research and decision recommendation

This is a design handoff, not implementation or a claim that correspondence is established. It applies only to `gy-corr`, attached `codex/corr-capability`. Research execution is recorded separately in `baseline*.json`; the first two runs are harness non-receipts caused by a wrong canonical path-dictionary key and a missing keyword-only helper argument, respectively. No production source or governed data was edited for this handoff.

## Property and owner

The required property is equality of the lever's legal subject and the norm's legal subject, in the same versioned namespace and applicable time scope. Provision existence, registry uniqueness, unit conversion and numerical truth do not decide that property (P38). The current runtime `resolve_law_bound_lever` has no subject input and emits an unknown-correspondence authority refusal only after it resolves the lever and invokes the numeric evaluator. `LawLeverResolution` requires a numeric result, so a sidecar comparison alone cannot implement missing-subject ambiguity before units.

Extend Foundry's existing validation package with the concept owner `legal_correspondence.py`. It owns the strict subject-spine artifact contract, its one canonical parser, CAS persistence and source-relative comparison. Export its candidate interface through the existing lazy `polisyos.foundry` facade. The existing numerical `constraints_engine.py` is not this owner; chronology's `VerifiedNativeSubjectIdentity` is restricted to denominator/query-context subjects and must not be relabeled a legal identity. Foundry cannot import Lex/runtime; the runtime bridge keeps the sole existing L6/owner-binding parser and resolves actual norm identities using Lex's existing store before passing typed identity bindings to Foundry.

Relevant measured source seams: `intervention_substrate.py` lines 288–355 (law types), 662–745 (real resolver), 2938–3012 (existing Lex mapping handoff); `credal_reference.py` lines 2085–2145 (law dependency handoff). Source blob identities are emitted by the corrected baseline. A complete repository-wide absence claim for all possible semantic owners is **not_established**; the bounded owner comparison above covers the actual importable chain and the relevant existing numerical/identity owners.

## Two planes and source independence

Recognition can be `passed`, `rejected`, or `ambiguous`. This lane can establish a recomputed comparison **relative to a synthetic source**. Its result and source artifact both carry `synthetic: true`, namespace/version, effective interval, exact input references/content bindings, and a scope such as `synthetic_source_relative`. It does not establish actual statutory subject meaning. Current governed authority remains `blocked`; no synthetic positive becomes an `admissible` law mapping, a confirmed credal edge, or a publishable design.

The source producer consumes separate pre-existing marked lever-subject and norm-subject annotations, not a proposed law-to-knob mapping or an expected answer. Persist those inputs and the spine before supplying any proposal. Each relation binds the actual referenced lever or norm identity and its content, not a substring or unit name. The synthetic annotations may refer to real L6/L3 identities for the real transposition control, but their assigned subjects remain explicitly synthetic. They are new annotation inputs; do not copy real manifests or store reproduced identity sets as audit evidence.

Known same-producer or proposal-ancestry overlap rejects as circular. Different producer names, CAS hashes, timestamps, or caller-provided `independent=True` cannot establish independent legal authority. CAS proves bytes and lineage, not legal truth. The synthetic producer does not impersonate the absent `CORR-B1` semantic identity owner; the latter remains a registered data/authority requirement. A same-producer marker mutation cannot unlock authority because no current path grants synthetic authority.

## Actual bridge and version decision

Use an optional typed artifact reference inside the existing hash-bound `owner_authority_manifest`; it is a binding to the existing Foundry source owner, not another artifact parser. Reuse core `ArtifactStore`/`FileSystemCAS` and the existing `.polisyos/cas` repository convention. Default runtime resolution delegates to Foundry; explicit store injection is useful for isolation, not a replacement orchestration path. Missing reference/source/subject produces a typed ambiguity before `resolve_intervention_lever` or any numeric/unit evaluation. A malformed present reference is not silently treated as absence.

Introduce a separate current law-result constant for `policyos.runtime.intervention_substrate_lift.v3`; do not bump unchanged bundle/knob/route v2 records. Current law v3 always retains `law_token` and `knob_id`, with recognition and an explicit numeric `not_run` state; resolved knob/evaluation may be absent only under the corresponding early outcome. Historical v1/v2 readers must recompute their own exact historical hashes. No old result is restamped as current.

Keep `credal_reference`'s existing incomplete law edge and every declared knob association. Its current v2 status algorithm need not change; embedding the changed law result naturally changes the reference content hash. Do not drop an incomplete association when numeric details are absent: the Phase5 empty-completion counterexample allowed CG0 to lose that dependency. The precise v2 reason/provenance projection should honestly reflect the source-relative result while retaining its authority ceiling. No generic CG0/S2 or N9 repair is proposed.

The S3 report changes to contract v3 and distinguishes complete real denominator outcomes from marked synthetic controls. A recognition success is not authoritative law/free-growth closure. Current full credal/N9 captures are not refreshed by hand: a historical readable capture remains historical until its actual owner recomputes it.

## Ordered falsifiers

1. **Red-first actual bridge:** the full real raw L6 law/knob set must reconcile against the independent owner binding registry by identities. Every missing-subject pair returns ambiguous with numeric evaluation `not_run`. Missing subject plus deliberately invalid units must still return subject ambiguity, with actual evaluator call count zero. No denominator selection based on outcomes.
2. **Source owner:** run marked independent annotations through producer → CAS → loader → comparator. Correct same-subject input passes recognition; wrong subject, unresolved identity, namespace/version mismatch, stale interval, duplicate conflicting memberships, corrupt content and circular provenance refuse or remain ambiguous. Subject values and namespaces are data, not a closed vocabulary.
3. **Decisive real transposition:** keep the independently persisted synthetic spine fixed, transpose the real budget/tax provision targets while retaining actual registry uniqueness and a numerically valid threshold, and require recognition rejection. Remove only subject comparison while retaining provenance/epoch/markers: the unchanged transposition test must go red while the correct synthetic positive remains valid.
4. **Default delegation:** the actual configured runtime bundle consumes the persisted source via its ordinary default resolver. Removing only source forwarding/delegation makes the unchanged positive go red; missing/null/forged source cannot fall back to an assumed subject.
5. **Authority handoff:** the same passed synthetic recognition remains authority-blocked through law result and the real credal consumer, retaining the whole declared knob dependency. Removing only the synthetic authority ceiling must make the consumer negative go red. If another independent permanent refusal masks that removal, assert the decisive law-admission/edge property instead of a downstream exit code.
6. **Data-only growth:** grow the real input set with a separately labeled new synthetic norm/lever/subject annotation using the same schema and no code change. Reconcile all real identities separately and retain them. Correct new recognition passes, wrong novel subject refuses; this does not replace the canonical denominator or claim real legal authority.
7. **Governed packet:** update the existing S3 recomputing validator/report owner and run its actual producer. Emit a `StrangleReceipt` for replacing the unknown-only law-recognition default with the Foundry delegation, with runtime behavior and removal probes as evidence. `--check` recomputes the report; corruption must fail. Do not construct a receipt in the test or accept marker presence as proof.
