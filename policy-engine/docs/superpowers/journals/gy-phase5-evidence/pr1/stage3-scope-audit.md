# PR1 execution-scope audit, 2026-09-08

This is an adversarial check of execution-plan D2, performed while S3 and PA1 are being
implemented. It makes no source/test/governed-artifact edits and creates no promotion receipt.
The question is whether an existing producer supplies an independently usable input for any of
the three N9 writer keys, even while N8/CG2/pilot authority stays refused. An institution's
absence is not permission to leave such a bridge unwired.

## Verdict and the limit of that verdict

**The three writers can persist honest negative evidence without a positive N8 receipt or
production CG2 binding. That mechanism is already implemented and exercised in the stage-1
production-port tests.** In particular, the existing EFFECT production-port test persists its
source and bridge, then refuses `effect_binding_authority_not_established`. A decision to do
nothing merely because the full promotion cannot succeed would be wrong.

**This audit did not establish an existing candidate-bound source that the default N9
composition could consume today.** It established concrete upstream source failures and a
loss of source objects at the actual default boundary. It does **not** establish that a generic
source adapter cannot be engineered. Preserve the residual labels `producer_missing` and
`bridge_missing`; neither a new signature slot nor an empty default context would discharge
them. D2's no-production-edit decision is defensible as avoiding a second always-empty carrier,
not as a claim that the first-promotion engineering work is completed or outside PR1.

The task remains `blocked` at its required real-candidate/near-miss outcome on the measured
governed scientific source and unestablished promotion-safety semantics. The default-source
engineering residual remains explicitly unfinished inside
`first-promotion-candidate-with-complete-evidence` / GY-PR1. A mere appointment is not its
blocker. An independently meaningful source, including a source that yields a substantive
refusal, would falsify this no-edit conclusion immediately and require wiring it without
waiting for the full positive promotion.

## What the default composition actually exposes

The actual `GenerationCycleController(repo_root=...)` creates
`CanonicalN9PromotionPort(..., context_provider=None)`. Calling its default generation port
without a model raises the typed `generation_port_missing`; supplying a model to the actual
N4 port without a substrate context returns `cycle_substrate_context_unavailable`. These are
configuration-boundary measurements, not a claim that configured production generation is
absent.

`PromotionContextProvider` is presently a callback of `(CandidateSummary, DesignProblem)`.
`CandidateSummary` carries candidate identity, current observation/refusal summaries and value
refs; it does not carry the atom/proposal, a measurement envelope or evidence portfolio.
`GenerationCycleRecord` similarly retains observations rather than the complete N4 organ
result. `GenerationUnderAResult` has a successful candidate/provenance branch and typed
dispositions; `N4GenerationPort` returns that result and discards the enclosing organ run's
Trinity bundle. A real source-carrying implementation must extend this existing owner chain,
not independently reconstruct a proposal from a hash or a receipt from markers.

The N9 default context is invoked only after the pre-N9 admitted batch resolves through its
actual epoch/open-world owners. With no admitted batch, the real production path returns
`epoch_validity_refused:pre_n9_admitted_batch_missing` before evaluating context. Moving evidence
production earlier could be engineered, but an additional always-empty intake before that
boundary is not by itself the missing candidate-evidence capability. The existing low-level
writer can already persist negative evidence when real inputs exist, as stage 1 proved.
