## GPR-A03 — build the bounded exact public owner snapshot

**Proceed to engineering.** A proposed stop for lack of a semantic model was challenged and
refuted before this decision was committed. The accepted handoff
`docs/research/policy-operations/consolidation/int-r7-r8/int-r7-r8-open-questions-and-next-research.md@034f30c64`,
**ENG-02, ENG-05, ENG-06**, assigns proof/evaluator/receipt construction to engineering.
Its “Engineering non-decisions” explicitly includes schema/API/solver selection. NXR-01 is
dormant until a concrete proof candidate fails its metadata obligation; it is not an abstract
scheduling blocker. No institution must be appointed to build and demonstrate this mechanism.

The positive proposition is: **the configured issuer issued this exact public record of
these owner-admitted assertions and statuses at the stated publication time, for the declared
bounded custody purpose and uses**. This is INT-K06's bounded custody family, not a claim
about firstness, complete public history, current policy authority or policy performance.
Bindings: `int-wave-claim-semantics-ratification.md`, **INT-K06**;
`int-r9-first-promotion-evaluation-protocol.md` §4.1–4.3 (the retired YAML is not a contract).

Source intake uses the existing root-verified Claim owner and a complete typed ledger snapshot, checked against its PUBLIC eligibility export. A persisted
packet's `claims_ref` can point to candidates; `claim_ledger_v2_ref` can be prepared but not
current. Neither presence nor status text is admission. Resolve the exact packet, its owner
root/current head, complete raw ledger and PUBLIC eligibility export. Derive custody claim IDs from that resolved
owner denominator. Refuse missing, ambiguous, candidate, changed-during-export or unverified
sources. Do not invent a second authoritative ledger with packet-to-claim projection.

For the initial profile, extraction is total over the selected raw typed owner ledger:
all field identities, JSON types, values, container membership and array order. It preserves
claims, statuses, support, provenance, limitations, lifecycle, comparisons, basis and denied uses.
The existing PUBLIC export omits raw metadata, comparisons and lifecycle material; exact equality
to that lossy view is insufficient. This second source-completeness finding is the same P37/P38
class one level deeper: widen to the raw owner denominator (P40), rather than patch an omitted field.
Initial admission requires every source claim to be PUBLIC-visible and refuses unsupported
arbitrary metadata or material redaction. It does not disclose hidden candidate claims to achieve
parity. This deliberately restricts accepted source instances; it does not weaken owner eligibility.
It performs no prose condensation. Any unsupported material alteration or redaction refuses.
Only explicitly typed reference relocation may replace private addresses with fresh opaque
public handles while preserving equality and relations; private identities remain internal.
A source requiring a broader transform is a declared bounded refusal, not an invitation to
relax parity. The authoritative source's PUBLIC eligibility rules remain intact.

The finite semantic model protects the exact source tree modulo that declared relocation.
Its verifier recomputes the full transformation rather than trusting a safe flag, expected
list or materiality assertion. Proof metadata factors through the emitted public document,
public issuer/key/purpose/rule/time and independently random record locator. Private source
refs/digests and protected values cannot select proof fields, key or linkage. The admitted
claim is bounded to this construction and its explicit observation model; it makes no
universal confidentiality or numerical disclosure claim.

PV-K01 dimensions remain separate. Issuer issuance and exact-profile faithfulness may be
established by their real signed-subject and recomputing owners. History establishment,
durability, current authority, snapshot selection and public evidence obtainability remain
independently not established unless their owners supply verified evidence. Issuance history
is retained after current authority changes (PV-K02). No complete all-green vector is needed.
PV-K03 forbids proof from minting content authority; PV-K04/05 govern preservation;
PV-K06/09 require the bounded reconstruction/metadata proof. PV-K07 controlled-prefix
claims are out of this profile. PV-K08 permits no invented canonical number.

The legacy `build_public_export_bundle` remains `projection_only`/`public_audit_only`.
Its output is not relabelled as admission. PA3's supplied fingerprint sets and S9's reference/
keyword checks are weaker than this property; their labels are not accepted as a substitute
for source resolution and total comparison (P37/P38). Detailed field rationales and readers:
[R3/R4](../research/2026-09-12-governed-public-record-projection.md).

## GPR-A04 — institutional configuration seam

The boundary ruling `policyos-identity-and-custody-boundary.md@034f30c64` §9 items 5/6 binds:
build the mechanism; leave signing typed and empty. Publication trust is separate from
verification-report trust, at the existing configuration service and runtime container.

The publication slot is a frozen typed value containing an optional Ed25519 signer, a
trusted verifier/key policy, signed institutional authorization reference, issuer identity,
verifier epoch and literal publication purpose. Empty is the production default. Configuration
loads key files and external authorization evidence; it generates neither keys nor appointments.
The authorization is a strict signed statement binding purpose, exact public content digest,
subject/owner scope, validity interval, custody interval and authority basis. The actual public signature additionally binds
exact public bytes and selected profile/rule. Signer identity and time live inside the signed
subject, not merely the unsigned signature sidecar. Resolve exact manifest/schema/bytes,
issuer/key/purpose, scope, revocation and interval; institution assertions cannot establish
mathematical parity or disclosure safety. Missing/malformed inputs refuse before issuance.

Reuse `AcquisitionAdmissionSigningSlot`'s empty/configured pattern, the existing report
service's signed-subject trust checks and core exact signed-evidence facilities. Do not reuse
acquisition purpose or `institutional_provenance.py`'s mapping-presence check as public mandate
authority. Appointing the publication signer later is configuration plus external evidence,
not a new Python type or rewrite of the consumer.

## GPR-A05 — production caller and explicit consumer changes

The existing authenticated POST `/api/v1/runs/{run_id}/public-verification-record` remains the
production caller. Add an explicit server-owned publication mode while preserving default
report-only behavior and rejection of caller documents/keys/verdicts. It resolves an owned
run and calls the admission owner. The owner persists and revalidates the signed record and
private source bindings before publishing an opaque locator. Anonymous verification GET
and the existing citizen viewer consume a distinct strict positive branch. Legacy signed
report schema/bytes and their negative checks remain unchanged.

Custody chain: `RuntimeContainer.startup` → report/governed population provider →
`ControlPlaneService` → embedded worker maintenance → `PublishedSignatureCustodyWatcher`
→ persisted scan → staleness monitor → claim lifecycle/decision validity/control outbox.
The provider must request independent admitted-member resolution from the real owner;
non-null input, report authentication and self-constructed DTOs remain insufficient.
The controlled local population does not claim globally complete publication history.

Consumer changes are explicit decisions: a new positive response branch; exact owner-backed
member intake; strict TypeScript parsing and a viewer that retains substantive status and
limitations. The advisory watcher is not weakened or made a mandate verifier. Private source
CAS addresses never appear in public proof. Trust's grounded-performance guard remains intact.
