# Core Module Documentation

## Обзор

Модуль `core` представляет собой фундаментальную часть системы PolisyOS, предоставляя основные протоколы и инфраструктуру для работы с артефактами, трассировкой, каноническим JSON и контекстами выполнения.

## Архитектура

Модуль `core` состоит из следующих основных компонентов:

```
core/
├── artifacts/     # Управление артефактами и их хранением
├── canon/         # Каноническая сериализация JSON
├── compiler/      # Отчеты компиляции и линковки
├── contracts/     # Контракты между модулями системы
├── registry/      # Сборка и загрузка реестров компонентов
├── run/           # Контексты и манифесты выполнения
└── trace/         # Трассировка и логирование операций
```

## Компоненты

### 1. Artifacts (Артефакты)

**Назначение**: Управление артефактами системы - неизменяемыми объектами с метаданными, хранящимися в Content-Addressable Storage (CAS).

**Основные компоненты**:
- `ArtifactID` - уникальный идентификатор артефакта
- `ArtifactManifest` - метаданные артефакта (производитель, схема, окружение, входы)
- `FileSystemCAS` - файловая система для хранения артефактов
- `RegistryBundle` - пакет реестров компонентов

**Функционал**:
- Хранение артефактов с SHA256 хешированием
- Верификация целостности артефактов
- Управление зависимостями между артефактами
- Поддержка различных типов артефактов (JSON, бинарные данные)

### 2. Canon (Канонический JSON)

**Назначение**: Обеспечивает детерминированную сериализацию данных в JSON формат для обеспечения воспроизводимости.

**Основные компоненты**:
- `CanonSpec` - спецификация канонизации (запрет float, сортировка ключей)
- `to_canonical_bytes()` - преобразование объектов в канонические байты
- `from_canonical_bytes()` - десериализация из канонических байт

**Особенности**:
- Запрет использования float чисел (только Decimal)
- Детерминированная сериализация с сортировкой ключей
- Поддержка Pydantic моделей и датаклассов
- Каноническое представление datetime и date объектов

### 3. Compiler (Компилятор)

**Назначение**: Управление отчетами компиляции и линковки политики.

**Основные компоненты**:
- `CompileReport` - отчет о компиляции политики
- `put_compile_report()` - сохранение отчета компиляции как артефакта
- `put_link_report()` - сохранение отчета линковки как артефакта

**Функционал**:
- Отслеживание результатов компиляции
- Ссылки на скомпилированные артефакты (программа-граф, план исполнения)
- Управление входами и выходами компиляции

### 4. Contracts (Контракты)

**Назначение**: Определяет контракты взаимодействия между различными модулями системы.

**Основные компоненты**:
- **Fabric контракты**: `QueryPlan`, `EvidenceBundle`, `FabricResult`
- **Foundry контракты**: `ProgramGraph`, `ExecPlan`, `LoweredIR`, `StateDelta`
- **Compiler контракты**: `CompileReportRef`, `LinkReportRef`

**Функционал**:
- Стандартизация интерфейсов между модулями
- Определение структур данных для обмена информацией
- Обеспечение типобезопасности при межмодульном взаимодействии

### 5. Registry (Реестр)

**Назначение**: Управление реестрами компонентов системы (механизмы, метрики, ограничения и т.д.).

**Основные компоненты**:
- `build_registry_bundle()` - сборка пакета реестров
- `load_registry_bundle()` - загрузка пакета реестров
- `RegistryBundleContent` - содержимое пакета реестров

**Функционал**:
- Автоматическая сборка стандартных реестров из IR-модуля
- Сохранение реестров как артефактов
- Загрузка и валидация реестров компонентов

### 6. Run (Выполнение)

**Назначение**: Управление контекстами и манифестами выполнения операций.

**Основные компоненты**:
- `RunContext` - контекст выполнения с трассировкой
- `RunManifest` - манифест выполнения (метаданные о запуске)
- `new_run_id()` - генерация уникальных ID запусков

**Функционал**:
- Инициализация контекстов выполнения
- Управление жизненным циклом запусков
- Интеграция с системой трассировки
- Хранение результатов выполнения

### 7. Trace (Трассировка)

**Назначение**: Система логирования и трассировки операций для отладки и мониторинга.

**Основные компоненты**:
- `TraceRecord` - запись трассировки с временными метками
- `TraceSink` - интерфейс для вывода записей трассировки
- `JsonlTraceSink` - реализация вывода в JSON Lines формат

**Функционал**:
- Структурированное логирование операций
- Поддержка распределенной трассировки (span_id, parent_span_id)
- Ссылки на артефакты в записях трассировки
- Метрики и предупреждения в записях

## Связи с другими модулями

### Зависимости от Core:
- **fabric**: использует `artifacts`, `contracts.fabric`
- **foundry**: использует `artifacts`, `contracts.foundry`, `trace`
- **ir**: использует `canon` для канонической сериализации
- **scientist**: использует `run` для контекстов выполнения

### Обратные зависимости на Core:
- `core` является фундаментом, большинство модулей зависят от его компонентов
- `artifacts` используются во всех модулях для хранения результатов
- `trace` интегрируется в контексты выполнения
- `contracts` определяют интерфейсы для всех модулей

## Примеры использования

### Создание контекста выполнения:

```python
from polisyos.core.run import RunContext
from polisyos.core.artifacts.store import FileSystemCAS

# Инициализация хранилища
store = FileSystemCAS(Path("/path/to/store"))

# Создание контекста выполнения
ctx = RunContext.start(
    store=store,
    registry_bundle=registry_ref,
    producer=ProducerInfo(component="my_component", version="1.0.0")
)

# Использование контекста для трассировки
ctx.trace.emit(TraceRecord(
    run_id=ctx.run_manifest.run_id,
    phase="processing",
    event="data_loaded",
    metrics={"records": 1000}
))
```

### Работа с артефактами:

```python
from polisyos.core.artifacts.store import FileSystemCAS, PutOptions
from polisyos.core.artifacts.manifest import SchemaInfo

# Сохранение данных как артефакта
artifact_ref = store.put_json(
    {"data": "example"},
    PutOptions(
        kind="example.data",
        media_type="application/json",
        schema=SchemaInfo(name="example.schema", version="1.0")
    )
)
```

### Каноническая сериализация:

```python
from polisyos.core.canon import to_canonical_bytes, from_canonical_bytes
from decimal import Decimal

data = {"amount": Decimal("123.45"), "timestamp": datetime.now()}
canonical_bytes = to_canonical_bytes(data)
restored_data = from_canonical_bytes(canonical_bytes)
```

## Заключение

Модуль `core` предоставляет фундаментальную инфраструктуру для всей системы PolisyOS, обеспечивая:

- **Надежность**: через систему артефактов с проверкой целостности
- **Воспроизводимость**: через каноническую сериализацию
- **Наблюдаемость**: через систему трассировки
- **Модульность**: через контракты между компонентами

Все компоненты модуля спроектированы для работы в распределенной среде и обеспечивают высокую степень надежности и отслеживаемости операций.
