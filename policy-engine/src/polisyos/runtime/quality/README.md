# Runtime Quality

- Last updated: 2026-10-17

`polisyos.runtime.quality` owns Policy Design Case runtime-quality artifacts:
the canonical quality-report role/file/ref map lives in `report_registry.py` so refs, scorecards, and canary assembly share one intake set.
authority/status composition, evidence and claim binding, replay, closeout
checks, and audit-oriented exports.

This package may orchestrate producer-backed signals, but it does not make LLM
output, corpus stubs, simulations, or historical priors into current evidence
authority by itself. Those paths remain candidates, caps, context, or replay
inputs until a producer-owned capability admits them.

Phase-barrier records remain candidate diagnostics until each required record is
produced and bound to the current run. The live NL control-job path persists an
owner binding only after reconciling the admitted creation event and active
lease. Terminal progress replacement runs one store-owned policy under that
same worker fence: it rederives the owner binding, then carries only typed
candidate projections present on the current row. This includes a matching
`RunIntentBinding`, runtime quality ref and selected-artifact maps, the
projection-only marker, trust-boundary attestation records, flattened role refs,
and diagnostic summary projections. Conflicting caller copies are refused;
current-row absence stays absent, and prior `details`/phase state is replaced.
The private local-canary assembler recomputes the owner from the current job
row, creation scope, terminal lifecycle event and completion outbox, indexed
Core run, and a fresh typed job GET inside the active runtime-client lifespan
for each serious scorecard decision.
The public `build_quality_scorecard` API remains mapping-only and fails closed;
a matching map, proof-shaped payload, or self-reported producer label cannot
replace the source join. The carried refs and attestations remain candidate
inputs that their existing consumers must validate; diagnostic summaries are
projections only. The normal NL `RunIntentBinding` still has absent
`time_context_ref` and `same_input_closure_ref`, and serious readiness stays
blocked. Missing time and barrier producers/artifacts remain
`producer_missing` and `artifact_missing`; standalone consumers fail closed.

## Selected HTE source content join

`hte_source_projection.py` joins one frozen HTE input to its exact selected
source-assignment, profile, projection, and array bytes. The existing Runtime
completion-outbox receiver injects this verifier through Scientist's typed
`SearchHTESourceProjectionVerifier` contract; Scientist does not import Runtime.
Missing verification leaves the native number intact with unavailable routing.
Its row reconstruction
uses `generation_cycle._value_owner_rows_from_source_rows`, the same intake as
the catalog ValueOwner loader: ambiguous unit-period cells, conflicting or
missing declared units, and mixed source datasets are refused. Optional join
refusals leave an independently verified point/native interval intact and make
candidate routing unavailable. The join establishes selected-snapshot internal
consistency only. It does not re-resolve active catalog receipt/passport
issuance, assign country-scope or unit conversions, establish source time, or
authorize roles. Ordinary admission transport and earlier-funnel wiring remain
separate bridge work.

schema epoch: absent historical fields remain absent and explicitly stored nulls
remain null. Ordinary `model_dump(mode="json")` is the complete DTO view and may
materialize defaults introduced after a legacy epoch; do not use it as a legacy
history write or reissue source. Every registered v2-v7 comparison owner rule uses this same historical
projection before applying its frozen typed profile, so absent legacy defaults
cannot change a stored comparison hash. The current v8 projection remains

Rule replay lives in `rule_replay_engine.py`. Closed cases should replay through
their stored rule, capability, and data references, and C33 rule-change classes
must produce explicit revalidation triggers rather than silently changing old
closeout meaning.

  simultaneous writes before invoking a selected engine. Duplicate writes merge

  any engine candidate, it compares the exact validated `HorizonSpec.steps()` grid

  check; it does not establish a physical origin, unit, or World Model temporal binding.
  It refuses missing,
  malformed, or non-finite selected outcomes, and projects only returned

  summary values do not fill its missing rows, and a run-level scalar without a
  time series is not repeated over a multi-step horizon. Dynamic trajectory diagnostics

  `queue/time` into a typed candidate trace after checking row count and queue-value
  correspondence. Its unit, origin, and relation to the requested horizon remain
  `not_established`. Only Python and NumPy integer/floating scalars are candidates;
  strings, booleans, complex values, and array/container shapes remain malformed, while
  missing fields remain distinct.
  No temporal diagnostic confers evidence authority. Persisted results label the numeric
  outcome-minus-request-baseline subtraction and comparator refs
