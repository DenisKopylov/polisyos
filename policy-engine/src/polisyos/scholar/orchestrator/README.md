# Orchestrator: Оркестратор процесса обогащения знаний

Модуль **Orchestrator** реализует основной пайплайн обогащения знаний, координируя работу всех компонентов системы Scholar для преобразования сырых источников данных в структурированные пакеты знаний.

## Архитектура

### Основные компоненты

- **`enrich.py`** - Основной оркестратор процесса обогащения
- **`bundle.py`** - Формирование и сохранение пакетов знаний
- **`__init__.py`** - Экспорт функций модуля

## Функционал

### Основной API обогащения

```python
from polisyos.scholar.orchestrator import enrich_topic

result = enrich_topic(
    cas=cas_store,
    fact_log_root=Path("/logs"),
    intent=research_intent,
    db=simulation_db,
    policy=scholar_policy
)
```

## Пайплайн обогащения

### 1. Валидация и подготовка
- Проверка параметров исследования
- Применение бюджетов и ограничений
- Инициализация политик обработки

### 2. Обнаружение источников (`discover`)
- Нормализация источников из `intent.sources`
- Дедупликация и ограничение количества
- Подготовка к получению данных

### 3. Получение данных (`acquire`)
- Параллельное получение данных из источников
- Обработка ошибок для каждого источника
- Фильтрация по бюджетам (размер, количество)

### 4. Обработка документов (`docs`)
Для каждого документа:
- **Нормализация** - приведение к стандартному формату
- **Структурирование** - выделение заголовков, секций
- **Чанкинг** - разделение на фрагменты для анализа
- **Сохранение** артефактов в CAS

### 5. Извлечение утверждений (`claims`)
- **Парсинг** фактов из документов с помощью экстракторов
- **Нормализация** утверждений к стандартной форме
- **Группировка** связанных утверждений
- **Оценка качества** извлеченных данных

### 6. Разрешение конфликтов (`reconcile`)
- **Обнаружение** противоречий между утверждениями
- **Применение политик** разрешения конфликтов
- **Выбор победителей** на основе доверия и качества
- **Документирование** решений

### 7. Оценка доверия (`trust`)
- **Анализ надежности** источников
- **Присвоение уровней** доверия (LOW/MEDIUM/HIGH)
- **Генерация отчетов** оценки доверия

### 8. Формирование пакета (`bundle`)
- **Сбор метаданных** всех артефактов
- **Генерация ID** пакета на основе содержимого
- **Создание отчета** обогащения
- **Сохранение** в хранилище и базе данных

## Ключевые структуры данных

### `EnrichResultV1`
```python
@dataclass(frozen=True)
class EnrichResultV1:
    knowledge_bundle_ref: KnowledgeBundleRef
    bundle_id: str
    report: EnrichmentReportV1
    report_ref: EnrichmentReportRef | None = None
```

### `KnowledgeBundlePayloadV1`
Структурированный пакет содержащий:
- Метаданные документов и источников
- Извлеченные утверждения и их артефакты
- Разрешенные конфликты
- Оценки доверия
- Отчеты качества
- Использованные политики

## Политики и бюджеты

### Управление ресурсами
- **Документы**: ограничение количества и общего размера
- **Утверждения**: лимиты на количество извлекаемых фактов
- **Время**: таймауты на операции получения данных

### Качество и доверие
- Минимальные уровни доверия источников
- Параметры обработки документов (чанкинг, нормализация)
- Настройки экстракторов утверждений
- Политики разрешения конфликтов

## Интеграция с другими модулями

- **`core.contracts`** - типизированные контракты

## Особенности реализации

### Параллельная обработка
- Одновременное получение данных из нескольких источников
- Пакетная обработка документов
- Оптимизированные алгоритмы дедупликации

### Отказоустойчивость
- Продолжение работы при ошибках отдельных источников
- Детальное логирование всех операций
- Сохранение промежуточных результатов

### Аудит и трассировка
- Полный лог всех операций с временными метками
- Content-addressed артефакты для воспроизводимости
- Детальные отчеты о каждом этапе обработки

### Производительность
- Потоковая обработка больших объемов данных
- Кеширование промежуточных результатов
- Оптимизированные алгоритмы сравнения и дедупликации

## Метрики и отчетность

### Отчет обогащения (`EnrichmentReportV1`)
Содержит статистику по:
- Количеству обработанных документов
- Извлеченным утверждениям
- Разрешенным конфликтам
- Оценкам доверия
- Качественным метрикам

### Агрегированные данные
- Распределение источников по типам
- Статистика ошибок по этапам
- Метрики производительности
- Сводка использованных политик
